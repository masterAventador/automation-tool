## 0. 先说这份清单不覆盖什么

一份清单最危险的时刻不是它漏掉了什么，而是别人以为它覆盖了。

- **不覆盖好不好用**。只覆盖「能不能跑起来、会在哪一步停」。文案质量、画面是否贴题、成片好不好看，一律不判断。
- **不覆盖断网**。断网就是演示失败，没有离线降级路径。本清单只验「现在通不通」，验不出「演示中途会不会断」。
- **不覆盖抖音平台侧的变化**。平台改版、风控弹窗、二维码过期都在清单之外，只能现场人工接管。
- **不是回归测试**。它不替代任何门禁，只回答「明天能不能演」。
- **不覆盖 Windows**。本轮演示形态是 macOS 正式包。Windows 侧另行验收（见 §D）。

## 1. 怎么读这份清单

每条格式固定：**做什么 → 命令或点击路径 → 期望看到什么 → 不对时怎么办**。

| 标注 | 含义 |
| --- | --- |
| `[本机]` | 在开发机上做，结论对演示机同样成立（例如包的签名判定——包是同一个文件） |
| `[演示机]` | **必须在演示当天真正要用的那台 Mac 上做**，本机做了不算数 |
| `[服务器]` | 在云端服务器上做 |

**排序原则：越早发现越省事。** 本清单不按模块排，按「这条如果挂了，补救要花多久」排：

| 阶段 | 什么时候做 | 挂了的补救成本 |
| --- | --- | --- |
| **A 段** | 演示前 2–3 天，**还来得及重出包** | 重新构建 + 签名 + 公证，以天计 |
| **B 段** | 演示前一天，在演示机上 | 以小时计（重扫码、重配密钥、清盘） |
| **C 段** | 演示当天开场前 10 分钟 | 只能取消或改脚本 |

**A 段任何一条不过，都不要往 B 段走。** 拿一个坏包去演示机上折腾一整天，是最糟的时间分配。

## A 段 · 还来得及重出包（`[本机]` / `[服务器]`）

### A1 ⚠️ 包内两个 Node 运行时能真的跑 JavaScript

**这条排第一，因为它是本轮唯一一条「挂了就必须重出包、且所有浅层检查都会骗你」的缺陷。**

2026-07-26 发现：`release_assembly.py` 给包内每个 Mach-O 加 `--options runtime`（硬化运行时）重签，而签名契约只为 `embedded-browser` 声明了 entitlements。两个 `node` 于是带着硬化运行时、没有 `com.apple.security.cs.allow-jit`，**V8 在 `Isolate::Init` 阶段拿不到可写可执行页，直接 abort（exit 133）**。

后果不小：Playwright 起不来 = **全部浏览器 RPA 不可用**（抖音登录、发布都死）；`motion-video-worker` 的 node 同样 133 = **品牌动效成片不可用**，而那正是本次选定的演示线。

**做什么**：把要交付的那个 App 装出来，对包内**每一个** `node` 求值一个表达式。

```bash
APP="/Applications/自动化运营工具.app"          # 换成实际路径
find "$APP/Contents/Resources" -name node -type f -perm +111 | while read -r N; do
  OUT=$("$N" -e 'console.log(1)' 2>&1); RC=$?
  echo "rc=$RC  out=${OUT:0:40}  $N"
done
```

**期望**：找到 **2 个** node，每个都 `rc=0` 且 `out=1`。

- `Contents/Resources/motion-video-worker/package/runtime/node`
- `Contents/Resources/local-executor/package/_internal/playwright/driver/node`

**⛔ 不要用 `node --version` 当判据。** 它在 V8 初始化前就打印退出，**坏包也能过**。这正是这个缺陷躲过所有检查的原因。

**✅ 2026-07-26 实测（在当时已安装的旧包上，用来验证判据本身有效）**：

```text
# 坏包 —— 求值探针
$ .../motion-video-worker/package/runtime/node -e 'console.log(1)'
rc=133          # 无任何输出

# 同一个二进制 —— 版本探针（会骗人的那个）
$ .../motion-video-worker/package/runtime/node --version
v22.23.1
rc=0

# 坏包 —— 执行器那个 node 的真实报错
Fatal process out of memory: Failed to reserve virtual memory for CodeRange
  ... v8::internal::Isolate::Init(...)
rc=133
```

**当时那个包同时满足 `spctl → accepted / source=Notarized Developer ID`。签名和公证全绿，功能是死的。**

**不对时怎么办**：**没有现场补救，必须重出包。** 修复已提交（`41a19d8`：补 entitlements + 新增 `scripts/check_packaged_javascript_runtimes.py`，已接进 `build_release_package.py` 的审计段，位置在签名之后、公证之前）。在开发机上也可以直接跑门禁脚本：

```bash
python3 scripts/check_packaged_javascript_runtimes.py "$APP"
```

期望：打印出它实际执行的每一个路径，然后通过。（该脚本把「一个 node 都没扫到」也判为失败——扫不到而报成功，是本仓库反复出现的形状。）

> **🚩 待确认（阻塞级）**：截至本文件编写时，`/Applications` 下那个包是**修复前**的坏包，且 `.local` 下**没有任何新 DMG**。**带修复的新包是否已构建、签名、公证完成，必须由发版线确认。** 在拿到新包并通过本条之前，整个演示处于「核心链路已知不可用」状态。

### B1 系统、芯片、磁盘

```bash
sw_vers && uname -m && df -h /
```

**期望**：`arm64`；**可用空间 ≥ 20 GB**。

**判据来源**：包约 510 MB 量级，安装后还要展开内置 Chromium、媒体工具链和两个视频 Worker，加上渲染中间产物与成片。另外 `ensure_free_space` 硬性要求「1 GiB + 视频大小」，不够时**导入成片会失败**——界面报错不是闪退，但演示当场就挂了。20 GB 是留了余量的保守线。

**不对时怎么办**：
- 不是 arm64 → 包的架构必须重新确认，macOS 验收是分 arm64 / x86_64 两条线的。
- 磁盘不够 → 清盘。**磁盘满会在渲染中途炸，是最难看的失败形态**（前面全绿、最后一步失败）。

### B2 两条零成本预检（来自 T61 启动 abort 风险调研）

App 的启动 setup 里有 **23 个 abort 点**，其中 21 个在 setup 钩子里——失败时**窗口先出现再瞬间消失，没有任何提示**，而且**结构上救不了**：Tauri 是先建窗口后跑 setup，setup 占着主线程，WebView 的 JS 一行都执行不了，所以那个 fail-closed 诊断页覆盖不到启动失败本身。

下面两条覆盖了风险表里除「强退」外的全部剩余风险，**不改代码、零成本**：

```bash
# 1) 磁盘空闲 > 5 GiB（B1 的 20 GB 已覆盖，这里是下限）
df -h /

# 2) 祖先目录没有软链
ls -ld /Users "/Users/$(whoami)" ~/Library ~/Library/Application\ Support
```

**期望**：四行**都不是 `l` 开头**（不是 symlink）。

**✅ 2026-07-26 实测（开发机）**：

```text
drwxr-xr-x   5 root       admin   160 Apr 15 01:18 /Users
drwxr-x---+ 59 aventador  staff  1888 Jul 26 19:52 /Users/aventador
drwx------@ 90 aventador  staff  2880 Jul 10 00:16 /Users/aventador/Library
drwx------+ 77 aventador  staff  2464 Jul 26 20:47 /Users/aventador/Library/Application Support
```

**不对时怎么办**：出现软链就换一个账号或换一台机器演示。**代码里这条是硬拒绝，没有开关能绕过。**

**为什么这两条值得做**：风险表里概率最高的一档是 **「Time Machine / 迁移助理恢复的账号」**——这类账号会造出带 group/other 权限位的密钥文件，而 `secure_store.rs:182` 对文件**只检查不修复**，结果是**启动即闪退、零提示**。领导的机器是不是从旧机迁移过来的，值得当面问一句。

### B7 抖音扫码登录（最容易被漏掉的一条）

**点击路径**：左侧「平台状态」→ 抖音卡片 → 点「**打开登录处理**」→ 在弹出的运营浏览器窗口中扫码 → 手机抖音确认。

**期望**：状态标签变为「**登录正常**」。

**然后必须做第二步**：**完全关掉 App 再打开**，回到「平台状态」，确认仍是「登录正常」、不再要求扫码。

**为什么必须提前一天做**：
1. 演示机的数据目录与开发机隔离，**开发机上登录过完全不算数**；
2. 抖音登录态是**按 Installation 记在服务端的**，**本地复制 cookie 文件无效**；
3. 现场扫码要掏手机、找入口、对二维码，**二维码还会过期**。这是演示最容易翻车的一步。

> ⚠️ **本机上有一个会骗人的东西**：开发期的抖音浏览器档案（UUID `df1c89f0-…`，Cookies 时间戳 2026-07-26 02:38）**被复制到了** `profiles/demo-xuanbai/embedded-browser-profiles/douyin/` 下（两边 inode 不同，确认是拷贝不是链接；产品代码里没有任何迁移逻辑，所以这是人手工复制的）。
>
> **它看起来像一份登录态，但它不是** ——登录态在服务端按 Installation 记账。**不要因为看到这个目录里有 Cookies 就以为抖音已登录**，必须以界面上的「登录正常」为准。

**不对时怎么办**：重新扫码。**如果 A1 没修（node 跑不了），这一步必然失败**——界面会报「暂时无法读取抖音登录状态，请稍后重试」，因为浏览器根本起不来。先回去修 A1。

### B8 ⚠️ 完整彩排一次：一句话 → 成片播放

**这是整份清单里唯一能证明「演示内容真的能跑通」的一条。前面全绿都只证明环境和包是好的。**

**点击路径**（与演示当天完全一致）：

1. 左侧「**视频制作**」
2. 「新建视频」标签页 → 在「选择制作方式」里选「**品牌动效成片**」
3. 上方出现「**一句话自动制作**」卡片 → 在输入框里写一句描述（**上限 500 字**）
4. 点「**开始自动制作**」
5. 提示「已提交一句话自动制作，可到"制作任务"查看进度。」
6. 切到「**制作任务**」标签页看进度：`准备中 → 逐帧渲染中 → 正在合成视频 → 已完成`
7. 切到「**成片**」标签页 → 点「**播放成片**」

**期望**：拿到一段**能播放的、画面在动的** mp4。

**已知固定值**（界面已明示）：**片长固定 12 秒**（= 默认 3 段 × 每段 4 秒，来自 `contracts/video/motion-storyboard-duration.v1.json`）。一句话入口**不能改片长**，界面会提示需要别的长度请用下面的「固定模板手工制作」。

**耗时基线（开发机，debug 构建）**：**3 分 34 秒** = 编排 178 秒 + 渲染编码 33 秒。成片 360 帧 / 12.000 秒 / h264 640×360。

**⚠️ 必须用秒表记下演示机上的实测秒数，写进 `docs/demo-runbook.md`。** 演示机没有基线，本条不给期望值，只要求记录。**演示最怕的不是慢，是演示者不知道要等多久而开始反复点击。**

**顺便在彩排时确认三件 runbook 需要的事**：

- [ ] 提交后**切到别的页面再切回来**，任务还在跑、进度还在更新吗？（runbook 的 3 分半填充方案依赖这个）
- [ ] 编排那 178 秒里界面显示的是什么状态文字？演示者要知道那不是卡死。
- [ ] 成片能播放后，**把这一条成片留在机器上**，演示当天作为兜底素材。

**不对时怎么办**：

| 现象 | 大概率原因 | 动作 |
| --- | --- | --- |
| 提示「请先到"设置与诊断"配置视频创作模型服务」 | 密钥没存 | 回 B6 |
| 「本机渲染组件暂时不可用」 | `media-toolchain` 或 `motion-video-worker` 缺失 | 回 A3 |
| 任务直接失败、无有效输出 | **`node` 跑不了（exit 133）** | 回 A1，**必须重出包** |
| 「这条成片的画面自始至终没有变化…」 | 静图门禁拦下，描述太空泛 | 换一句更具体的描述重试 |
| 导入成片失败 | 磁盘不足 1 GiB + 视频大小 | 回 B1 清盘 |
