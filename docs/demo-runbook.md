# 客户演示当天 Runbook

> 用途：演示当天拿着它照做。每一步写清**说什么、点什么、用户看到什么、要多久**，以及**这一步挂了怎么办**。
>
> 配套文件：`docs/demo-preflight-checklist.md`（演示前逐项检查）。本文件假设那份清单已经全绿——**没跑完清单就别照这份 runbook 开演。**
>
> 初版 2026-07-26；**2026-07-27 随清单一起重核（T70）**。当晚到凌晨主线合了四十笔改产品界面的提交，本文件里基于旧行为的点击路径、讲解词和时间编排都已改对。变了的地方用 `〔07-27 改〕` 标出，并写清原来是什么。

## 0. 一页纸速查

| 项 | 值 |
| --- | --- |
| 演示形态 | **品牌动效成片**：一句话 → 一段 12 秒会动的 mp4 |
| 全程时长 | 约 **11–14 分钟**（含约 2–3 分钟生成等待） |
| 唯一的长等待 | 一句话生成：中位数 **124 秒**，实测最长 **178 秒**，7/7 成功（开发机基线） |
| 对客户怎么说 | **「大概三分钟」**。心里按 **4.5 分钟**准备——实测最大值随样本数单调上涨（121→146→178），右尾没探到底 |
| 演示机实测耗时 | ⬜ **_____ 分 _____ 秒**（彩排时填，见清单 B8） |
| 兜底素材 | 彩排时生成的那条成片，留在「视频制作 → 成片」页 |
| 出事找谁 | ⬜ **_____________**（填现场技术支持的联系方式） |

**三条铁律**

1. **不要临场改任何设置。** 演示机上的每一项配置都是前一天验过的，改了就没人知道还成不成立。
2. **不要点 §4 列出的任何禁区功能。**
3. **卡住超过 30 秒就走降级路径（§5），不要在客户面前 debug。**

〔07-27 改〕耗时那两行原来写的是「约 3 分 34 秒」，并把它当成典型值。**那是单次最坏样本**，而且当时跑的是 debug 构建的 `control-plane-e2e`，不是这条演示链路。七次连跑的真实分布是 85 / 124 / 178 秒（最小 / 中位 / 最大），所以全程时长跟着从 12–15 分钟收到 11–14 分钟。新增「对客户怎么说」一行，因为**讲出去的数字和内部基线不该是同一个**——内部要记中位数，对外要留余量。

## 2. 演示脚本

### 幕 0 · 打开与定位（约 1 分钟）

**动作**：打开 App，停在工作台。

**说什么**（大意，不必逐字）：

> 这是一个本地运行的运营自动化工具。它装在您自己的电脑上，浏览器操作、视频渲染都在本机完成，账号和素材不上传第三方。左边这几项是它现在能做的事——今天重点看「视频制作」这一块。

**用户看到**：左侧八项导航（工作台 / 新建任务 / 任务记录 / 视频制作 / 视频剪辑 / 作品发布 / 平台状态 / 设置与诊断）。

首页的「最近任务」每行叫「**07-26 21:33:53 的任务**」这种按时间的名字——可以顺口带一句「每次跑过什么都留着记录」。

**⚠️ 这一幕里不要点开「视频剪辑」**，理由见 §4。

**⚠️ 也不要展开首页下面那个「诊断信息」**。它折起来是有意的：里面是 `Revision`、`事件水位` 这类给排查用的字段，展开只会请客户问一个你不想在这里回答的问题。

**失败预案**：App 打不开或白屏 → 直接走 §5 降级路径 A。**不要在客户面前反复双击。**

〔07-27 改〕补两句。`T93`（`ec17ae0`）把首页的 `Revision` / 事件水位折进了默认收起的「诊断信息」，最近任务也从裸 UUID 改成了按创建时间的名字——**前者是新增的一个别点它，后者是新增的一个可以顺口讲的点**。原文两样都没有，因为当时首页还不长这样。

### 幕 1 · 提交一句话（约 1 分 30 秒）

**这一幕要尽早做完，因为幕 2 的等待要靠它开始计时。**

**点击路径**：

1. 左侧「**视频制作**」（默认就停在「**新建视频**」标签页）
2. 页面下半部分「选择制作方式」里，点那张卡片上的「**选择品牌动效成片**」按钮
   　→ 按钮上写的是完整的「选择品牌动效成片」，两张卡片各有一个，**别点成旁边那张**
3. 页面**自动把「一句话自动制作」卡片滚进视野**（不用自己找）
4. 在输入框里写一句描述（**上限 500 字**，写一句就够）
5. 点「**开始自动制作**」
6. **App 自己跳到「制作任务」标签页** —— 不要再去手动切

**说什么**：

> 我不需要写脚本、不需要挑素材、不需要自己剪。我只要用一句话说清楚想要什么，剩下的分镜、文案、画面都由模型生成，渲染在这台电脑本地跑完。

（点下按钮后）

> 它现在开始工作了，大概三分钟——模型要先把这句话拆成分镜、文案和整套画面，然后本机一帧一帧渲染出来再合成视频。您看这里有个计时器，它自己会说这次跑了多久、正常范围是多少。

**用户看到**：页面自动切到「制作任务」，上面一行走字的状态：

```text
正在自动编排这条视频 · 已用 0 分 8 秒 · 通常 2 分钟左右，最长约 3 分钟
```

**这行字是你的朋友，指给客户看。** 它同时回答了「还活着吗」和「这算正常吗」——不用你去解释。

超过 178 秒之后它会自己换成「已经超过实测最长的 3 分钟，可能是视频创作模型服务没有回应」。**那不是失败通知**，是它诚实地说「超出我见过的范围了」。真到了那一步，按 §5 降级路径 B 处理。

**关键信息（要主动说，别等客户问）**：

> 这个入口生成的是**固定 12 秒**的片子。需要别的长度，用下面那个「固定模板手工制作」，段数和每段时长都能自己调。

**为什么要主动说**：界面上已经明示了这一点，客户自己会看到。**由你先说出来，是产品有边界；被客户先发现，是产品有缺陷。**

**失败预案**：

| 现象 | 现场怎么办 |
| --- | --- |
| 提示「请先到"设置与诊断"配置视频创作模型服务。」 | **不要现场配密钥。** 直接走 §5 降级路径 B（放彩排成片） |
| 「本机渲染组件暂时不可用」 | 走 §5 降级路径 B |
| 「自动编排没能完成…视频创作模型服务可能连不上…」 | 模型服务侧的问题，**不是描述的问题**。走 §5 降级路径 B，**不要试图改一句话再跑一次** |
| 按钮点了没反应 | 等 5 秒，再点一次；仍无反应走 §5 降级路径 B |
| 描述被拒（提示要先描述） | 输入框是空的，补一句再点 |

〔07-27 改〕四处：
> ① **点击路径错了两步**：按钮实际叫「选择品牌动效成片」（原来写「点选品牌动效成片」，听起来像点卡片本身）；提交后 App **自动跳页**，原来写的「可到制作任务查看进度」会让演示者多做一次没必要的操作。
> ② **原来引用的提示原文「已提交一句话自动制作，可到"制作任务"查看进度。」在代码里已经不存在了**。现在等待期显示的是那行带计时器和参照范围的字，改成指着它讲反而更好讲。
> ③ 「大概要三分半钟」改成「大概三分钟」，依据见 §0。
> ④ 新增「自动编排没能完成」这一行。这是 T90 改掉的那条缺陷：**模型服务连不上以前会被说成「你的描述做不出来」**——演示者照旧文案会当场去改那句话，越改越错，而问题根本不在那里。

### 幕 2 · 那两三分钟讲什么（约 2–3 分钟）

**这是整个演示的设计难点，也是最容易翻车的地方。**

**核心思路：留在「制作任务」页上讲，不要切走。**

这一点这次改了。原来的编排是「提交完立刻走开去讲别的」，理由是让等待变成议程的一部分。现在改成不切页，两个原因：

1. **等待变短了。** 中位数 124 秒，不是三分半。两分钟不足以走完一趟「平台状态 → 设置 → 任务记录」再走回来，走到一半被「好了」打断反而更乱；
2. **页面上现在有东西可指。** 那行带计时器和参照范围的字本身就是讲解材料——它替你回答了客户心里那句「是不是卡了」。

**切走本身已经不再有风险**（`a109178` + `7c5d5d6` 修掉了「切页丢任务、丢句子、丢失败」，并有 e2e 用例守着；渲染阶段失败也会在侧边栏亮红色「失败」角标）。**但不切页是零成本的，所以默认就不切。**

**推荐编排（站在「制作任务」页上讲，随时可被"好了"打断）**：

| 时段 | 讲什么 | 眼睛看哪里 |
| --- | --- | --- |
| 0:00–0:20 | 指着那行走字的状态，说明它在干什么、正常要多久 | 「制作任务」标签页那行计时 |
| 0:20–1:10 | **平台登录与人工接管**：这个工具用的是 App 自己的独立浏览器档案，不碰你日常用的 Chrome，也不读你的 Cookie；扫码登录一次就记住；遇到验证码、滑块、风控，它会停下来交给人，不会替你绕过 | **口头讲，不切页**。客户要求看再切到「平台状态」 |
| 1:10–1:50 | **密钥都在本机**：模型密钥保存在这台电脑的受保护存储里，页面上永远不回显 | 口头讲 |
| 1:50– | **任务留痕**：每个任务什么时候跑的、做了什么、结果如何都有记录 | 口头讲，讲完看计时收尾 |

**如果客户明确要求「让我看看那个平台状态页」**：切过去没问题，任务不会丢。看完切回「视频制作 → 制作任务」即可。**万一在你切走期间失败了**，左侧「视频制作」那一项会挂一个红色的「**失败**」角标（不是小蓝点），你不会错过。

**其他注意**：

- **不要在这段时间点「测试连接」**。它要发真实请求，多一次网络往返就是多一个失败点，而且此刻你的注意力在讲话上。
- **不要点「安全注销」**（§4）。
- 如果客户问「怎么这么慢」——**别道歉，给数字**：

  > 这两三分钟里，我们本机总共只花了十毫秒。其余全是模型在写——它不只是写文案和分镜，还要把整套画面动效一起写出来，光这一项就占它输出的七成。之后本机渲染合成大概三十秒。这台电脑没有连任何渲染农场，全部本地跑完。

**失败预案**：超过 **4 分半**仍未完成 → 别再等了，走 §5 降级路径 B，把话接成「我们先看一条之前生成的」。

〔07-27 改〕四处：
> ① **默认编排从「切走去讲别的」改成「留在原页讲」**，理由写在上面。原来那套的前提是三分半的等待，现在等待只有两分钟出头。
> ② 原来挂着的那个待确认前提（「切走会不会中断」，清单 D6）**已经有答案了：不会中断，已修且有用例**。所以那句「如果彩排发现切走会中断就不能用这套编排」删掉了——它问的那件事不再是未知数。
> ③ 「怎么这么慢」的解释口径换成有依据的版本。原来说「大部分是模型在写分镜和文案，渲染只占三十几秒」——方向对，但漏掉了**最占时间的那一项**（模型还要写整份动效画面，占它输出的 70%），也没有「本机只花十毫秒」这个最有说服力的数。
> ④ 超时阈值从 6 分钟收到 4 分半，跟 §0 的备用余量对齐。

### 幕 3 · 成片播放（约 2 分钟）

**点击路径**：「视频制作」→「**成片**」标签页 → 找到刚才那条 → 点「**播放成片**」。

**说什么**：

> 这就是刚才那一句话生成的结果。整个过程里我没有写脚本、没有找素材、没有开剪辑软件。

**用户看到**：App 内嵌播放器播放一段 12 秒、画面在动的视频。

**可以顺带说的**：

> 生成出来的片子就在这里，可以直接进入发布流程，也可以导出后自己再加工。

**失败预案**：

| 现象 | 现场怎么办 |
| --- | --- |
| 「暂时无法读取这条成片」 | 点彩排那条成片播放（它前一天验过能播） |
| 画面自始至终不动，提示换一句描述 | 这是静图门禁拦下的。**照实说**：「它检测到画面没有变化，主动停下来了，不会给你一个假成品。」然后放彩排那条 |
| 播放器黑屏但有时长 | 换彩排那条 |

> 「画面没变化就拒绝交付」这件事，**如果发生了就大方讲出来**——一个会承认自己没做好的产品，比一个交付废片的产品更可信。

### 幕 4 · 发布链路（约 1 分 30 秒，**只讲不做**）

**点击路径**：左侧「**作品发布**」。

**说什么**：

> 成片可以从这里发布到平台。它的流程是：选好视频、填标题和简介，然后会**先弹出一个确认页，把要发到哪个账号、发什么内容完整列给你看**，你点确认它才真的发。这个确认步骤是不能跳过的。

**用户看到**：发布页、待发布视频卡片、标题与简介输入框、「发布到抖音」按钮。

**⛔ 到此为止。可以填标题和简介，可以点「发布到抖音」让确认卡片出现，但绝对不要点「确认发布」。** 详见 §4。

**如果客户说「那你发一个试试」**：

> 这台演示机连的是我们的测试账号，真发出去就是一条真实作品。我们不在演示里往真实平台投稿。回头在您自己的账号上，我们陪着走一次完整的。

**⚠️ 注意（写给准备演示的人，不是台词）**：产品**没有「草稿箱」这个选项，也没有任何「先存起来不发」的降级路径**。

这不是「暂时没做」，是**产品在契约层面就没有这个状态**。发布结果的取值集合由 `contracts/publishing/publish-workspace.v1.json` 定死，全部五种是：

```text
published            已发布
outcome_uncertain    结果待人工确认
not_published        未发布
handed_off           需要你在浏览器里处理
cancelled            已取消
```

**里面没有 draft。** 曾经有过「发布一律走草稿箱」的约束，但它**从未实现**。

所以：**点了「确认发布」就是真投稿，没有安全网、没有后悔按钮、没有「其实只是存了个草稿」这种可能性。** 演示前请确认自己完全理解这一句。见 §4。

〔07-27 改〕原文只说「产品没有草稿箱这个选项，代码里不存在」。这次补上了契约层的证据（五种 outcome 逐个列出，确认没有 draft），因为**这一条弄错的后果是在客户面前真发一条内容出去**——它值得有比「我记得没有」更硬的依据。

## 3. 演示素材建议

### 3.1 那条「一句话」怎么写

品牌动效成片产出的是**文字动效 / 数据可视化**风格，不是带实拍素材的口播视频。**描述要往这个方向写，别让客户期待错。**

**好的方向**：产品亮点罗列、数据增长说明、活动预告、要点总结。
**不好的方向**：「拍一段员工在办公室工作的画面」——这条线做不出实拍素材。

### 3.2 备选描述（提前写好，别现场憋）

- 「用蓝色商务风做一段本周销售增长说明」
- 「用品牌动效介绍新品的三个亮点」
- ⬜ 第三句：**贴合客户行业的那一句** ← **强烈建议现场化一句**，效果比通用句子好得多；**但必须在彩排时先跑通它**，别把没试过的句子留到现场。

## 4. 不要演示什么

**下面每一项都不要出现在演示里。理由写清楚了，是为了让你判断客户临场提问时怎么回。**

| 功能 | 位置 | 为什么不演 | 客户问起怎么说 |
| --- | --- | --- | --- |
| **安全注销** | 平台状态 → 抖音卡片 | `T50` 已把原来的 5 秒过早超时对齐到完整 60 秒预算，代码与契约门禁已通过；但修改后尚未用真实抖音账号复验「点击注销 → 权威态 missing → 页面成功」。在补齐这条证据前仍不放进演示脚本，**不再沿用旧稿的故障结论** | 「注销和账号管理我们单独看，今天先聚焦生成这条线」 |

## 5. 降级路径

**判断标准：任何一步卡住超过 30 秒，就切降级，不要在客户面前 debug。**

### 路径 A — App 起不来 / 白屏 / 闪退

**先别修。** 按顺序试：

1. 完全退出 App，重新打开（一次，只一次）；
2. 仍不行 → **改用讲解 + 现成视频文件**：把彩排那条 mp4 从访达里直接播放，讲 §2 幕 1/3 的内容；
3. 同时安排技术支持在后台查（磁盘满？数据目录权限？），**但演示继续**。

**台词**：

> 这台机器上有点环境问题，我们先看生成出来的结果，具体环节我边放边讲。

### 路径 B — 生成失败或超时

**用彩排那条成片顶上。**

**点击路径**：「视频制作」→「成片」→ 找到彩排那条 → 「播放成片」。

**台词**：

> 这条是我们之前用同样的方式生成的，流程完全一样。

**不要说**「刚才那条失败了」。也不要重新提交一次——第二次同样要三分半，而你已经用掉了预算。

### 路径 C — 会场网络不通

**这是最难受的一种，因为一句话生成需要调模型，必须联网。**

1. 先切手机热点重试（**提前把热点准备好、连过一次**）；
2. 仍不通 → 全程改为**讲解 + 播放现成成片**，跳过幕 1、幕 2；
3. 平台状态、设置页、任务记录这些**本地页面仍可正常展示**，讲解材料够用。

**台词**：

> 现场网络到我们服务的链路不太稳，生成这一步要调模型必须联网。我先把结果和流程讲清楚，回头在您那边网络环境下我们完整跑一次。

### 路径 D — 抖音登录态掉了

**不要现场扫码**（掏手机、找入口、二维码过期，全在客户面前）。

幕 2 默认就不切页，所以这条基本不影响脚本：**平台登录那一段照讲不误，只是别切到「平台状态」页去展示**。如果客户主动要求看，就说「平台连接我们单独找时间过一遍」，把话头带回生成这条线。

〔07-27 改〕原文写「跳过**幕 4** 的「平台状态」展示」——**幕号写错了**，平台状态在幕 2，幕 4 是发布链路。顺带按幕 2 改成不切页后的新编排重写。
