# Customer Demo 演示后退场与清理手册

本手册用于 `customer-demo-v1` 演示结束后的环境退场。目标不是“把机器关掉”，而是让演示期间产生的访问能力、账号、数据、缓存和分发物都进入一个有负责人、有截止时间、可复核的终态。

本手册不授权操作者扩大清理范围。任何删除都必须指向清理单中已经登记的精确资源 ID；目标不明、归属不明、仍有任务运行、出现 `outcome_uncertain`、保留期未获批准或只有一份未验证备份时，立即停止并升级给环境负责人。不得用通配符、仓库根目录、用户主目录或 `docker compose down --volumes` 代替逐项确认。

## 1. 开始前：建立唯一清理单

由退场负责人创建一张清理单，先填标识，不填任何 Secret 值：

- Demo 名称、演示结束时间和客户/环境标识；
- 云厂商 project、Compose project、公开 origin、数据库实例 ID、对象存储 bucket 与演示专用 prefix；
- Demo 账号的不可变 user ID、Installation ID 和当前 revision；
- 演示机资产编号、操作系统账号和 App 版本；
- 使用过的第三方凭据、运维 capability、TLS/签名密钥的**凭据 ID、指纹或版本号**；
- 需要保留的备份、审计和事故证据及其精确销毁时间；
- 每一类资源的执行人、复核人和最终批准人。

凭据库存目录和云 Secret Store 只能用于核对“对象是否存在、归谁、当前是否启用”。**不得打开、复制、打印、截图或粘贴真实密钥值**，不得把值放进清理单、命令参数、环境变量、终端历史或日志。若无法只凭 ID/指纹区分两个凭据，交给凭据所有者在对应控制台处理，不通过读取值来猜。

清理单必须先选择并记录数据库处置之一：

1. `destroy_now`：无需保留业务数据，完成最小证据封存后立即销毁；
2. `quarantine_until`：因合同、审计或事故调查短期隔离保留，并写明 UTC 截止时间与到期执行人。

不得填写“以后再说”或没有日期的长期保留。现有 Demo 备份策略是 7 天；超过 7 天必须有单独批准和依据。

## 2. 第一阶段：冻结业务并确认外部副作用

本阶段在 Control Plane 仍可用时完成，顺序不能颠倒。

- [ ] 通知演示结束，禁止创建新任务、登录新设备、上传新素材或再次发布。
- [ ] 在 App“任务记录”中处理每个运行中任务：先请求“紧急停止”，等待终态；不得直接强杀 App 来冒充任务已停止。
- [ ] 对每个 `outcome_uncertain` 逐一去目标平台核对实际结果，并把“已发生 / 未发生 / 仍未知”写入清理单。仍未知时保留对应最小证据，不得删除后宣称已回收。
- [ ] 核对演示中已经发布的作品、评论或私信。需要撤回的内容必须在对应平台处理；卸载 App 或删数据库不会撤回外部动作。
- [ ] 停止任何演示专用定时器、临时上传作业、迁移/备份 one-shot job，并记录其最终状态。

完成判据：没有新的业务写入，所有任务都有可解释终态，所有外部副作用都有明确处置结果。

## 3. 第二阶段：回收身份、Session 与凭据

### 3.1 平台登录状态

- [ ] 在演示机 App 的“平台状态”中执行“退出该平台登录并清理运营档案”。
- [ ] 到平台账号安全设置中撤销演示机对应的登录设备或 Session。只删除本机浏览器档案不能清掉平台侧设备记录。
- [ ] 关闭再打开 App，确认平台状态为“需要登录”，而不是仅删除界面缓存。

若 App 无法安全退出平台，先在平台侧撤销设备，再按第 5 节隔离并清理本机私有数据；不得为了清理而重新登录。

### 3.2 产品 Demo 账号与设备

- [ ] 按 [`customer-demo-operations-runbook.md`](customer-demo-operations-runbook.md) 第 5 节，对每个 Demo 账号执行认证运维 one-shot `emergency-revoke`。
- [ ] 每个账号使用清理单登记的 user ID、最新 expected revision 和唯一 request ID；capability 只允许经正式只读 runtime Secret 和 stdin 提供。
- [ ] 记录 disabled 状态、新 revision、吊销设备数量和 append-only audit ID。
- [ ] 用既有 App 会话验证 access/refresh Session、Installation、设备凭据和设备 Session 均已失效；同时抽查一个非 Demo 账号未受影响。
- [ ] 删除演示账号的明文交接副本和临时密码记录；不得把密码复制进验证记录。

项目没有账号硬删除入口。账号停用与全 Session/设备吊销是产品层终态；业务行的最终物理删除随第 6 节数据库整体退场完成，禁止直接改表“清账号”。

### 3.3 第三方 API 凭据

对演示使用过的模型服务 API Key 和其它临时 Token 逐项处理：

- [ ] 演示专用凭据：停止一切新调用；若它仍是删除演示临时对象的唯一授权，先完成该精确
      prefix 的清理，再在供应商控制台禁用和删除凭据。记录凭据 ID、操作者、时间和供应商
      receipt。
- [ ] 与非 Demo 环境共用的凭据：不得直接删除。凭据所有者先创建替代版本、切换合法调用方并验证，再撤销旧版本；清理单记录例外范围和完成期限。
- [ ] 若凭据疑似泄露，不继续用它做清理：立即禁用，再由凭据所有者使用独立、最小权限的
      运维身份处理遗留对象。
- [ ] 验证时只记录“已禁用 / 已删除 / 认证被拒绝”的状态与固定错误码，不记录请求头、响应正文或凭据值。

App 私有目录或凭据库存中的文件删除，只能消除本地副本，不能代替供应商侧撤销。
若凭据曾经进入 Git，必须按“已暴露”处理并先在供应商侧撤销；删除当前文件不能清除历史。
本次退场不直接重写共享 Git 历史，另建经仓库所有者批准的安全任务处理当前副本、历史和所有
已知 clone。

### 3.4 运维、TLS 与签名密钥

- [ ] 演示专用运维 capability、数据库迁移/备份身份和临时 TLS 私钥：在服务停止后从 Secret Store 和 runtime Secret volume 撤销或销毁。
- [ ] 服务停止并完成数据库处置后，删除演示服务器上的精确 runtime Secret 文件
      `/etc/automation-tool-demo/secrets.json`；只验证文件已不存在，不读取或备份其内容，
      也不触碰同机其它业务目录。
- [ ] 演示专用 Demo Profile 签名私钥：停止分发旧包后销毁所有临时导出副本；若该 key 还被其它有效 Profile 使用，交由签名负责人轮换，不得由退场操作者直接删除。
- [ ] App 公证/发行签名身份若为长期发行资产，不属于 Demo 数据，禁止“顺手清理”。只清除本次导出的临时副本；若私钥可能暴露，立即交由签名负责人走证书吊销和重签流程。
- [ ] 公钥、证书指纹、签名 receipt 和已发布包摘要不含私钥，可作为退场证据保留。

## 4. 第三阶段：停止云端入口与服务

账号和凭据吊销完成后，按现有运维手册第 8 节执行环境紧急停服：

1. 先停止公开 Ingress；
2. 再停止唯一 Control Plane；
3. 确认 HTTPS 不再提供业务响应；
4. 保持 PostgreSQL、网络、Secret volume 和部署证据原样，进入数据处置阶段。

此时不得运行 `down --volumes`，不得先删除数据库，也不得直接重启 Ingress 绕过迁移、身份和健康门禁。紧急停服是可恢复隔离，不等于永久退场。

对当前固定演示 origin 的只读检查可使用：

```sh
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 10 https://at.xuanbai.tech/api/v1/health
```

退场后的预期是连接失败或 `000`。返回 `200` 表示环境仍开放；返回其它 HTTP 状态只证明入口仍存在，不能作为已退场证据。

## 5. 第四阶段：清理演示机与本地副本

先确认第 2 节所有外部副作用已核对，并把仍需保留的成片复制到清理单批准的位置。

### macOS

- [ ] 正常退出 App，在“活动监视器”确认 App、Executor 和内置浏览器均无残留进程。
- [ ] 将“应用程序”中的 App 移到废纸篓。
- [ ] 将精确目录 `~/Library/Application Support/com.aventador.automationtool` 移到废纸篓。该目录包含浏览器档案、Session、设备凭据、服务密钥、视频工作区、日志/诊断和更新缓存，不能只删其中一个看起来敏感的文件。
- [ ] 在“下载”目录查找并移走 `automation-tool-diagnostics-` 开头的诊断包。
- [ ] 移走本次演示另存的成片、截图、录屏、DMG 和临时安装副本；客户批准保留的成片除外。
- [ ] 完成最终验证前先不要清空废纸篓；验证通过且复核人确认目标正确后再永久清空。

### Windows

- [ ] 正常退出 App，在任务管理器确认 App、Executor 和内置浏览器均无残留进程。
- [ ] 从“已安装的应用”卸载 App。
- [ ] 将精确目录 `%APPDATA%\com.aventador.automationtool` 移到回收站。
- [ ] 在“下载”目录处理诊断包，并处理本次演示另存的成片、截图、录屏、安装包和临时副本。
- [ ] 完成最终验证和双人复核后再清空回收站。

### 开发机与交接介质

- [ ] 盘点 `.local/customer-demo-release/` 中本次 Demo 的构建/分发副本，按精确版本和摘要移入废纸篓；不得清扫整个 `.local/`。
- [ ] `.local/secrets/` 或凭据库存中的文件必须逐项对应第 3 节已撤销的凭据 ID。共享或归属不明的文件保持原样并升级给所有者。
- [ ] 对 `~/Documents/at-tools-credentials/project-secrets/` 只按清理单中的凭据 ID
      处理演示专用副本；不得打开文件读取值，也不得删除仍服务其它环境的长期签名资产。
- [ ] 清理邮件、聊天、网盘、U 盘和客户交接目录里的旧安装包、Demo Profile 包和临时凭据副本；记录每个分发位置的处理结果。
- [ ] 不删除源码、Git 历史、worktree、锁文件、构建依赖或 submodule；这些不是演示数据。

Demo Profile 被编译进安装包，不能靠删除某个 AppData 文件单独“卸载 Profile”。必须停止旧包分发、卸载已安装 App、清掉所有安装包副本，并通过停止其唯一云端 origin 让旧包无法继续使用。

## 6. 第五阶段：处置持久数据、缓存和云资源

### 6.1 PostgreSQL 与备份

- [ ] 停服后生成最终只读库存：数据库 ID、schema revision、账号/Installation/任务数量、备份 receipt 和摘要；不得导出业务正文到清理单。
- [ ] `destroy_now`：由数据库负责人和批准人双人确认精确实例/volume ID 后，销毁 Demo PostgreSQL、相关 volume 和 Demo 专用备份。
- [ ] `quarantine_until`：撤销应用和人工访问，保持加密、私网隔离和只读封存；设置到期工单，到期后按上一条销毁。
- [ ] 销毁后从云控制台重新查询，确认实例、volume、快照与备份均不存在；“服务已停”不等于数据已删除。

禁止逐表手工删除、原地覆盖恢复或删除唯一未验证备份。若存在事故调查、客户保留要求或 `outcome_uncertain`，只隔离不销毁，直至批准人解除保留。

### 6.2 对象存储与外部内容

- [ ] 删除 Demo 专用对象存储 prefix 下的输入素材、中间文件、输出成片和未完成 multipart upload，并确认对象数为 0。
- [ ] 删除或下架演示产生的测试作品、评论和私信；需要客户保留的外部内容必须在清理单逐项列为例外。
- [ ] 若 bucket 与其它环境共用，只删除清理单登记的 Demo prefix，禁止清空整个 bucket。

### 6.3 容器、网络、DNS 与证书

- [ ] 删除 Demo 专用 Ingress/Control Plane 容器、网络、runtime Secret volume 和停止后的 one-shot job。
- [ ] 按镜像保留策略删除 Demo 专用 tag；保留用于审计的不可变 digest 与 SBOM/签名 receipt，不保留含运行时数据的容器文件系统。
- [ ] 数据处置和证据封存完成后，删除 Demo 专用 DNS 记录、TLS Secret 和证书；共享证书交由证书所有者处理。
- [ ] 删除 Demo 专用云主机、防火墙规则、临时 operator tunnel 和未使用公网地址，并从云资产清单复查为 0。
- [ ] 若云主机、公网地址或防火墙还承载其它业务，禁止删除宿主资源；只处理清理单登记的
      Demo Compose project、容器、网络和专用规则，并由其它业务所有者复核未受影响。

### 6.4 日志、缓存与证据

- [ ] 删除容器可写层、构建临时目录、下载缓存、临时 operator payload 和演示专用状态目录。
- [ ] 原始日志、截图、录屏和诊断包按清理单销毁；不得因为“日志已脱敏”就无限期保留。
- [ ] 最小退场证据只保留资源 ID、镜像 digest、schema revision、请求 ID、吊销 revision、对象数量、时间、操作者和供应商 receipt。
- [ ] 证据中不得出现 Secret、Token、Cookie、密码、授权头、数据库 URI、评论/私信正文、页面正文或客户素材。

## 7. 最终验证

执行人和独立复核人逐项签字；任一项为“未知”时不得关闭清理单。

| 范围 | 必须看到的终态 |
| --- | --- |
| 任务与外部动作 | 无运行中任务；所有 `outcome_uncertain` 已核对或处于批准的证据保留 |
| 产品账号 | Demo 账号 disabled；全 Session、Installation 和设备凭据失效；非 Demo 账号不受影响 |
| 平台账号 | 演示机平台设备/Session 已撤销；需撤回的外部内容已处理 |
| 第三方凭据 | 演示专用 key/capability 已禁用或删除；共享 key 有已完成的轮换记录 |
| Demo Profile | 旧包不再分发；演示机已卸载；旧 origin 不再提供业务响应 |
| 演示机 | 无相关进程、App、私有数据目录、诊断包、录屏或未批准成片 |
| PostgreSQL | 已销毁，或处于有截止时间、无应用访问的隔离保留状态 |
| 对象存储/剪辑 | Demo prefix 对象数和未完成上传数均为 0；临时媒资到达删除终态 |
| 云资源 | Demo 专用计算、容器、volume、Secret、网络规则、公网地址、DNS/TLS 均符合清理单处置；共享宿主上的其它业务未受影响 |
| 日志与证据 | 原始副本按策略销毁；仅剩脱敏、最小、带销毁日期的退场证据 |

最终回执至少包含：

- 清理单编号和 Demo/environment 标识；
- 每类资源的处置结果、时间和 receipt/审计 ID；
- 数据选择 `destroy_now` 或 `quarantine_until` 及批准人；
- 所有例外、负责人和精确截止时间；
- 执行人、独立复核人、环境负责人和安全/凭据所有者签字。

## 8. 责任边界

| 角色 | 负责 | 不得擅自做 |
| --- | --- | --- |
| 退场负责人 | 维护唯一清理单、排序和阻塞条件、关闭回执 | 代替资源所有者销毁共享凭据或共享基础设施 |
| Demo 操作者 | 停任务、核对副作用、注销平台、清理演示机 | 直接改数据库、读取 Secret 值、把未知结果写成成功 |
| 账号/平台所有者 | 产品账号吊销、平台设备撤销、外部内容处置 | 把 AppData 删除当成服务端吊销 |
| 云与数据库负责人 | 停服、隔离、备份/数据库/对象/网络退场 | 在保留决策未知时删库，或用广域删除命令省事 |
| 凭据/签名负责人 | 第三方 key、capability、TLS 与签名资产的撤销或轮换 | 销毁仍被其它环境使用的长期签名身份 |
| 独立复核人 | 用云端、供应商和设备的重新查询验证终态 | 只看执行人截图或“命令退出 0”就签字 |

若清理失败，保持入口关闭和凭据吊销状态，保留最小脱敏诊断，创建带负责人和截止时间的补救项。不得为了重试清理而恢复公网入口、重新启用旧凭据或重新登录演示账号。
