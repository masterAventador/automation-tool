01 · Executive decision

结论先行

可行

Browser Use 值得做技术验证

它适合解决页面改版、弱结构页面和任意网站的语义理解问题，但不适合直接取代现有执行状态机。

混合

不是“全 AI 点网页”

生产优先级应是：平台当前正式开放的 API/SDK/H5，其次确定性适配器，最后才是受限的 Browser Use 语义兜底。

分镜

视频不要一把梭

一句话先变成脚本和镜头计划；人物/产品镜头用参考图或首尾帧，最后在 Timeline 中合成。

建议立项，但先做两个相互独立的技术可行性验证。 浏览器部分只验证“语义定位能否在页面变化下稳定工作，且不破坏安全边界”；视频部分只验证“30 秒竖屏成片的一致性、成本和云剪辑闭环”。两者通过后，再接入自动发布与私信/评论。
2026-07-22 发布能力复核勘误 先前搜索缓存中的抖音服务端“上传/创建视频”链接已经在官方站点跳转 404，不能作为现行接口。抖音 2026-07-14 最新规范明确的是 SDK/H5 投稿并由用户手动发布。当前可确认的服务端直投稿能力是 B 站；快手也有服务端上传/发布 API，但 2026-03 规范要求用户在第三方应用前台确认。小红书与微信视频号均没有可直接采用的通用服务端内容投稿 API。
决策项建议原因
全面替换 Playwright不建议当前代码的价值不只在选择器，还包括授权、限制、幂等账本、单次副作用与不确定结果处理。
引入 Browser Use建议，受限引入承担读操作、页面探索、语义候选定位和新版页面恢复，不拥有最终成功判定。
运营浏览器来源改为 App 内置随安装包提供与 Playwright 严格匹配的完整 Chromium，运行时离线，不依赖用户安装 Chrome/Edge；仍使用 App 私有 Profile 和可见窗口。
Browser Use Cloud / stealth / CAPTCHA 绕过禁止与项目“可见浏览器、人工接管、不得绕过风控”的既有边界冲突。
跨平台内容发布逐平台选路B站走服务端 API；快手走 API + 前台确认；抖音走 SDK/H5 手动投稿；小红书、视频号暂无通用服务端投稿 API。
一句话直接生成整段长视频仅用于快速预览人物、产品和叙事连续性不可控，也难以局部重做与控制成本。
智能素材成片作为低成本素材成片方式适合口播知识类、资讯类，以及用城市、办公、生活等补充画面配合旁白的内容；不承担数字人、品牌人物一致性或真实文生视频。
品牌动效成片作为品牌与信息动效方式适合网址转产品视频、图表、标题、产品演示和品牌动效；已有说话人物可作为输入素材，但底层渲染器本身不生成人物。
阿里 IMS/ICE 云剪辑建议作为首个云剪辑 ProviderTimeline API、异步任务、字幕/音频/转场能力完整；同时保留本地 FFmpeg Provider。
02 · Repository audit

项目现状：脆弱的是“页面感知层”，不是整个执行骨架

当前抖音能力确实大量依赖固定 URL、中文文案、ARIA 和 data-e2e 选择器。例如搜索、评论和私信页面分别维护了一组写死的候选选择器；真实平台换文案、换 DOM 或插入登录/风控层后就会失效。

应当替换/增强

  • search_page.py、comment_page.py、direct_message_page.py 中的固定页面感知。
  • 把“元素在哪里、页面现在是什么状态”从硬编码选择器升级为多策略感知。
  • 用真实站点快照与多版 DOM 回放，代替只依赖 data-e2e 测试锚点的信心。

必须保留

  • ActionGate：签名授权、账号/平台/动作限制和本地限额。
  • 本地 SQLite side-effect ledger：prepare → dispatch → verified / uncertain。
  • 单次点击/发送、最终状态独立确认、结果不确定时绝不自动重放。
  • 应用独立浏览器 profile、可见运营浏览器窗口、验证码人工接管。

相关实现入口包括 backend/src/automation_tool/executor/browser_runtime.py、backend/src/automation_tool/executor/rpa/douyin/ 以及 action operation/ledger 代码。现有路线图也已预留供应商无关的 Material、Timeline、RenderJob、PublishJob、Artifact，以及阿里云剪辑与本地 FFmpeg 的选型任务。新方案应沿用这些边界，而不是再造一套平行系统。

本报告已按新策略修订浏览器目标。 当前代码仍会发现并选择用户安装的 Chrome/Edge；实施时先用 ADR 更新项目基线，再把系统浏览器发现、选择设置和启动门禁替换为 App 内置 Chromium 发行物校验。Profile、原生锁、Playwright Page、页面对象和副作用安全链路继续复用。
当前测试结论要克制。 仓库里的官方域名本地回放能够证明状态机与防重复机制，但不能证明真实抖音页面可用。现有真实会话已遇到 verifycenter/CAPTCHA，搜索、评论和私信仍需要真实账号与人工风控窗口验收。
03 · Browser Use feasibility

Browser Use 能带来什么，以及不能让它做什么

Browser Use 是 MIT 许可的 Python 浏览器 Agent 框架，支持本地运行、自选 LLM、自定义工具、结构化输出和浏览器会话参数。调研时最新 release 为 0.13.6（2026-07-17），0.13 系列还在引入 Rust-backed beta Agent，说明项目迭代很快：必须精确锁版本并做升级回归，不能追 latest。

能力对本项目的价值生产约束
语义理解 DOM + 视觉可按“搜索框”“发送按钮”“当前是否登录”等意图找元素，降低 CSS/文案变更影响。视觉会把截图发给模型；敏感页默认关闭，必要时只发裁剪区域。
自定义 Tools可以只暴露“观察、候选定位、读文本”等少量动作。默认工具包含导航、输入、上传、JS、文件读写等广泛能力，必须删减。
allowed_domains / prohibited_domains可把执行限定在批准的网站。域名限制只是第一道门，还需路径、动作、账号和目标对象校验。
结构化输出可让 Agent 返回 ActionProposal、候选元素和证据，不直接返回“任务成功”。最终状态必须由独立 verifier 检查平台回执、URL、实体 ID 或稳定页面证据。
CDP 会话可接 App 内置运营 Chromium 的独立 profile。当前版本底层是直接 CDP 而非 Playwright；调试端口只能监听 loopback、随机端口、短生命周期，若做不到则技术验证失败。
网页内容是不可信输入。 恶意页面可以把“忽略系统指令、上传文件、泄露密钥”写进 DOM 诱导 Agent。模型不得获得 Cookie、平台 token、任意文件路径、shell、任意 JS、任意上传和跨域导航能力；敏感数据按域名分组注入，并关闭匿名遥测、脱敏历史与截图。

推荐的能力等级

等级允许审批示例
L0 观察截图、读 DOM、提取可见文本、识别页面状态首次授权域名判断是否登录、列出搜索结果
L1 无副作用导航同域打开页面、滚动、切换标签、搜索策略自动批准打开某个公开视频详情
L2 可逆输入填表但不提交、选择文件但不上传动作前展示预览填写评论草稿
L3 外部副作用提交评论、发送私信、上传和发布授权 + 本地账本 + 首期人工确认点击一次“发表评论”
L4 高风险支付、删除、账号安全、风控绕过默认禁用不在当前产品范围
04 · Controlled browser architecture

推荐架构：AI 提案，确定性执行，独立验收

Control PlaneTaskIntent、账号/域名/动作策略、额度、审批、任务状态机、审计。
Authorization Envelope冻结目标、操作、内容哈希、有效期、最大步骤、最大一次副作用。
Local Executor独立 profile 锁、ActionGate、本地 side-effect ledger、凭据与进程生命周期。
PlatformActionPortOfficialApiAdapter / OfficialHandoffAdapter（SDK/H5）/ DeterministicPlaywrightAdapter / SemanticBrowserUseAdapter。
Independent Verifier平台回执、实体 ID、最终 URL/状态证据；失败则 fixed failure，不明确则 outcome_uncertain。
1. 观察AI 识别页面状态、候选元素与风险，不做提交。
2. 提案输出结构化候选、依据、置信度和预计副作用。
3. 门禁校验 origin、账号、目标、内容哈希、授权与本地限额。
4. 单次执行确定性工具只点击/调用一次，并写入 dispatch。
5. 验收独立证据确认；超时不自动重试，进入不确定态。

建议新增的内部契约

BrowserTaskSpec

task_id、account_id、allowed_domains/routes、operation、risk_level、content_hash、max_steps、max_duration、vision_policy、approval_id、policy_version。

ActionProposal

page_state、candidate_element、semantic_role、evidence、confidence、expected_side_effect、target_fingerprint；它不是执行结果。

ActionReceipt

prepared_at、dispatched_at、adapter、exact_action、request/entity ID、evidence_hash、verification_state。

WebCapabilityPolicy

按站点声明可用能力；“任何网页”意味着可扩展的 capability registry，不意味着任意权限。

App 内置 Chromium 的供应链

Build Pin锁定 Playwright，并在构建阶段下载与其严格匹配的完整 Chromium；“最新”指本次发布时最新的兼容组合。
Signed Manifest记录 Playwright、Chromium 修订、平台、架构、每文件摘要、许可证与 SBOM。
Tauri Resolver只从 resource_dir 解析，拒绝 symlink/reparse、摘要错、平台错和目录替换；React 看不到绝对路径。
Executor Runtime把验证后的路径交给现有 BrowserLaunchRequest，继续使用 headed persistent context 和 App 私有 Profile。
First Release UnitApp、Executor、Playwright 与浏览器在同一个首发安装包内锁定并联合验收；运行时不下载，不回退到用户浏览器。

App 尚未发布，因此不设计旧版兼容或 Profile 迁移。首发版本直接删除外部浏览器选择入口，在 App 私有数据根创建一套全新的内置浏览器 Profile；不读取、复制或导入系统 Chrome/Edge、开发环境或测试环境的 Cookie/Profile，用户首次使用时正常扫码登录。最终必须在没有 Chrome/Edge 的 macOS 与 Windows 全新环境完成正式包纵向验收。

与现有同步 Playwright 的集成方式

现有 BrowserRuntime 是同步 Playwright，Browser Use 主流程偏异步且直接使用 CDP。不要在同一线程、同一 profile 上让两个框架同时持有页面对象。技术验证应采用独立的 bounded worker/async loop，并由 profile 单实例锁保证串行；真正执行副作用时，选择一个 adapter 完成从 prepare 到 verify 的完整临界区。

CDP 隔离是 Browser Use 技术验证的硬门禁。 只允许 127.0.0.1、随机临时端口、进程归属校验、任务结束立即关闭；严禁固定 9222、监听局域网、连接用户日常默认 profile。若当前 Browser Use 版本无法满足，就保持 Playwright 主引擎，只抽取其语义定位能力或暂缓集成。
05 · One sentence to video

最稳的文生视频方案：一句话不是 prompt，而是生产 Brief

万相 2.7 已支持 2–15 秒、720P/1080P、9:16、有声与多镜头叙事；图生视频支持首帧、首尾帧和视频续写；参考生视频支持多张人物/场景参考。能力已经足够，但“30 秒人物稳定、产品准确、字幕清楚的营销视频”仍应拆镜头生产，而不是交给一次长 prompt。

1. ContentBrief目标、受众、平台、时长、风格、卖点、CTA、版权。
2. Script & Shots旁白、4–8 个镜头、时长、景别、运动、字幕与转场。
3. References人物/品牌 Bible，关键帧、首尾帧、产品图与声音。
4. Generate逐镜头选 T2V / I2V / R2V / 数字人，失败只重做局部。
5. Edit & QATimeline 合成、字幕/BGM/封面、机器质检、人工审批。

镜头模型路由

内容类型首选方式为什么注意
无固定人物的场景与氛围画面Wan T2V起步快，适合场景与情绪探索。用于预览或短镜头，不依赖它生成准确文字。
产品/品牌/固定人物参考生视频 R2V可提供人物、场景、产品多参考，连续性更好。保存 reference 版本与授权来源；产品外观仍需 QA。
构图必须可控首帧 I2V先生成/审核关键图，再赋予镜头运动。竖屏关键帧直接按 9:16 设计，字幕留安全区。
明确起点和终点首尾帧 I2V适合产品变换、转场与精确落版。首尾差异过大时容易产生形变。
固定数字员工口播 ≤20 秒Wan S2V：人物图 + TTS 音频口型、表情和身体动作专用，强于通用 T2V。长文拆段，统一音色与人物 reference。
长时间简单头像口播LivePortrait可覆盖更长音频，成本/稳定性通常更合适。表现力较弱，适合说明类而非强剧情。

建议的数据对象

ContentBrief → ScriptPlan → ShotPlan[] → CharacterBible/BrandBible → GenerationJob[] → Timeline → RenderJob → Artifact → PublishJob。每个生成产物保存 provider、model/version、prompt、negative prompt、seed、reference hashes、task_id、费用、内容合规结果和 lineage。

生成结果链接只有约 24 小时，必须立即归档。 API 返回 task_id 后先持久化，再轮询任务；成功后马上下载到受控对象存储并校验 hash/媒体信息。网络中断时按 task_id 对账，不能盲目重新提交昂贵任务。

视频 QA 门禁

技术质量

9:16、H.264/AAC、帧率、时长、响度、黑帧/冻帧/静音、字幕安全区、文件完整性。

内容质量

人物相似度、产品形态、镜头与脚本一致、字幕/口播一致、转场和节奏、封面可读性。

合规质量

素材版权/肖像/声音授权、敏感内容、平台禁限词、AIGC 显式与隐式标识、发布声明。

中国《人工智能生成合成内容标识办法》已于 2025-09-01 施行，要求对视频等生成合成内容添加显式标识和文件元数据中的隐式标识，发布者也需主动声明。流水线应自己负责标准化标识与 metadata，不应只依赖模型的 watermark 参数。抖音 2026-07 最新投稿规范同时禁止用水印导流，并限制明显营销内容的投稿准入，因此应区分“合规 AIGC 标识”和“无必要的供应商/导流水印”。

06 · Stock montage baseline

智能素材成片：能用，但它是“自动素材混剪”，不是视频生成模型

截至 2026-07-22，最新正式版是 v1.3.2（2026-07-12），采用 MIT License，要求 Python 3.11 及以上；仓库 main 仍在快速开发。它最有价值的不是某个模型，而是把写稿、搜素材、配音、字幕、混剪和输出串成了一条能直接运行的流水线。

判断：建议接入为 StockMontageProvider，不建议把它当成最终文生视频内核。 用户说一句话后，它确实能快速产出一条“旁白 + 公共素材 + 字幕 + BGM”的成片，适合低成本验证选题或生产无固定人物的知识类短视频；需要固定数字员工、准确产品外观、连续剧情或品牌级画面时，仍应走分镜后的 I2V / R2V / S2V 路线。

它的实际原理

1. 写文案LLM 根据主题生成一段旁白脚本，也允许直接输入自定义文案。
2. 生成搜索词LLM 从脚本提炼 5 个英文素材词；顺序匹配模式使用 8 个按叙事先后排列的词。
3. 找素材调用 Pexels、Pixabay 或 Coverr 搜索并下载库存视频，也可使用本地素材。
4. 声音与字幕TTS 生成旁白；用 TTS 时间戳或 faster-whisper 生成、校正 SRT。
5. 混剪输出MoviePy/FFmpeg 切段、缩放、补黑边、转场、循环铺满，再叠字幕、旁白与 BGM。

这里的“AI 选镜头”要准确理解：正式版并不会先生成逐镜头脚本，再把每句旁白和某段素材做视觉语义对齐。默认路径是生成少量英文关键词，把搜索结果合并或打乱后按固定片段时长拼接；开启 match_materials_to_script 后，只是让关键词按文案顺序生成，并按关键词组轮询下载、顺序拼接。可选 TwelveLabs Marengo 也只是把搜索词按主题相关性重排；仓库虽然提供 Pegasus 的 analyze_clip helper，但正式生成主流程没有调用它逐条验收素材。

目标内容适合度原因
知识口播、观点、鸡汤、资讯摘要适合画面主要用城市、办公、生活等补充素材配合旁白，不要求固定人物和严格情节，生成速度快、边际成本低。
热点快报、批量账号矩阵有条件适合需要事实核验、时效素材、自有模板和人工抽检；同质化库存素材可能影响平台原创度与账号质量。
固定数字员工出镜不适合没有人物 reference、口型驱动和跨镜头一致性，应走人物图 + TTS + S2V/数字人 Provider。
产品广告、品牌故事、连续剧情不适合做主引擎搜索素材无法保证产品外观、品牌元素、镜头调度和叙事连续性。
生成视频的低成本预览/失败降级非常适合昂贵的生成模型不可用或预算不足时，仍可快速交付一个可审核的草稿版本。

为什么有很多模型服务商，但主页面看不到选择

v1.3.2 的 WebUI 确实支持 Moonshot、OpenAI、Gemini、DeepSeek、Qwen、Azure、火山、MiniMax、Ollama、OneAPI、LiteLLM、Groq 等文案模型服务。入口藏在页面顶部的设置按钮里，打开弹窗后的第一个 LLM Settings 页签才会出现服务商、API Key、Base URL 和模型字段；只有部分服务能动态列出模型，其余主要靠默认值或手工输入。没有打开设置弹窗、使用旧版本，或者只看主生成表单时，很容易误判成不能切换。

App 应把它改成清晰的“文案模型服务”设置，和“智能素材成片 / 品牌动效成片”这一级制作方式分开，避免两个“Provider”概念混在一起。

对 automation-tool 的接法

源码与运行时隔离

  • 以 Git submodule 固定 v1.3.2 / b1588e1，不修改上游源代码，不跟随 main 自动升级。
  • 使用独立 Python Worker，不和 RPA Executor 共用 Python 环境；Tauri 负责启动、版本握手、健康、取消和退出。
  • 发布功能保持关闭；其第三方发布能力不能替代国内平台 adapter。

首版 WebUI 与长期边界

  • 首版用专用子 WebView 展示完整 Streamlit 功能，通过 App 自有主题配置和初始化脚本统一外层视觉，不改 submodule。
  • 只监听随机 loopback，经过会话令牌、来源/路径白名单和文件范围检查的 App 网关；不能把上游 FastAPI 直接暴露到局域网。
  • 标题、DOM、可访问性树、错误、日志、外链和任务记录都不能出现上游项目名；页面结构不兼容时 fail closed。
  • 任务仍统一进入 ContentBrief → Material[] → Timeline → RenderJob → Artifact，避免 WebUI 和 App 各有一套结果状态。
MIT 只覆盖 MoneyPrinterTurbo 源码，不覆盖下载到的素材、字体、音乐、人物肖像和商标。 每个素材必须记录 provider、原始 ID/URL、下载时间、许可版本和授权限制。Pexels 禁止暗示人物或品牌为产品背书；Pixabay 对可识别商标、人物和其他第三方权利另有约束；Coverr 当前许可页还区分免费下载归因及其他权利，商业投放前不能只靠“免费素材”四个字放行。

最终建议：保留两条视频生产路线

本期只实现两条路线：material_montage_v1 服务低成本、高速度的旁白素材视频；motion_composition_v1 服务品牌、产品、数据和网页动效。两条路线共享脚本、Timeline、QA、Artifact 和 PublishJob。真人、电影感镜头与真实世界场景生成只保留未来扩展位，本期不实现。

07 · Brand motion video

品牌动效成片：把 HTML、网页资产和动画确定性渲染成视频

该方案的核心不是扩散模型，而是让 AI 编写普通 HTML/CSS 和可按时间定位的 GSAP、Web Animations、Lottie、Three.js 等动画，再用 App 内置完整 Chromium 的独立无头进程逐帧截图，最后交给 FFmpeg 编码。它非常适合产品发布、网站演示、数据图表、标题动画、代码讲解和品牌模板化视频。

上游默认下载 chrome-headless-shell 152.0.7928.2，但源码明确支持通过 chromePath / HYPERFRAMES_BROWSER_PATH 使用普通 Chrome。它并非在所有平台都只有一种取帧方式：macOS、Windows 即使用自带无头壳也默认通过 Page.captureScreenshot 逐帧取图；Linux 配合无头壳时优先使用 HeadlessExperimental.beginFrame 驱动合成器，方法不可用或强制截图时再回退。因此在本项目当前两个目标平台共用完整 Chromium 不会改变原本的取帧方式，仍需验证 Puppeteer/CDP、字体、GPU、视频解码、透明画面和结果稳定性。

规划因此改为优先只打包 Playwright 严格匹配的完整 Chromium：RPA 用可见持久进程，视频用独立无头临时进程。不能让 RPA 使用上游无头壳，因为它没有可供扫码、验证码和人工接管的正常窗口。

共用验证必须成为最前置门禁。 在开发浏览器打包、视频页面和渲染适配器之前，先在 macOS/Windows 用同一 Chromium 验证 RPA 启动、12 套风格、公开 100 项动效冒烟、字体/图片/视频/音频/Lottie/Canvas/WebGL/WebGPU、透明画面、横竖屏和并发隔离。通过后 Manifest 只允许这一套浏览器，后续禁止上游下载或发现第二套；失败则先调整共同版本重跑，再单独决策，不静默双打包。
判断：适合作为本期第二种视频制作方式，但不要把官网示例中的人物误判为内置真人生成。 渲染器可以把现有的人物讲话视频、自拍视频或数字人视频放进全屏/小窗并叠加字幕、图表和转场；人物、声音和口型本身需要由其他服务预先生成，或由用户提供授权素材。
1. 输入一句话、品牌资料，或获授权的公开网站 URL。
2. 脚本与分镜锁定一个核心信息，拆成逐镜头文案、布局和节奏。
3. 整体风格从 12 套 frame.md 中选择，并映射品牌色、字体和 Logo。
4. 动效零件按镜头调用转场、字幕、图表、身份条和 3D 效果。
5. 验收与渲染lint、截图预览、用户确认、逐帧渲染、成片入库。

网址转视频不是“录屏”，而是抓取品牌后重新编排

官网的 URL → Video 会抓取页面各滚动位置的截图、计算后的配色、字体文件、图片、SVG、Lottie、页面视频、可见文字、区块、按钮和动画，再由 Agent 生成品牌说明、脚本、分镜、旁白和 HTML 镜头。它可以做品牌短片、产品演示、发布预告或功能介绍，并支持 16:9 / 9:16、旁白、字幕、音乐、音效、声音和核心信息设置。

不能直接调用官网私有接口，也不能裸用上游 capture 处理任意网址。 App 应使用 submodule 中公开的 capture 与工作流，在自己的 Worker 内执行。上游素材下载已对部分私网地址和重定向做拒绝，但主页面导航仍直接调用 page.goto(url)；外围必须补协议、DNS/IP、每次跳转、请求拦截、私网/云元数据、DNS 重绑定和网页指令注入防护。首期只抓用户拥有或获准使用的公开网站，不抓登录后页面。

08 · Alibaba cloud editing

阿里云剪辑：用 IMS/ICE Timeline API，不把 WebSDK 放进 MVP

阿里智能媒体服务的云剪辑支持多视频、音频、图片裁剪拼接，以及字幕、贴纸、滤镜、特效、转场、TTS/ASR 和高级模板。后端可提交 SubmitMediaProducingJob，由异步任务输出成片。这与仓库现有 provider-neutral Timeline 规划吻合。

Controlled Storage生成片段先归档；阿里 Provider 将所需素材 staging 到同地域 OSS/IMS 媒资。
Timeline Compiler把内部 Timeline 编译为 VideoTracks / AudioTracks / SubtitleTracks / EffectTracks。
IMS/ICE Job提交异步剪辑任务，持久化 JobId、请求哈希、费用估算与输出规格。
MNS + ReconcileMNS 回调推进状态，同时周期性 Get job 对账，避免只依赖回调。
Artifact Store下载/登记最终成片、封面、字幕、metadata 和 lineage，之后才能进入发布审批。

为什么适合

  • 服务端异步，不要求桌面端长期占用 CPU/GPU。
  • Timeline 和模板适合批量改字幕、片头尾、Logo、BGM 和多比例输出。
  • 成功成片按时长计费，失败任务不计费；1080P 云剪辑价格相对生成模型很低。

必须处理的约束

  • 输入只接受 IMS 媒资或 OSS，不接受任意外部/CDN URL；需要同地域 staging。
  • HTTP 回调重试次数有限，推荐 MNS，并保留主动查询的 reconciliation job。
  • WebSDK 许可证成本和产品复杂度高；MVP 只做 API/模板，不做在线视频编辑器。

Provider 设计

内部只定义 VideoRenderProvider.submit(timeline)、get(job_id)、cancel(job_id) 和 fetch_artifact(job_id)。首期实现 AliyunImsProvider 与 LocalFfmpegProvider：云端用于批量、模板和弹性；FFmpeg 用于离线、隐私数据、小修复和供应商故障降级。

数字员工回复策略

入站评论/私信先经过 webhook/API 或浏览器只读采集，再由 AI 输出结构化 ReplySuggestion（意图、情绪、风险、建议文本、引用事实、置信度）。审核器过滤隐私、承诺、价格、医疗/法律等高风险表达；首期由人确认。只有低风险 FAQ、明确知识库命中、处于工作时间/频率上限内的回复，才逐步灰度自动发送。

10 · Delivery plan

建议的落地路线与验收门槛

P0 · 依赖、安全与共用浏览器前置验证（3–5 天） 锁定 Browser Use、Playwright 与完整 Chromium；最先在 macOS/Windows 验证同一浏览器二进制能分别以可见 RPA 进程和隔离无头渲染进程运行，覆盖 12 套风格、100 项动效与关键媒体/GPU 矩阵。同时验证 Python 3.12、PyInstaller/Tauri sidecar、CDP loopback、独立 Profile、遥测关闭和工具裁剪。任一硬门禁失败就不进入后续集成。
P1 · 通用网页只读 Agent（约 1 周） 实现 BrowserTaskSpec、域名能力策略、结构化观察与审计；只允许 L0/L1。用多站点和恶意 prompt-injection 页面测试，不接账号副作用。
P2 · 抖音语义页面适配（1–2 周） 先把 Browser Use 放在现有搜索/评论/私信状态机的“候选定位”位置。构造 30+ 个 DOM/文案/遮罩变体；真实账号只做观察，再做一次人工批准的低风险回复。
P3 · 30 秒视频闭环技术验证（2–3 周） 先跑通“智能素材成片”和“品牌动效成片”两条路线，共用 ContentBrief、分镜、Timeline 与 Artifact；验证一句话成片、网址转产品视频、12 套整体风格和 100 个动效零件，并记录质量、耗时和真实成本。真人生成不在本期任务内。
P4 · 分平台发布能力接入（约 2–3 周） 先实现 B站服务端投稿，再实现快手“前台确认后 API 发布”和抖音 H5 投稿 handoff；小红书、微信视频号保留可见浏览器 adapter。所有路径统一进入现有 ActionGate 与 ledger，并在账号接入时记录官方能力、scope、授权时间与复核日期。
P5 · 灰度数字员工 从草稿建议 → 人工批准 → 低风险白名单自动化，逐级开放。按账号、域名、动作设置 kill switch、额度与回滚。

技术验证通过标准

维度必须达到
安全越权域名/路径/工具 100% 拒绝；prompt injection 不得触发文件、密钥、跨域和提交动作；CDP 不暴露到 loopback 之外。
副作用每个授权最多一次 dispatch；断网/超时/进程退出后不得重复评论、私信或发布；无法确认即 outcome_uncertain。
页面韧性30+ 个结构/文案/遮罩变体中，读任务成功率 ≥95%；副作用任务宁可拒绝，也不得点错目标。
视频3 类 30 秒样片均可局部重做、自动成片；人物/产品/字幕/技术规格通过预设 QA；成本和延迟可追溯。
分发B站 API 能取回 resource_id/审核状态；快手与抖音保留规范要求的用户确认；小红书/视频号浏览器路径有独立终态证据；验证码可暂停并恢复。

风险概率/影响控制与止损
页面 prompt injection高 / 高网页视为不可信；自定义最小工具集、域名/路径 allowlist、敏感页关视觉、模型无 secret/文件/shell 权限。
AI 点错/谎报成功中 / 极高AI 只提案；确定性单次执行；独立 verifier；低置信度拒绝；首期人工确认。
重复发布/评论/私信中 / 极高沿用 ledger、内容哈希与幂等键；dispatch 后异常一律不自动重试，先 reconcile。
平台风控/封号高 / 高只使用平台当前正式开放并已获批的 API/SDK；其余使用可见浏览器、真实速率、人工确认/验证码和账号级限额；不 stealth、不绕验证码。
CDP 远程控制面暴露中 / 极高随机 loopback 端口、短生命周期、独立 profile、进程归属检查；不能满足即否决 Browser Use 生产接入。
人物/版权/虚假内容中 / 极高reference 权利证明、肖像/声音同意、内容审核、AIGC 标识与发布声明、人工终审。
库存素材同质化/权利不清高 / 高逐素材许可快照和来源台账；语义与重复度检测；品牌、人物、商标进入人工审核；stock_montage 不用于高要求品牌内容。
生成成本失控高 / 中任务前预算冻结、候选上限、720P 草稿/1080P 定稿、局部重做、task_id 对账、按效果统计成本。
供应商锁定/故障中 / 高内部 Timeline/Artifact/Job 契约；AliyunImsProvider + LocalFfmpegProvider；生成 Provider 可替换。
最终产品定义建议 “可操作任何网页”应对外表述为“在用户授权的站点和能力范围内，可扩展地完成网页任务”。这既符合真实技术边界，也为每个站点建立可审计、可灰度、可停用的 capability，避免把数字员工变成一个持有全部权限的通用浏览器机器人。
