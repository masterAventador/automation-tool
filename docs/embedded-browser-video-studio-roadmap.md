## 1. 这份 Roadmap 的定位

docs/development-roadmap.md 仍是项目进度、任务状态和完成证据的唯一事实源。本文件只负责把“内置运营浏览器”和“两种视频制作方式”拆成可执行设计，不维护第二份实时进度。

实施前必须先完成 AV-01 和 AV-04：

1. 用 ADR 和基线文档正式替换“依赖用户安装 Chrome/Edge”的现行方案；
2. 把本文件中准备启动的任务加入 docs/development-roadmap.md，或由主路线图明确引用并登记状态；
3. 之后只在主路线图更新 RED、实现中、待验收和已完成状态，本文件保留规划基线与验收定义；
4. 已完成的旧任务和历史证据不删除，要标明“被内置浏览器方案替代”以及仍可复用的部分。

本文件不是实施完成声明。当前代码仍以外部 Chrome/Edge 为正式基线，直到 AV-01 完成。

## 2. 已确定的产品与架构决策

### 2.1 浏览器

- App 随安装包内置浏览器，不再要求用户预先安装 Chrome 或 Edge。
- “最新版本”定义为：构建候选版本时，使用与项目锁定 Playwright 版本严格匹配、经过测试和签名的 Chromium；不在用户电脑上运行时下载，也不独立追逐浏览器最新版本。
- 浏览器仍是可见窗口，继续使用 App 管理的独立运营 Profile，支持人工接管；验证码、滑块和平台风险提示继续暂停给用户处理。
- App 尚未发布，没有需要兼容或迁移的旧版用户数据；内置浏览器直接从一套全新的 App 私有 Profile 开始。
- 现有 ActionGate、任务状态机、本地副作用账本、单次执行、结果不确定和独立最终状态验收全部保留。
- 当前已实现的抖音登录、会话检测、搜索、浏览、候选提取、评论、私信和恢复链路全部迁移。当前代码没有正式“点赞”实现，因此点赞不是迁移项，要在未来单独立项。
- 用户默认浏览器 Profile、Cookie 和本机日常浏览器数据不得读取、复制或导入。

### 2.2 视频制作

首期只提供两种视频制作方式：

| 用户界面名称 | 内部稳定标识建议 | 底层实现 | 适合的内容 | 不适合的内容 |
| --- | --- | --- | --- | --- |
| 智能素材成片 | material_montage_v1 | MoneyPrinterTurbo | 知识讲解、新闻摘要、观点、榜单、教程、旁白配字幕，并自动匹配生活、办公、城市等补充画面 | 固定真人连续出镜、电影感剧情、精确产品动作、同一人物跨镜头一致 |
| 品牌动效成片 | motion_composition_v1 | Hyperframes | 品牌宣传、产品发布、数据图表、网页或产品演示、标题动画、代码讲解、模板化批量视频 | 凭一句话生成逼真人物、自然运动、真实世界复杂镜头 |

用户界面使用“视频制作方式”，不使用容易和文案模型混淆的英文 Provider。代码内部继续通过 VideoRenderProvider 或 VideoCreationProvider 隔离实现。

真人、电影感镜头和真实世界场景的生成属于未来第三种方案。本 Roadmap 只保留扩展接口，不拆任务、不引入依赖，也不把它展示成当前可选项。

“品牌动效成片”还提供两种不同层级的能力：

- 12 套整体风格：决定整条视频的配色、字体、留白、组件外观和镜头气质；
- 100 个公开动效零件：决定某个镜头使用什么转场、字幕、人名条、图表、地图、社交卡片或 3D 效果。

这两层不能在产品中混称为“视频风格”。

### 2.3 名称与品牌边界

真实上游项目名允许出现在以下内部位置：

- Git submodule 路径、依赖锁、构建脚本和适配器实现；
- 内部诊断原始文件、SBOM、开源许可证和依法必须保留的第三方声明；
- 仅开发者可见的技术文档与升级记录。

真实上游项目名不得出现在以下用户可见位置：

- 左侧菜单、页面标题、制作方式卡片、按钮、加载文案；
- 设置、任务列表、任务详情、通知、错误提示和用户日志；
- 生成文件名、导出报告、分享页和最近任务；
- WebView 页面标题、可访问性树、外链、崩溃页和版本提示。

唯一例外是独立的“第三方软件声明”法务页面。该页面不得作为功能品牌入口。

## 3. 现状审计与迁移边界

### 3.1 当前浏览器链路

当前正式链路是：

    Rust 发现并验证用户安装的 Chrome/Edge
        → 用户在设置页选择浏览器
        → Rust 保存 canonical 枚举
        → 创建 App 私有运营 Profile 并取得原生排他锁
        → Executor 接收 executable_path 和 profile_directory
        → Playwright launch_persistent_context
        → 抖音页面对象执行登录、搜索、评论和私信

可以直接复用：

- BrowserWindow 和 Playwright Page 的消费边界；
- App 私有 Profile Store、原生排他锁和浏览器进程树清理；
- 抖音页面对象、动作编排、ActionGate、本地账本和独立验收；
- 任务暂停、取消、紧停、结果不确定与人工接管状态；
- Rust 管理 Executor 生命周期和敏感路径不进入 React 的边界。

必须替换：

- macOS/Windows Chrome/Edge 发现和验签作为生产启动前置；
- 浏览器选择设置、首次启动“未找到浏览器”门禁和相关用户文案；
- “正式包不得包含浏览器缓存”的旧打包验收口径；
- 以系统浏览器 executable_path 为信任根的启动与诊断逻辑；
- 外部浏览器选择配置和开发期 Profile 的生产入口；正式版本直接建立全新内置浏览器 Profile，不设计迁移分支。

### 3.2 当前视频链路

App 左侧菜单目前没有“视频制作”入口。主路线图已经预留 Material、Timeline、RenderJob、PublishJob 和 Artifact，以及云剪辑、本地 FFmpeg、成片管理和平台发布任务。新方案必须细化和复用这些对象，不建立第二套视频任务、文件和发布状态。

## 4. 目标架构

### 4.1 浏览器供应链与运行链

    构建阶段
    Playwright 锁定版本
        → 下载对应完整 Chromium
        → 平台/架构裁剪与许可证审计
        → 生成版本、文件摘要和平台清单
        → 随 Tauri 安装包签名、公证或签名发布

    运行阶段
    Tauri EmbeddedBrowserDistribution
        → 校验平台、架构、版本、摘要、路径和签名上下文
        → 创建并取得全新 App 私有 Profile 排他锁
        → 通过现有 Executor 协议传入已验证路径
        → PackagedBrowserRuntime 启动 headed persistent context
        → 现有 RPA 状态机和页面对象

关键约束：

- 运行时完全离线，不执行 playwright install，不从网络补浏览器；
- React 和 Control Plane 看不到浏览器绝对路径；
- App、Executor、Playwright 和内置 Chromium 在同一首发安装包中作为一个经过验证的兼容单元交付；
- 清单拒绝 symlink、Windows reparse point、目录替换、摘要不一致和平台错配；
- macOS 必须先签 Chromium 内层 Framework/Helper，再签 Tauri App 并公证；
- Windows 必须覆盖首次安装、卸载、代码签名、杀进程和残留文件；
- 正式包内容审计改为“只允许清单中的一套完整运营 Chromium”，继续拒绝意外缓存、测试浏览器和 WebDriver。

### 4.2 全新 Profile，不做迁移

App 尚未发布，不存在需要保留的旧版用户 Profile、Cookie 或浏览器选择设置，因此首个正式版本采用全新安装策略：

1. 生产代码直接移除外部 Chrome/Edge 选择和旧 Profile 根的调用入口；
2. 首次启动在 App 私有数据根创建一套新的内置浏览器 Profile，并执行权限、稳定路径和排他锁校验；
3. 用户第一次进入抖音运营功能时正常扫码或登录，健康检查通过后才把该 Profile 标记为可用；
4. 不读取、复制或导入系统 Chrome/Edge、开发环境和测试环境里的任何 Cookie 或 Profile；
5. 不增加 v1/v2 分支、迁移标记、旧数据回滚窗口或遗留 Profile 清理任务。

开发期已经产生的测试 Profile 只按开发清理规则丢弃，不进入产品迁移逻辑。

### 4.3 优先共用一套完整 Chromium

共用的是同一个经过签名和摘要校验的浏览器二进制，不是同一个运行进程、CDP 会话或 Profile：

| 用途 | 进程与数据 | 启动方式 | 用户是否看见 |
| --- | --- | --- | --- |
| 运营 RPA | 独立可见进程 + 持久 App 私有 Profile | Playwright headed persistent context | 看见，可扫码和人工接管 |
| 品牌动效渲染 | 独立无头进程 + 每个 RenderJob 的临时数据目录 | Node Worker 把同一完整 Chromium 路径作为 `chromePath` 传入 | 不看见，只负责隔离渲染 |

不能让 RPA 反过来使用上游自带的 `chrome-headless-shell`：它是无头渲染壳，没有正常浏览器窗口，无法满足扫码、验证码和人工接管。可以让视频渲染使用 RPA 的完整 Chromium：上游明确支持 `chromePath` / `HYPERFRAMES_BROWSER_PATH`。

上游不是在所有平台都只有一种取帧方式。锁定版本的实际分支是：macOS、Windows 即使用自带无头壳也默认通过 `Page.captureScreenshot` 逐帧取图；Linux 配合无头壳且未强制截图时优先使用 `HeadlessExperimental.beginFrame` 驱动合成器，方法不可用时再回退截图。因此本项目当前两个目标平台共用完整 Chromium 不会改变原本的取帧方式，验证重点是 Puppeteer/CDP 兼容、字体布局、GPU/WebGL/WebGPU、视频解码、透明画面、资源占用和结果稳定性。

这项共用验证必须放在浏览器供应链最前面。EB-02 在任何正式打包和视频页面开发前，使用 Playwright 锁定的完整 Chromium 同时完成 RPA 启动与动效渲染矩阵。通过后，ADR 和 Manifest 只允许这一套 Chromium，后续所有任务都按共用基线开发；不再下载、缓存或打包 `chrome-headless-shell`。若失败，先尝试调整 Playwright/Chromium 的共同锁定组合并重跑；仍失败才暂停并单独决策是否接受第二套渲染内核，不能在后续任务里静默引入。

### 4.4 视频控制面与本地执行器

    React 视频制作页
        → Tauri 窄接口
        → Control Plane：ContentBrief / Storyboard / Timeline / RenderJob / Artifact
        → LocalVideoOrchestrator
            ├─ 智能素材成片 Python Worker
            └─ 品牌动效成片 Node Worker
        → 共同的受控任务目录、FFmpeg/ffprobe、结果导入与清理

生产 UI 不直接调用任一上游本地 HTTP 接口。Tauri 管理 Worker 的启动、随机 loopback 端口、高熵会话令牌、健康、崩溃恢复、取消和退出。Control Plane 保存业务状态和稳定 ID，不保存用户本机路径或第三方明文密钥。

每个 RenderJob 使用独立私有目录，只允许访问声明的输入 Artifact。生成的 HTML、网页内容、文件名、模型输出和远程素材都视为不可信输入，禁止直接进入 Shell、任意路径或任意网络请求。

## 5. “智能素材成片”集成设计

### 5.1 适用范围

它的实际工作方式不是凭空生成真实镜头，而是：

    一句话
        → 文案模型生成主题、脚本和检索词
        → 素材站搜索并下载补充画面
        → 语音合成
        → 字幕生成和校时
        → MoviePy/FFmpeg 组合画面、旁白、字幕和音乐
        → 输出成片

典型示例：用户输入“做一个 30 秒视频，讲三个提高睡眠质量的小习惯”，系统生成旁白和字幕，并自动匹配卧室、喝水、放下手机等补充画面。

上游当前稳定版本核对为 v1.3.2，计划以 Git submodule 固定在 vendor/moneyprinterturbo，并锁定 commit b1588e1。升级只能通过单独任务完成，不跟随 main 分支。

### 5.2 为什么用户可能看不到模型厂商选择

上游 WebUI 支持选择文案模型服务，但入口不在主表单：

- 顶部设置按钮打开设置弹窗；
- 第一个页签是 LLM Settings；
- 里面才显示 LLM Provider、API Key、Base URL 和模型；
- 只有部分厂商会动态列模型，其余厂商主要靠默认值或手工输入模型名；
- 旧版本界面或没有打开设置弹窗时，很容易误以为不支持切换。

App 应把这一能力直接放在“视频制作设置 → 文案模型服务”中，至少展示服务商、模型、连接地址、密钥是否已配置和连接测试。这里可以展示 OpenAI、Kimi、DeepSeek 等模型服务商名称，因为它们是用户选择的外部服务，不是本产品底层视频引擎品牌。

### 5.3 不修改上游源码的 WebUI 方案

首个版本按用户要求先展示完整 WebUI 功能，但不改 submodule：

1. 独立 Python Worker 从锁定 submodule 启动 Streamlit；
2. 只监听随机 127.0.0.1 端口，不允许 0.0.0.0；
3. Tauri 用专用子 WebView 打开经过 App 网关保护的地址；
4. App 自有启动配置注入主题 token，子 WebView 初始化脚本只做标题、顶部品牌、外链和外层间距处理；
5. 页面上方和左侧导航始终由 App React 提供；
6. DOM、可访问性树、标题、错误页和外链做上游名称泄漏测试；
7. 上游 DOM 不兼容或泄漏测试失败时 fail closed，显示“当前组件版本不兼容”，不得把原始页面直接暴露给用户；
8. 后续如果仅靠主题和稳定初始化脚本不能达到项目 UI 门槛，改用 App 原生 React 表单调用适配器，仍不修改上游代码。

不能直接暴露上游 FastAPI：其默认监听、CORS、部分鉴权和静态任务文件边界不满足本项目要求。必须由 App 自有网关做会话认证、严格来源、路径白名单、请求大小、超时、文件范围和错误脱敏。

## 6. “品牌动效成片”集成设计

### 6.1 适用范围

它把 HTML、CSS、图片、视频片段、字体和可按时间推进的动画确定性渲染为 MP4，不是生成逼真现实镜头的扩散模型。

推荐流程：

    一句话 ContentBrief
        → 选择或推荐视觉风格
        → 生成脚本和分镜
        → 为每个镜头生成 HTML/CSS/动画
        → 静态检查与安全检查
        → 低成本预览
        → 用户确认
        → 逐帧渲染与 FFmpeg 合成
        → 技术质量检查和 Artifact 入库

典型示例：用户输入“用蓝色商务风做一段本周销售增长说明”，系统生成标题、数字、折线图、重点结论和转场动画，不需要寻找真实拍摄镜头。

上游当前稳定版本核对为 v0.7.68，Apache-2.0，要求 Node 22 以上。建议同样以固定 submodule 集成，因为官网风格资源不全部包含在发布的命令行 npm 包中，而且需要离线、可复现和版本锁定。

### 6.2 AI 创作层与无 AI 手工流程

渲染器本身不依赖 AI。已经有合法 HTML/CSS/JavaScript Composition 时，上游默认手工流程可以完整运行：

    init 从空白或示例建立工程并导入素材
        → 人工编辑 index.html / compositions/*.html
        → Studio 实时预览、时间线移动/裁切、属性检查和代码编辑
        → lint / check / snapshot
        → render 输出 MP4

这条流程的问题不是不能渲染，而是“谁来写 H5 代码”。Studio 是预览和编辑器，不会仅凭一句话自动写出脚本、分镜和动画 Composition。

上游提供的 7 步 Pipeline 和 skills 是给外部 AI 编码代理或人工团队使用的制作规范：Capture → Design → Strategy → Storyboard/Script → Voice/Timing → Build → Validate。它们不等于库内置了 LLM，也不会在用户没有配置模型时自动创作。skills 本质上是路由、操作手册、领域规则和配套脚本说明，不是“调用一下就生成视频”的远程 API。

对“一句话自动成片”而言，AI 必须贯穿创作与验收决策，但不进入逐帧渲染循环：

    AI 创作与决策
    理解 Brief / 选择 workflow
        → 生成 DESIGN、SCRIPT、STORYBOARD
        → 选择风格和 Catalog 零件
        → 编写可按时间 seek 的 HTML/CSS/JavaScript Composition
        → 调用 lint/check/snapshot 并查看结果
        → 局部修正，达到门禁后提交 RenderJob

    确定性程序执行
    capture / TTS / transcribe / lint / snapshot / render
        → Chromium 按时间点逐帧取图
        → FFmpeg 编码、混音和封装
        → Artifact 入库

AI 不为每一帧分别写一份代码。它写的是一套时间轴和动画规则，渲染器随后把第 0 秒、第 1/30 秒、第 2/30 秒等时间点确定性求值并取图。RenderJob 一旦冻结输入，最终逐帧取图与 MP4 合成不需要模型在线。

automation-tool 必须增加自己的受限 `MotionAuthoringAgent`：

- 默认“AI 自动制作”使用 App 已配置的创作模型，把一句话或网站抓取结果转成 DESIGN、SCRIPT、STORYBOARD 和 Composition；
- 固定使用 submodule 中经过审计的 workflow/skill/reference 版本，运行时不联网安装或更新 skills；Agent 读取这些规则后只能调用 App 暴露的封闭工具，不直接执行 skill 里的任意命令；
- 模型只返回封闭的结构化 Artifact 和待写入 RenderJob 私有目录的 Composition 内容；capture、TTS、转写、lint、snapshot 和 render 由类型化工具执行，模型不获得 Shell、任意文件、浏览器 Profile、密钥或任意网络工具；
- 模型未配置时，“一句话自动制作”和“网址自动成片”明确不可用，不调用隐藏默认服务；用户仍可从固定模板开始，替换声明过的文字、颜色、Logo、图片和视频，并在 Studio 中手工精修和渲染；
- 设置页使用普通用户能理解的“视频创作模型”名称，并说明哪些脚本、网页文字和品牌资料会发送给外部模型；渲染仍可完全在本机完成。

因此 Studio 是生成后的预览与精修界面，AI 创作代理才是一句话到 H5 的作者，两者不能互相冒充。

### 6.5 网址转视频到底是什么

官网的 URL → Video 不是录制一遍网页，也不是把网址直接交给视频模型。开源工作流是：

    用户输入公开网站 URL 和一句创意要求
        → 浏览器滚动抓取页面
        → 提取截图、配色、字体、图片、SVG、Lottie、视频、文字、区块和按钮
        → 生成品牌说明和 frame.md
        → 文案模型确定一个核心信息、脚本和分镜
        → 可选生成旁白、字幕、音乐和音效
        → 为每个镜头生成 HTML/CSS/动画
        → 检查、预览并渲染为视频

因此它很适合把公司官网、产品落地页或 SaaS 网站变成品牌短片、产品演示、发布预告和功能介绍。官网当前向用户提供的可选项也印证了这一点：

- 横屏 16:9 或竖屏 9:16；
- 自动、品牌短片、产品演示、发布预告、功能介绍；
- 自动音频，或分别控制旁白、字幕、音乐和音效；
- 选择声音和填写必须表达的核心信息。

automation-tool 不调用或逆向官网私有生成接口。App 使用固定 submodule 中公开的 capture 命令和产品视频工作流，在自己的 Worker、模型配置、任务状态机和 Artifact 边界内重建这条链路。

首期只抓取用户拥有或明确获准使用的公开网页，不复用用户日常浏览器 Cookie，不抓登录后页面。网址输入必须经过协议、DNS、IP、每次跳转和最终连接地址检查，拒绝 localhost、私网、链路本地、云元数据、file URL、DNS 重绑定和跨域异常跳转。

上游已经对素材下载的部分 URL 和重定向做了私网拒绝，但主页面导航仍直接调用 page.goto。App 不能把这一点当作完整的 SSRF 防护，必须在外围网关和浏览器请求拦截中补齐。

### 6.7 官网说话人像示例的真实边界

官网的 avatar-explainer 预览中可以直接看到 avatar-scene12-bg-video.mp4 和 avatar-scene3-bg-video.mp4；页面把人物视频作为静音画面轨，再把对应 mp4 音轨单独放进 audio 元素。另一个财务复盘示例也加载了现成的人物讲话视频。

这证明“品牌动效成片”能够把已有说话人物视频放入全屏或小窗，再叠加标题、字幕、图表和转场；不能证明开源渲染器自己生成了这个人、声音或口型。素材可能由 HeyGen 数字人服务预先生成，也可能由作者上传，公开页面不足以进一步确认。

本期允许把用户已经拥有且明确授权的视频作为普通输入素材，但不提供数字人创建、真人克隆或口型生成入口。这些仍是未来第三种方案的范围。

### 6.8 渲染安全边界

模型生成的 HTML/JavaScript 可能包含恶意导航、远程脚本、文件访问或死循环。渲染 Worker 必须：

- 只访问当前 RenderJob 私有目录；
- 默认断开外网，字体、脚本和组件走已校验的本地资源；确需远程素材时走下载服务和域名白名单；
- 拦截非预期导航、file URL 越界、弹窗、下载和新窗口；
- 浏览器进程不拥有 Node 文件系统能力；
- 设置帧数、总时长、CPU、内存、输出大小和单镜头超时；
- 取消、崩溃、电脑休眠和 App 退出后可恢复或安全清理；
- 产出的视频、日志和错误不得包含本机路径或上游产品名。

## 7. 用户界面信息架构

左侧菜单新增“视频制作”，进入后：

1. 新建视频：输入一句话或获授权的公开网站 URL，再选择目标平台、时长、画幅、语言和品牌资料；
2. 选择制作方式：展示“智能素材成片”和“品牌动效成片”两张卡片；
3. 设置：根据所选方式显示素材来源/配音/字幕，或视频类型、12 套整体风格、品牌色、字体和 100 个动效零件的高级设置；
4. 脚本与分镜：用户可修改文案和镜头；
5. 预览与生成：显示预计耗时、磁盘、外部 API 需求、预算和本地资源；
6. 成片：预览、下载、保留、删除和进入现有发布链路。

两张制作方式卡片必须直接回答：

- 最适合做什么；
- 不适合做什么；
- 一个普通人能看懂的示例；
- 是否需要外部模型或素材服务；
- 是否可以主要在本机完成；
- 预计耗时、磁盘和网络消耗；
- 数据会不会离开本机。

不要使用未经解释的行业词。统一写“补充画面”或直接举例，例如“城市街景、办公、跑步、做饭等用来配合旁白的素材画面”。

## 11. 实施门禁

### 11.1 每个任务的工程流程

每个任务激活后都必须：

1. 在主路线图检查依赖并把唯一当前任务置为 RED；
2. 先写能证明目标行为且当前失败的测试，实际运行并记录正确失败；
3. 写最小实现进入 GREEN；
4. 运行任务相关测试、静态检查和适用的正式入口验收；
5. 覆盖任务适用的失败矩阵和资源清理；
6. 同一提交更新代码、测试、主路线图状态和证据；
7. 没有 macOS/Windows 正式包、真实 App 或真实平台证据时，只能标待验收，不能标完成。

文档调研本身不冒充任何实现任务完成。

### 11.2 浏览器失败矩阵

- 发行物缺失、摘要错、版本错、平台或架构错；
- 共用浏览器只通过 RPA 或只通过渲染、渲染器试图下载第二套浏览器、两个用途误用同一进程/Profile/CDP；
- 安装包资源缺失、版本错配、签名失败和 Executor/浏览器组合错误；
- 全新 Profile 创建失败、已锁、权限错、路径被替换和磁盘满；
- 浏览器启动超时、窗口被用户关闭、Playwright driver 崩溃和进程树残留；
- 登录失效、验证码、风险页、页面改版、断网和电脑休眠；
- 评论/私信 dispatch 后断线、最终状态不明确、暂停/取消/紧停竞争；
- 无 Chrome/Edge、完全离线、普通用户权限和卸载重装。

### 11.3 视频失败矩阵

- Worker 缺失、版本不匹配、启动超时、崩溃、挂起和端口被占；
- 会话令牌错、来源错、路径越界、symlink/reparse 和敏感路径泄漏；
- 文案模型、语音、素材站或下载服务超时、限流、返回大文件或非法内容；
- 生成 HTML 远程导航、文件访问、死循环、无限动画和异常大输出；
- FFmpeg 缺失、编解码器不兼容、字体缺失、字幕越界和音频异常；
- 磁盘满、CPU/内存不足、取消、紧停、App 退出、休眠和重启恢复；
- 两个 Worker 与运营 RPA 并发导致资源争抢；
- 上游 WebUI/Studio 出现真实项目名、外链或原始错误；
- 视频创作模型未配置却显示可自动生成、模型获得 Shell/任意文件/运营 Profile/秘密或用户资料发送范围未说明；
- 当前锁定版本内风格缺失、摘要变化或同一 RenderJob 无法重现；
- 网站 URL 指向私网、云元数据、登录页、跳转换域、DNS 重绑定或超大页面；
- 网页文字诱导模型执行工具、泄漏密钥或偏离用户视频目标；
- Catalog 零件依赖远程 CDN、GPU 不兼容、示例人物/商标/音效未替换或权利不明；
- 成片导入成功但任务状态失败，或任务显示成功但 Artifact 不存在。

## 12. 阶段完成定义

只有同时满足以下条件，专项方案才算完成：

- 用户电脑没有 Chrome/Edge 也能安装并运行运营 RPA；
- App、Executor、Playwright、RPA 和动效渲染共用的唯一 Chromium 发行物在首发安装包内版本兼容且可验证；
- 现有抖音登录、搜索、浏览、评论、私信和恢复链路在内置浏览器保持安全语义；
- 左侧存在“视频制作”，用户能从一句话完成两种视频制作方式；
- “智能素材成片”功能完整且不修改上游源码；
- “品牌动效成片”提供官网当前公开的全部 12 套整体风格，并能推荐、预览、微调和冻结；
- 获授权的公开网站可以从 URL 生成品牌短片或产品演示，私网、登录页和未授权网站默认拒绝；
- 官网公开的 100 个动效零件全部进入固定清单和兼容性测试，用户能按中文分类使用，但不会被误导为 100 套整体风格；
- UI、任务、错误和导出中没有两个上游项目名，法务声明除外；
- 普通用户无需理解行业术语就能选对制作方式；
- macOS 和 Windows 正式包完成全新安装、卸载、资源清理和干净机纵向验收；
- 所有真实状态、提交、RED/GREEN 和边界证据进入 docs/development-roadmap.md。
