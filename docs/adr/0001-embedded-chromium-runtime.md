# ADR-0001：桌面 App 内置统一 Chromium 运行时

> 状态：已接受
>
> 决策日期：2026-07-23
>
> 适用范围：首发 macOS arm64、Windows x86_64 桌面安装包，以及 Local Executor、Playwright、Browser Use 和品牌动效逐帧渲染
>
> 替代：产品规划中的 ADR-P002“使用用户电脑外部 Chrome/Edge”

## 背景

现有实现发现用户电脑已安装的 Chrome 或 Edge，再由 App 管理独立运营 Profile。该方案把产品可用性绑定到用户环境：浏览器可能未安装、版本与 Playwright 不匹配、安装位置或签名发生变化，也可能被企业策略限制。App 尚未发布，因此没有需要兼容或迁移的已发布 Profile、浏览器选择设置或客户数据。

本 ADR 替代 ADR-P002。既有 B5 系列实现和验收记录作为历史证据保留，但系统浏览器发现、选择和运行时回退不再是新生产架构；后续任务按专项 Roadmap 逐步替换生产入口。

## 决策

### 单一发行物

- App 安装包携带一套完整 Chromium。它是 RPA、Browser Use 和品牌动效逐帧渲染唯一受支持的生产浏览器二进制；三种用途可以共用二进制，但默认使用不同进程、Context、Profile 和控制通道。
- Chromium 必须与项目的 Playwright 锁定版本严格匹配。这里的“最新”是每次发布候选构建时升级并重新锁定 Playwright 与其对应 Chromium 修订，不是运行时下载最新浏览器，也不是独立追逐 Chromium 版本号。
- macOS arm64 与 Windows x86_64 分别构建发行物。构建期记录来源、Playwright/Chromium 版本、修订、平台、架构、许可证和逐文件 SHA-256；安装后只从 Tauri `resource_dir` 解析并逐文件验证。
- 文件缺失、多出未声明浏览器、摘要或架构不符、版本不兼容、路径被 symlink/reparse point 替换时失败关闭。运行时不联网下载浏览器，不发现或回退到系统 Chrome/Edge，也不接受用户提供的浏览器路径。

### 运行所有权

- Tauri/Rust 是浏览器发行物与进程生命周期的信任根：验证资源、创建运行租约、把已验证路径通过受认证启动协议交给 Local Executor，并在 App 退出、取消、超时或崩溃时清理本次拥有的完整进程树。
- Local Executor 继续使用 Playwright headed persistent context 执行既有平台 Adapter。Browser Use 通过受限 Agent/BrowserSession 使用同一发行物；品牌动效渲染使用独立无头进程逐帧截图。是否能由三者共用同一 Chromium 版本必须在 EB-02 提前验证，通过前不得开始后续打包迁移。
- “共用 Chromium”只代表共用经过签名和摘要校验的二进制。运营 RPA 与 Browser Use 需要操作同一抖音页面时，必须通过独占页面租约串行交接；渲染进程永远不能连接运营 Profile 或运营 CDP 会话。

### Profile 与登录态

- 首次启用平台时创建全新的 App 私有运营 Profile。App 从未发布，不设计旧 Profile、旧浏览器选择或旧 Cookie 迁移，也不为开发期数据保留兼容分支。
- 不读取、复制或迁移用户默认浏览器 Profile、Cookie、Local Storage 或浏览历史；用户也不能导入任意 Profile 路径。
- Profile 继续使用本机生成的规范 UUID、私有权限、稳定目录身份、跨进程排他锁和平台隔离。Cookie 只由 Chromium 在 Profile 内管理，不进入 React、Control Plane、日志、事件或导出。
- 注销继续先阻止新任务、停止关联浏览器并释放锁，再定向删除该平台 Profile；停止或结果不确定时保留 Profile 并失败关闭。

### 可见操作与人工接管

- 运营浏览器默认有界面。用户可以看到实际网页操作，并从 App 的固定入口请求人工接管；接管期间自动控制器必须释放或暂停页面租约，不能与用户同时操作。
- 验证码、滑块、登录过期、风险提示和平台安全校验一律暂停交给用户处理。产品不实现绕过验证码、stealth、指纹伪装或隐藏无人值守触达。
- 品牌动效逐帧渲染是独立无头进程，不属于人工接管范围，也不能读取运营页面或登录态。

## 首期边界

- 先把现有抖音登录、会话检测、搜索、浏览、候选提取、评论、私信、恢复和注销保持行为不变地迁移到内置 Chromium；既有固定 Playwright 页面脚本本期不重写为 AI。
- Browser Use 首期只用于新建的抖音作品发布链路。B站首期使用 API；快手、小红书和微信视频号只保留后续规划。
- Browser Use 的任意网站通用操作入口、自愈式自动化、抖音搜索/评论/私信的 Browser Use 重构均不在本期。
- 本 ADR 不宣称浏览器已经打包或生产入口已经迁移。兼容矩阵、三方共用验证、构建暂存、Manifest、Rust 验证、Executor 协议迁移和正式包验收分别由 EB-01～EB-17 完成。

## 影响

- 设置页不再让用户检测或选择 Chrome/Edge，改为显示“浏览器组件正常 / 浏览器组件损坏 / 浏览器组件版本不兼容”及安全修复说明。
- 正式安装包体积会增加，发布流程必须承担双平台浏览器供应链、许可证、签名、摘要、SBOM、升级和卸载验证。
- 自动化稳定性不再受用户浏览器安装版本影响，但每次 Playwright 或 Chromium 升级都必须作为一个整体重新验证 RPA、Browser Use 和逐帧渲染。
- 既有系统浏览器代码在迁移期间只作为待替换实现存在；不得通过 fallback、兼容开关或用户路径输入重新成为生产路径。

## 验收

- 本 ADR 与 `CLAUDE.md`、产品规划、工程结构、前端架构、后端架构和专项 Roadmap 对同一决策无冲突。
- AV-01 只完成架构决策和基线切换；不以文档代替 EB 系列代码、正式包或真实平台验收。
- 后续任何用户可操作的浏览器功能，只有从正式 App 正常用户入口按真实操作路径跑通，并核对真实浏览器或平台最终状态，才能完成；Mock、单元测试、UI Harness、直接内部调用和测试专用入口都不能替代该验收。缺少真实环境时保留 `待验收`，但不阻塞可独立推进的任务。
