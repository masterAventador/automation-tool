## 三、两个当场会坑人的坑（我今晚都踩了）

### 1. `hdiutil create -srcfolder` 在这台机器上对已签名 App 包完全不通

四组对照（都用真实已签名并公证的包）：

| 暂存内容 | 结果 |
|---|---|
| `自动化运营工具.app` | EPERM |
| 同一个包改名成 `payload` | 成功 |
| 合成的 `Probe.app` 桩 | 成功 |
| 直接把 `.app` 交给 `-srcfolder`（T84 之前的老写法） | EPERM |

结论：既不是名字也不是体积，是**真正的已签名 App 包**；老写法今天同样失败，**不是 T84 引入的回归**。本进程用 `ditto` 把同一个包拷进同一个挂载卷完全正常，说明拒绝发生在 hdiutil 委派的拷贝助手那一侧。

现在的实现是：建空的可写映像 → 挂到私有 mountpoint（**不进 `/Volumes`**）→ 自己 `ditto` 填充 → 卸载 → 压缩。附带消灭了卷名冲突这一整类问题。**不要试图改回 `-srcfolder`**，`scripts/test_build_release_package.py` 有门禁挡着，理由写在它的 docstring 里。

### 2. 内置浏览器缓存过期会把 36 个桌面验收驱动全堵死

**先看这条，因为你多半会撞到。** 症状：

```
embedded browser distribution rejected: staging exclusion record differs from the target contract
```

原因：`d5e5111`（07-26 21:29，剔除 Widevine）改了暂存契约，比它早建的缓存全部作废。`desktop_e2e_prerequisites.py` 里暂存**目标**验证失败会 `rmtree` 后重建（自愈），**源缓存**验证失败直接抛（死路）。**36 个驱动**走到这一行。

解法（主线已把它写进拒绝信息，提交 `73687e7`）：

```

from desktop_e2e_prerequisites import build_embedded_browser_cache; print(build_embedded_browser_cache())"
```

### 3. 子代理在远程机器上起长任务，会以为自己能「等」

**今晚发生了两次**，两次都是派去 winbox 干活的线：它在远程起了个长时间的构建/测试链，然后回一句「我等它跑完再报」——**而它一说完话就终止了**。远程那个进程还在跑，但没有任何东西会替它收结果。

派这类任务时在 prompt 里写明：**「你回消息就等于这一轮结束，远程任务不会有人替你收；要么等到拿到退出码再回，要么把日志路径交出来说明还没收」**。发现之后用 SendMessage 唤回去继续即可（名字/ID 都能唤醒，它带着原来的上下文）。

## 三之二、合并之后立刻改台账状态，别等下一轮

**今晚犯了两次**（T113、T57b）：分支合并进 main 了，而它在未收口区那一行还写着旧状态，各挂了一到两小时。两次都不是被通知发现的，是我用解析器扫未收口列表时才现形。

`CLAUDE.md` §2.1 写着「验收通过 → 立刻把台账状态改对 → 才轮到总结、汇报、下一个任务」。**问题在于「合并」和「改台账」是两个动作，中间隔着写总结**，而总结一写完就容易以为这条结束了。

可操作的做法：**`git merge` 和 `docs/demo-sprint-roadmap.md` 的状态更新放进同一次提交序列，中间不插入任何对用户的汇报**。或者合并后立刻跑一次未收口列表解析（下面这段），拿它和你以为的状态对一遍：

```
backend/.venv/bin/python - <<'PY'
import re, pathlib
text = pathlib.Path("docs/demo-sprint-roadmap.md").read_text(encoding="utf-8")
for line in text.splitlines():
    if line.startswith("|") and re.match(r"^\| T\d+", line):
        cells = [c.strip() for c in line.split("|")]
        if len(cells) >= 6:          # 未收口表是四列，已收口表是两列
            print(cells[1], cells[3][:10], cells[2][:40])
PY
```

## 四、并行开发的三条硬约束

1. **worktree 一律用 `python3 scripts/new_worktree.py <名字> [提交]`**，理由见 `CLAUDE.md` §8.1（软链会被 vendor 门禁拒、硬链会穿透污染另一棵树）。它默认从 `origin/main` 建，**如果本地 main 更新了要显式传提交**。
2. **不要软链 `backend/.venv` 或 `frontend/node_modules`**。pnpm 11 会先删再装，而且报错时建议你设 `CI=true`——照做就静默删掉主树那份。
3. **两轮全量回归不能在同一个检出并行跑**，它们抢同一个 1420 端口，必然有一轮假红。我今晚就制造过一次，已停掉旧那轮。

**审子代理交付时**：diff 一定要用 `git merge-base main <分支>` 做基点。用错基点会把「它的分支比 main 旧」显示成「它删了一堆文件」——我今晚差点因此误报子代理删了 T104 的文档，**同一个错误今天犯了两次**。
