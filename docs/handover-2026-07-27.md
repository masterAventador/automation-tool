## 二、出包会比以前慢很多，这是预期的

T111 把三个视频运行时产物的缓存键补齐了输入，**键全变**，所以每台机器要一次性重建三个产物，其中 **ffmpeg 从源码编译**。

**这一步我已经在 03:14–03:17 跑完了**（`scripts/prepare_video_runtime.py --platform macos`），就是为了让解锁后的出包只剩 Tauri 构建 + 签名 + 公证 + 打映像。四个产物都带着新 stamp：

```
~/Library/Caches/automation-tool-build/
  material-video-worker  357M   03:16
  motion-video-worker    108M   03:14
  media-toolchain         42M   03:14
  subtitle-fonts          32M   03:15
```

**暂存根是 `~/Library/Caches/automation-tool-build`，不是 `.local/video-runtime`**（后者是旧布局的残留，只有 07-26 的 media-toolchain，我一度查错地方并误判成静默失败）。用 `prepare_video_runtime.py --print` 可以让它自报位置。

接手时若需要重跑：**不要和出包并发跑**（四者共用每机一份的缓存目录，`ensure_cached` 会先 `rmtree` 再建）。

**出包前先核一遍缓存还命不命中，别凭「我记得预建过」。** 08:20 实测撞到过：T122 改了 `build_material_video_worker_candidate.py`，而那个文件在素材成片 Worker 的缓存键里（T111 刚加的），于是那份 357 MB 产物已经失效。**这恰好证明 T111 修对了**——旧缓存键只摘要两个契约，改构建驱动不会失效，出包就会静默复用旧 Worker，正是 T32「提交在包里、效果不在」的机制。

核对方式（拿当前文件重算指纹与 stamp 比，不是看时间戳）：

```
backend/.venv/bin/python -c "
import sys; sys.path.insert(0,'scripts')
from prepare_video_runtime import MEDIA_TOOLCHAIN_INPUTS, MOTION_WORKER_INPUTS, MATERIAL_WORKER_INPUTS
from video_runtime_cache import contract_fingerprint, cache_root
import json
root = cache_root()
for name, inputs in [('media-toolchain', MEDIA_TOOLCHAIN_INPUTS), ('motion-video-worker', MOTION_WORKER_INPUTS), ('material-video-worker', MATERIAL_WORKER_INPUTS)]:
    was = json.loads((root / f'{name}.stamp.json').read_text()).get('fingerprint')
    print(name, '命中' if was == contract_fingerprint(inputs) else '已失效')
"
```

失效的用 `--only <名字>` 单独补，不必三个都重跑。

另外这个脚本**成功时不打印任何东西**，日志只有你自己追加的那行 `EXIT=`。别把「日志是空的」当成没干活——去看上面那个目录的 stamp 时间。

## 三、当场会坑人的坑（每一条我今晚都踩过）

### 1. `hdiutil create -srcfolder` 在这台机器上对已签名 App 包完全不通

四组对照（都用真实已签名并公证的包）：

| 暂存内容 | 结果 |
|---|---|
| `自动化运营工具.app` | EPERM |
| 同一个包改名成 `payload` | 成功 |
| 合成的 `Probe.app` 桩 | 成功 |
| 直接把 `.app` 交给 `-srcfolder`（T84 之前的老写法） | EPERM |

结论：既不是名字也不是体积，是**真正的已签名 App 包**；老写法今天同样失败，**不是 T84 引入的回归**。本进程用 `ditto` 把同一个包拷进同一个挂载卷完全正常，说明拒绝发生在 hdiutil 委派的拷贝助手那一侧。

现在的实现是：建空的可写映像 → 挂到私有 mountpoint（**不进 `/Volumes`**）→ 自己 `ditto` 填充 → 卸载 → 压缩。附带消灭了卷名冲突这一整类问题。**不要试图改回 `-srcfolder`**，`scripts/test_build_release_package.py` 有门禁挡着，理由写在它的 docstring 里。

## 五、并行开发的硬约束

1. **worktree 一律用 `python3 scripts/new_worktree.py <名字> [提交]`**，理由见 `CLAUDE.md` §8.1（软链会被 vendor 门禁拒、硬链会穿透污染另一棵树）。它默认从 `origin/main` 建，**如果本地 main 更新了要显式传提交**。
2. **不要软链 `backend/.venv` 或 `frontend/node_modules`**。pnpm 11 会先删再装，而且报错时建议你设 `CI=true`——照做就静默删掉主树那份。
3. **两轮全量回归不能在同一个检出并行跑**，它们抢同一个 1420 端口，必然有一轮假红。我今晚就制造过一次，已停掉旧那轮。

**审子代理交付时**：diff 一定要用 `git merge-base main <分支>` 做基点。用错基点会把「它的分支比 main 旧」显示成「它删了一堆文件」——我今晚差点因此误报子代理删了 T104 的文档，**同一个错误今天犯了两次**。
