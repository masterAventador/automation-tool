# 自动化运营工具产品规划

> 文档性质：产品范围、优先级、阶段路线图和验收基线
> 建立日期：2026-07-18
> 当前阶段：第一期单设备 MVP 规划，业务后端独立可部署
> 竞品依据：[`dt-ai-helper-competitive-analysis.md`](dt-ai-helper-competitive-analysis.md)

## 1. 产品结论

本产品不是从“AI 中台”起步，而是从用户每天真正要完成的运营动作起步：

```text
RPA 运营
  ↓ 产生任务、素材、会话和运营数据
内容生产与分发
  ↓ 沉淀可重复流程
AI 员工与工作流
```

固定优先级：

1. RPA 运营；
2. 内容生产与分发；
3. AI 员工与工作流。

第一期目标不是一次性复刻竞品所有菜单，而是先完成一个用户真正能用的纵向闭环：打开 App，无需注册或登录本产品，配置一个抖音运营任务，完成平台登录、执行、人工接管、结果记录和重启恢复。

产品交付形态只有 Tauri 桌面客户端。项目保留的 Vite 浏览器运行模式只是开发与 Playwright 使用的测试专用 UI Harness，不是 Web 产品，不部署到服务器，也不能作为真实 RPA 或微信能力的验收替代品。

## 2. 第一阶段产品原则

### 2.1 本地 MVP 先无账号，客户 Demo 前补齐账号体系

Wave 1～Wave 9 先完成单设备 RPA 闭环，此阶段不建设：

- 产品注册和登录；
- 用户、组织、租户和成员；
- RBAC、套餐、Entitlement 和计费；
- 设备席位、云端账号中心和跨设备同步；
- 依赖云端身份才能启动的授权链。

P9 本地候选版启动后直接进入 RPA 运营工作台。任务、结构化事件和运行记录保存在 Control Plane PostgreSQL；平台 Cookie、浏览器 Profile、微信数据和原始本机证据只保存在 App 私有目录。

在任何客户 Demo 交付前，必须完成 U9-01～U9-06 的产品账号体系：客户使用产品账号登录，Demo 账号由认证运维入口创建和恢复，首版不开放匿名自注册；登录成功后 Installation 通过既有设备密钥证明自动绑定当前账号，不使用配对码、设备轮询或后台逐设备审批。组织、租户、RBAC、套餐、计费和跨设备业务数据同步仍不进入首个 Demo 范围。

客户 Demo 启动时未登录只显示登录与恢复状态，不能进入业务工作台；账号会话和设备归属都有效后进入工作台。产品账号只控制 automation-tool 的服务访问，不改变平台 Cookie、浏览器 Profile 和原始本机证据的本地存储边界。

### 2.2 产品账号与平台登录态分离

“本地 MVP 暂不做产品账号”以及后续增加产品登录，都不代表可以绕过抖音、小红书等平台自身的登录：

- 用户第一次使用某个平台时，需要在外部浏览器窗口完成平台扫码或登录；
- 登录态保存在 App 管理的独立运营浏览器 Profile 中；
- 后续任务复用该登录态，正常情况下不需要每次重新扫码；
- 登录失效、二维码过期、验证码和平台风险提示时暂停任务并交给用户处理；
- App 不读取用户日常浏览器的默认 Profile 和 Cookie。

### 2.3 先闭环，再扩平台

MVP 只承诺：

- 单台电脑；
- 单个本地用户；
- 单个运行中任务；
- 抖音一个平台；
- 搜索目标、预览目标、受控评论/主动私信这一条运营链路；
- 可见浏览器、硬频控、暂停、取消、人工接管、结果与证据；
- App 重启后的任务与平台会话恢复。

小红书、内容发布、微信和 AI 不得挤占首条闭环的稳定性工作。

### 2.4 后端开发与 Demo 部署

从第一天就把 Python 分成两个逻辑和进程边界：

- `Control Plane`：独立 FastAPI 业务后端，负责任务、事件、配置，以及后续内容、AI 和工作流；
- `Local Executor`：随 App 运行在用户电脑，负责浏览器、微信、OCR、文件和平台登录态。

开发时，Control Plane 在开发机本地启动，App 的 `baseUrl` 指向 loopback，便于热更新和快速调试。打包客户 Demo 时，同一 Control Plane 和数据库迁移部署到云端，App 只通过环境 Profile 切换 HTTPS `baseUrl`，不能维护本地版和云端版两套业务代码。

P9 本地 MVP 没有产品注册或登录页面；云端客户 Demo 必须等待 U9 账号体系完成。客户先登录产品账号，Rust 在登录态下复用既有设备密钥证明，把 Installation 自动绑定当前账号并持有可撤销、限环境、限权限的设备凭据；不使用匿名设备申请、配对码、设备轮询或后台逐设备审批。账号停用、产品 Session 注销和设备吊销均能独立阻止服务访问，服务端接口不得匿名裸露。平台 Cookie、微信数据和浏览器 Profile 始终只保存在本机 Local Executor。

## 4. MVP：抖音 RPA 运营闭环

### 4.1 目标用户与场景

目标用户是需要在抖音搜索潜在目标并进行少量、受控互动的运营人员。

首条用户旅程：

```text
打开 App
  → 环境检查
  → 新建抖音任务
  → 配置关键词、目标和动作
  → 如未登录，外部 Chrome/Edge 扫码
  → 预览待执行目标
  → 用户确认
  → 可见浏览器执行
  → 实时查看进度
  → 成功 / 失败 / 暂停 / 人工接管
  → 查看结果与证据
```

### 4.2 MVP 页面

#### A. RPA 运营工作台

- 当前 Installation 的累计任务/动作总数、成功、失败、待人工接管和结果不确定；MVP 未建立用户时区前不展示可能误导的“今日”口径；
- 当前运行任务和一键紧急停止；
- 最近任务；
- 抖音平台会话状态；
- “新建任务”主按钮；
- 环境异常和可操作的修复入口。

#### B. 新建任务

第一版只提供“抖音搜索曝光”模板：

- 搜索关键词；
- 动作：只浏览、评论、主动私信；
- 评论或私信模板；MVP 支持固定文案，可选且仅允许 `{{target_display_name}}` 目标展示名变量；
- 单任务目标上限；
- 动作间最小间隔和随机等待区间；
- 目标预览中的本次排除；
- 是否先预览；MVP 固定为开启，不允许关闭；
- 高风险动作的最终确认。

可配置的目标过滤器和用户维护黑名单不属于当前 MVP；当前只执行固定的任务内去重、历史去重窗口与服务端黑名单策略，待真实账号数据证明筛选口径后进入增强阶段。

#### C. 登录与人工接管

- 明确说明将打开外部 Chrome/Edge；
- 展示“等待扫码”“已检测登录”“二维码过期”“登录失效”；
- 验证码、滑块或风险提示时给出“打开浏览器处理”；
- 用户处理完成后点击“我已处理，重新检查”；
- 提供“退出该平台登录并清理运营 Profile”。

#### D. 目标预览

- 展示识别到的目标摘要和来源；
- 默认不展示或持久保存非必要个人信息；
- 用户可以取消单个目标、全部取消或确认执行；
- 重复目标、黑名单和超出限额的目标有明确标记。
- 最终确认必须同时展示动作、原始文案模板、选中目标数量和确认版本；弹窗打开后冻结该次审阅快照，目标或任务变化时旧提交必须拒绝并要求重新审阅。

#### E. 任务运行详情

- 当前状态、总进度、当前步骤和浏览器状态；
- 事件时间线；
- 目标级结果：跳过、成功、失败、结果不确定；
- 暂停、恢复、取消和紧急停止；
- 人工接管入口；
- 失败时的脱敏诊断结论和建议动作；
- 完成后的结构化目标摘要。

当前 MVP 会按固定安全策略保存受限截图/Trace，并可导出脱敏诊断包，但不在任务页直接浏览原始截图，也不提供业务结果文件导出；截图直览和结果导出在完成隐私、权限与留存设计后进入增强阶段。

#### F. 本地设置与诊断

- Chrome/Edge 检测和选择；
- App 私有数据目录健康状态；
- 平台会话清理；
- 浏览器、Python Control Plane 和 Local Executor 健康检查；
- 版本、用户主动“检查更新”和诊断信息导出。

当前截图、Trace、Artifact 和日志使用代码内固定的数量、大小与保留期限，用户不能在 UI 放宽；占用空间明细、可配置留存和分类清理属于后续设置增强。

### 4.3 MVP 状态

用户可见任务状态：

| 状态 | 含义 | 用户动作 |
| --- | --- | --- |
| 草稿 | 尚未提交 | 编辑、删除 |
| 校验中 | 检查参数和本机环境 | 等待、取消 |
| 等待平台登录 | 需要扫码或重新登录 | 打开浏览器、取消 |
| 等待确认 | 已生成目标预览 | 确认、修改、取消 |
| 运行中 | 正在执行平台动作 | 暂停、取消、紧停 |
| 已暂停 | 停在安全检查点 | 恢复、取消 |
| 等待人工处理 | 验证码、风控、页面变化等 | 接管、重试检查、取消 |
| 已完成 | 任务正常结束 | 查看、复制新任务 |
| 部分完成 | 部分目标成功，部分失败或跳过 | 查看、受控重试失败项 |
| 失败 | 无法继续 | 查看原因、复制任务 |
| 已取消 | 已确认执行器停止 | 查看已产生结果 |
| 结果不确定 | 外部动作可能已发生但无法确认 | 人工核对，不自动重放 |

### 4.4 MVP 风险护栏

以下规则不能被用户在 UI 中放宽到不安全值：

- 单任务目标数量硬上限；
- 每个平台、每个动作的每日硬上限；
- 动作最小间隔；
- 同一目标去重窗口；MVP 固定为 30 天且 UI 不可放宽；
- 连续失败自动熔断；
- 登录失效和风险提示立即停止新副作用；
- 评论和主动私信执行前必须预览并确认；
- 验证码、滑块和风控只允许人工处理；
- 紧急停止在所有页面始终可达；
- MVP 只允许一个任务运行，避免账号并发操作。

具体默认值需通过受控账号 PoC 校准，不能在没有真实测试的情况下写死成“安全值”。

### 4.5 MVP 验收标准

MVP 必须同时满足：

1. 全新安装后打开 App，不出现产品注册或登录页面；
2. App 自动完成 Control Plane 连通性、Local Executor、浏览器和数据目录诊断；
3. 未登录抖音时，任务进入“等待平台登录”，并拉起可见的外部浏览器；
4. 用户扫码一次后，App 能检测登录并在下一次启动复用平台登录态；
5. 用户能创建关键词任务，看到真实目标预览并排除目标；
6. 用户确认后能在可见浏览器中完成受控动作；
7. 每个目标都有结构化结果，成功必须由页面最终状态或平台可核对结果证明；
8. 用户可以暂停、恢复、取消和紧急停止；
9. 遇到验证码、风控、登录失效或未知页面时不误点、不自动绕过，进入人工处理；
10. App、Control Plane 或 Local Executor 崩溃重启后，不重复已经确认完成的副作用，并能恢复任务快照；
11. 结果不确定的动作不会自动重试；
12. 日志、事件和截图不泄漏 Cookie、Token、完整页面私密内容或本机私有路径；
13. macOS 和 Windows 分别完成安装、启动、外部浏览器、Local Executor 生命周期和真实测试账号验收；
14. 正式安装包不包含测试驱动、调试端口、测试凭据或真实运行数据。

## 5. 分阶段路线图

### P0：本地执行底座

目标：提供所有后续 RPA 共用、但不超出 MVP 需要的最小底座。

- Tauri/React App 骨架；
- 可独立部署的 Python FastAPI Control Plane；开发时本机启动，客户 Demo 时部署云端；
- Python Local Executor Sidecar；
- Control Plane 与 Executor 之间受认证、版本化的执行协议和事件通道；
- PostgreSQL 仓储、数据库迁移、任务状态机和事件存储；
- 环境诊断、日志脱敏和本地数据目录；
- 与业务解耦的桌面自动更新：启动/周期/手动检查、后台下载、可选更新的立即安装/暂缓/跳过版本，以及不可跳过的强制更新；
- 外部浏览器启动、独立 Profile 和一次登录长期复用；
- 暂停、取消、紧停、人工接管和崩溃恢复。

完成标志：使用假平台 Adapter 可以跑完与真实 MVP 相同的任务状态和用户界面链路。

### P1：RPA 运营

#### P1.1 抖音 MVP

- 关键词搜索；
- 目标预览、筛选和去重；
- 只浏览、评论、主动私信；
- 频控、熔断、接管和结果记录。

#### P1.2 抖音运营增强

- 自动曝光、定向曝光、链接曝光和账号搜索；
- 多模板、批次和失败项受控重试；
- 运营看板和转化标记；
- 抖音账号健康与发布准备。

#### P1.3 小红书运营

- 独立平台 Adapter 和 Profile；
- 搜索、目标预览、评论和主动私信；
- 平台独立频控、页面版本和失败隔离；
- 不在动态验证前承诺入站私信自动回复。

#### P1.4 抖音客服

- 优先评估官方接口；
- 私信会话、欢迎语、回复建议和人工发送；
- 自动回复必须在风险策略和真实验收后灰度；
- 会话跟进、黑名单、退订和人工接管。

#### P1.5 快手运营

- 搜索、目标互动和主动触达；
- 独立 Adapter、页面版本和真实账号验证。

#### P1.6 微信回复

- Windows UI Automation 为第一实现目标；
- 环境、版本、窗口、DPI 和锁屏诊断；
- 未读识别、最小上下文读取和回复建议；
- 第一版默认人工确认后发送。

#### P1.7 微信私域

- 好友申请、联系人分群和个性化群发；
- 沉默客户激活；
- 朋友圈发布和营销；
- 独立频控、黑名单、退订、熔断和紧停。

### P2：内容生产与分发

#### P2.0 素材与任务

- 本地素材库、标签、搜索和引用；
- 下载任务、缓存、空间限制和清理；
- 成片与发布任务稳定关联。

#### P2.1 视频生产

- 供应商无关 Timeline 和模板；
- 一键剪辑、模板剪辑和批量任务；
- `VideoRenderProvider`；
- MVP 后根据成本和网络条件在阿里云 IMS/ICE 与本地 FFmpeg 之间做正式 Provider 决策。

#### P2.2 多平台分发

- 抖音、小红书、快手和视频号发布 Adapter；
- 单平台、聚合和批量发布；
- 标题、话题、封面、发布时间和平台差异；
- 发布记录、最终状态确认、失败隔离和重试。

#### P2.3 内容策略

- 标题、文案、话题和模板库；
- 内容日历与发布计划；
- 素材到成片到发布的效果关联。

#### P2.4 AI 视频增强

- 图生视频、人物替换等供应商能力；
- 输入授权、内容审核、成本与失败降级；
- 不把某个供应商对象泄漏到业务模型。

### P3：AI 员工与工作流

#### P3.0 模型与知识基础

- 供应商无关模型 Adapter；
- 本地或远程模型配置；
- Prompt、知识、黑名单和敏感词；
- AI 不是 RPA 任务状态的事实来源。

#### P3.1 AI 运营员工

- 运营诊断助手；
- 内容策划与文案员工；
- 客服回复员工；
- RPA 异常诊断和人工决策建议；
- 所有外部副作用仍由确定性任务和风险门禁执行。

#### P3.2 工作流

- 组合素材、剪辑、发布、曝光、客服和审批节点；
- 条件、等待、重试、暂停、取消和人工接管；
- 工作流只编排稳定公开能力，不直接操纵页面选择器；
- 长任务可靠性需求被真实验证后，再评估 LangGraph 或 Temporal，不提前引入。

## 6. 核心产品指标

MVP 不以“菜单数量”衡量进度，重点观察：

- 任务端到端成功率；
- 目标级动作成功率；
- 登录态复用成功率；
- 页面改版导致的失败率；
- 人工接管率和接管完成率；
- App、Control Plane 和 Local Executor 崩溃后的恢复成功率；
- 结果不确定动作占比；
- 每个有效动作的平均耗时；
- 因频控、风控和安全门禁主动阻止的动作数；
- 用户从打开 App 到首次任务完成的时间。

这些指标来自结构化任务和事件，不从非结构化日志猜测。

## 7. 第一阶段明确不做

- 产品账号、登录、企业组织、多租户、RBAC 和计费；
- 面向用户的 Web 版、网页入口或 Web 部署；
- 多设备、云端调度和跨设备任务接管；
- 多账号并发、任务并行和无人值守大规模触达；
- 内嵌社交平台浏览器；
- 自动接管用户默认浏览器 Profile；
- 读取或迁移用户主浏览器 Cookie；
- Headless 隐藏执行、stealth、指纹伪装和验证码绕过；
- 全平台一次性铺开；
- 以 AI 生成内容作为抖音 MVP 的硬依赖；
- AI 中台、知识平台、Skill 市场和通用 Agent 编排；
- 未经用户明确指令的云端部署、采购和公网开放。

## 8. 关键产品风险

### 平台规则与封号风险

自动评论、主动私信和批量互动具有高风险。产品必须支持硬上限、可见执行、预览确认、测试账号验证、人工接管和紧停；不能宣传“防封”“绕风控”或“完全无人值守”。

### 页面改版风险

浏览器 RPA 依赖页面结构。必须把平台 Adapter、页面版本、定位器、诊断证据和回归样例作为持续维护的正式产品成本。

### 登录与隐私风险

独立运营 Profile 会保存平台登录态，因此必须位于 App 私有目录，提供清晰的注销与清理入口。不能因为追求免登录而读取用户所有日常浏览数据。

### 结果不确定

网络或进程可能在点击平台按钮后中断。此时不能简单重试，否则可能重复评论或重复私信。产品必须能表达“结果不确定”并引导人工核对。

### 跨平台差异

抖音和小红书浏览器链路可以跨 macOS/Windows；微信桌面自动化需要分别适配操作系统和客户端版本，不能假设同一实现通用。

## 9. 决策记录

### ADR-P001：本地 MVP 延后账号，客户 Demo 前必须实施

- 决策：P9 以前以单安装实例、打开即用验证 RPA 闭环；任何客户 Demo 必须先完成产品账号登录、Session、恢复、账号停用和账号绑定设备，未登录不得进入工作台；
- 原因：账号体系不应阻塞首条 RPA 闭环，但客户云端交付必须具备明确的用户身份和设备归属；
- 影响：首个 Demo 账号由认证运维入口创建，不开放匿名自注册；不使用配对码或逐设备审批；组织、租户、RBAC、计费和跨设备业务数据同步继续后置。

### ADR-P002：不内嵌运营浏览器

- 决策：使用可见的外部 Chrome/Edge 窗口；
- 原因：竞品主链路也是受程序管理的外部浏览器，外部浏览器更接近平台正常使用环境，调试和人工接管更直接；
- 影响：App 需要可靠管理浏览器进程、窗口和 Profile 生命周期。

### ADR-P003：不自动化用户默认浏览器 Profile

- 决策：调用系统浏览器可执行程序，但使用 App 独立运营 Profile；
- 原因：默认 Profile 存在目录锁、会话污染、隐私扩大和现代 Chrome 自动化限制；
- 影响：每个平台首次需要扫码一次，后续持久复用。

### ADR-P004：抖音单平台纵向切片优先

- 决策：首个真实闭环只做抖音搜索曝光；
- 原因：先验证平台登录、页面定位、副作用、恢复和风险护栏，再复制稳定接口到小红书；
- 影响：小红书和微信菜单不会在 MVP 中做空壳展示。

### ADR-P005：桌面更新使用官方安装底座和自有通用策略层

- 决策：macOS/Windows 平台识别、feed 检查和安装原语采用官方 Tauri updater；为满足断点恢复，下载缓存复用同一 Rust 依赖树的 HTTP 与 Minisign 原语；启动/周期/手动触发、可选/强制策略、暂缓、跳过版本、缓存覆盖和提示 UI 由不引用任何运营业务的本机通用协调层负责；
- 原因：安装包替换、平台安装器和签名校验属于成熟原生底座，不应重复造轮子；竞品业务、任务、客户或社交平台规则也不应进入更新器；
- 当前实现：H8-21 已在 H8-20 的独立服务端 feed、Rust-only official updater、启动/6 小时周期/手动统一入口、断点续传和 SHA-256 + Minisign 单候选私有缓存上，接通立即安装/暂缓/跳过与强更下次启动安装。安装前安全停止 Executor/释放 Profile，Windows 交由官方安装器退出接管，macOS 成功替换后重启；双平台真实签名包跨版本升级仍按 H8-22 实施；
- 影响：React 不能直接获得 updater 插件权限或下载地址，发布私钥只存在于受控构建环境；强制更新表示用户不能跳过，并不放宽安装包验签、操作系统代码签名或 App 安全退出要求。
