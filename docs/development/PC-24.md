## 交付结果

`spain-map`、`us-map`、`us-map-bubble`、`us-map-flow`、`world-map` 和
`vfx-iphone-device` 已从独立渲染豁免清单移除。发布树构建器把它们在运行时读取的三份
TopoJSON 与两份品牌中立 GLB 编码为 base64 data URL，写入最终发布树的六份 HTML；
vendor submodule、BM-12 暂存树和原始资源文件均不修改。

发布契约 `runtimeDataInlining` 锁定六份文档、七个引用、精确源文件和封闭 MIME 类型。
构建器要求每个旧引用恰好出现一次，源/目标必须是发布树内的普通文件；发布门禁按源文件重新
计算期望 data URL，并拒绝旧引用残留、内联内容漂移、重复声明、路径越界、未知 MIME 或统计漂移。

## 路线实验

交接给出的两个候选先按真实发布树量过：

| 数据 | 字节 |
|---|---:|
| Spain TopoJSON | 37,420 |
| US TopoJSON | 114,554 |
| World TopoJSON | 107,761 |
| portable-device.glb | 944 |
| portable-display.glb | 1,044 |

US 数据虽被三个零件各内联一次，整体增量仍不足以抵消随机 loopback 静态服务带来的端口、
进程生命周期、请求鉴权与新攻击面成本。因此选择构建期 data URL 内联；没有采用
`--allow-file-access-from-files`，Worker 源码门禁明确禁止该旗标。

## 真实边界

- data URL 只在最终 App-owned 发布树生成，第三方 submodule 不写入。
- 原始数据/模型仍作为已锁定发布文件保留，便于摘要、权利与来源门禁复核；HTML 内联副本由同一
  源字节确定性产生。
- 本任务只解决已定性的六个 `runtime-fetch-blocked` 零件；其余 19 项各有独立内容/架构原因，
  没有顺带宣称完成。
- 不提交 `.local` 发布树、Chromium、帧文件或 BM-16 运行证据产物。
