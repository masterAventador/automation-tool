## RED

`uv run pytest tests/integration/test_embedded_browser_lifecycle.py` 首轮
2 failed / 2 passed / 1 skipped，两条真实失败：

1. `DID NOT RAISE BrowserRuntimeRejected`——**真实产品缺陷**：浏览器进程被外部
   SIGKILL 后，`BrowserRuntime.primary_window()` 仍返回窗口而不 fail-closed；
2. `assert '' ... browser lifecycle must emit bounded diagnostics`——**测试断言
   不当**（非产品缺陷）：诊断是有界恢复语义，健康启动本就不应写诊断；断言改为
   “健康生命周期零诊断 + 不可用路径恰好一条固定码且脱敏”。

针对缺陷 1 的定位实测（临时探针，已删除）：浏览器被杀后
`context.pages` 仍返回缓存句柄 1 个、`pages[0]` 可取；只有一次真实往返
（`context.cookies()`）才抛 `TargetClosedError` 并顺带 pump 事件使 `pages` 归零。
因此仅订阅 `context.on("close")` 不足以在同步 API 下感知崩溃。

## 失败矩阵

- 浏览器崩溃 / 外部强杀 / 用户手动关窗：连通性探测 fail-closed + 一次有界诊断，
  不把死进程的窗口交给上层；
- 多实例竞争：Profile 锁释放后才允许重启，未释放时启动即拒绝（既有 B5 锁矩阵）；
- 资源泄漏：进程树零残留断言贯穿成功与崩溃路径；
- 日志泄漏：Profile、可执行文件、主目录路径均不得进入诊断；
- 线程归属：`_require_owner_thread` 既有约束保持。

## 真实边界

- Playwright 同步 API 的事件只在真实往返时 pump：仅靠事件订阅无法感知崩溃，必须
  有一次真实往返探测——这是本任务发现并修复的真实边界；
- 连通性探测每次窗口获取多一次 CDP 往返（毫秒级），换取崩溃 fail-closed；
- 本轮回归发现 6 个 Postgres 迁移生命周期测试断言 head 为 `20260723_0033`，而仓库
  最新迁移为 VE-07 引入的 `20260723_0034`。属既有缺陷，与本任务无关（本任务只改
  `browser_runtime.py` 与新增集成测试），单独修复，不夹带本提交；
- Windows 侧进程树语义（无 `pgrep`/SIGKILL）需独立验收。
