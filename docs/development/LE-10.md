## 开工前【先定】

### 进程与路径边界

1. Control Plane 只把 `EditingProject.output` 与 `Timeline` 的 visual 轨投影进
   `protocol/`；协议只含 UUIDv4 MaterialId、种类、毫秒边界、输出尺寸/fps 与转场，不含
   路径、stat、codec、命令行或 FFmpeg 诊断。
2. Executor 只消费共享协议。素材路径由本机登记表解析后，以本地绑定交给渲染器；每次
   FFmpeg 使用前后都继续执行 LE-07 的公开 `require_source_unchanged` 窗口检查。
3. FFmpeg/ffprobe 只使用 Rust 已验证并下发的 `PackagedMediaTools`，不查 PATH、不读环境
   变量、不运行时下载。

### 帧栅格与时间对账

1. 输出 fps 是领域合法的整数 `12..60`。绝对毫秒边界用
   `floor(ms * fps / 1000 + 0.5)` 半向上取整成帧号；只量化绝对边界，不逐段四舍五入后
   累加，避免误差随 clip 数增长。
2. 目标总帧数唯一等于量化后的 `Timeline.duration_ms`。每个 clip 的帧长为量化后
   `end_frame - start_frame`；结果小于一帧固定拒绝，不制造重复帧掩盖非法时间线。
3. 转场帧数由量化后 `previous_end_frame - incoming_start_frame` 得到。领域里合法但量化后
   为 0 帧的 1ms 等转场固定拒绝；不把它静默降级成硬切。每次 xfade 的 offset 使用
   incoming 的绝对 `start_frame / fps`，因此最终输出仍精确结束于目标总帧。
4. ffprobe 必须核对最终 frame count、尺寸、fps、H.264 codec、无音频与容器时长；帧数
   是首要判据，容器时长必须与 `target_frames / fps` 的有理数结果一致到容器声明精度。

### 画面与失败行为

1. VIDEO 先按 source in/out 取等长片段；IMAGE 不制造源时间轴，以单帧循环到量化帧长。
   二者统一 `scale(force_original_aspect_ratio=increase) → crop → fps → yuv420p`。
2. 无转场相邻段用 concat；fade、dissolve、wipe 分别映射随包 FFmpeg 的 `fade`、
   `dissolve`、`wipeleft` xfade。首期不增加转场方向字段。
3. 渲染写入调用方已创建的受控任务目录中的临时文件，只有 ffprobe 核验、摘要和大小全部
   成功后才原子发布固定文件名；既有终态不覆盖。非零退出、超时、工具不可用、素材变化、
   空间/权限、输出超限与产物形状错误收敛为固定、无路径拒绝码。
4. LE-10 不依据 codec 决定 stream copy：所有画面都经过 scale/crop/fps/filter graph，
   必须解码并统一编码为 libx264。`MaterialFacts.video_codec` 留在 Executor 侧，不需要新增
   Control Plane 字段。
