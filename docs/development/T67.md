# T67 — Windows 路径规范化：UNC 重定向会启动即失败

> 状态：**已修复**，并把 junction / SUBST 的拒绝从「偶然行为」变成断言。
> 只能在 Windows 上做：`browser_profiles_windows.rs` 是 `#[cfg(target_os = "windows")]`。

## 一、UNC：这是 `normalized_path_key` 自身的缺陷

`GetFinalPathNameByHandleW`（`VOLUME_NAME_DOS`）对 UNC 路径返回**扩展写法**：

```
\\?\UNC\server\share\browser-profiles
```

而 `normalized_path_key` 只剥 `\\?\`，剩下 `unc\server\share\browser-profiles` —— 这个串**等于任何人都请求不出来的路径**。于是

```
final_path(&file) != normalized_path_key(&path)
```

恒成立，所有落在 UNC 上的 Profile 根一律 `UnsafeDirectory`。企业域把 AppData 重定向到文件服务器就是这种形状。

**关键在于这不是「UNC 该不该被允许」的策略问题**：同一条路径由两侧生成出两个不同的 key，函数没有履行「产出可比较的规范键」这一契约。所以修的是 key 的正确性，`\\?\UNC\server\share` 现在规范化为 `\\server\share`。UNC 之后是否放行，由后面那些真实守卫（reparse 检查、identity 复验、ACL 校验）决定，而不是由一次字符串比对意外决定。

## 二、junction 与 SUBST：判定为继续拒绝

上一条线的探针三条腿都证实了现象。但「让测试变绿」不等于「应该放行」，逐条判：

| 场景 | 判定 | 依据 |
|---|---|---|
| **UNC** | 修正 key | 上一节：函数契约破了，与策略无关 |
| **junction 组件** | **继续拒绝** | junction 是 reparse point，**任何能写父目录的人都能改它的指向**。`ensure_no_reparse_components` 存在的目的就是挡这个经典重定向/TOCTOU 面。「把 AppData 搬到 D 盘、原地留 junction」确实会被拒——这是有意的取舍，代价是一次响亮的失败，而不是静默降级到一个不再私有的目录 |
| **SUBST 盘** | **继续拒绝** | `subst` 是登录会话级别的盘符别名，同会话里任何进程**无需任何特权**就能重新指向它。「请求的路径是否就是解析后的那个对象」这条检查，要挡的正是这种间接层；放行它等于这条守卫再也区分不出路径别名 |

## 三、此前这两条没有任何测试

`browser_profiles_windows.rs` 1050 行里 **0 个 `#[test]`**，UNC / junction / SUBST 在任何地方都没有覆盖。也就是说 junction 和 SUBST 被拒绝是**偶然行为**：没人断言过，改坏了也没人知道。

本任务补上真实文件系统用例，各配一条**对照**证明用例不是恒红：

| 用例 | 断言 | 对照 |
|---|---|---|
| `a_junction_component_is_refused` | 真 `mklink /J` 后经 junction 访问 → `UnsafeDirectory` | 同一目录走真实路径必须被接受 |
| `a_subst_alias_drive_is_refused` | 真 `subst` 后经别名盘访问 → `UnsafeDirectory` | 同上 |
| `a_unc_path_and_its_final_path_form_share_one_key` | 两种写法产出同一个 key | — |
| `a_drive_path_and_its_extended_form_share_one_key` | `C:\x` ≡ `\\?\C:\x` | — |
| `keys_ignore_case_separator_and_trailing_slashes` | 大小写 / `/` / 结尾反斜杠 | — |
| `an_alias_drive_does_not_share_a_key_with_its_target` | 别名盘与目标**不得**同键 | — |

## 五、已知边界

`a_subst_alias_drive_is_refused` 在 `runas /trustlevel:0x20000` 的**受限令牌**下无法运行：`subst` 本身返回 `Access denied`（已单独探针确认，见下）。用例此时**显式 panic**，而不是静默 `return` —— 它没能真的验证那件事，就不该报 ok。普通标准用户会话不受影响；受限令牌只是本轮为拿非提权证据搭的临时手段。

```
--- subst attempt ---
Access denied - C:\Windows
Z_NOT_MAPPED
```

真实 UNC 的文件系统级用例没有加：`\\localhost\C$` 是管理共享，非提权会话受 UAC 远程限制访问不到；建真实共享需要改机器状态。UNC 的缺陷本身在字符串函数里，已被上面的键用例直接钉住。
