- 账号范围：客户 Demo 账号只能由与终端用户认证分离的运维 capability 创建；首版只使用不可变、大小写不敏感的 canonical `login_name`，状态封闭为 `active/locked/disabled`。不开放匿名自注册，不要求收集邮箱/手机号，也不引入组织、租户、RBAC、套餐、计费、社交登录或账号硬删除
- 凭据与恢复：密码限定 12～128 字符并使用 Argon2id、每条唯一 salt 和数据库外部署 Pepper，明文不持久化。正常修改要求当前密码；遗忘恢复只允许运维在产品外身份核验后签发 15 分钟、256-bit、digest-only、单次消费的票据，不提供可枚举账号的公开恢复申请端点
- Session 与秘密边界：产品 access/refresh 均为服务端只存摘要的 opaque 256-bit secret；access 最长 10 分钟，refresh 绝对最长 30 天并单次旋转，重放即吊销 family。每次使用复验账号状态、凭据版本和 Session 状态；App 只用 Authorization header，秘密只由 Rust 私有存储持有，React/Tauri IPC 不接收 secret，也不把产品 Session 与平台 Cookie/Profile 混为一体
- 设备与授权：一个账号可拥有多台 Installation，每台 Installation 首次绑定后只有一个不可变 owner；绑定必须同时证明活跃账号 Session 与 I2 设备私钥，跨账号重绑、匿名申请、配对码、审批轮询全部拒绝。业务请求必须同时满足活跃账号 Session、活跃且归属该账号的 Installation 和所需 capability，前端可见性不构成授权
- 吊销与审计：密码修改/重置递增凭据版本并吊销全部账号 Session；停用还拒绝登录、refresh、设备换票和业务 API；单设备吊销不影响同账号其他设备。16 类账号/凭据/Session/设备事件使用 append-only 最小审计，只保留稳定 actor/subject、结果、原因和 request ID，禁止密码、Token、凭据、原始登录标识、IP、User-Agent 与平台 Cookie
- 威胁覆盖：机器契约逐项冻结账号枚举、credential stuffing、暴力破解、密码库泄露、恢复票据窃取/重放、access 窃取、refresh 重放、跨账号设备绑定、停用后继续访问、WebView/日志泄密、产品/平台 Session 混淆和运维入口滥用 12 类威胁；每类至少绑定两个明确控制，并以 13 条不可变安全约束约束 U9-02～U9-06
