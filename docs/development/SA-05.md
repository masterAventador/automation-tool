决策只取决于回放器记录的一个事实——失败时是否已 dispatch 外部副作用：

- **未 dispatch → `resume_browser_use`**：从最近检查点交回 Browser Use 完成剩余步骤，
  已通过的前缀不重复；差异（失败步序号/原因/恢复点）收集给 SA-06 编译候选 v2；
- **已 dispatch → `reconcile_only`**：平台可能已经动作，结果不确定，`may_continue` 与
  `may_resend` 都为假，只能对账（BU-05 / ActionGate 领域）。

回放器为此扩展 `ReplayFailed`：新增 `failed_index` 与 `dispatched`（默认值，未破坏
SA-04）。dispatch 状态在**外部步 `act` 之后**置真——正是从这一刻起结果变得不确定，
直到后置条件确认。所以「找不到锚点」（act 前）判未 dispatch 可恢复，「点了但后置
条件不成立」（act 后）判已 dispatch 只对账。
