## 本计划「本计划有意不做的事」（整表照抄）

| 不做 | 理由 |
| --- | --- |
| `EditingJob` 不带 `kind` 字段 | 首期只有渲染一种作业。AI 起草作业（LE-16 产出 Timeline 草稿）落地时才知道它的真实形状，现在加一个只有一个取值的字段就是预测性抽象 |
| 字幕不含颜色字段 | 台账登记的基线是「字号/描边/行距/字体」四项。白字黑描边是短视频字幕的通行约定，首期没有让用户改颜色的用户故事 |
| 不做变速、不做画中画 | 沿用 LE-03 的首期锁定 |
| 模型调用类失败码不在本 task | LE-13/15/16 落地时按实际失败形态扩枚举，枚举是可扩展的 |
| `EditingProject` 不含素材清单 | 素材与项目的关联属仓储层（LE-05），领域对象不持有集合引用 |

## 另外必须记进 LE-04.md 的四笔账

1. **我在 T1 那轮关于正则锚点的说法是错的，已更正。** 当时把 domain 层 7 处 `^...$` 改成 `^...\Z` 并让 5 个模块各加一条「结尾换行拒绝用例」，声称那些用例钉住了锚点。**并没有**——LE-09 线的子代理实测顶回：把 6 个模块全部 7 处 `\Z` 改回 `$`，整个域套件 **713 passed 零失败**，因为 16 个调用点全用 `fullmatch`，而 `fullmatch` 下 `$` 与 `\Z` 完全等价。只有 (`$` + `match`) 这一种组合会放过结尾换行。正确的钉法是**用 `match` 调用测那条属性**（`assert PATTERN.match("x\n") is None`），已在 `f11656d` 补上并逐处变异验证。原来那 5 条注释里说错的机制一并改掉了。

2. **`CANCELLING` 的 ack 责任归 LE-12。** T4 的审查转交的问题：一个从未被 worker 取走的作业进了 `CANCELLING` 之后由谁 ack 到 `CANCELLED`。答案已写进 `EditingJob` docstring——调度器在派发时撞见竞态需自己调用 `confirm_cancelled`；调度器崩溃/失联的兜底是带取消超时的对账把作业判 `FAILED`（`WORKER_LOST`），不构成死锁因为 `CANCELLING → FAILED` 是合法边。**实现调度与对账逻辑本身属 LE-12，本任务只登记责任归属。**

3. **`is_terminal` 对裸字符串静默返回 `False`**（T4 审查的低置信度提醒）。`False` 的含义是「仍在运行」，是不安全的那个方向。缓解是聚合根在持久化边界处就把状态解析成枚举——本任务已落实，但 LE-05 建仓储时要沿用。

4. **一次提交归属事故与它的教训。** 我在提交锚点改动时用了 `git add <目录>` 而不是逐文件，把 T5 子代理当时未提交的 188 行测试卷进了那个提交。功能未受损，但历史归属错了，已用 `git reset --soft` + 逐文件重新暂存拆开。**拆分未丢失任何内容**——`git diff 9696772 cbdff34` 只剩子代理在拆分之后继续写入的增量。（此处原写「最终树逐字节相同」，按字面不成立：三个提交的树哈希互不相同，因为子代理在我拆分之后还在继续写。实质无误但措辞过强，由 LE-04 终审查出并更正。）`--force-with-lease` 推送，两条并行分支均未含该提交故无影响。**规矩要写准确**：不是「等子代理跑完再提交」（它什么时候落盘看不见），而是**只要有子代理可能在同一棵树里写文件，控制方一律逐文件 `git add`，绝不用目录或 `-A`**。
