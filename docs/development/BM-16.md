## 失败矩阵

- 断网/VPN 缺失：worker 渲染默认死代理（`--proxy-server=127.0.0.1:9` +
  `<-loopback>`），发布检查证明零远程 URL；sweep 中 12 个代码主题各有一个上游

  套件另覆盖远程请求拒绝；
- 并发/多实例：单 Worker 编排占用时提交返回 `render_unavailable`（BM-08 真实
  验收覆盖恢复重试路径）；
- 崩溃/挂起：sandbox 套件的 wall/CPU/内存预算全部杀进程组并清理帧；协议漂移、
  版本不匹配拒绝；
- 磁盘：`maxOutputBytes` 超限即失败并清理（sandbox 覆盖）；
- 输入契约漂移：发布锁 pin 四份输入契约，任一摘要漂移拒绝构建与验收；
- 低配置：以预算矩阵（CPU/内存上限强制）作分层证据；专门低配机验收未执行，

## Windows 真机验收（2026-07-25 补充）

Mac 经 SSH 远程发起、Windows 真机执行同一入口 `python scripts\run_bm_16_acceptance.py`。
**已通过**：前置确定性门禁、12 套风格冻结与渲染、30 帧双跑逐帧 SHA-256 确定性、无 URL
入口检查、134 项 sweep 前 53 项。

过程中在真机上暴露并修复了五层真实缺陷（macOS 全量回归通过，逐条见
`docs/development/windows-evidence-checklist.md` 第 10 节表格）。其中最根本的一层是
**CSS 动画与过渡跑在真实时钟上，本身就是非确定源**——前四层修复（等字体、等合成帧、
固定抗锯齿与颜色配置、预热）都只是缩小了漂移窗口而没有消除根源。改为暂停全部动画并把
每帧的 `currentTime` 设成与 timeline seek 相同的时刻后，整帧成为该时刻的纯函数；视觉
效果保留，因为动画时间仍按帧推进，只是不再依赖墙钟。

**剩余阻塞（一项，非产品缺陷）→ 根因已修复，待真机复验（2026-07-25）**：134 项 sweep 在
整机被前序渲染压满后，某一项触发 `render_resource_exceeded`。局部探针已证明同一项单独渲染
在同一预算下通过（`cpu=280 memory=2048 -> PASSED`）。根因是 CPU 秒按整棵浏览器进程树累加，
对渲染是错误的约束维度——16 核满载 20 墙钟秒即 320 CPU 秒，而沙箱契约把 CPU 与墙钟共用同一个
300 秒上限。

该契约缺陷已由独立任务 `docs/development/FIX-sandbox-cpu-budget.md` 修复：CPU 秒改用独立上限
`maxDurationSeconds × cpuParallelismMaximum = maxDurationSeconds × 8`，墙钟继续作卡死保护；
本脚本的 `RENDER_CPU_BUDGET_SECONDS = 280` 随之删除，改为由墙钟预算派生。**修复只在 macOS 完成
契约层与三层测试验证，Windows 16 核真机的 134 项 sweep 尚未重跑**，故本条仍未闭合。
