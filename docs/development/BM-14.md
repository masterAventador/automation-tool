## 真实边界

- 合成产物是构建期目录，只存在于 `.gitignore` 覆盖的 `.local/motion-catalog-release/1.0.0/`，
  不提交 Git；“可复现”已按同输入两次构建 manifest 逐字节一致验证（无时间戳等不确定因素），
  重建只需重跑构建脚本。
- 商标替换语义：字面形态按 `(?<![0-9A-Za-z])form(?![0-9A-Za-z])` 词边界大小写不敏感匹配，
  134 个目录项名（如 `data-composition-id="vscode-dark-2026"`）与封闭技术保护清单
  （`-apple-system` 系统字体关键词、`Apple Color Emoji` 字体栈、上游播放器运行时全局
  `__hyperframes`）内的匹配不替换——目录项 ID 保留上游词供代码寻址是 BM-13 已冻结的约定；
  camelCase 内嵌（如 `createVSCodeThemeComposition`）按词边界规则天然不命中，且构建器与
  门禁的扫描规则一致，不会漏报。类名/标识符与其所有 CSS/HTML/JS 引用在同一 item 内同步
  替换，选择器一致性由同规则全文替换保证。
- 指示词字面形态覆盖以对 134 项全量文本的逐一扫描为依据：68 个被标记项之外仅
  `caption-emoji-pop` 的 `Apple Color Emoji` 与 `lower-third-bild` 的 `window.__hyperframes`
  命中，均已进技术保护清单；`youtube`/`twitter` 等按 BM-11 视觉审计标记但无文字命中的指示词
  替换规则为空转，不视为失败。
- 素材替换文件名规则：有字面引用或媒体类型变化 → 使用 BM-13 中性替换文件名并改写引用
  （消除 `iphone.glb`、`instagram.jpg` 等商标文件名与 `.jpg` 字节实为 SVG 的类型错配）；
  无字面引用且媒体类型不变 → 保留上游文件名（`caption-texture` 六张纹理靠
  `vars.texture + ".png"` 动态寻址，改名会破坏运行时）。仅通过运行时动态拼接引用且媒体类型
  变化的素材当前数据集中不存在；若上游升级引入，构建器按“旧路径残留”拒绝，需人工重审。
- 替换后 HTML/JS/CSS 的实际运行验证（浏览器渲染、时间线播放）归 BM-15/BM-16 从正式 App
  入口完成；本任务以静态一致性（引用改写完整、选择器与标识符同步替换、零残留、零远程 URL）
  作为构建期门禁，不宣称逐项渲染已验收。
- 指示词扫描范围是 `items/` 下的文本文件；`offline-deps/` 下的第三方库为按许可原样分发的
  内容（GSAP 许可禁止移除版权声明），继续由 BM-12 的封闭文档域名白名单治理，不做品牌改写。
- 本任务不修改 `vendor/hyperframes`（构建前逐文件核对 BM-11 冻结摘要）、不改 BM-11/BM-12/
  BM-13 已冻结契约；overlay 中 `libraryOnly` 的插画母版不进入本目录，仍由 BM-15 作为可选
  素材池接入。
- macOS arm64 与 Windows x86_64 均已生成相同 310 文件和相同聚合摘要。Windows 另以
  `st_mode` 写位 + `FILE_ATTRIBUTE_READONLY` 双断言、Unicode 文件名、NTFS 大小写折叠、
  casefold 碰撞和真实 junction 夹具闭合平台语义；生成文本在所有平台固定 LF。
