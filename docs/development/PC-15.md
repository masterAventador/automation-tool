## 0. 这是一道评估题，交付物是结论加依据

路线图问的是：让素材成片线改用动效线那份可变 woff2，还是各留各的。

## 1. 先把两个先入为主的判断推翻

**「PIL 读不了 woff2」——不成立。** 冻结的素材 Worker 包里 `libfreetype.6.dylib`
链接了 `libbrotlidec.1.1.0.dylib`，woff2 是能解的：

```
$ otool -L .../material-video-worker/package/_internal/PIL/.dylibs/libfreetype.6.dylib
  @rpath/libbrotlidec.1.1.0.dylib (compatibility version 1.0.0, current version 1.1.0)
```

**「跨 bundle 取路径」——也不是真正的拦路石。** PC-16 之后 `motion-catalog` 是
`Contents/Resources/` 下的一等资源，与素材 Worker 同级。

真正的拦路石是第三条：**上游按文件名从它自己的 `resource/fonts/` 里选字体，一个字重
一份文件**。单个可变字体只能给出默认实例，要它同时当 Regular 和 Bold 就得调
variation API——那要改上游源码，规则第 6 条禁止。

所以「改用可变 woff2」的唯一可行形态是：**构建期从可变字体实例化两个静态字重**，
放进 Worker 自己的资源目录。

## 2. 实测这条路的账

```
可变源字体 NotoSansSC-wght.ttf            17.8 MB
实例化 Regular                            10.6 MB
实例化 Bold                               10.6 MB
                                  合计    21.2 MB

现用 NotoSansCJKsc-Regular                16.4 MB
现用 NotoSansCJKsc-Bold                   17.0 MB
                                  合计    33.4 MB

净省 12.2 MB（安装包 539 MB 的 2.3%）
```

## 3. 代价：字形覆盖

```
现用 NotoSansCJKsc-Regular   覆盖 44,810 码位
Noto Sans SC 可变            覆盖 30,890 码位

换过去丢失 13,920 个码位
  其中汉字区（U+4E00–9FFF）丢失 0 个
  丢的是谚文（U+1100 起）等非汉字区
反向：新字体多出 0 个码位
```

## 4. 结论：不整合

**12.2 MB 换不来 13,920 个码位的覆盖倒退。**

- 省下的是安装包的 2.3%，用户感知接近于零；
- 丢掉的是字幕里出现日韩文字时的显示能力。字幕来自用户内容与 AI 写的脚本，
  歌名、品牌名、引用里出现假名或谚文并不罕见，而失败形态是**豆腐块**——
  不报错、不失败，只是难看，正是本项目一路在消灭的那类静默失败；
- 且这条路要新增构建步骤、新增权利台账条目、新增一个失败面。

**动效线继续用 7.42 MB 可变 woff2**（它按 `(family, weight)` 逐条声明 `@font-face`，
可变字体在那里恰好是最省的形态，一个文件覆盖 7 个字重）。
**素材线继续用两个静态 OTF**（上游按文件名选字重，静态是它唯一认得的形态）。

两条链路的字体形态不同，是因为**两边选字体的机制不同**，不是疏忽。

## 5. 顺带更正一个数字

路线图记的是「41 MB 冗余」。实测两份中文字体合计 40.8 MB（33.4 + 7.4），
但其中并没有 41 MB 可以省——两份都在服务各自那条链路，能省的上限就是第 2 节算出的
12.2 MB，且要付第 3 节的代价。
