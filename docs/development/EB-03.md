## 失败矩阵

- 归档摘要不匹配、输出目录已存在、未知/不可构建目标（含 Windows 目标提前构建）：
  构建前拒绝；
- 路径穿越（`..`）、绝对路径条目、绝对 symlink、逃逸 symlink、重复条目：解压中拒绝，
  已建目录不含越界文件；
- 非预期第二根目录、`chrome-headless-shell` 等禁止条目、锁定可执行文件缺失或不可
  执行：暂存后校验拒绝；
- Manifest 目标与固定可执行路径不一致、macOS CPU type/Windows PE Machine 不匹配，
  或发行物顶层出现另一平台/架构 Chromium 根：解析阶段拒绝；
- 契约损坏、字段缺失或形状漂移：加载即拒绝；
- 全部拒绝路径均为固定消息，不反射归档内容。

## 2026-08-04 收口：Intel Mac 退出交付目标

用户当日决定不再验证 Intel Mac。按「退出受支持目标」整条摘除而不是只划掉验收项——
`macos-x86_64` 当时是兼容契约里的**强制**目标，只删台账会让构建链继续为一个没人验证的
架构装配出包。

改动落点（同一提交）：兼容与暂存两份契约各去掉该目标、删除
`contracts/browser/fixtures/component-valid-macos-x86_64.json`、两份 Worker 打包契约去掉
对应条目，以及 Rust 分发/授权与 14 个脚本里的 Intel 分派分支——分支删掉后，Intel 主机会
落到各自既有的 `fail` / `reject` 上，即硬拒绝而非回退到一个能打但没人验过的包。

**刻意保留的反例证人：** `scripts/verify_macos_chromium_archive.py` 的 x86_64 CPU type 常量
没有跟着删，改名为 `FOREIGN_CPU_TYPE_X86_64`。这个脚本的价值是「arm64 包里混进别的架构就
拒绝」，x86_64 正是那个「别的架构」；一起删掉，自检就只剩「不是 Mach-O」一种反例，
「是合法 Mach-O 但架构不对」这条路径会失去唯一证人。为确认自检不是空的，做过一次变异：
把该常量改成 arm64 自身（即取消反例），自检立刻报
`self-test accepted a wrong architecture`。
