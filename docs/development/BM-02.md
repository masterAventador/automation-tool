## 失败矩阵

- Node 版本、官方归档摘要、Worker/协议版本或包目录漂移：构建或启动拒绝。
- 包目录、运行时或入口为相对路径、符号链接、重解析点、缺失文件或不可执行文件：Tauri 拒绝。
- bootstrap 多字段/少字段、版本/类型错误、WebUI/模型越权、非绝对素材目录或令牌格式错误：固定
  退出码 65，错误不回显令牌、路径或输入正文。
- 健康请求缺令牌、路径/方法错误：只返回 401；ready/health/cancel 证明不匹配时 Rust 拒绝。
- 取消只接受规范 UUID v4 和有效 HMAC；错误命令被忽略，不产生伪造完成事件。
- stdin 关闭后监听端口关闭；App stop/drop 继续使用既有进程树清理，避免孤儿 Worker。
- 原 Windows runner 如果因 `#![cfg(unix)]` 实际执行 0 个 Rust 测试会被明确拒绝；现在
  独立 Windows 目标必须输出 `1 passed; 0 failed`，防止平台过滤假绿。

  `node-v22.23.1-win-x64.zip`，只抽取随包 `node.exe` 和许可证；候选运行时大于

  系统根；

  新增 Windows 原生目标后，随包 Node 由正式 `LocalVideoOrchestrator` 完成 ready、
  认证 health、UUIDv4/HMAC cancel、stop，1/1 通过并确认进程退出；
- 候选暂不包含上游构建产物和 npm 依赖；BM-03～BM-05 接入实际 SDK/CLI、Chromium 与作者 Agent

## 清理

- 下载归档和候选包全部位于系统临时目录，验收结束自动删除；仓库不提交 Node 二进制。
- 构建与验收不执行上游包管理器、不写 submodule；验收前后上游 HEAD 与工作树严格一致。
- Worker 只监听操作系统分配的 `127.0.0.1` 随机端口；Windows 验收按进程 ID 复查
  编排器停止后的进程清理；临时候选、下载目录和端口无残留。
