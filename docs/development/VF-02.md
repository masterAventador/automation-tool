## RED

聚焦集成测试先定义 Python/Node 两类 Worker 的共同生命周期协议：两个进程各自取得
随机回环端口和独立高熵会话、完成带证明的版本握手与真实 HTTP 健康检查、接收带证明
的取消命令、异常退出后在预算内恢复，并在停止或 Orchestrator 释放时清理进程。

首次运行在补齐 Tauri 构建所需的本地 `frontend/dist` 空目录后，准确失败于
`automation_tool_desktop_lib::local_video_orchestrator` 不存在。实现后新增的后代进程
夹具又准确暴露“父进程退出后先等待日志线程会被继承管道卡住”的缺口；修复前用例耗时
约 5.48 秒并失败，调整为先终止完整进程树后进入 GREEN。

## GREEN

- `LocalVideoOrchestrator` 以两个互斥槽位分别管理 Python/Node Worker；重复启动被拒绝，
  `status` 在真实异常退出后按有限预算重新握手并恢复，预算耗尽稳定收敛为 stopped。
- 每次启动生成新的 256-bit 会话令牌，只经 stdin bootstrap 传入，不进入 argv/env、状态、
  Debug 或用户 DTO；ready、health、cancel/cancelled 都使用分域 HMAC 证明。
- Worker 自行绑定 `127.0.0.1:0`，Tauri 只接受其带证明的非零端口，并通过真实 TCP
  `/health`、Bearer 会话和精确 JSON 响应复验协议及 Worker 版本。
- 从既有 Executor 抽出唯一 `ManagedProcessTree`；Unix 进程组和 Windows kill-on-close
  Job Object 由 Executor 与视频 Worker 共同复用，没有复制第二套清理实现。
- Tauri 正式组合根持有唯一 Orchestrator State，但没有向 WebView 注册启动/停止 Worker
  Command；后续业务 Adapter 只能通过该所有者接入。
- 8 项 VF-02 集成测试与 1 项 Windows reparse 属性单测、19 项既有 Executor 回归通过；
  Tauri crate 全量 208 项通过（4 项环境型测试按既有约定 ignored）；Rustfmt 与严格
  Clippy 通过。

## 失败矩阵

- 相对路径、叶子或任意上级目录符号链接、非文件、不可执行文件、非法版本/超时/恢复
  参数和重复槽位启动均 fail closed；路径不进入公开错误。
- 伪造 ready 证明、协议/类型/精确 Worker 版本不匹配、无响应启动和带错会话的健康响应
  被拒绝；失败启动进程随完整进程组清理。
- 取消命令与回执绑定 Worker 类型、协议、规范 UUID 和独立证明域，不能把 ready 证明
  重放为命令或回执。
- 非零异常退出只在预算内恢复；恢复使用全新会话和随机端口，预算耗尽稳定停止。
- 显式 `stop_all`、Orchestrator Drop、父进程已退出但后代仍继承管道三条路径都清理真实
  进程，不等待后代自然退出。

## 正常用户路径验收

不适用。VF-02 是后续视频制作正式入口消费的 Tauri 内部进程生命周期底座，本任务不新增

## 真实边界

测试启动真实隔离 Worker 进程、绑定系统分配的 `127.0.0.1` 随机端口并通过真实 TCP
健康请求通信；不调用模型、视频上游、云服务或用户数据。

## 清理

全部测试端口由 Worker 绑定 `127.0.0.1:0`，没有固定端口或监听服务残留。临时脚本、
计数器和 PID marker 使用本任务唯一名称并由所有者删除；测试逐 PID 核对停止，未发现
遗留 Worker/后代。`frontend/dist` 只是本机已有的 ignored 构建前置目录，未提交制品。

## 遗留项

VF-02 不负责 Worker 本体打包、RenderJob 工作区、FFmpeg、模型配置或视频制作页面。
因此本任务不声称用户已经可以制作视频；IM-02/BM-02 才接入两类真实发行物，VF-06
才建立正式页面入口。当前恢复由每次正式状态协调触发，不建立第二个后台 supervisor；
后续业务 Gateway 必须持续读取状态，不能绕过 Orchestrator 直接持有 Worker。
