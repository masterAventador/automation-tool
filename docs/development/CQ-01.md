## 失败矩阵

门禁篡改矩阵（`scripts/test_user_facing_branding.py`，共 29 个场景：25 个 `expect`
用例 + 1 个内联零件投影用例 + 3 个真实 App 抓取判定用例，全部要求非零退出或明确放行）：

- 契约缺 `unexplainedIndustryTerms`、缺 `videoCreationMethodCardLabels`、
  `conceptDistinctions` 为空、缺 `partsCatalogProjection` → 失败；
- `explanationScope` 越出 `{segment, file}`、`file` 范围缺 `reason`、
  被强制执行的术语在 `plainLanguageMappings` 里没有词条、映射值不是中文、
  术语归一化后重复 → 失败；
- 渲染文案中出现裸术语的三种载体各一例：中文字符串字面量、JSX 文本节点、模板字符串
  → 失败；纯英文 JSX 文本节点（如 `No data Executor`）同样失败；
- 同句给出通俗说法（“本机执行器 Executor …”）→ 放行；
- `file` 范围术语在同一源文件别处有中文解释 → 放行，整个文件都没有 → 失败；
- 标识符与类名（`renderJobId`、`providerLabel`、`className="timeline-preset-asset"`）
  不得误报 → 放行；
- 概念区分文案被删除、概念声明的源文件不存在、`requiredCopyFrom` 引用的卡片必答项
  从源码消失 → 失败；
- 动效零件投影里出现只有英文的 `applicabilityLabel` → 失败；
- 复审补入的四种漏检：复数形式（`剩余 Tokens 1234`）、带括号的中文文案
  （`由 Executor 处理 (自动重试)`）、JSX 自闭合标签同行后续字面量
  （`<Foo bar={1} /> {x ? "等待 Executor 确认" : "已完成"}`）、
  无障碍名称（`aria-label={`${t} Executor`}`）→ 均要求失败；
- 真实 App 抓取判定：页面文本含裸术语 → 失败；术语与中文说法同页出现 → 放行；
  抓取结果为空 → 失败（不允许“没抓到就算通过”）。

真实 App 侧的失败路径：五条断言在修复前全部真实失败（见 RED），修复后全部通过；
门禁与真实 App 判定共用同一份契约和同一个 Python 匹配函数，术语表漂移会同时打断两侧。

## 真实边界

- 覆盖范围是 App 内 React 渲染文案与可访问名称。134 个动效零件的**英文名本身**
  （如 `Glitch RGB`、`Blend Difference`）来自 BM-11/BM-15 锁定投影
  `contracts/video/motion-catalog-ui.v1.json`，改名等于重算锁定投影，属 BM-15/BM-16 范围；
  本任务改为强制“英文名旁必须有中文类型/分类/适用说明”，并在真实 App 里逐卡断言；
- `API Key`、`AccessKey`、`RPA` 三个词按 `file` 范围保留：前两者是阿里百炼/阿里云控制台
  的原样字段名，改名会让用户在控制台里找不到对应输入框；`RPA` 是产品品类名。三者在契约里
  都必须写明 `reason`，并在同一源文件内渲染中文解释，否则门禁失败。该范围以“同一源文件”
  近似“同一页面”：多组件拼成的页面可能误报，同一文件被多个 Tab 复用可能漏报，
  字段因此命名为 `file` 而非 `page`，偏差已写入 `docs/frontend-architecture.md`；
- 静态门禁把三类内容视为用户文案：带中文的字符串字面量、JSX 文本节点、以及
  `aria-label`/`aria-description`/`alt`/`title`/`placeholder` 属性值（无障碍名称不论是否含中文
  都送检）。纯 ASCII 的普通字符串字面量按标识符/协议值处理，
  `frontend/src/api|platform|schemas|stores` 仍按既有 `excludedGlobs` 排除；这是为避免把变量名
  误判成文案，代价是纯英文的非 JSX、非属性文案不会被静态发现，由真实 App 逐页抓取兜底；
- 术语的中文说法只有一份事实源 `plainLanguageMappings`；`unexplainedIndustryTerms` 只声明
  强制执行范围，中文说法回查映射表，查不到即 fail closed。行业词匹配（含复数形式）只有
  一份实现 `industry_term_occurs`：真实 App 的页面文本与无障碍名称由 spec 写入抓取文件后，
  回灌同一个函数判定，不再在 TypeScript 侧另写一份正则；
- WebKit WebDriver 的 `getText()` 会附带 `Tab 3 of 7` 这类由无障碍树推导的英文串，
  它由 antd/WebKit 生成而非本产品文案，用户视觉上看不到，未纳入断言；
- `Control Plane`、`Executor`、`Installation`、`Token`、`Demo` 的改名发生在本次构建
  不会渲染的页面（启动门、工作台运行状态、任务详情、新建任务、账号门），
  这几处由单元测试与静态门禁覆盖，未取得真实 App 页面证据（见遗留项）。
