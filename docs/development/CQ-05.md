## 台账一致性：这次补的是反方向

AV-04 的门禁查"已激活任务有没有证据文件"。**反方向没人查**：一个任务被改名、拆分或撤销
之后，它的证据文件会留在原地，读的人以为那还是一项在做的工作——台账于是开始说谎，
而且是那种没人会发现的谎。

`scripts/cq_05_evidence_completeness.py` 双向核对当前专项的任务族：

```text
python3 scripts/test_cq_05_evidence_completeness.py            11 tests OK
对真实仓库跑 → 87 行任务，78 个已激活，证据文件双向对得上
```

未激活的任务（`⬜ 未开始`、`⏸ 后置`）没有证据文件是正常的——它们还没开工。把这种情况判成
缺失，只会逼人为没做的事先写一个空台账，那比没有台账更糟。当前 9 个没有证据文件的任务
全部是 `⏸ 后置`（BM-09、BM-10、SA-01～SA-07）。

`docs/development/` 是多份 Roadmap 的共享目录。2026-07-31 实跑时，门禁把后来新增的
PC-01～PC-26 与 UI-01 误报为本专项孤儿；现已按当前 Roadmap 声明的任务族限定反向检查。
PC/UI 由各自台账负责，同一任务族里不存在的任务（例如合成测试中的 `AA-99`）仍然拒绝，
因此没有用“忽略所有未知文件”掩盖真正的改名或撤销残留。

落空防护：扫不到任何任务行时直接拒绝，那时这次检查什么都没证明。

## 诊断导出包逐条脱敏（2026-08-04 补齐）

CQ-02 把这一项挂到本任务名下，此前状态是「未做」。

**缺口的准确形状**：`diagnostic_export.rs` 里既有用例
`exports_only_valid_fixed_artifacts_and_redacts_logs` 只读回 `executor/diagnostics.txt`
一条并断言不含 `private-value` 与 `/Users/`。而一个诊断包有五条：

| 条目 | 此前有无脱敏断言 |
| --- | --- |
| `executor/diagnostics.txt` | ✅ 有 |
| `page-drift/<id>.json` | ❌ 无 |
| `browser/traces/<id>.json` | ❌ 无 |
| `browser/screenshots/<id>.png` | ❌ 无 |
| `manifest.json` | ❌ 无 |

三条 JSON 恰恰是最可能带上 URL、选择器与本机路径的地方。诊断包是要发给排查方的
东西，所以「逐条」不是措辞讲究，是这条要求的全部意义。

**新增** `redacts_every_text_entry_not_only_the_log`：把四种真实会泄漏的东西
（Cookie 值、Bearer 令牌、本机绝对路径、CDP 端点）种进导出输入，导出后遍历压缩包
**每一条**读回来核对五个禁用串。两个刻意的设计：

1. 制品保持各自 schema 要求的形状——否则写入前就被拒掉，那样测的是校验不是脱敏；
2. 结尾 `assert_eq!(checked, 5)`——循环体全是否定断言，漏读一条不会自己报错，
   条数必须钉死。这与 PB-07 那条「页面空白也会绿」是同一类陷阱。

**先证明它会红**：把 `redact_diagnostic_line(` 临时换成恒等函数后跑，测试报
`诊断包条目 executor/diagnostics.txt 泄漏了 private-cookie-value`；恢复后 `1 passed`。

## 2026-08-04：词表随上游依赖同步的强制机制

**缺口**：品牌扫描（`scripts/check_user_facing_branding.py` 规则 1）只会去找
`forbiddenUserFacingTerms` 里列出的名字。这份列表跟真实依赖集合之间**没有任何约束**，
所以加进第三个 submodule 之后，扫描对它就是瞎的——绿灯不是因为界面里没有那个名字，
而是因为从来没去找过。这两种情况在输出里长得一模一样，正是本仓库判定「等于没有检查」
的那种形态。

**修法**：`contracts/quality/third-party-sources.v1.json` 是「什么被 vendored」的权威
（`scripts/check_third_party_sources.py` 把它钉在固定 tag 上），所以覆盖率这个问题是
可回答的。新增规则：其中每个 source 的 `id` **与**仓库名都必须被词表覆盖（比较用
`compact()`，大小写与分隔符无关）。

三条反例场景：新增上游未进词表、仓库名与 id 不同且未进词表、权威文件本身缺失/为空。
变异确认：把 `violations.extend(scan_upstream_name_coverage(...))` 那一行摘掉，
三条立刻变红。

## 2026-08-04：原生扫描把中文 docstring 当用户文案

CQ-02 记录的既有误报，详情见 `CQ-02.md` 同名小节。判据是「带中文的字符串字面量＝
用户可见文案」，而 docstring 形式上就是字符串字面量，于是内部技术文档被要求改写成
通俗说法。当时的处理是把 docstring 改回英文——门禁因此实际上在制造一个错误激励。

**修法**：`.py` 改走 `ast` 解析，按**位置**判定——只跳过模块/类/函数体内第一条语句
是字符串的那个字面量。Rust 不动，它的文档是 `///` 注释，扫描器本来就跳过。解析失败
时回落到原扫描器，而不是跳过整个文件。

三条场景：中文 docstring 通过；**同一文件里真实用户文案仍然红**；模块与类 docstring
同样跳过。第二条是这组测试的承重墙——没有它，「docstring 被跳过」与「原生扫描被关掉」
会产生完全相同的绿。已单独验证它不是空的：

```text
正常实现: 退出码 1 → 抓到
扫描全盲: 退出码 0 → 放行
```
