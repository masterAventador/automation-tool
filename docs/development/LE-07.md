# LE-07 素材探测

用户可操作：否
证据类型：分层实现

LE-07 在 Local Executor 侧用随包 ffprobe/ffmpeg 读出一个源文件的事实——时长、分辨率、
编码、有无有效音频与响度、内容摘要——并保证这些事实**填得满 `Material` 且不含任何路径**。
路径与素材 ID 的映射留在本机，不上报 Control Plane。

本任务不含 VAD 与 ASR（三级漏斗第 2、3 级，属 LE-14）、不含抽帧（LE-08）、
不含把已验证路径下发给剪辑 Worker 的 Rust 装配（LE-12）。

计划：`docs/superpowers/plans/2026-07-29-le-07-material-probe.md`

## 调研实测（2026-07-29）

随包工具链已在本机构建缓存中，**无需重建**：
`~/Library/Caches/automation-tool-build/media-toolchain/`，ffmpeg/ffprobe 8.1.2，共 42 MB，
构建参数含 `--enable-gpl --enable-libx264 --disable-network`。本任务需要的
`silencedetect`、`ebur128` 均在；下游 LE-08/LE-10 要的 `select`、`scdet`、`xfade` 也在。

三条只有真跑才拿得到的行为，直接决定了实现形状：

| 实测 | 后果 |
| --- | --- |
| ffprobe 失败时 **exit=1、stdout 是合法 JSON `{}`** | 只解析 stdout 不判 returncode，会拿到空 dict 再一路编默认值——静默失败。必须先判 returncode |
| ffprobe/ffmpeg 的 **stderr 带文件路径**（`notmedia.txt: Invalid data found`） | 两者的 stderr 一律不得进入异常消息与日志（§7） |
| `ebur128` 不加 `framelog=quiet` 每 100 ms 打一行 | 4 小时素材约 14 万行 stderr；加了以后稳定 54 行，与时长无关 |

另外：**图片的判别信号是 `format` 里根本没有 `duration` 键**，不是 duration=0；
`ebur128` 的地板 `-70.0 LUFS` 正好等于 `Material` 允许的响度下界。

### 与 `Material` 对齐时发现的不可表示状态

`material.py:135` 的 `kind is AUDIO and not has_audio → reject` 使得**一条全程数字静音的
纯音频文件构造不出 `Material`**。这是模型有意的不变式，故探测阶段直接拒绝
（`MaterialProbeRejection.SILENT_AUDIO`），不交出填不进 `Material` 的事实对象。

## 边界

`executor/` **零处 import `control_plane`**——实测确认非推断：

```
grep -rnE "^\s*(from|import)\s+.*control_plane" backend/src/automation_tool/executor/   →  0
```

宽口径 grep 的 2 条命中都是 `runtime.py:201/215` 的 `_is_control_plane_restart` 函数名。
故 `ProbedMaterialKind` 在执行器侧另立，取值一致性由 T7 的跨层测试钉住。

工具路径**不做发现**：`PackagedMediaTools` 照 `browser_runtime.BrowserLaunchRequest`
（内置 Chromium 的同款先例）只复核已授权路径的形状，不查 PATH、不读环境变量、不设默认值。
生产由 Rust `video_media_toolchain.rs` 校验 manifest 与逐文件 SHA-256 后下发，测试传缓存路径
——同一条代码路径，只是配置值不同。

2. **护栏零拒绝检查**——`TestPackagedMediaToolsGuardsBothTools` 专门证明第二个工具
   （`ffmpeg_path`）也真的被拒过，而不只是在接受路径上被执行。
