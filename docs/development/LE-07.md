# LE-07 素材探测

用户可操作：否
证据类型：分层实现

LE-07 在 Local Executor 侧用随包 ffprobe/ffmpeg 读出一个源文件的事实——时长、分辨率、
编码、有无有效音频与响度、内容摘要——并保证这些事实**填得满 `Material` 且不含任何路径**。
路径与素材 ID 的映射留在本机，不上报 Control Plane。

本任务不含 VAD 与 ASR（三级漏斗第 2、3 级，属 LE-14）、不含抽帧（LE-08）、
不含把已验证路径下发给剪辑 Worker 的 Rust 装配（LE-12）。

### T1 代码质量审查（首轮不通过）与修复

**Critical 1：`ENAMETOOLONG` 逃逸成裸 `OSError`，完整私有路径进了异常消息。**

`_has_symlink_component(path)` 原本在 `try/except OSError` **之外**。而
`Path.is_symlink()` 只吞掉 `pathlib._IGNORED_ERRNOS = (ENOENT, ENOTDIR, EBADF, ELOOP)`，
**不含 `ENAMETOOLONG`**。实测复现（总长 369 字符，远在 4096 上限内，只是单个分量超过
`NAME_MAX` 255）：

```
BUG -> raw OSError errno 63
       private path leaked into message: True
```

两处后果：调用方按契约捕 `MaterialProbeRejected` 捕不到，失败关闭被绕过；异常消息带完整
本机私有路径，§7 被完整绕开——而本模块的固定文案 + 封闭拒绝码设计正是为了防这个。

**它此前被更早的判据遮蔽**：唯一构造超长分量的用例用的是 `"a" * 4097`，被总长上限先短路，
根本到不了软链那一行。新用例把单分量压到 300 字符、总长留在上限内，绕开遮蔽。

修法是把软链判据挪进 `try`：`_reject` 抛的是 `RuntimeError` 子类，不会被 `except OSError`
吞掉，所以软链拒绝仍按 `UNSAFE_PATH` 原样穿过，而 `is_symlink()`/`stat()` 的任何 `OSError`
统一落到 `UNREADABLE`。

补的两条用例先实跑见红（`OSError: [Errno 63] File name too long`），修完转绿。
变异体「软链判据挪回 `try` 之外」作为回归哨常驻。

## T2 ffprobe 读时长/分辨率/编码

**GREEN**：71 passed。**覆盖率 156 语句 / 44 分支，100% 且 0 partial。**

### 三条实测结论如何落进实现

| 实测 | 实现 |
| --- | --- |
| 失败时 exit=1 而 stdout 是合法 JSON `{}` | **先判 returncode 再碰 stdout**；并有一条用例用「exit=1 + 完整合法负载」证明它，不判就会报出一条完全正常的 3 秒片 |
| stderr 带文件路径 | stderr 从不读回，异常消息固定为 `material probe rejected` |
| 图片没有 `duration` 键 | 判别用「键不存在」而非 duration==0；变异体把该判别反转会被 12 条用例杀掉 |

命令只用 `-show_entries`，不加 `-show_format`/`-show_streams`——两者会让选择变成叠加并把 `tags` 一起带出来，那是文件内攻击者可控的元数据。有专门用例断言 argv 里没有这两个开关且 entries 不含 `tags`。路径前有 `--` 分隔符，另有用例用 `-rf.mp4` 这种以短横开头的文件名钉住。

### 拒绝理由：不可区分的就不假装能区分

实测三种坏文件的结果**逐字相同**：

```
[notmedia.txt] exit=1 stdout={}
[corrupt.mp4]  exit=1 stdout={}
[empty.mp4]    exit=1 stdout={}
```

要分开「格式不支持」与「编码损坏」只能去匹配 ffmpeg 的英文诊断，既随版本与 locale 漂移，又正是 §7 禁止外传的那段文本。故合并为一个 `UNDECODABLE`，并在代码注释里写明依据。其余新增成员各自对应一个不同的用户动作：`NO_USABLE_STREAM`、`UNUSABLE_DURATION`、`TOO_LONG`、`UNUSABLE_FRAME_SIZE`、`FRAME_TOO_LARGE`、`PROBE_FAILED`。

### 与 `Material` 的形状对齐

音频素材的 `width`/`height` 产出 `None`（`Material` 禁止音频带画幅）；图片的 `duration_ms` 产出 `None`。时长与画幅上限镜像自 `material.py`，不 import——跨层一致性由 T7 的测试钉住。

### 变异自证（第一轮）：抽样 30 个，全杀（含 canary）

**首轮 6 个存活，全部是真实缺口，不是误报。** 逐条记录，因为其中一条正是方法论第 2 条点名的形态：

| 存活的变异体 | 为什么能活 | 补的用例 |
| --- | --- | --- |
| `len(stdout) > MAX` 整条删掉 | **这条护栏一个拒绝用例都没有**：超限负载是一串 `x`，本来就被 JSON 解析拒掉，删掉护栏结果不变 | 「合法 JSON 但超限 1 字节」——不删护栏才拒得掉 |

### T2 代码质量审查（第二轮不通过）与修复

**Critical：容器不报时长的真实视频被静默判成图片。**

原判据是「`format.duration` 键不存在 → 图片」。用真实文件跑生产代码路径实测，**两个方向都是错的**：

```
pipe_av.mkv   -> kind=image dur=None  64x64 v=h264 a=aac    ← 真实 2 秒 H.264 被判成图片
pipe_v.mkv    -> kind=image dur=None  64x64 v=h264          ← 同上，且无音轨时 Material 照单全收
shot.jpg      -> kind=video dur=40    80x60 v=mjpeg         ← 真实静图被判成 40 毫秒视频
```

复现要点是**输出不可 seek**：写普通文件时 ffmpeg 会回填 duration，只有管道输出才复现
（`ffmpeg ... -f matroska - > pipe.mkv`）。浏览器 `MediaRecorder` 的 WebM、OBS/ffmpeg 管道输出的
MKV 就是这个形状，对内容生产产品是普通用户素材，不冷僻。

两条分支后果相反、都很糟：**带音轨**时 `Material._validate_audio` 对「图片却有声」抛
`InvalidMaterialModel`，调用方 `except MaterialProbeRejected` 接不住，与本模块「拒绝一律走封闭
枚举」的设计冲突；**不带音轨**时 `Material` 完全接受，一条 2 秒视频永久变成一张静帧，全程无错。

同一个信号两种待遇正是漏判的证据：纯音频缺时长**会被拒**（`test_rejects_audio_whose_container_states_no_duration`），
视频缺时长却被悄悄改判成图片。

**修法：改用正向信号。** `_PROBE_ENTRIES` 一直在要 `format_name` 却从不使用（这同时是 I4）。
实测容器名：PNG/BMP 是 `png_pipe`/`bmp_pipe`，JPEG 是 `image2`，而 `mov,mp4,...` 与 `matroska,webm`
都不是图片容器。仅当**无音轨且容器是图片容器**才判 IMAGE，否则一律 VIDEO 并要求可用时长。
「无音轨」这个附加条件挡住「图片容器却带音轨」——那是 `Material` 明令禁止的组合。

修完五个真实文件全部判对，见上方实测。

**I1 编码名端点**：`> MAX` → `>=` 变异体存活，补 `test_accepts_a_codec_name_at_the_length_limit`。
本模块其余上限都有端点接受用例，只有编码名漏了。

**I2 `stdin=subprocess.DEVNULL` 零用例**：它不是卫生习惯——Local Executor 的 stdin 就是 Tauri 下发
bootstrap 与命令的活通道（`executor/cli.py:137`、`:201`），子进程继承它就可能从协议流里吃掉字节。
补用例：父进程给自己 stdin 塞哨兵字节，存根**主动排空**它拿到的 stdin，断言探测后哨兵仍在、且存根
读到的是空。

**I3 stderr 被捕进进程**：模块 docstring 说 ffprobe 诊断「never read back」，实际它被
`capture_output=True` 完整读进内存，只是没人读那个字段。后果三条：`MAX_PROBE_OUTPUT_BYTES` 只守
stdout、stderr 无上限；**完整私有路径留在 traceback 栈帧里**，会被抓 `f_locals` 的崩溃采集器带走。
改为 `stdout=PIPE, stderr=DEVNULL`，三条一起消失，docstring 也才变成真的。

补的用例遍历异常 traceback 中**属于本模块的栈帧**，断言没有任何局部变量的 `repr` 含该路径。
实测确认它对旧行为真红（`CompletedProcess` 的 repr 里就带着那段诊断）、对新行为绿。
（注意作用域：只查本模块栈帧——测试自己的栈帧天然持有它刚写进去的诊断字符串。）

**I5 被信号杀死报成 `UNDECODABLE`**：那是把「工具死了」说成「你的文件坏了」，用户换一百个文件都
没用。**这跟 `UNDECODABLE` 的合并不是一回事**：那两者确实无法区分，而这条区分是免费的——POSIX 上
`returncode < 0` 就是被信号杀死，不读任何英文诊断、不随版本或 locale 漂移。新增 `PROBE_CRASHED`。
诚实的限定：Windows 崩溃给的是大正数，这条只在 POSIX 白拿；macOS 是一等目标平台。

### 测试速度：258 ms → 5 ms

测试用**真实存根可执行文件**而非打桩 subprocess，好处是真正走了参数拼装、`execve`、退出码与两条流。代价一开始很大：整个文件 12 秒。

实测原因是 macOS 对**新建**的可执行文件首次运行要做一次校验：

```
fresh script x10 : 2.72s  (272 ms each)
reused script x10: 0.05s  (5 ms each)
hardlink to warmed x10: 0.05s (5 ms each)
```

校验按 inode 而非路径。故改成：一份内容固定的存根（按内容摘要命名，改了不会用旧的），每个测试**硬链接**过去，行为则从源文件旁边的控制文件读。**71 个用例 1.45 秒。**

### stderr 必须读，但不能被任何栈帧持有

T2 为了防路径外泄把 stderr 设成了 `DEVNULL`，而 silencedetect 与 ebur128 的结果**恰恰写在 stderr**。

它，尺寸也能在读之前检查。更关键的是**读完立刻解析成数字**——`_measure_report` 把文本直接传给
解析函数、不绑定成局部变量，解析函数只返回三个数且从不抛异常。等到任何拒绝被抛出时，持有过
文本的栈帧都已经返回，traceback 里带不走文件名。

第一版没做到这点：`read_audio_facts` 把报告文本存成局部再判「没有 `I:` 行」就抛，泄漏用例当场判红。

#### C2 选了哪条修法，为什么（审查单点名要求写明）

审查给了两条路。**先说为什么没选第二条**——「响度落在地板 + 静音覆盖音轨」合并判定，
实测走不通，而且它自己会打自己：

| 素材 | 静音是否覆盖 | `I:` | 想要的答案 |
| --- | --- | --- | --- |
| `partial.m4a` 前半静音后半有声 | 覆盖前半 | **-22.2** | 有声 |
| `faint_45.m4a` 衰减 45 dB | **全覆盖** | **-66.8** | 无有效音频 |
| `short_audio.mp4` 10 秒画面 / 2 秒静音音轨 | **不覆盖**（2.02 < 10） | -70.0 | 无有效音频 |

两处硬伤：一是 `short_audio.mp4` 的静音**根本覆盖不了容器**，AND 起来照样判成有声，
**C2 原地没修**；二是要把 `partial` 和 `faint_45` 分开，只能在 -66.8 和 -22.2 之间凭空
划一条响度线——而 S1 刚刚裁定「地板表示测不出、不表示安静」，再拿响度当有无声音的判据
等于把刚推翻的判据换个位置装回去。

**所以选第一条：读音轨自己的时长（ffprobe `stream=duration`）。** 时长比较这个机制本身没错，
错的是拿错了时长——`silencedetect` 量的是音轨时间轴，`format.duration` 是容器（通常由视频轨
决定）的。

落地细节，三条都是实测决定的：

1. **不是所有容器都报流时长。** 实测：mp4 / mov / m4a / wav / flac / MPEG-TS **报**，
   **Matroska 与 FLV 不报**（只有容器时长）。所以「流时长缺失」是常态不是畸形，
   缺失时退回容器时长——那正是今天的行为，不制造新的拒绝；
2. **取两者中较短的那个**（`min`），不是直接用流时长。理由是流时长来自文件、可伪造：
   取 `min` 让这次改动**只可能把判定往「无有效音频」推，永远不可能往 bug 的方向推**，
   同时把「伪造一个超长音轨时长」这条路直接堵死（`min` 会拿回容器时长）。
   实测 MPEG-TS 正好用得上：容器 2.023 秒里装着 1.904 秒的音轨；
3. **诚实说明一处没有变好也没有变坏的地方**：伪造一个**极短**的音轨时长仍然是一条误拒杠杆
   （任何有 ≥0.3 秒静音的文件都会被判成全程静音）。

   > **⚠️ 这一条当时写错了，第二轮已推翻。** 原文写的是「这条杠杆今天就存在——伪造
   > `format.duration` 有一模一样的效果，不是本次引入的新类别」。**两者不等价**：伪造
   > `format.duration` 会**同时**把 `MediaStreamFacts.duration_ms` 压成 1 ms，一个十分钟的
   > 文件在素材库里显示成 0:00，用户一眼看得出不对；伪造**流**时长时 `duration_ms` 仍是
   > 10000，画幅、编码、时长各项全都正常，只有音频判定错了。**旧杠杆是响的，新杠杆是哑的。**
   > 而且 `min` 让更小的那个永远赢，所以新杠杆的下限比旧的还低。第二轮实测（3 字节改动，
   > 见下文 C2）确认这是一条真实误拒通道，已连同时长比较本身一起删除。

#### M2 的真实二进制结论：是死代码，删掉，并把假设改成有测试守着

审查要求对着真实二进制确认「未闭合静音」分支是防御性还是死代码。**四种形状全部实测，
全部闭合**——silencedetect 在 EOF 无条件冲刷出 `silence_end`，包括容器被从静音中间截断的那种。
再加上 C1 修完之后正则锚到了行首，注入也造不出未闭合的 `silence_start`。

按 T3 自己删 `math.isfinite` 时立的同一条标准（「留着会带着满分伪装成一道检查」），**删掉**：
`_SILENCE_START_PATTERN`、`_SILENCE_END_PATTERN`、`max(0.0, ...)` 夹断，以及被它拖着穿过
`_measure` / `_parse_measurement` 的 `duration_seconds` 参数一并去掉。

**删掉不等于把假设丢了。** 换成一条真实二进制用例顶上：一条 3 秒全程数字静音的 m4a 必须被判
`SILENT_AUDIO`——这个结论**只有在 silencedetect 闭合了那段静音时才成立**，所以哪天 ffmpeg 改了
行为，它会直接判红，而不是悄悄把静音文件报成有声。**把一个进不去的分支换成一条守着的断言**，
比留着死代码强。

顺带一个结构收益：`duration_seconds` 原本在两个地方各干一件事（未闭合静音的补算、静音覆盖判定），
删掉之后只剩一个使用点——**C2 的根因正是同一个时长值被当成两种东西用**。

#### C1 通道选型：两条候选各自实测到了什么

审查单裁定「换通道，不要再加锚点」，并要求先实测再选。逐条量：

**候选 1 `ametadata=mode=print:file=<独立通道>`——选它。** 量到的四件事：

1. **随包 ffmpeg 支持**，`file=-` 走 stdout，输出形状固定为两种行：
   `frame:<n> pts:<t> pts_time:<s>` 与 `lavfi.<key>=<value>`。实测对一个视频+音频输入，
   stdout 里**不匹配这两种形状的行数为 0**；
2. **stdout 不会被别的东西写**：`-f null` 声明了 `AVFMT_NOFILE`，ffmpeg 根本不打开输出。
   实测把输出写成 `/no/such/directory/out.bin` 仍然 `exit=0`；去掉 `ametadata` 后 stdout
   是 **0 字节**；
3. **`silencedetect` 的结果确实进得去**，但**只进得去一半**——这是全流程最关键的一条实测：
   `silence_start` 在帧上，`silence_end`/`silence_duration` 在**跨越到 EOF 时进不去**，
   因为 EOF 之后没有帧可挂。实测一条 3 秒全程静音的 m4a：stderr 有
   `silence_end: 3.018594 | silence_duration: 3.018594`，**通道里只有 `lavfi.silence_start=0`**；
4. **`ebur128` 的 `metadata=1` 能把 `lavfi.r128.I` 送进同一条通道**，每 100 ms 一条，
   取**最后一条**即最终积分值：440 Hz 正弦波通道里是 `-21.776`，它自己的摘要打的是 `-21.8`。

**候选 2「剥掉 metadata 段再解析」没有选**，理由与审查单倾向一致且被上面第 2 条加强：
界定 metadata 段的边界本身还是一次解析，而键名注入正是让「段的边界」不可靠的那件事。

**由第 3 条实测直接改变了判定方式**（这一点比选哪条候选更重要）：既然闭合信息进不了通道，
就不能再「把静音时长加起来跟音轨时长比」。改成读**形状**：

> silencedetect 一见到声音就闭合当前区间，所以**任何一个闭合区间本身就是有声音的证据**；
> 唯一可能不闭合的是最后一个，它一直延伸到轨尾。**于是「静音覆盖全程」恰好等于
> 「有一个从最开头打开的区间，且没有任何区间闭合过」。**

这个判据**一个时长都不需要**，C2 那条杠杆随之整条消失（见下）。附带三条实测支撑：
ffmpeg 的滤镜时间轴无论容器起始时间为何都从 0 开始（mp4/mov/mkv/flac/ogg/mpegts 六种实测
首帧 `pts_time:0`），所以「最开头」写成 `<= 0`；多区间实测 3 个 start / 2 个 end，形状与
推导一致；编码器补白导致的「静音比文件还长」不再需要 `>=` 容忍——不做减法就没有这个问题。

**响度也一并搬走了**：不再读 stderr 摘要，改取通道里最后一条 `lavfi.r128.I`。

**代价，如实登记**：`ebur128` 每 100 ms 一条，实测 60 秒素材 34,580 字节 = **576 B/s**。

> **这里原先写的「4 小时上限约 8.3 MB」是线性外推，第三轮审查点出后已实测**：真跑一趟
> 四小时（`sine` 直接喂进同一条滤镜链，13.5 秒跑完）得 **9,085,156 字节 = 8.66 MiB**，
> 比按 60 秒外推的 7.91 MiB 高 **9.5%**——帧号与时间戳位数变长，每块就变长。
> 与新加的上限用例里「1.5 倍余量是为了盖住投影看不见的位数增长」是同一个口径，
> 那条外推数字不该单独留在注释里。

所以 `MAX_MEASURE_OUTPUT_BYTES` 从 1 MiB 提到 **16 MiB**（对实测的 8.66 MiB 留 1.85 倍）。
这不是放宽护栏而是换了被守的对象：原来那 1 MiB 守的是**解码诊断**，速率不可控（审查者实测
7 次轮询 0.72 秒就写到 141,798,342 字节 = 上限的 135 倍）；现在诊断整条走 `DEVNULL`，
**磁盘增长这条通道直接没有了**，剩下的通道尺寸是时长的确定函数，上限由时长上限推出来。
顺带把 `ebur128` 六个状态里用不到的五个用 `ametadata=mode=delete:key=...` 删掉——
不删是 1763 B/s，删了 576 B/s。

**另外多做的一步**：滤镜链**第一个**就是 `ametadata=mode=delete`（无 key = 清空整个帧
metadata 字典），把 demuxer/decoder 可能挂上去的东西在两个测量滤镜之前先清掉。这样通道里
的键**只可能**来自这两个滤镜。行首/行尾锚点仍然留着，但它现在是这一层背后的纵深，不是主
防线——实测五个伪造文件的通道里注入命中数均为 **0**。

#### 由 C1 带来的一处行为收窄，与它的补偿

通道里的判定改成「形状」之后，**`lavfi.r128.I` 成了唯一的「这一趟真的跑起来了」证据**，
而实测**短于 100 ms 的音轨一条 `r128.I` 都不打印**（0.05 s、0.09 s 为 0 条，0.10 s 为 1 条）。
若照旧「没有响度就 `PROBE_FAILED`」，一条 50 ms 的真实音频会从今天的「接受、响度 None」
变成硬失败——那正是本单在修的误拒。

故把两种「没有」分开：**通道里一帧都没有** = 音轨短于一个积分窗，接受；**有帧却没有响度**
= 这趟没按要求跑，`PROBE_FAILED`（ebur128 每 100 ms 一条，有帧就意味着它早该报过好几条了）。
两侧各有用例，其中「50 ms 真实素材必须被接受」是随包 ffmpeg 现造的。

#### C2：不是二选一，而是被 C1 的新判定整条消掉

审查单给了两条修法。**先说为什么两条都没选**：

- **修法二「用 report 里最大的 `silence_end` 当音轨长度下界」，实测修不好它自己的反例。**
  `lead1s` 这条素材只有一个从 0 开始的区间，`silence_end = 1.000023`，而静音总量也正好是
  `1.000023`——下界与总量相等，`>=` 一比照样判「全程静音」。**这条修法在给定反例上无效**；
- **修法一「相对容器时长设合理性下界」能缓解但不能关闭。** 实测 `short_sound.mp4` 是
  10 秒画面配 2 秒音轨——**真实素材的合法比值就有 20%**，阈值只能定得比它更松，攻击者把
  伪造值抬到阈值之上照样有一段可用的误拒窗口。

**实际做法是 C1 的形状判定本身不需要任何时长**，于是这条杠杆没有「变窄」而是**不存在了**。
连带删掉的有：`_sound_track_seconds`（含 `min`）、`_optional_duration_ms`、
`MediaStreamFacts.audio_duration_ms`、以及 `-show_entries` 里的 `stream=duration`——
**不再向 ffprobe 要这个字段**，有专门用例断言 argv 里 stream 段不含 duration。

登记两件事：

- **`audio_duration_ms` 是本轮删掉的一个「事实」**，删它的依据是全仓 grep 后它**只有
  `_sound_track_seconds` 一个消费者**，且 `Material` 没有对应字段。若 LE-14 之后真需要
  音轨自身时长，重新加回来是几行的事；留着一个没人读、又由文件说了算的字段不是零成本，
  上面那 3 字节反例就是它的成本；
- 随之删掉的还有 `read_audio_facts` 里对时长的入参校验（`UNUSABLE_DURATION` 那两条）。
  它们存在的唯一理由是保护那个窗口计算，窗口没了就是死守卫——**按 T3 自己删
  `math.isfinite` 时立的同一条标准处理**。现在换成一条参数化用例：`duration_ms` 取
  `None / 0 / 1 / 10_000_000` 四个值，判定必须**逐个相同**。

#### I2：轮询体里抛错时超时保证消失，且 ffmpeg 不被杀

`report.stat()` 在飞行中抛 `OSError`（tmp 清理器、卷消失、EIO）时，异常离开 `with`，
`Popen.__exit__` 调的是**不带 timeout 的 `wait()`**，而子进程**从没被 kill**——审查者实测
超时设 1.0 秒、子进程 sleep 30，整轮 **30.59 秒**。

修法：轮询整体包一层 `except BaseException: process.kill(); raise`。**用例模拟的是飞行中**——
存根在写完输出后、赖着不走**之前**把工作区删掉（失败矩阵「文件在脚下被删」，不是注入异常）。
判据仍是存根的标记文件不存在（= 被杀，不是等出来的）。

**为什么是 `BaseException` 而不是 `Exception`，以及这条用例怎么才有捕捉力**：Ctrl-C 期间
`KeyboardInterrupt` 不是 `Exception`，窄一档就会让它从那个「不带超时地等」的出口溜出去，
把一个正在解码四小时素材的 ffmpeg 变成孤儿进程。第一版用例用「标记文件不存在」来断言，
**变异 `BaseException` → `Exception` 存活**——查出来的原因是 CPython 在 `Popen.__exit__` 里
**对 `KeyboardInterrupt` 有特判**：只等 `_sigint_wait_secs`（0.25 秒）就返回，所以没被杀的
子进程不是「拖慢断言」而是「活过断言」。改成让存根写下自己的 PID、断言事后
`os.kill(pid, 0)` 抛 `ProcessLookupError`，变异当场被杀。

### T3 第四轮修复（第三轮审查：1 Critical 回归 + 2 Important）

**上一轮换通道时引入了一个回归，而且是本任务里最贵的那一类：普通有声文件被硬拒。**

#### C1 回归：`silencedetect` 放在 `ebur128` 上游，闭合事件被合帧丢弃

`ebur128` 在 `config_input` 里把输入链的 `min_samples`/`max_samples` 都设成
`sample_rate/10`，libavfilter 于是把解码帧**并成一个窗口的长度**再交给它；而
`take_samples()` 只做 `av_frame_copy_props(buf, frame0)`——**组内非首帧的 metadata 全部丢弃**。
AAC 一帧 1024 样本、一个窗口 4410 样本，约四帧并一组，于是**放在 ebur128 上游的滤镜，
每四个事件只活一个**。

丢掉的正是证明「声音回来了」的 `silence_end`。没有它，一个前面静音、后面有声的文件
读起来与「一直静到 EOF」完全一样，而后者对 `kind=AUDIO` 就是硬拒。

实测（本机随包 8.1.2，四组编码 × 六个前导静音长度 = 24 个含 4 秒清晰可闻 440 Hz 的文件）：

| 组 | 上游（改前） | 下游（改后） |
| --- | --- | --- |
| AAC 44.1 kHz | **4/6 错** | 0/6 |
| AAC 48 kHz | **3/6 错** | 0/6 |
| FLAC 44.1 kHz | 0/6 | 0/6 |
| PCM s16le 44.1 kHz | 0/6 | 0/6 |
| **合计** | **7/24 被硬拒 `silent_audio`** | **0/24** |

最干净的一对是前导静音 **0.30 秒通过 / 0.31 秒硬拒**，只差 10 毫秒。

**判据是块长，不是编码格式**（第三轮审查纠正了我这里写错的机理，实测复核如下）。
一整帧连同 metadata 被吞掉，只发生在「一组吃进两整帧」时，也就是**解码帧长 ≤ 半个窗口**。
44.1 kHz 下窗口是 4410 样本，实测解码帧长：**AAC 1024、PCM s16le 4096、FLAC 默认 4608**。

我原先写的「FLAC/PCM 的帧本来就 ≥ 一个窗口」**是错的**——PCM 的 4096 比窗口还短，
只是超过半个窗口，所以每组只吃一整帧加下一帧的一小截，那一截成为下一组的首帧，
没有任何整帧被吞。用 `-frame_size` 把 FLAC 块长压下去，八个静音位置逐个实测：

| FLAC 块长 | 两整帧塞得进窗口 | 上游顺序（改前） | 下游顺序（改后） |
| --- | --- | --- | --- |
| 512 | 是 | **8/8 硬拒** | 0/8 |
| 1024 | 是 | **8/8 硬拒** | 0/8 |
| 2048 | 是 | **7/8 硬拒** | 0/8 |
| 4096 | 否 | 0/8 | 0/8 |

2048 那格值得单记：**第一次只测一个素材时它是通过的**，再测八个相位才看出 7/8 会挂——
和这一整条 bug 逃过 168 个用例的原因是同一个（单个样本恰好落在安全相位）。

**结论：外部编码器产出的 1024/2048 块长 FLAC，行为与 AAC 完全相同。** 用户素材不由
本项目的编码器产出，所以「我们的默认块长比较大」不构成任何保护。

> 审查单报的是 17/24，我自己这组测出来是 7/24。**不是分歧，是取的前导静音长度不同**
> （我用 0.30 / 0.31 / 0.35 / 0.55 / 0.77 / 1.00，其中两个恰好在网格上）。分组形态
> 与审查单一致：AAC 两组出错、FLAC 与 PCM 两组不出错。此处记我自己实测到的数。

**修法**：把 `silencedetect` 挪到 `ebur128` **下游**。此时它看到的已经是 4410 定长帧，
自己产生的 metadata 直接进 sink。样本值不变、响度不受影响，24 个文件判定归零错误。
argv 用例钉住这个顺序，三条真实素材用例钉住行为。

#### 我自己写的用例翻车了一次，一并记

为 `except BaseException` 补的 Ctrl-C 用例，第一版让存根把自己的 PID 写进文件、再断言
事后 `os.kill(pid, 0)` 抛 `ProcessLookupError`。**它是 flaky 的：30 次跑挂 2 次**，因为
父进程在 spawn 后 0.1 秒就抛 `KeyboardInterrupt`，而子进程（`sh` + 一次 `dirname` 子进程）
偶尔还没走到写 PID 那一步，读回来是空串。把写 PID 挪到脚本第一行也没解决——**只要判据
依赖子进程跑到某个位置，就是在跟它的启动赛跑**。

改成断言**父进程自己手里的那个 `Popen`**：记录下它，事后 `wait(timeout=10)` 收尸再断言
`returncode == -SIGKILL`。杀了就是 `-9`，没杀就是存根睡完自己退出的 `0`，两边都确定，
不依赖任何时序。30 次跑 0 次挂，变异 `BaseException` → `Exception` 仍被它杀掉。

**这件事也污染过一次结论**：上一轮那句「34/34 全杀」里，有一个本该存活的等价变异体
（`starts[0]` → `starts[-1]`）是被这条 flaky 用例**误杀**的。修稳之后重跑，它如期存活。
