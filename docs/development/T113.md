## 二、补进清单的两条现场事实（原来一条都没有）

### A9 🆕 出包必须在屏幕解锁状态下做

07-27 凌晨真实撞上：屏幕锁着时公证失败，报的是

```text
No Keychain password item found for profile: at-tools-notary
```

**这句话看起来像凭据丢了，其实没丢**——照它去重配凭据会白花时间还可能改坏。

判据与实测（本轮跑的时候屏幕正好锁着，所以这条判据当场就验到了它该报的那一面）：

```text
$ ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked
<key>CGSSessionScreenIsLocked</key>
<true/>
```

**边界（不夸大）**：我没有重新触发一次公证来复现（那意味着真提交一次构建），
所以「锁屏 → 取不到凭据」这层因果是**从现场观测加机制推断**得来的，
不是我这轮实测出来的。可以佐证的是：`security` 在当前状态下确实找不到该条目
（`find-generic-password` 按 service / account / label 三种查法均 not found，
`dump-keychain` 无匹配）。**现场那次失败本身是硬事实**，判据命令也是硬事实。

相关实现：`scripts/release_assembly.py:526-538` 的
`xcrun notarytool submit --keychain-profile <profile>`；
profile 名 `at-tools-notary` 来自 `contracts/quality/macos-release-signing.v1.json:6`。

清单里同时写了「把自动锁屏关掉」——**出包要跑很久，中途人不在电脑前，锁屏是不管它就一定会来的**。

### A10 🆕 出包会变慢；卡在下载字体那一步就重试

两件事合成一条：

**慢**：三个视频运行时产物的缓存键补齐之后全部判定失效，每台机器要一次性重跑三个构建，
其中媒体工具链是从源码编译。依据 `docs/development/T111.md` 第七节实测：

```text

material-video-worker: stamped=642c1c07eecd new=dd51583280ca -> REBUILD
```

同一节还写明**三者共用每机一份缓存目录、重建前会先清空目标目录**，所以出包期间不得并发跑
这些构建——清单里照写了。

**字体**：构建期要从 `raw.githubusercontent.com` 取 Noto CJK 字体与许可证，
07-27 03:13 真实撞上 `SSL: UNEXPECTED_EOF_WHILE_READING`，整条预建流程退出 1；重试即过。
本轮实测该地址仍通：


它确实在出包关键路径上：`scripts/prepare_video_runtime.py:217` 调 `ensure_subtitle_fonts`，
而 `scripts/build_release_package.py:718` 调 `prepare_video_runtime`；地址在
`scripts/subtitle_font_assets.py:70`。

清单里特别写了一句「**它发生在很靠后的位置**（三样已经做完两样），一眼看上去像是都快好了却挂了，
容易误以为是构建本身坏了。它不是。重试。」
