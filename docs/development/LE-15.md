1. 消费方只依赖 `ScriptSegmentationAdapter` 以及供应商无关的 Options、Reply、Sentence
   和 Result；百炼 URL、Bearer 凭据、OpenAI-compatible 请求与响应形状只存在于百炼

   `qwen3.7-max-2026-06-08`；显式模型必须同时出现在该用途 `allowed_model_ids` 和
   顶层 `models`，且声明 `text=true`。provider、API mode、HTTPS Base URL、用途和模型
   任一漂移均 fail closed。
3. `enable_thinking` 是供应商无关的请求级布尔配置，默认精确为 `false`；百炼请求体每次
   都显式发送该布尔值，不按模型名推断、不省略。LE-24 后续只传入总开关值，不改
   Adapter。
4. 模型只收到用户文案和固定结构化输出指令；不携带素材路径、输出目录、视频、音频、
   浏览器或发布平台信息。API Key 不进入 `repr`、结果、异常或日志。

### 结构化分句与边界

1. 模型正文只接受一个严格 JSON 对象，顶层精确为 `sentences`，值为有序字符串数组；
   重复 key、未知字段、数组为空、非字符串元素、首尾空白和不安全控制字符均拒绝。
   `sequence` 由本地按数组顺序生成 `1..N`，不让模型自报序号。
2. 用户文案最多 4,000 字符；最多产出 128 句，单句最多 1,000 字符且总脚本文本最多
   4,000 字符。单句上限必须直接复用既有
   `motion_authoring.voiceover.MAX_NARRATION_CHARS`，保证 T1 产物天然可被 T2 的唯一
   TTS 实现消费，不建立第二个旁白长度常量。
3. 模型回复体、结构化正文、请求 ID、token 和超时均有硬上限；只接受
   `finish_reason=stop` 且无非空 refusal 的第一条回复。超时、拒答、截断、空正文、
   畸形 JSON 或任何边界漂移都转换为无异常链的固定
   `ScriptSegmentationRejected("script segmentation request rejected")`，不回显上游正文、
   请求 ID、密钥或本机路径，不自动重试。
4. T1 的完成证据是供应商无关协议、目录选择、默认/开启 thinking、封闭请求与有序结果的
   聚焦自动化；没有用户入口，因此最多是分层证据。真实模型、TTS、PostgreSQL 与正式包
   在 T4 模块收口时统一验收，不在每个小任务重复跑全量。

## T1 Codex Review finding 修复

实现检查点 `6bf4132` 提交并推送后执行 Codex Review。审查复跑原专项 `22 passed`、
Ruff、严格 mypy、差异、路线图计数与证据深度门禁，并以最小探针报告六项 P2：

1. 默认 `2,048` token 预算不足以覆盖允许的 4,000 字符脚本；
2. 模型目录虽在 JSON 解码时检查 256 KiB，却先用 `read_bytes()` 无界读入；
3. `schema_version=true/1.0` 会利用 Python 相等语义冒充整数 `1`；
4. `script` 用途可以增加与根配置冲突的 `api_mode`/`base_url` 覆盖；
5. timeout 在精确类型校验前调用 `float()`，会接受布尔值，并让私有路径与超大整数分别
   泄漏原生 `ValueError`/`OverflowError`；
6. 4,000 个非 BMP 字符用合法 JSON 代理对转义时约为 48 KiB，旧 32 KiB 正文上限会按
   等价序列化方式误拒绝，外层响应上限也无法覆盖转义后的内容字符串。

六组测试先落地，旧实现精确得到 `10 failed, 22 passed`。最小修复把默认预算提高到既有
允许上限 `16,384`，正文/外层响应分别保持有界的 64 KiB/256 KiB；目录先核对 stat 大小，
再只读取 `limit + 1` 字节；版本必须是精确整数，`script` 不允许用途级端点覆盖；timeout
在转换前要求精确数值类型和 `(0,300]` 范围。专项恢复 `32 passed`，Ruff 与严格 mypy
全绿。

捕获力复核临时把正文上限改回 32 KiB，最大合法转义脚本用例立即得到
`1 failed, 31 deselected`；还原后完整专项仍为 `32 passed`，工作树未保留变异。本轮只
运行 T1 聚焦门禁，LE-15 的模块全量仍按会话约定留到 T4 收口统一执行。

修复提交 `9ea7b25` 推送后再次执行 Codex Review；审查独立复跑 32 条专项、Ruff、

## T2 开工前【先定】

### 逐句协议与唯一时长事实

1. T2 只消费 T1 的 `ScriptSegmentationResult`，按本地 `sequence` 顺序逐句调用既有
   `synthesize_voiceover`；不复制百炼请求、模型目录、密钥或音频下载实现。每句固定写到
   `voiceover/sentence-NNNN.wav`，输出携带原 `ScriptSentence`、相对路径、真实
   `duration_ms` 与字节数，不携带宿主绝对路径。
2. 时长只由 LE-07 交付的 `PackagedMediaTools` 与公开 `read_stream_facts` 读取；要求产物
   精确为 `ProbedMaterialKind.AUDIO` 且 `duration_ms > 0`。TTS 响应、文件后缀、WAV 头或
   字符数估算都不是时长事实；旧 `measure_audio_seconds` 不进入 T2 调用链。
3. 批次是全有或全无：任一句 TTS、写盘或 ffprobe 失败，都调用
   `AuthoringWorkspace.rollback_authored_files()` 清除本批已经生成的音频，并只抛固定、
   无异常链的 `ScriptVoiceoverRejected("script voiceover request rejected")`。正常路径
   不自动重试，避免一次结果不确定的云调用产生重复费用。
4. 同一工作区已有任一句固定输出时，必须在发起云调用前拒绝，不覆盖已有文件，也不把
   旧文件算成本批结果。T2 不建立幂等仓储；任务级恢复、显式重试和取消归 LE-12，T2 只
   保证一次函数调用内的原子文件边界。
5. T2 的真实媒体回归用随包 ffmpeg 现造刻意偏离整秒和 100 ms 网格的 1.237 秒音频，再
   由随包 ffprobe 读回 1,237 ms。真实百炼付费调用、完整失败矩阵和正式包用户路径统一
   留到 T4 模块收口，不在本子任务跑模块全量。
