## 结论

`build_signed_executor()` 的 PyInstaller 失败分支已经会保留 stdout/stderr，但紧接着的
`package_manifest` 签名失败仍只抛出 `E4-07 package signing failed`。该调用没有
`text=True`，捕获到的是 bytes；C7 复用既有的每流 20 行诊断 helper，并补上 UTF-8
replacement 解码，使签名失败同时保留两个流、继续有界，而且不会被非 UTF-8 输出触发二次
异常。

本次没有改动成功路径、签名输入、签名策略或真实产物，只改善失败可见性。

## RED

先新增
`BuildSignedExecutorTests.test_package_signing_failure_preserves_both_output_streams`，让
PyInstaller 成功、`package_manifest` 返回 7，并分别在 bytes stdout/stderr 放入唯一标记。

实际命令：

```text
backend/.venv/bin/python scripts/test_run_e4_07_acceptance.py \
  BuildSignedExecutorTests.test_package_signing_failure_preserves_both_output_streams
```

修复前真实结果为退出码 1：

```text
FAIL: test_package_signing_failure_preserves_both_output_streams
AssertionError: 'manifest stdout: invalid bundle entry' not found in
'E4-07 package signing failed'
Ran 1 test
FAILED (failures=1)
```

这是真实行为断言 RED：代码被导入并走到目标失败分支，不是路径、依赖或语法造成的假红。

## GREEN

最小实现包含两点：

1. `_completed_process_diagnostic()` 同时接受 `CompletedProcess[str]` 与
   `CompletedProcess[bytes]`，bytes 用 UTF-8 replacement 解码；
2. `package_manifest` 非零退出时，把同一 helper 生成的 stderr/stdout 各 20 行 tail
   附到原固定错误前缀后。

同一条测试命令修复后真实结果为退出码 0：

```text
.
Ran 1 test
OK
```

原错误前缀保持不变，调用者如果按 `E4-07 package signing failed` 分类不会失效。
