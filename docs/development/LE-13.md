## 范围

本任务消费 LE-08 的自适应抽帧结果，经供应商无关 Adapter 调用百炼多模态模型，产出素材
描述、标签和镜头时间区间，并在不覆盖用户描述的前提下写回 Material。覆盖超时、拒答、
空描述和 token 超限，最后用真实百炼与真实素材核对请求 ID 和 PostgreSQL 写回行。

本任务不建立 App 页面、不把百炼类型放进领域层、不改变抽帧策略，也不实现 LE-14 的人声
检测或转写。

## 开工前【先定】

### Adapter 与配置边界

1. 消费方只依赖 `MaterialUnderstandingAdapter` 协议和供应商无关的请求/回复值；百炼 Base
   URL、API Key、OpenAI-compatible 请求体与上游错误形状只存在于百炼 Adapter。
2. 复用 `contracts/video/bailian-model-catalog.v1.json` 已锁定的 `video_creative` 用途：
   当前正式设置面已为该用途装配唯一允许图片输入的
   `qwen3.7-max-2026-06-08`，不另造第二份模型目录或密钥来源。
3. 配置由调用方显式注入，不从环境变量、PATH 或任意本机文件自行发现。API Key 不进入
   `repr`、返回值、异常或日志。
4. `enable_thinking` 是请求级配置，默认 `false`，百炼请求体始终按配置发送布尔值；
   LE-24 后续只需把总开关值传入同一配置，不改 Adapter 代码。
5. Adapter 输入只携带受控 JPEG bytes、相对素材起点的毫秒时间戳和切点标志；不携带源
   文件路径或输出目录路径。请求按单条素材一次完成，避免把不同素材混进同一模型上下文。

### 结构化产物与写回边界

1. 模型回复在 Adapter 外解析为供应商无关结果；描述、标签和镜头区间使用封闭字段，
   不接受任意扩展字典。顶层固定为 `description`、`tags`、`shots`，每个镜头固定为
   `startMs`、`endMs`、`description`；重复 JSON key、未知字段、布尔冒充整数和超出既有
   Material 文本/数量上限都直接拒绝。
2. 镜头区间必须有序、非空、互不重叠并落在素材时长内；Material 最终仍只持有既有
   `shot_boundaries_ms`，区间在写回前转换为每段起始边界，避免把供应商 DTO 放入领域模型。
3. 消费 LE-08 产物时不重新相信路径字符串：只接收 LE-08 的相对受控文件名和已记录大小，
   通过其稳定输出目录句柄以只读、拒绝符号链接方式打开，读前读后都核对普通文件、单硬链、
   权限、大小与 JPEG 首尾；任一产物漂移则整次理解拒绝，模型不被调用。
4. 用户写描述与 AI 写理解结果使用两个仓储入口。用户入口只更新
   `ai_description`、`ai_tags`、`description_source`、`described_at` 四列，绝不从调用方
   快照重写镜头边界；AI 入口在同一条 SQL 中同时更新上述四列和
   `shot_boundaries_ms`，并把 `description_source != user` 放进该 SQL 的 WHERE。
5. 当前快照已是 USER 时，领域层直接保留整份 Material；模型调用期间用户接管时，AI SQL
   零行命中并返回 `MaterialDescriptionProtected`。两种情况下描述、标签、时间戳和镜头边界
   全部不写，不重试，不做字段级合并；API 测试必须证明旧镜头边界仍在。
6. 当前项目未发布，不保留旧 AI 描述写入口的兼容形状：AI 请求必须携带
   `shotBoundariesMs`，应用层以一次 `update_understanding` 调用接收完整结果；USER 请求
   不接受该字段。

4. 附加安全探针确认模型响应使用无参数 `read()` 时，请求里的 token 上限不能约束恶意或
