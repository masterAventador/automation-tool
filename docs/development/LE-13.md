## 范围

## 开工前【先定】

### Adapter 与配置边界

1. 消费方只依赖 `MaterialUnderstandingAdapter` 协议和供应商无关的请求/回复值；百炼 Base
   URL、API Key、OpenAI-compatible 请求体与上游错误形状只存在于百炼 Adapter。
2. 复用 `contracts/video/bailian-model-catalog.v1.json` 已锁定的 `video_creative` 用途：
   当前正式设置面已为该用途装配唯一允许图片输入的
   `qwen3.7-max-2026-06-08`，不另造第二份模型目录或密钥来源。
3. 配置由调用方显式注入，不从环境变量、PATH 或任意本机文件自行发现。API Key 不进入
   `repr`、返回值、异常或日志。
4. `enable_thinking` 是请求级配置，默认 `false`，百炼请求体始终按配置发送布尔值；
   LE-24 后续只需把总开关值传入同一配置，不改 Adapter 代码。
5. Adapter 输入只携带受控 JPEG bytes、相对素材起点的毫秒时间戳和切点标志；不携带源
   文件路径或输出目录路径。请求按单条素材一次完成，避免把不同素材混进同一模型上下文。

### 结构化产物与写回边界

1. 模型回复在 Adapter 外解析为供应商无关结果；描述、标签和镜头区间使用封闭字段，
   不接受任意扩展字典。
2. 镜头区间必须有序、非空、互不重叠并落在素材时长内；Material 最终仍只持有既有
   `shot_boundaries_ms`，区间在写回前转换为起始边界，避免把供应商 DTO 放入领域模型。
3. AI 描述写回必须经过 `MaterialService.update_description` 和仓储原子保护。当前快照已是
   USER，或模型调用期间用户接管描述，两种情况都视为正常丢弃 AI 文本，不重试、不覆盖。
4. 镜头边界与描述属于同一次理解结果，T2 必须决定并用 PostgreSQL 事务锁住二者的原子写回；
   在该决策落地前不增加半套“描述成功、边界失败”的应用接口。

## T1 首轮 Codex Review 修复

提交 `ebdedd5` 已推送。Codex Review 复跑专项 `6 passed`、Ruff、严格 mypy 与路线图计数，
并用最小探针找到三项正式 finding，修复过程另补一项响应体上限：

1. 固定脱敏异常虽然不含密钥，但在处理上游异常时直接抛出会保留原始 `__context__`，
   `traceback` 和 `logger.exception` 仍能带出 API Key 与操作者私有路径；
2. 公开配置类型可以绕过加载器直接构造，从而把 Bearer API Key 发往任意 HTTP 端点；
3. 服务端声明长度后提前断开时，`http.client.IncompleteRead` 会逃逸固定脱敏拒绝；
4. 附加安全探针确认模型响应使用无参数 `read()` 时，请求里的 token 上限不能约束恶意或
   异常响应占用的内存。

异常链、配置绕过与无界响应先补测试，RED 精确得到 `3 failed, 5 passed`；修复提交后再按
正式 Review 文本补截断响应用例，RED 精确得到 `1 failed, 8 passed`。实现让异常在离开原
异常处理上下文后再转换为固定拒绝，锁定配置自身在构造时校验官方 HTTPS Base URL、图片
模型、API Key 形状和超时范围，捕获 HTTP 协议层异常，并在 JSON 解析前把响应体读取上限
固定为 `256 KiB`（多读 1 字节用于判定超限）。修复后专项 `9 passed`，Ruff 与严格 mypy
通过。

修复提交 `b24122e` 的 Codex Review 没有 finding，但审查过程中用标准库
`http.client.HTTPResponse` 做出的真实探针证明：一旦调用 `read(n)`，带
`Content-Length` 的响应提前 EOF 时会静默返回短数据，不保证抛出 `IncompleteRead`。此前
测试替身直接抛异常，虽然验证了异常映射，却没有验证真实读取语义。

将测试替身换成真实 `HTTPResponse` 后，构造“声明长度比实际 JSON 多 128 字节”的响应，
RED 精确得到 `1 failed, 8 passed`，旧实现错误接受了这个仍可解析的残缺 JSON。实现现在
读取前保存标准库解析出的声明长度，读取后同时核对 256 KiB 上限和实际长度；无声明长度的
合法 EOF 响应不受影响，HTTP 协议异常仍走固定脱敏拒绝。专项恢复 `9 passed`，Ruff 与严格
mypy 通过。

提交 `7f653f5` 的 Codex Review 又用真实标准库响应找到一处 P2：只读取
`HTTPResponse.length` 会漏掉原始 `Content-Length` 中不可解析、重复冲突以及逗号合并冲突
三种形状；第一项恰好等于可解析 JSON 的实际长度时，旧实现会错误接受畸形响应。三种形状
先参数化落成真实 `HTTPResponse` RED，精确得到 `3 failed, 9 passed`；实现改为读取全部
原始长度声明，逐项只接受 ASCII 十进制数字，并要求每项完全一致，再与实际读取字节数
核对。专项恢复 `12 passed`，两个相关 Python 文件 Ruff format/check 与严格 mypy 均通过，
等待本轮修复提交后的 Codex Review。
