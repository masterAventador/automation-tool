## 交付范围

- 锁定 FFmpeg 8.1.2 官方源码及 SHA-256，锁定 x264 r3222 对应提交、源码归档摘要和
  GPL 许可证。
- macOS arm64 与 Windows x86_64 均从相同源码原生构建，关闭自动依赖探测和网络协议，
  仅显式引入 x264、zlib；不采用系统 PATH、用户路径、运行时下载或上游自带程序。
- 两平台候选均包含二进制、完整对应源码、许可、构建信息和逐文件摘要 Manifest；
  Rust fail-closed 解析器向两种制作方式提供同一对已验证路径。
- 能力门禁覆盖编解码器、容器、滤镜和本地协议，并实际生成素材片段+AAC+concat 与
  PNG 逐帧序列两条 H.264 MP4，再由 ffprobe 独立读取。

## RED

初始实现缺少供应链契约、检查器、Rust 解析器和测试。macOS 源码构建先后暴露
SHA-256 格式化、测试 UUID feature、canonical 路径、Bash 3.2 空数组和系统库自动探测
问题。

2026-07-24 的 Windows 原生构建又实际暴露以下平台缺口：

- 原生 MINGW64 被错误声明为带 `x86_64-w64-mingw32-` 前缀的交叉构建，x264 endian
  probe 调用不存在的 `x86_64-w64-mingw32-strings`；
- FFmpeg 的 Windows make 目标是 `ffmpeg.exe`/`ffprobe.exe`，无后缀目标无法命中；
- 相对输出目录在进入源码目录后失效；
- 动态链接的 `libwinpthread-1.dll`、`zlib1.dll` 未随候选交付，普通 PowerShell 启动
  返回 `0xC0000135`；
- 非管理员 Windows 默认无创建 symlink 权限，原自测无法建立拒绝夹具。

实现改为原生 MINGW64 参数、带 `.exe` 的 make 目标、构建前规范化输出目录、静态链接
GCC/pthread/zlib，并在自测中以非管理员可创建的 NTFS junction 覆盖 reparse-point
拒绝边界。

## 失败矩阵

- 版本、源码摘要、GPL 声明、目标/Runner、必需能力或 Worker 环境变量漂移均拒绝。
- Manifest 未覆盖全部文件、重复/越界路径、摘要或大小不符、缺失/额外文件、symlink、
  NTFS reparse point、不可执行文件和错误架构均拒绝。
- 构建脚本拒绝错误宿主/架构、源码摘要错误和未知目标；禁止 nonfree、自动依赖探测、
  网络协议、系统 PATH 与运行时下载。
- Windows 原生构建固定无交叉前缀、`.exe` 目标、绝对输出路径及静态运行时；回归契约
  防止恢复会产生不可启动候选的参数。
- 候选缺少任一编解码器、容器、滤镜或本地协议，或任一真实编码/ffprobe 对账失败，均
  不能进入待打包 Artifact。

真实编码边界已经闭合，因此本任务完成；安装包资源装配及两种制作方式从正式 App 入口
生成成片仍分别由 EB-16、IM-08 和 BM-16 验收，本任务不提前宣称这些用户功能完成。
