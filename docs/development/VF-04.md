## 交付范围

- 锁定 FFmpeg 8.1.2 官方源码及 SHA-256，锁定 x264 r3222 对应提交、源码归档摘要和 GPL 许可证。
- 两平台均从相同源码原生构建，关闭自动依赖探测和网络协议，仅显式引入 x264、zlib；不采用系统 PATH、用户路径、运行时下载或上游自带程序。
- 建立 macOS arm64 与 Windows x86_64 独立 CI 构建矩阵，生成包含二进制、完整对应源码、许可、构建信息和逐文件摘要 Manifest 的目录。
- 建立 Rust fail-closed 解析器；两种制作方式拿到同一对已验证路径，但使用各自上游已支持的环境变量。
- 建立能力探测和两条真实编码烟测：素材片段+AAC+concat，以及 PNG 逐帧序列成片，结果均由 ffprobe 独立读取。

`python3 scripts/run_vf_04_acceptance.py` 初始明确缺少供应链契约、检查器、Rust 解析器和测试。随后编译与构建分别暴露 SHA-256 格式化、测试 UUID feature、canonical 路径及 Bash 3.2 空数组问题并逐项修复。

Windows x86_64 不能在当前 Apple Silicon 本机正式执行。实现推送后由 `Video media toolchain` 的 `windows-2025` Job 原生构建和运行相同烟测；拿到成功证据前 VF-04 保持 `🔍 待验收`，不得作为 IM-08/BM-16 双平台完成依据。

实现提交触发 GitHub Actions run `29953539585`。macOS Check `89036830952` 与 Windows
Check `89036830904` 都在执行任何 step 前失败；GitHub 注解明确说明近期账号付款失败或
spending limit 需要提高。该结果证明当前托管执行环境被账单策略阻断，不是源码构建、
能力检查或烟测失败。账单恢复后可从 `workflow_dispatch` 原样重跑，不需要修改契约。

## 失败矩阵

- 版本、源码摘要、GPL 声明、目标/Runner、必需能力或 Worker 环境变量漂移均由契约拒绝。
- Manifest 未覆盖全部文件、重复/越界路径、摘要或大小不符、缺失/额外文件、symlink、
  reparse point、macOS 不可执行文件和错误目标均由 Rust 解析器拒绝。
- 构建脚本拒绝错误宿主/架构、源码摘要错误和未知目标；禁止 `--enable-nonfree`、自动依赖
  探测、网络协议、系统 PATH 与运行时下载。
- 候选缺少任一编解码器、容器、滤镜或本地协议，或任一真实编码/ffprobe 对账失败，均
  不能进入待打包 Artifact。

## 正常用户路径验收

VF-04 是内部发行物与 Worker 启动依赖，没有新增用户界面。最终标准是安装包内资源和两种制作方式真实生成；当前只完成 macOS 候选实机验证，Windows 与最终 App 正常用户路径由本任务 CI 及后续 IM-08/BM-16 承接，不把单测当成用户能力完成。

## 真实边界

本机实测仍是当前唯一平台运行证据；Windows 只有原生构建/验收代码，尚无运行结果。
Rust 测试使用真实文件系统，但不冒充正式安装包。
