## 交付范围

- Node Worker（`workers/motion_composition/worker.mjs`）bootstrap 协议新增必填
  `renderBrowser` 通道：`null` 或 `{chromiumMajor, executablePath, launchTimeoutSeconds}`
  的精确键集合；可执行文件必须是绝对路径、常规文件、非符号链接，POSIX 带执行位，
  Windows 为 `.exe` 且带 `MZ` PE 签名，
  Chromium major 限定 100–999，启动超时限定 1–60 秒，任何偏差固定退出码 65 且不回显
  路径、令牌或输入。
- 新增 HMAC 认证命令 `worker.render.verify`：Worker 只使用 bootstrap 里 Rust 已验证的
  单一 Chromium 路径，在 `automation-tool-renderjob-<jobId>-` 专属临时目录内以独立
  detached 无头进程启动（`--headless` + `--remote-debugging-pipe`，无监听调试端口），
  POSIX 先经 `--version` 探测 actual major，所有平台再经 CDP 管道
  `Browser.getVersion` 核对运行中产品版本并与 Rust 显式声明的 major 一致。
  Windows 的 GUI 子系统可执行文件不使用会挂起的 `--version`；收到 `Browser.close`
  应答后定向终止仍持有继承管道的本次自有进程树。
- 成功发出 `worker.render.verified`（含 chromiumMajor 与 HMAC 证明）；失败只发固定
  reasonCode（`render_browser_unavailable` / `render_browser_unusable` /
  `chromium_major_mismatch` / `render_timeout` / `render_protocol_invalid`），不泄漏路径。
- 禁用一切 fallback：Worker 不读 `HYPERFRAMES_BROWSER_PATH`、`PRODUCER_HEADLESS_SHELL_PATH`、
  `PUPPETEER_CACHE_DIR`、`CHROME_PATH` 或 HOME 缓存目录；渲染浏览器子进程环境只含指向
  RenderJob 目录的 `HOME`/`TMPDIR`，Windows 同时隔离 `USERPROFILE`/`TEMP`/`TMP` 并只
  保留启动系统程序所需的 `SystemRoot`/`WINDIR`；上述发现类变量不会传播。
- Rust 侧（`frontend/src-tauri/src/local_video_orchestrator.rs`）新增
  `VideoWorkerRenderBrowserConfiguration`（复用 `validate_executable_path` 的绝对路径/
  祖先符号链接/执行位校验 + major/超时范围校验）、`VideoWorkerLaunch::with_render_browser`
  bootstrap 注入，以及 `LocalVideoOrchestrator::render_verify`（命令签发、verified/failed
  事件 HMAC 校验、major 与期望一致性校验、`RenderRejected` 错误码）。
- 新增 `scripts/test_motion_video_render_adapter.py`（Worker 层失败矩阵门禁）与
  `scripts/run_bm_03_acceptance.py`（按宿主选择 EB-03/EB-04 原生目标，Windows 构建
  官方 Node 22 候选，再跑通 Rust→Node→真实 Chromium 纵向链路）。

## 失败矩阵

- 路径缺失 / 相对路径 / 非常规文件 / 无执行位 / 符号链接 / 多余字段 / 类型错误 /
  major、超时越界：bootstrap 固定退出码 65，错误不含路径与输入正文。
- bootstrap 后可执行文件被替换或删除：渲染时 `render_browser_unusable`，不启动。
- `renderBrowser: null` 且发现类环境变量全部指向可记录诱饵浏览器：只回
  `render_browser_unavailable`，诱饵从未被调用——无系统浏览器发现、无缓存 fallback、
  无上游下载。
- POSIX 的 `--version` major 与声明不符：`chromium_major_mismatch`，且记录证明未发起
  无头启动；运行中产品版本漂移（getVersion 与 `--version` 不一致）同样拒绝。
  Windows 不依赖 GUI 子系统可执行文件的 `--version`，直接以 CDP 返回的实际产品
  major 拒绝声明错配。
- CDP 管道响应为垃圾数据 / 超长 / 非零退出：`render_protocol_invalid`。
- 无头进程挂起：launchTimeoutSeconds 后终止整个自有进程树，POSIX 使用进程组
  SIGKILL，Windows 使用绝对系统 `taskkill.exe /T /F`；Windows 实测父子 PID 都被杀死，
  事件为 `render_timeout`。RenderJob 目录在成功、失败、超时路径一律删除（finally，
  Windows 带有界重试）。
- 伪造 HMAC 的 render 命令被静默忽略，不触碰浏览器也不产生事件；Rust 侧伪造事件
  证明、reasonCode 非法字符、major 与期望不符均按 `AuthenticationRejected` 拒绝；
  Worker 返回 failed 事件映射为 `RenderRejected`。
- 未配置 renderBrowser 时 Rust `render_verify` 直接 `ConfigurationInvalid`，不发 IPC，
  Worker 保持健康。
- Worker 无监听调试端口（断言禁止 `--remote-debugging-port`），CDP 只经 stdio 管道。

## 真实边界

- macOS arm64 与 Windows x86_64 均已用真实 Chrome for Testing 149.0.7827.55 完成
  Rust→Node→Chromium 纵向验收；Windows 另以真实 NTFS junction、PE 路径和挂起父子树
  闭合 reparse/清理语义。macOS x86_64 发行暂存仍属于 EB-03 自身的原生目标验收，
  不改变本任务已验证的跨平台适配契约。
- macOS 验收链路使用开发机 Node wrapper；Windows 使用由 BM-02 唯一 builder 当场生成
  的官方 Node 22.23.1 x64 候选。BM-16 冻结完整生产包时仍需把上游引擎一并复验。
- 实测发现完整版 Chrome 149 `--headless --screenshot` 不会自行退出（keychain/GCM 服务
  常驻），因此健康探测采用 CDP 管道；真实逐帧渲染由 BM-16 接入上游引擎（引擎配置
  `chromePath` + `expectedChromiumMajor` 显式传入，本任务的 major 声明即其单一来源）。
- 上游引擎的 `PRODUCER_HEADLESS_SHELL_PATH`/`HYPERFRAMES_BROWSER_PATH`/家目录缓存
  fallback 属于上游进程内逻辑；本任务从进程边界禁用（环境不传播 + 显式 chromePath），
  BM-16 打包时需复核上游进程内仍不可达这些 fallback。

## 清理

- 每个 RenderJob 临时目录（`automation-tool-renderjob-<jobId>-*`）在 finally 中删除，
  测试与验收结束后断言系统临时目录无该前缀残留。
- 无头浏览器为 Worker 的 detached 自有进程树：POSIX 正常路径 `Browser.close` 退出，
  超时路径 SIGKILL 进程组；Windows 在 `Browser.close` CDP 应答后用绝对
  `taskkill.exe /T /F` 收走仍持有管道的整树，超时也走同一清理入口。Worker 停止时
  既有 `ManagedProcessTree` 再提供外层兜底；验收按暂存绝对路径扫描进程并断言零残留。
- 暂存目录位于 `.local/embedded-browser-video-studio/ebvs-bm03-<pid>/`，验收结束整体
  删除；仓库不提交浏览器二进制；测试全部使用无头模式，不弹窗口。
