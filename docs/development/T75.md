## 结论

多个 PyInstaller 调用使用 `capture_output=True`，失败时却丢弃 stdout/stderr，使构建机只有
退出码而没有原因。原提交让 E4-07、E4-09、E4-10 和 Windows candidate 都在异常中保留两个
流各自最后 20 行；空输出使用固定诊断，避免又回到沉默失败。

## RED

实际失败测试要求异常必须包含：

- `PyInstaller stdout: missing hidden import`
- `PyInstaller stderr: build traceback`

修复前两段都不在异常里，测试准确失败。

## GREEN

- `scripts/test_run_e4_07_acceptance.py` 的
  `BuildSignedExecutorTests.test_pyinstaller_failure_preserves_builder_output`；
- `backend/tests/unit/executor/test_windows_candidate.py::test_a_failed_pyinstaller_run_carries_its_own_reason`；
- `scripts/test_run_e4_07_acceptance.py` 的
  `BuildSignedExecutorTests.test_pyinstaller_failure_keeps_only_twenty_tail_lines_per_stream`
  覆盖每流只保留 20 行；
- E4-09 进程树探针和 E4-10 诊断探针也覆盖输出保留；
- 空 stdout/stderr 使用封闭占位，不抛二次错误。

## 失败矩阵

| 场景 | 结果 |
| --- | --- |
| stdout 有信息、stderr 为空 | 分别显示真实 tail 与固定空诊断 |
| stderr 有 traceback | 保留最后 20 行 |
| 两个流都很长 | 各自独立限界，不把整份日志塞进错误 |
| Windows builder 返回非 UTF-8 bytes | `_builder_output()` 以 UTF-8 replacement 有界转换 |
| E4-07/E4-09/E4-10 的 `text=True` 解码失败 | 本提交未覆盖；仍由 Python 子进程文本解码边界决定 |
| PyInstaller 成功 | 不改变成功控制流 |
| 构建失败发生在正式构建机 | 能看到 builder 原因；本任务未故意破坏真实候选构建做现场演示 |

## 真实边界

测试通过受控失败的真实 `subprocess` 结果验证错误文本，不是仅 grep 源码；但没有在正式签名
候选构建上故意制造失败。该任务只改善诊断，不把构建失败改为成功。

## 清理

受控测试使用临时输出；没有保留失败构建目录或敏感路径。

## 文档与遗留

原提交同时审计了同型调用点。以后新增 `capture_output=True` 的构建调用时，必须明确失败分支
如何处理两个流，不能依赖本任务自动覆盖未来文件。
