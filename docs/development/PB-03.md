  - 幂等准备：每个 PublishJob 一条持久意图，含规范化请求摘要（digest v1：素材

    是否带封面）；同意图重复准备返回 `replayed=true`，意图变化 fail closed 拒绝；
  - 上传编排：init（按 100MiB 阈值判定 utype 0/1）→ 复用 PB-02 `plan_upload_parts`
    的 8MiB 分片计划 → 分片上传（每片完成即持久记录，重启后跳过已完成分片续传）

  - 封面上传：jpeg/jpg/png、≤5MiB、只接受平台返回的 https 地址并持久；
  - 「幂等准备后只创建一次」：创建稿件前必须处于 `video_uploaded`（含封面就位），
    `begin_archive_creation` 原子单次准入进入 `dispatched`；成功记录 `resource_id`
    进入 `submitted`；平台明确拒绝按错误码分类进入 `failed`；断网/超时/响应不可
    解析进入 `outcome_uncertain` 且永不自动重发；重启后遗留 `dispatched` 同样只报
    结果不确定、不重发（留待 PB-04 对账）；已 `submitted` 的重复调用返回回执重放；
  - access_token 过期在 init/封面步骤刷新一次后重试一次，仍失败即定性失败；
    token 一律不落任何持久存储。

## 存储边界决策

resource_id、稿件请求摘要、分片进度等持久状态放在 **Control Plane PostgreSQL**，
不放本机 Executor SQLite，理由：

- 专项 2.7 节将 B站定义为“当前正式开放的视频投稿 API + 服务端上传”路径，与抖音
  Browser Use（本机浏览器副作用，A7-07 Executor 账本边界）不同：B站调用是纯出站
  HTTPS，不依赖浏览器、运营 Profile 或平台 Cookie，不落入 §4.3 Executor 专属边界；
- PB-01（PublishJob 状态机）与 PB-02（契约与解析器）都在 Control Plane domain，
  Executor 包声明只依赖 shared protocol，无法复用 PB-02 契约模块；
- 后端架构文档明确“Control Plane 保存业务状态和稳定 ID，不保存用户本机路径或
  第三方明文密钥”：resource_id/请求摘要/阶段正是 PB-04 对账与重启恢复的业务权威
  状态；本实现不持久 access/refresh token、不记录本机路径（素材经受控根目录端口
  抽象）；
- A7-07 本机账本模型是抖音动作专用封闭校验（platform == "douyin"），本任务复用其
  prepared/dispatched/verified(submitted)/uncertain 语义而非其存储；
- `upload_token` 是短期上传会话句柄（无账号权限，脱离签名凭据无用），为满足
  “断点续传跨重启”必须持久，故入库但不进入日志与错误响应；access_token、
  refresh_token、app_secret 一律不持久。
