## 0. 一句话结论

新增 `voiceover.py`：把一段旁白合成为音频、落进 RenderJob 工作区、用渲染链路那把 `ffprobe`
量出真实秒数。真实端到端跑通，三段旁白 2.080s / 7.120s / 4.320s。

## 1. 为什么时长必须量而不能算

镜头时长是 `max(旁白, 动效)`（P0-1d），所以时间轴在拿到旁白真实长度之前排不出来——
**而网关不返回时长**。实测（真实服务，背靠背三段）：

```
10 字 → 2.160s     35 字 → 6.080s     72 字 → 14.000s
```

约每字 0.19 秒，够线性，**可以当预算交给模型**让它写得大致合身；但远不够精确到能拿来排时间轴。

## 2. 接口形态：三件实测出来的事

**一、TTS 不在 OpenAI 兼容端点上。**

```
POST https://dashscope.aliyuncs.com/compatible-mode/v1/audio/speech  → HTTP 404
```

所以这条走 DashScope 原生的 `/services/aigc/multimodal-generation/generation`。因此
`bailian-model-catalog.v1.json` 里的 `voiceover` 用途**自带 `base_url` 与 `api_mode`**，
不继承目录顶层那个 OpenAI 兼容地址。

**二、返回的不是字节，是一条有签名、会过期的对象存储链接。**

```json
{"output": {"audio": {"data": "", "expires_at": 1785234388,
  "url": "http://dashscope-a717.oss-cn-beijing.aliyuncs.com/...wav?Expires=...&Signature=..."}},
 "usage": {"characters": 34}}
```

**三、那条链接是明文 `http://`，但同一个 host 用 https 取同一个对象是通的**（也是实测的：
同一次请求把 scheme 换成 https 后拉到 38,444 字节）。所以实现里**先升级 scheme 再取**，
而不是把音频裸着拉下来。

## 3. 这是编排路径上唯一一处「去取远端服务指定的 URL」

所以它按闭集处理，而不是拿到什么取什么：

- 只接受 `http` / `https`，其余（`file:`、`ftp:`、`data:`、scheme-relative 的 `//host/path`）一律拒绝；
- host 必须落在**契约里声明的后缀**内（`audio_host_suffixes: [".aliyuncs.com"]`），
  声明位置就在 endpoint 旁边，不是代码里的字面量；
- 后缀匹配按标签边界判，这正是 `x.aliyuncs.com` 与仿冒的 `aliyuncs.com.evil.example` 的区别；
- 单段音频有字节上限（32 MiB），一个错误的回答不能在别的环节察觉之前把用户磁盘写满。

## 6. 真实端到端验收

真配置（从真实 secret 与契约装配）→ 真网关 → https 升级后真下载 → 真 `ffprobe` →
文件落在 `AuthoringWorkspace` 内：

```
配置：qwen3-tts-instruct-flash-2026-01-26｜voice=Cherry｜host 允许 ('.aliyuncs.com',)

beat-1 10 字 →  2.080s ｜   99,884 B ｜ 合成 1.1s ｜ sha256 a92856cf0d9a2fd4… ｜ 每字 0.208s
beat-2 35 字 →  7.120s ｜  341,804 B ｜ 合成 2.2s ｜ sha256 2928acd060646a1a… ｜ 每字 0.203s
beat-3 22 字 →  4.320s ｜  207,404 B ｜ 合成 1.8s ｜ sha256 b29183fa01cb4ccb… ｜ 每字 0.196s

三段合计 13.520s
工作区内文件: ['audio/beat-1.wav', 'audio/beat-2.wav', 'audio/beat-3.wav']
```

音频格式 `pcm_s16le / 24000 Hz / 单声道`。合成本身很快（1～2 秒），发生在渲染之前，
不占渲染预算。

## 7. 失败矩阵

| 情况 | 期望 | 覆盖 |
| --- | --- | --- |
| 网关地址不是 https | 拒绝 | 单测 |
| API key 形状不对 / 出现在 `repr` 里 | 拒绝 / 不出现 | 单测 |
| 音频 URL 是 `file:` `ftp:` `data:` 或 `//host/path` | 拒绝 | 单测 |
| 音频 URL host 是 `evil.example` 或 `aliyuncs.com.evil.example` | 拒绝 | 单测 |
| 音频 URL 是明文 http | 升级为 https 后再取 | 单测断言实际取用的是 https |
| 回答里没有 `output.audio.url`，或它不是字符串 | 拒绝 | 单测（四种残缺形状） |
| 音频超过字节预算 | 拒绝 | 单测 |
| 旁白为空 / 全空白 | 在任何网络调用之前拒绝 | 单测（并断言没有发生 fetch） |
| 写入路径逃逸工作区 | 拒绝 | 单测 |
| 网关超时 vs 传输失败 | 两种不同的拒绝原因 | 实现区分（同 `call_video_creation_model` 的既有做法） |
| `ffprobe` 读不出时长 | 拒绝 | 实现 fail closed |

## 8. 两处刻意的选择

**一、时长问 `ffprobe`，不解析 WAV 头。** 自己解析头更快也无依赖，但那会是**第二个关于
「这段音频多长」的意见**，而最终把音频混进片子的是 ffmpeg。两者一旦不一致，表现就是旁白
越过镜头边界而没有任何报错。所以只留一个来源。

**二、`AuthoringWorkspace` 的包含性检查抽成 `_write`，`write_text` 与新增的 `write_bytes`
共用。** 文本与音频只差最后一句写盘，把路径校验、软链拒绝、回滚各复制一份，等于让「字节
可以落在哪里」这条规则有两个副本。

## 9. 没做什么

- **没有接进出片链路。** 现在没有任何调用方；把旁白接进分镜、按 `max(旁白, 动效)` 排时间轴
  是 PC-08，混进成片是 PC-06；
- **没有把「每字 0.2 秒」写进提示词。** 那是 PC-08 决定预算形态时的输入，此处只留实测值；
- **没有验证「同一句话分段不同语气」。** `instruct` 档留了这个门，但它不阻塞 MVP，归后续。

## 10. 清理

验收用的工作区是 `TemporaryDirectory`，退出即删。无后台进程、无本地服务。
本任务产生真实调用费用（`usage.characters` 三段合计 134 字符）。
