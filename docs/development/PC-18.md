## 0. 这个任务是从哪冒出来的

台账里 PC-05、PC-06、PC-08、PC-09、PC-12 五条的「剩」字后面写的都是同一句话：**产品入口调用**。分段渲染的每一层都做完了——单零件渲染、拼接判定、时间轴、片长解除、第二批槽位——而 Rust 侧那条正式链路一次都没调用过它们。这不是五个任务各自的尾巴，是它们共用的一段缺口，所以单开一项。

## 1. 先发现的是：main 上这条路今天是断的

`975f867` 之后 Python 每次应答都带 `segments` 字段：

```python
# backend/src/automation_tool/executor/motion_authoring/entry.py
"segments": [segment.to_payload() for segment in submission.segments],
```

而 Rust 侧的应答结构体带 `deny_unknown_fields`：

```rust
#[serde(rename_all = "camelCase", deny_unknown_fields)]
struct AuthoredCompositionAnswer { … }   // 没有 segments
```

**也就是说「一句话生成视频」从那次提交起就 100% 失败**，报 `authoring_answer_invalid`。两侧各自的测试都是绿的，因为没有一条测试拿 Python 真正产出的那份文档去喂 Rust。这是本轮第一条 RED，也是接线这件事本身的理由。

## 2. RED → GREEN

### 2.1 应答带 segments（`motion_authoring_runtime.rs`）

RED：新增 `an_authored_answer_carries_the_segments_the_film_is_made_of`，构造 Python 实际产出的形状（模板段 640×360 dsf=2 / 90 帧 + 零件段 1920×1080 dsf=1 / 144 帧）。首跑编译失败——`PreparedMotionRenderJob` 没有 `segments()` 也没有 `film_frame_count()`。

GREEN：`AuthoredCompositionAnswer` 增 `segments`（**必填不是可选**——可选加回退就是 PC-04 那种「模型选了、没人用」的沉默），逐段校验：

| 校验 | 交给谁判 |
| --- | --- |
| 入口与每个资产是工作区内的真实文件 | `workspace_relative_file`，与顶层资产同一条 |
| 模板段必须带动画运行时 | 本函数（脚本没到会画出第一帧然后定住，其余信号全绿） |
| 画布合法 | `VideoWorkerRenderCanvas::new`，不在这里重抄 320/2560/3686400 |
| 单段帧数 ≤ 600 | `SANDBOX_FRAMES_MAXIMUM` |

八条篡改用例全部要求 `AuthoringAnswerInvalid`。

**成片帧数刻意不等于 `durationSeconds × fps`**：镜头长度 = `max(说完, 播完)`，片长 = Σ 镜头（产品负责人 2026-07-27 的更正），所以用户给的时长是引导分镜的、不是裁片子的。`film_frame_count()` 与 `frame_count()` 因此是两个数，测试里写死 `90 + 144 = 234` 把这件事钉住。

### 2.2 请求带 `catalogRoot`

RED：`the_authoring_request_tells_the_child_where_the_packaged_parts_are` 引用不存在的 `motion_authoring_request` 与 `MOTION_CATALOG_DIRECTORY`，编译失败。

GREEN：请求构造抽成可测函数，目录名 `motion-catalog` 从 `release-package-resources.v1.json` 的 `catalog` 资源读，测试断言两者相等。**这是 PC-04 那条沉默的最后一段**：零件 PC-16 装进包了、每个 beat 有 `catalogParts` 了，中间这个请求却从没告诉子进程零件在哪，于是子进程的目录恒为空、每个选了零件的 beat 都被拒、片子回落到唯一那个内置合成。

### 2.3 逐段渲染与拼接

`run_motion_render_job` 从「一次渲染 → 一次编码」改成按镜头循环：

```
for 每个镜头:
    查取消 → 进度(5..85 按镜头均分) → 清空 frames/ → 在镜头自己声明的舞台上渲
    → 查取消 → 静帧闸 → 编码到 segments/segment-NNN.mp4（编码时归一到成片画布）
拼接 → 复量 → 导入产物
```

三处设计决定，都有理由：

- **不改 Node worker。** 它的帧目录 `frames` 是常量，N 段会互相覆盖；「渲一段就立刻编码掉再清空」绕开了它，不必给 worker 加输出目录参数。
- **归一放在编码那一步，不是拼接那一步。** 因为 Rust 是从 PNG 帧编码而不是重编码成品 mp4，多带一个 `-vf` 是免费的，于是拼接永远是纯 `-c copy`，不需要再调和任何东西。
- **静帧闸按镜头问，不按整片问。** 九个镜头里有一个没动，出来的片子和整片没动一样是废的，而九选一比一选一容易发生九倍。

## 3. 一个我设计错了、被测试当场抓住的地方

原设计是：**只在拼完之后量成片**。写完 `a_join_that_exits_zero_is_still_refused_when_the_film_is_not_what_was_asked_for`（1920×1080 接 1080×1920，故意不归一）跑，**这条测试是绿的** —— 因为拼出来的坏文件量出来全对：

```
ffprobe -count_frames 拼接产物（未做拼前检查时）
  width=1920  height=1080  avg_frame_rate=30/1  pix_fmt=yuv420p  nb_read_frames=45
期望             1920            1080                30              yuv420p            45
```

**我要检查的每一项它都对。** 坏在像素里：后半段是竖屏内容装在横屏容器里。

所以防线必须在**拼之前**逐段探形状，拼后复量是另一件事——它抓的是「少了一段」「帧数不够」，抓不了这个。两半防的东西不一样，缺一个都不行。这段经过写进了 `join_motion_film` 的注释，连同「早期版本只检查产物、那条测试是绿的」这个事实。

## 4. 新增契约字段

`motion-render-canvas.v1.json` 加 `film` 段：成片画布 `16:9 → 1920×1080`、`9:16 → 1080×1920`、30fps、`yuv420p`，以及「按比例缩放后补边、不拉伸」和 `setsar=1` 的理由。两个画幅取自 `motion-one-sentence-brief.v1.json` 提供的那两个，第三个要加就得两边一起加，否则界面会接受一个交付不出来的 brief。

## 5. 顺手修的两处（本轮第二条重要发现）

`scripts/test_motion_authoring_agent.py` **在我动手之前就是红的**：`git stash` 后在 `975f867` 上复跑，2 failures / 10 errors 逐字相同。

- **10 个 error** 全是同一句：`the storyboard names catalog parts but this installation carries no parts catalog`。默认测试 beat 写死 `catalog_parts: ["data-chart"]`，而这些测试的 agent 没有目录——于是十个考别的事（script 标签、预算、超时）的测试，全被一句正确的拒绝拦住。默认改成空数组（prompt 本来就写明可为空），naming a part 变成「以零件为主题时才做的事」。
- **2 个 failure** 更值得记：它们断言 `worker.mjs` 里有 `const RENDER_VIEWPORT_WIDTH = 640;`，而 PC-05 已经把视口改成随请求走、删掉了那对常量。同一时刻 `frontend/tests/motion-render-canvas-per-render.test.mjs` 断言的是**相反的事**——worker 不得保留自己的视口常量。**两道门禁对同一个文件说反话，其中一道红了很久没人看见**，因为这个文件是脚本、不在任何人跑的套件里。删掉过期的两条，保留只有这份契约能回答的那部分（`outputWidth == width × scale`），并写明检查搬去了哪。

同时补上 [T15] 点名的缺口：`NoPartsCatalogTests` 两条，分别钉住「点了零件却无目录 → 拒绝」和「没点零件 → 就是那一个模板段」。**做过突变检查**：把 `if named:` 改成 `if False:`，只有第一条转红，改回后 `git diff` 为空。

## 7. 失败矩阵

| 情形 | 处理 |
| --- | --- |
| 应答不带 `segments` | 拒绝，`AuthoringAnswerInvalid` |
| 段入口/资产指向工作区外或不存在 | 同上 |
| 模板段缺动画运行时 | 同上（否则出静止片，其余信号全绿） |
| 段画布超出沙箱单帧像素预算 | 同上，由 `VideoWorkerRenderCanvas` 判 |
| 单段帧数 0 或 > 600 | 同上 |
| 某一段渲染失败 | 整片失败 `RenderFailed`，已编码的段随工作区清理 |
| 某一段全是相同帧 | `StaticRender` |
| 渲染/编码中途取消 | 杀 ffmpeg、删半成品、终态 `Cancelled` |
| 段未归一到成片画布 | **拼接前拒绝**（拼后量不出来，见 3 节） |
| 成片帧数 ≠ Σ 段帧数 | 拼接后拒绝并删除产物 |
| 拼接产物形状不对 | 同上 |
