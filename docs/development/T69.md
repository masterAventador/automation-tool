## 结论

原 Tauri App 没有日志设施，现场故障没有任何可诊断信息。原提交增加固定事件白名单和
AppData 私有落盘：单文件 1 MiB、最多 8 个、保留 7 天；异步有界队列满时丢日志而不阻塞
业务。日志只记录固定事件和封闭字段，不写原始错误详情。

## RED

实现前，敏感输入进入落盘日志测试实际失败：

`sensitive error detail reached the desktop log: Cookie=session-cookie`

这条 RED 证明旧做法若直接记录错误对象会泄漏 Cookie，而不是只证明“没有日志文件”。

## GREEN

`app_logging.rs` 内 7 个测试覆盖：

- token/Cookie 错误详情不能落盘；
- 大小轮转、总文件数和 7 天保留；
- 任意任务状态文本不进入事件；
- 队列满时不等待；
- 日志目录/文件软链被拒绝且外部目标不受触碰；
- 目录和文件保持私有权限。

固定事件已接到 setup、Control Plane 请求失败、任务状态与 Executor/Sidecar 生命周期。
第二批最终 Rust 门禁记录为 420 项通过、12 项忽略。

## 失败矩阵

| 场景 | 结果 |
| --- | --- |
| 错误含 Cookie/Token/私有路径 | 只落固定安全事件，不落原文 |
| 日志写入过快、队列满 | 丢弃日志，不阻塞产品 |
| 单文件超过 1 MiB | 轮转 |
| 文件总数/保留期越界 | 维护时清理到上限 |
| 日志目录或文件被软链替换 | 拒绝且不触碰外部目标 |
| 日志目录不可写 | 初始化/记录失败保持有界，不改变业务控制流 |

## 真实边界

测试使用真实文件、权限、软链和轮转，不是内存 logger；但第二批没有保留一次正式 App
发生 Control Plane/Sidecar 故障后，从实际 AppData 导出安全日志的验收记录。因此代码层可用，
演示现场诊断价值尚待真实事故或故障注入证明。

## 清理

测试日志位于临时目录并被回收；没有读取用户日志或泄漏敏感样本。
