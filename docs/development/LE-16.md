## 开工前【先定】

### T1 模型协议、输入与排序

1. 复用 `contracts/video/bailian-model-catalog.v1.json` 的 `script` 文本用途、固定 HTTPS
   端点和既有密钥来源，不新增第二份模型目录。供应商无关的
   `SemanticMatchingAdapter` 只接收句子、候选证据和请求级 Options；百炼请求/响应形状
   只存在于百炼 Adapter。
2. 输入脚本必须是完整的 `ScriptSegmentationResult`；候选必须是 `Material` 中可提供
   画面的 VIDEO/IMAGE，且已有非空 `ai_description`。AUDIO、重复 MaterialId、空候选或
   未理解素材全部在付费调用前拒绝，绝不静默过滤。
3. 模型只看到本地生成的 `m0001..mNNNN` 临时候选键、句子 sequence/text、素材描述与
   标签；`has_speech=true` 时必须把完整 `speech_transcript` 一并放入匹配依据，
   `has_speech=false` 时不制造 transcript 字段。模型看不到 MaterialId、摘要、尺寸、
   响度、时长、路径、浏览器或发布平台信息。
4. 首期最多一次匹配 32 条素材。为完整消费 LE-15 合法的 128 句，句子按固定 16 条一批
   请求；每批都含全部候选，最后在本地合并为完整矩阵。请求 JSON 最多 2 MiB，超过即在
   首次付费调用前整体拒绝，不截断描述或转写；模型响应与结构化正文继续使用硬上限。
5. 模型必须为本批每个 `sentenceSequence × candidateKey` 恰好返回一个整数分数
   `0..100`；缺项、重复、未知键/句号、额外字段、布尔冒充整数、非 `stop`、拒答、超时
   和畸形 JSON 都转换成固定、无异常链的
   `SemanticMatchingRejected("semantic matching request rejected")`，且不自动重试。
6. 模型不返回赢家。每句结果由本地按“分数降序、素材输入顺序升序”排列；首期相关阈值
   定为 `60`，`score >= 60` 才合格。T1 保留完整分数矩阵；T4 再决定没有合格候选时的
   产品结果。
7. `enable_thinking` 是请求级布尔配置，默认精确为 `false`，每个批次都显式发送；
   LE-24 后续只负责把同一用户总开关传入，不改协议。配置和 Adapter 的 `repr` 不得含
   API Key。

### T2 片段边界与 LE-07 截断事实

1. 视频的 `Material.duration_ms` 只代表容器头声明，不证明该时刻有可解码帧。选片器在
   造草稿前必须消费执行器对当前已批准源文件给出的“实际可解码区间”证据；不得用
   `duration_ms`、文件大小或失败码推断帧完备，也不得把验证结果回写成伪造素材时长。
2. 镜头候选区间由 `shot_boundaries_ms` 与实际可解码区间求交；没有镜头边界时只使用
   已验证区间。视频的 `source_out_ms - source_in_ms` 必须精确等于旁白占位时长，
   继续服从 LE-03 的不变速约束；静态图片没有源时间轴，可占任意合法旁白时长。
3. 片段选择只在语义合格且足够长的候选中进行：先按 T1 排名，再选能完整容纳占位时长
   的最早镜头区间；同分、同素材、同镜头都以输入和时间顺序稳定决胜，不再发模型请求。

### T3 有人声素材

1. 文案句子只分配给 `has_speech=false` 的素材；有人声素材不会消耗句子、不会排 TTS
   narration，也不会与无人声素材竞争句子槽位。
2. 每条有人声视频按素材输入顺序独立占段。取片范围覆盖它的主体
   `speech_segments_ms`，时长由原声区间决定；排同源 ambient 原声与
   `speech_transcript` 字幕。首期不做说话人分离。
3. 全部素材均有人声是合法的纯原声成片：忽略未使用的文案/TTS 结果，不因“没有句子
   分配”报错。纯无人声则自然退化为纯 TTS 旁白成片。

### T4 四类产品行为

| 场景 | 【先定】行为 |
| --- | --- |
| 无人声素材数量少于待分配句子 | 不复用同一素材，不产部分草稿；返回 `INSUFFICIENT_MATERIALS` |
| 有候选但实际可解码区间都短于对应占位时长 | 尝试下一名合格素材；全失败后返回 `SOURCE_TOO_SHORT` |
| 某句全部分数低于 60 | 不以最高低分硬配；返回 `NO_RELEVANT_MATERIAL` |
| 全部素材均有人声 | 成功产出纯原声草稿，不调用 TTS、不返回错误 |

固定产品失败结果不得携带文案、转写、MaterialId、模型请求 ID 或本机路径；同一次生成
全有或全无，不留下半份 Timeline。

### T5 Timeline 草稿

1. Visual 轨从 0 开始连续相接并精确结束于 Timeline.duration；首期不自动加转场。
2. 无人声段的 visual、narration、caption 三者起点与时长完全一致；有人声段的 visual、
   ambient、caption 三者按原声区间一致，且没有 narration clip。
3. 所有视频 clip 都携带等长 source in/out；图片 clip 不携带 source window。生成结果
   必须直接通过 `TimelineClip`、`TimelineTrack`、`Timeline` 构造器，不复制或绕开领域
   校验。

## T1 RED 目标

1. 百炼实现满足供应商无关协议，默认/开启 thinking 均精确进入请求，密钥不进 repr；
2. 请求只含临时候选键、句子、描述/标签和有声素材转写，不含领域身份与私有元数据；
3. 16 句固定分批仍合并出完整矩阵，每个句子 × 素材组合恰好一项；
4. 本地按分数和素材输入顺序稳定排序，`60` 分含边界、`59` 分不含；
5. AUDIO、重复素材、缺描述、超数量/请求预算在首次付费调用前拒绝；
6. 未知/缺失/重复矩阵项、越界/伪整数分数、超时/拒答/非 stop 只产生固定无泄漏异常。

首次运行聚焦测试必须因 `automation_tool.executor.semantic_matching` 不存在而在收集期
失败；确认 RED 后才允许创建生产模块。
