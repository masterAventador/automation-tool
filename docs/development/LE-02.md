## 不变式清单（`Material.__post_init__` 与两个演进方法共同守住）

1. `material_id`/`kind` 必须是各自的枚举/标识类型；`width`/`height` 落在
   `[1, MAX_MATERIAL_DIMENSION]`。
2. `content_digest` 固定 64 位小写十六进制（sha256 格式约束；"同摘要素材是否已
   存在"的去重判断需要查询已有素材集合，属于仓储职责，归 LE-05，见「真实边界」）。
3. `duration_ms`：`IMAGE` 必须为 `None`；`VIDEO`/`AUDIO` 必须落在
   `[1, MAX_MATERIAL_DURATION_MS]`。
4. `has_audio=False` ⟹ `audio_loudness_lufs is None` 且 `has_speech is False`；
   `IMAGE` 一律不得 `has_audio=True`。
5. `has_speech=False` ⟹ `speech_segments_ms == ()` 且 `speech_transcript is None`；
   `has_speech=True` ⟹ 区间非空、每个区间有序不倒置、互不重叠、且不超过
   `duration_ms`。
6. `shot_boundaries_ms` 严格递增、落在 `[0, duration_ms)`；`IMAGE` 不得携带。
7. `ai_tags` 去重、单条不超过 `MAX_TAG_CHARACTERS`、总数不超过 `MAX_TAGS`；
   `ai_description` 非空时不超过 `MAX_DESCRIPTION_CHARACTERS`。
8. `description_source` 与 `described_at` 耦合：`AI` 且有描述时必须带时间戳；
   `USER` 时必须不带时间戳（AI 生成时间对用户写的文本没有意义）。
9. `with_ai_description`：`description_source is USER` 时原样返回 `self`（用户
   改过的描述不被 AI 覆盖，见「真实边界」对这条不变式的强制范围说明）；否则写入
   新描述、新标签、新时间戳，来源标记为 `AI`。
10. `with_user_description`：写入新描述，清空 `ai_tags`，来源永久切换为
    `USER`（终态，`with_ai_description` 此后原样返回 `self`）。

## 失败矩阵

- **类型错误当运行时异常**：任何字段类型或取值不对，`__post_init__` 统一走
  `_reject()` 抛 `InvalidMaterialModel`（`ValueError` 子类），不允许构造出半有效
  对象。
- **交叉字段被绕过**：`has_audio`/`has_speech`/`speech_segments_ms`/
  `speech_transcript` 四个字段互相依赖，任何一个单独校验都无法堵住越界组合
  （例如 `9f975c4` 修复的图片携带人声区间的漏洞）；已按四个字段联合校验并各自
  补测试用例覆盖两个方向。
- **描述保护被绕过（已知边界，未在本任务内堵住）**：`with_ai_description` 只挡住
  走这个方法的调用方；`dataclasses.replace()`（`material.py` 内部已在用来实现
  两个演进方法）与直接构造 `Material(...)` 都能绕过它到达"AI 覆盖了用户描述"这个
  应被禁止的状态。这是"转换不变式无法由单快照构造校验表达"的结构性限制——
  `__post_init__` 只能看到一次构造的快照，看不到"上一个状态的 `description_source`
  是不是 `USER`"。已把结构性边界测试登记进 `docs/local-video-editing-roadmap.md`
  的 LE-05 行（仿 `backend/tests/unit/executor/test_shipped_package_boundary.py`
  的 AST 检查思路，禁止 `material.py` 之外的模块调用 `replace(` 于 `Material` 或
  直接构造它），归属 LE-05 而非本任务，见下方「真实边界」。

## 真实边界

1. **领域层无 I/O**：`material.py` 不导入任何网络、文件系统、数据库或子进程相关
   模块（`import re` / `unicodedata` / `dataclasses` / `datetime` / `enum` /
   `typing` 之外只依赖同目录的 `resource_ids`）；探测（ffprobe/silencedetect）、
   理解（多模态模型调用）、转写（ASR）都在 LE-07/LE-13/LE-14 的执行器/AI 编排层
   发生，`Material` 只表达这些结果，不产生这些结果。字段间的交叉依赖直接来自
   设计文档描述的三级漏斗结构（`silencedetect` 判有无声音 → Silero VAD 判是
   人声还是环境音 → 仅对人声素材调 ASR 转写）：`has_audio` 是第一级的产物，
   `has_speech`/`speech_segments_ms` 是第二级的产物，`speech_transcript` 是
   第三级的产物；下游没有产出就不可能有上游没有的东西，所以校验方向固定是
   "没有的东西不能带，有的东西必须配齐"，而不是任意组合。
2. **描述保护只在方法层面成立，不在类型层面成立**：见上方「失败矩阵」。
   `with_ai_description` 是当前代码库里从素材理解管线（LE-13）产出结果写回
   `Material` 的唯一预期入口，只要 LE-13 及后续所有调用方都走这个方法，保护就
   成立；但类型系统本身不阻止绕过——`replace(material, description_source=...)`
   或重新 `Material(...)` 都不会触发 `with_ai_description` 里的判断。这不是本
   任务遗漏，而是不变式的性质决定的：它是"跨两个快照的转换规则"（新状态是否
   由旧状态的 USER 标记允许），`__post_init__` 只能校验单个快照内部的字段一致性，
   校验不了"这次构造相对上一次构造是否合法"。真正堵住绕过需要结构性约束（禁止
   在 `material.py` 之外调用 `replace(` 于 `Material` 或直接构造它），这类检查
   需要 AST 扫描整个代码库，其正确的落脚点是仓储层收口时——`docs/local-video-editing-roadmap.md`
   的 LE-05 行已经登记这项要求，本任务不越界代做。
3. **去重只做格式约束，不做存在性判断**：`content_digest` 的 sha256 格式校验
   在类型层面完成；"这个摘要对应的素材是否已经在库里"需要查询已导入素材集合，
   领域对象不持有集合、也不该为了去重去认识仓储，这部分留给 LE-05 的仓储实现。
4. **`speech_transcript`/`has_speech` 当前只覆盖 LE-02 定义的字段本身**：转写
   内容的语言检测、说话人分离等能力不在 `Material` 的字段范围内（`docs/local-video-editing-roadmap.md`
   §6 首期不做已登记"说话人分离"）。
