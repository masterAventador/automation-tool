## 不变式清单（`Material.__post_init__` 与两个演进方法共同守住）

1. `material_id`/`kind` 必须是各自的枚举/标识类型；`width`/`height` 落在
   `[1, MAX_MATERIAL_DIMENSION]`。
2. `content_digest` 固定 64 位小写十六进制（sha256 格式约束；"同摘要素材是否已
   存在"的去重判断需要查询已有素材集合，属于仓储职责，归 LE-05，见「真实边界」）。
3. `duration_ms`：`IMAGE` 必须为 `None`；`VIDEO`/`AUDIO` 必须落在
   `[1, MAX_MATERIAL_DURATION_MS]`。
4. `has_audio=False` ⟹ `audio_loudness_lufs is None` 且 `has_speech is False`；
   `IMAGE` 一律不得 `has_audio=True`；`AUDIO` 一律必须 `has_audio=True`（对称
   规则，Finding 1 补上——此前只有 `IMAGE ⟹ not has_audio`，没有
   `AUDIO ⟹ has_audio`，能构造出"没有声音的音频素材"）。
5. `has_speech=False` ⟹ `speech_segments_ms == ()` 且 `speech_transcript is None`；
   `has_speech=True` ⟹ 区间非空、每个区间有序不倒置、互不重叠、且不超过
   `duration_ms`。
6. `shot_boundaries_ms` 严格递增、落在 `[0, duration_ms)`；`IMAGE` 与 `AUDIO`
   均不得携带（Finding 1 补上 `AUDIO` 这一支——`_validate_shot_boundaries` 此前
   只按 `duration_ms is not None` 放行，而 `AUDIO` 恰好满足这个条件，能构造出
   "带镜头切点的音频素材"）。
7. `ai_tags` 去重、单条不超过 `MAX_TAG_CHARACTERS`、总数不超过 `MAX_TAGS`；
   `ai_description` 非空时不超过 `MAX_DESCRIPTION_CHARACTERS`。
8. `description_source` 与 `described_at` 耦合：`AI` 且有描述时必须带时间戳；
   `USER` 时必须不带时间戳（AI 生成时间对用户写的文本没有意义）。`USER` 还必须
   同时满足 `ai_description is not None`（Finding 2 补上——否则构造出一个没有
   任何描述、又因为来源已经是 `USER` 而永远不会被 `with_ai_description` 写入的
   死胡同实例）且 `ai_tags == ()`（Finding 3 补上——`USER` 来源携带 AI 标签与
   `with_user_description` 会清空旧标签这条既有行为自相矛盾，见不变式 10）。
9. `with_ai_description`：`description_source is USER` 时原样返回 `self`（用户
   改过的描述不被 AI 覆盖，见「真实边界」对这条不变式的强制范围说明）；否则写入
   新描述、新标签、新时间戳，来源标记为 `AI`。
10. `with_user_description`：写入新描述，清空 `ai_tags`，来源永久切换为
    `USER`（终态，`with_ai_description` 此后原样返回 `self`）。

## 失败矩阵

- **类型错误当运行时异常**：任何字段类型或取值不对，`__post_init__` 统一走
  `_reject()` 抛 `InvalidMaterialModel`（`ValueError` 子类），不允许构造出半有效
  对象。
- **交叉字段被绕过**：`has_audio`/`has_speech`/`speech_segments_ms`/
  `speech_transcript` 四个字段互相依赖，任何一个单独校验都无法堵住越界组合
  （例如 `9f975c4` 修复的图片携带人声区间的漏洞）；已按四个字段联合校验并各自
  补测试用例覆盖两个方向。
- **`kind` 的规则只写了一半，没写对称的一半（终审发现，本轮已修）**：`IMAGE`
  的两条限制（`not has_audio`、不得携带镜头边界）最初是当特例写的，不是按"kind
  决定能力"的规则写的，导致后续几轮审查都没理由去看第三个枚举成员
  `MaterialKind.AUDIO`——它此前没有任何专属规则，能构造出"没有声音的音频素材"
  （`has_audio=False`）和"带镜头切点的音频素材"（`shot_boundaries_ms` 非空，
  因为 `_validate_shot_boundaries` 只按 `duration_ms is not None` 放行，
  `AUDIO` 恰好满足）。本轮补了对称规则 `AUDIO ⟹ has_audio=True` 与
  `AUDIO` 一律不得携带 `shot_boundaries_ms`，并新增 3 个直接构造 `AUDIO` 素材
  的测试（此前整个测试套件唯一提到 `AUDIO` 的地方只是检查枚举包含这个字符串，
  从未真正构造过一个 `AUDIO` 实例）。
- **描述保护被绕过——仅剩转换不变式这一半（本轮已缩小范围）**：`with_ai_description`
  只挡住走这个方法的调用方；`dataclasses.replace()`（`material.py` 内部已在用来
  实现两个演进方法）与直接构造 `Material(...)` 仍能绕过它到达"AI 覆盖了用户
  描述"这个应被禁止的状态。这是"转换不变式无法由单快照构造校验表达"的结构性
  限制——`__post_init__` 只能看到一次构造的快照，看不到"上一个状态的
  `description_source` 是不是 `USER`"，真正堵住它需要 AST 级别的结构性约束，
  已登记进 `docs/local-video-editing-roadmap.md` 的 LE-05 行，归属 LE-05。
  **这与本轮新补的两条规则是两类问题**：`USER` 来源必须带描述、`USER` 来源不得
  携带 `ai_tags`，这两条是**单个快照内部字段是否自洽**的问题（这个实例本身，
  不看它是怎么来的），`__post_init__` 完全有能力校验，本轮已经补上并测试覆盖，
  不需要也不应该推给 LE-05——上一轮把"USER 不得携带 `ai_tags`"一并推给 LE-05
  是过度扩大了范围，本轮已收回并直接实现。

## 真实边界

1. **领域层无 I/O**：`material.py` 不导入任何网络、文件系统、数据库或子进程相关
   模块（`import re` / `unicodedata` / `dataclasses` / `datetime` / `enum` /
   `typing` 之外只依赖同目录的 `resource_ids`）；探测（ffprobe/silencedetect）、
   理解（多模态模型调用）、转写（ASR）都在 LE-07/LE-13/LE-14 的执行器/AI 编排层
   发生，`Material` 只表达这些结果，不产生这些结果。字段间的交叉依赖直接来自
   设计文档描述的三级漏斗结构（`silencedetect` 判有无声音 → Silero VAD 判是
   人声还是环境音 → 仅对人声素材调 ASR 转写）：`has_audio` 是第一级的产物，
   `has_speech`/`speech_segments_ms` 是第二级的产物，`speech_transcript` 是
   第三级的产物；下游没有产出就不可能有上游没有的东西，所以校验方向固定是
   "没有的东西不能带，有的东西必须配齐"，而不是任意组合。
2. **描述保护——推给 LE-05 的只是转换不变式那一半，快照级的规则本任务已经堵上**：
   `with_ai_description` 拒绝覆盖用户描述这件事，只在"新状态是否由旧状态的
   `USER` 标记允许"这个**跨两个快照的转换规则**上留有绕过口子——
   `replace(material, description_source=...)` 或重新 `Material(...)`
   都不会触发 `with_ai_description` 里的判断，因为 `__post_init__` 只能看到
   一次构造的快照，看不到"上一个状态是什么"。这部分真正堵住需要结构性约束
   （禁止在 `material.py` 之外调用 `replace(` 于 `Material` 或直接构造它），
