# 客户演示前一天检查清单

> 状态：🚧 功能链路部分待补（一句话生成视频仍在接线，见 §7）
>
> 日期：2026-07-26
>

>
> 交付形态：客户自己装包 → 装到领导的 Mac（M4 Air / macOS 26 / 24G）→ 领导现场演示。

## 0. 这份清单不覆盖什么

先写这一节，是因为**一份清单最危险的时刻不是它漏掉了什么，是别人以为它覆盖了。**

- **不覆盖功能是否好用**，只覆盖"能不能跑起来、跑到哪一步会停"。渲染质量、文案质量、素材是否贴题，这份清单一律不判断；
- **不覆盖演示机上的真实渲染耗时**。M4 Air 比开发机慢多少，只有在演示机上实测才知道，§4.5 要求实测但不给期望值——**没有基线可比**；
- **不覆盖断网**。断网就是演示失败，没有降级路径（§2 只验通不通，验不出会不会中途断）；
- **不覆盖抖音平台侧的变化**。平台改版、风控、二维码过期都在这份清单之外，只能现场人工接管；
- **不覆盖"安全注销"**。它有已知缺陷（注销成功但界面报失败，5 次复现 4 次），**演示脚本必须绕开**，见 §8；
- **不覆盖客户自己那台机器**。清单假设演示只在领导那台 M4 Air 上进行；如果临时换机，整个 §4 和 §5 要重跑；
- **不是回归测试**。它不替代任何门禁，只回答"明天能不能演"。

## 1. 怎么读这份清单

每条格式固定：**命令或观察动作 → 期望结果 → 失败了怎么办**。

标注含义：

| 标注 | 含义 |
| --- | --- |
| `[本机]` | 在开发机上做就行，结论对演示机同样成立（例如包的签名判定，包是同一个文件） |
| `[演示机]` | **必须在领导那台 Mac 上做**，本机做了不算数（登录态、磁盘、网络、首次启动的 Gatekeeper 弹窗） |
| `[服务器]` | 在云端服务器上做 |

**顺序建议**：先跑 `[本机]` 和 `[服务器]`（发现问题还能改代码重出包），最后带包去 `[演示机]`。

## 2. 后端与网络

### 2.1 `[本机]` 云端后端活着 ✅ 已实测

```bash
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 10 https://at.xuanbai.tech/api/v1/health
```

**期望**：`200`。**2026-07-26 本机实测输出：`200`。**

**失败**：先 `[服务器]` 上看容器是否在跑；不是容器问题就是 DNS/证书。这条不过**演示直接取消**，没有本地降级。

### 2.2 `[本机]` 未认证请求被拒 ✅ 已实测

```bash
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 10 https://at.xuanbai.tech/api/v1/account-installations
```

**期望**：`401`。**2026-07-26 本机实测输出：`401`。**

**失败**：如果返回 `200`，裸露的匿名接口是安全问题，不是演示问题——**停下来报告，不要带着这个上演示**。
如果返回 `404`，是端点路径变了，不是服务坏了，先核对下面这张表。

**已实测可用的端点集**（都是实跑的，不是从代码推的）：

| 端点 | 期望 |
| --- | --- |
| `GET /api/v1/health` | 200 |
| `GET /api/v1/version` | 200（本机实测 200） |
| `GET /api/v1/account-installations` | 401（未认证） |
| `/api/v1/account-sessions` | 登录用 |
| `/api/v1/account-sessions/current` | 需认证 |
| `/api/v1/account-sessions/refresh` | 刷新 |

### 2.3 `[本机]` HTTP 被强制跳转、安全响应头齐全 ✅ 已实测

```bash
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 10 http://at.xuanbai.tech/api/v1/health
curl -sI --max-time 10 https://at.xuanbai.tech/api/v1/health | grep -iE 'strict-transport-security|x-content-type-options|x-frame-options'
```

**期望**：第一条 `308`；第二条三行齐全。**2026-07-26 本机实测输出：**

```text
308
strict-transport-security: max-age=31536000; includeSubDomains
x-content-type-options: nosniff
x-frame-options: DENY
```

**失败**：不影响演示能否进行，但要在演示前告知客户。不阻塞。

### 2.4 `[演示机]` 演示现场的网络能到后端

**在演示要用的那个网络下**（会场 WiFi / 手机热点，不是办公室网络）跑：

```bash
for i in 1 2 3 4 5; do curl -sS -o /dev/null -w '%{http_code} ' --max-time 10 https://at.xuanbai.tech/api/v1/health; done; echo
```

**期望**：`200 200 200 200 200`。**命令形式已在本机实测，输出正是这一行**；但网络不同，**这条仍必须在演示机、演示网络下重跑**。

**失败**：换网络。**如果只能用会场网络且不通，演示取消**——没有离线模式。

**这条是整份清单里最容易被跳过、也最容易翻车的一条**：办公室通不代表会场通。

## 3. 安装包与签名

以下把交付给客户的那个 DMG 记作 `$DMG`，装出来的 App 记作 `$APP`。先定位：

```bash
find .local -maxdepth 4 -name '*.dmg' -newermt '-3 days' 2>/dev/null
```

**必须确认这个 DMG 就是要发给客户的那一个**（同一次构建产出）。不确定就重出包——**验一个包、发另一个包，等于没验**。

### 3.1 `[本机]` 公证已装订

```bash
xcrun stapler validate "$DMG"
```

**期望**：`The validate action worked!`

**失败**：包没装订，客户机器在离线状态下会被 Gatekeeper 拦。重新走公证 + 装订。

### 3.2 `[本机]` 带 quarantine 标记的 Gatekeeper 判定

```bash
xattr -w com.apple.quarantine '0083;00000000;Safari;' "$DMG"   # 模拟客户下载
spctl -a -vvv -t open --context context:primary-signature "$DMG"
```

**期望**：`accepted`，且 `source=Notarized Developer ID`。

**失败**：客户双击会看到"无法打开，来自身份不明的开发者"。**这是最难现场补救的一类**——必须重新签名公证。

> **不要用 `xattr -d` 清掉标记再验**，那验的是本机特权路径，不是客户会走的路径。

### 3.3 `[本机]` 装出来的 App 本身通过校验

```bash
codesign --verify --deep --strict --verbose=2 "$APP"
spctl -a -vvv -t install "$APP"
```

**期望**：`satisfies its Designated Requirement`；`accepted / source=Notarized Developer ID`。

**失败**：同 3.2。

### 3.4 `[本机]` 包内没有测试痕迹

```bash
grep -rl 'TAURI_WEBDRIVER_PORT\|wdioTauri\|automation-tool-test-harness' "$APP" 2>/dev/null | head
```

**期望**：**无输出**。

**失败**：出厂包带调试端口是安全问题，重出包。

### 3.5 `[本机]` 包体大小符合预期

```bash
du -sh "$DMG" "$APP"
```

**期望**：DMG 约 510 MB 量级；`$APP` 展开后更大。**数字对不上（尤其明显偏小）就要查资源是否缺席**——三个视频运行时资源曾经整体缺失而所有门禁全绿。

**失败**：跑 `python3 scripts/check_release_package_wiring.py`，再看 `frontend/scripts/audit-production-package.mjs` 的结论。

## 4. 演示机环境

**本节全部 `[演示机]`，本机做了不算数。**

### 4.1 系统版本与芯片

```bash
sw_vers && uname -m
```

**期望**：macOS 26.x；`arm64`。

**失败**：如果是 Intel 机，包的架构必须重新确认——**本项目的 macOS 验收是分 arm64 / x86_64 两条线的**。

### 4.2 磁盘余量

```bash
df -h /
```

**期望**：**可用空间 ≥ 20 GB**。判据：包 510 MB，安装后还要装配内置 Chromium、媒体工具链和两个视频 Worker，加上渲染中间产物和成片。20 GB 是留了余量的保守线。

**失败**：清盘。**磁盘满会在渲染中途炸，是演示现场最难看的失败形态之一**（前面全绿、最后一步失败）。

### 4.3 首次启动的 Gatekeeper 观察

**动作**：双击 DMG → 拖进"应用程序" → **右键点"打开"**（不是双击）→ 观察弹窗。

**期望**：出现一次"macOS 已验证此 App 不含恶意软件"或直接启动；**不出现"无法打开、来自身份不明的开发者"**。

**失败**：回到 3.1/3.2。**这一步必须在演示前一天做掉，让 App 完成首次授权**——不要留到演示当天现场第一次打开。

### 4.4 App 能起来并停在工作台

**动作**：启动 App，观察主界面。

**期望**：看到 RPA 运营工作台（或产品账号登录页，取决于 Profile）。**不出现白屏、不出现"制作界面暂时不可用"**。

**失败**：查 App 数据目录是否可写（4.6），再看是否是内置 Chromium 装配缺失。

### 4.5 渲染耗时实测（**没有期望值，只记录**）

**动作**：按演示脚本完整跑一次视频制作，**用秒表记录从提交到成片的时间**。

**期望**：**无**。这台机器上没有基线，本条的目的是让演示者知道"这一步大概要等多久"，而不是判断快慢。

**把实测秒数写进演示脚本**，让演示者提前知道该在这里说什么话填时间。**演示最怕的不是慢，是演示者不知道要等多久而开始反复点击。**

**失败**（跑不完/报错）：这条属于功能链路，见 §7。

### 4.6 App 数据目录健康

```bash
ls -la ~/Library/Application\ Support/com.aventador.automationtool/
```

**期望**：目录存在且当前用户可写。

**失败**：权限问题，`chown` 回当前用户。

> ⚠️ **这个目录里有人工扫码得到的抖音凭据。任何情况下都不要删除它，也不要运行 `scripts/run_u9_06_acceptance.py`（它会清空该目录）。**

## 5. 账号与登录态

### 5.1 `[服务器]` 演示账号凭据在位

```bash
ssh <服务器> 'ls -l /etc/automation-tool-demo/secrets.json'
```

**期望**：文件存在，权限 `-rw-------`（0600）。

**失败**：重新下发凭据。

> **未实测。** 本机 `~/.ssh/config` 里有 `old` / `new` / `vpn` / `winbox` 四个别名，
> 而 `at.xuanbai.tech` 在本机解析到 `198.18.1.102`（VPN 改写过的地址），
> **无法据此判断是哪一台**。我没有去逐台试登录——朝生产机器盲试 SSH
> 不是排查手段。执行前请把 `<服务器>` 换成正确别名。

### 5.2 `[演示机]` 产品账号能登录

**动作**：在演示机 App 里用演示账号登录一次。

**期望**：登录成功并进入工作台；设备自动绑定当前账号，**不出现配对码、审批或轮询等待**。

**失败**：先跑 2.1 确认后端活着，再确认 App 的 `baseUrl` Profile 指向 `at.xuanbai.tech` 而不是 loopback。

### 5.3 `[演示机]` 抖音登录态（**最容易被漏掉的一条**）

**动作**：在演示机上打开需要抖音的功能，**人工扫码登录一次**，然后**关掉 App 再打开**，确认登录态还在。

**期望**：第二次打开不再要求扫码。

**失败**：重新扫码。

**为什么必须提前做**：演示机的数据目录与开发机隔离，**开发机上登录过不代表演示机登录过**。现场扫码要掏手机、要对二维码、二维码还会过期——**这是演示最容易翻车的一步，必须在前一天做掉。**

### 5.4 `[演示机]` 登录态在演示当天仍然有效

**动作**：演示当天开场前重跑一次 5.3 的"关掉再打开"观察。

**期望**：不要求扫码。

**失败**：现场重新扫码（留 5 分钟余量），或改用不需要抖音的演示路径。

## 8. 演示脚本禁区

**这些功能不要出现在演示脚本里：**

| 功能 | 原因 |
| --- | --- |
| **安全注销** | 已知缺陷：注销成功但界面报失败，5 次复现 4 次。**演示者会以为出错了。** |
| 背景音乐 | 当前版本不提供，界面已明确说明，但不要主动提起 |
| 任何需要断网恢复的演示 | 没有降级路径 |

**另外**：不要在演示中打开"完整制作界面"以外的上游界面入口。

### ⛔ 绝对不要在演示机上运行 `scripts/run_u9_06_acceptance.py`

**它会删掉整个 App 私有数据目录** `~/Library/Application Support/com.aventador.automationtool/`，
**包括前一天辛苦扫码登录的抖音凭据**。

后果很具体：演示当天早上有人抱着"我验证一下环境"的好意跑了它 → 抖音登录态没了 →
现场要掏手机、打开抖音、找到扫码入口、对准二维码，而**二维码还会过期**，
演示者不懂技术、大概率对着屏幕愣住。**清单里全绿过的那一条会在开场后当场失效。**

同理，**演示机上不要运行本仓库任何 `scripts/run_*_acceptance.py`**——
它们会起服务、建临时目录、动数据。演示机只用来演示，不用来验证。
要验证就在开发机上验。
