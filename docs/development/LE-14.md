## 范围

本任务在 Local Executor 建立三级漏斗：先消费 LE-07 已测得的有效声音事实，再用随包
Silero VAD 区分人声与环境音，只对判为人声的素材抽取音轨并调用百炼 ASR。最终产出
`has_speech`、`speech_segments_ms` 和 `speech_transcript`，写回既有 Material 字段。

本任务不重复运行 `silencedetect`，不做说话人分离，不把视频上传给 ASR，不实现有人声
素材的成片编排，也不引入本地 Whisper。

## T1 开工前【先定】

1. 第一级只消费 LE-07 `MaterialFacts.has_audio`，不从 `audio_codec`、响度、文件扩展名或
   是否存在音轨重新推断。`has_audio=False` 即使同时带有 `audio_codec`，也必须在加载
   VAD、抽音轨或调用 ASR 之前结束。
2. Executor 不依赖 Control Plane 领域对象。T1 定义供应商无关的
   `MaterialSpeechAnalysis`，字段形状与既有 Material 三个语音字段一致；无有效声音的唯一
   结果是 `has_speech=False`、空区间、无转写。
3. 二、三级先收敛在惰性的 `AudibleSpeechAnalyzerFactory` 与
   `AudibleSpeechAnalyzer` 协议后。只有 `has_audio=True` 才创建一次下级分析器并把同一份
   路径无关 `MaterialFacts` 交给它；T2/T3 再把真实 VAD、音轨抽取和 ASR 装进该实现，
   不为 T1 建测试专用生产分支。
4. T1 不接收源路径，也不发现模型、FFmpeg、环境变量或 PATH。这样无声音素材从类型上就
   无法触碰磁盘、VAD 模型和网络，路径窗口与随包装配留给真正拥有这些资源的后续层。
5. 输入不是精确 `MaterialFacts`、分析器不满足协议，或下级返回形状不合法时统一
   fail closed 为固定、路径无关的 `MaterialSpeechRejected`；不把下级异常、素材元数据或
   私有路径带进消息。

## T1 RED 目标

1. 带 AAC 音轨但 `has_audio=False` 的真实一级事实直接得到规范空结果，下级分析器零调用；
2. `has_audio=True` 时同一份事实只下发一次，并原样返回合法的下级结果；
3. 非法输入和不合法下级结果固定拒绝，不返回半成品。

破坏既有行为的问题。T1 收口。

## T2 开工前【先定】

1. 唯一模型锁定为 Silero VAD 官方 `v6.2.1` 标签、提交
   `7e30209a3e901f9842f81b225f3e93d8199902b1` 下的
   `src/silero_vad/data/silero_vad_16k_op15.onnx`。只支持 T3 即将产出的单声道
   16 kHz PCM，不为 8 kHz 或任意采样率保留兼容分支；模型精确为 `1,289,603` 字节，
   SHA-256 为 `7ed98ddbad84ccac4cd0aeb3099049280713df825c610a8ed34543318f1b2c49`。
2. ONNX Runtime 锁为 CPU 版 `onnxruntime==1.24.3`，只允许
   `CPUExecutionProvider`。该版本的 Python 3.12 macOS arm64 与 Windows x86_64 轮子均
   已从 PyPI 官方元数据核对；Executor spec 必须同时收集其 Python 模块、原生库和数据，
   不从系统 Python、GPU Provider 或运行时下载补齐。
3. 新增唯一模型资产契约 `contracts/quality/silero-vad-runtime.v1.json`。它同时锁定
   上游仓库、标签、提交、下载地址、长度、摘要、MIT 许可证正文和包内相对路径
   `speech/silero-vad/silero_vad_16k_op15.onnx`；模型二进制不进 Git。
4. `scripts/silero_vad_assets.py` 仿照 `subtitle_font_assets.py`，只按契约下载模型和
   许可证正文，逐字节核对长度与 SHA-256，并通过 `video_runtime_cache.ensure_cached`
   写入机器级 `silero-vad` 构建缓存。Executor spec 只从这份已验证缓存装入固定目录，
   失败即终止构建，不静默省略。
5. 运行时解析仍只有一套：冻结包从 `sys._MEIPASS/speech/silero-vad` 读取，源码运行从
   同一机器级构建缓存读取；两边随后共用同一个普通文件、非链接、长度和摘要门禁。
   模型缺失、链接、损坏、契约漂移、ONNX Runtime 缺失、CPU Provider 缺失或 Session
   无法加载，均在创建 VAD 之前转换成固定、路径无关的 `SileroVadUnavailable`。不回退为
   “无人声”，也不把操作者路径、下载地址或底层异常带出边界。
6. T2 的 VAD 只消费有界的 16 kHz `float32` PCM chunk 并产出供应商无关的语音概率；
   T3 才负责用受限 FFmpeg 从已守卫素材抽 PCM、聚合区间并接 ASR。这样 T2 的模型门禁
   与 T3 的私有源路径窗口相互独立，且模型缺失 RED 不需要伪造测试专用生产分支。

## T2 RED 目标

1. 模型文件缺失、为链接或任一字节损坏时，factory 在尝试创建 ONNX Session 前固定拒绝；
2. ONNX Runtime 不可导入、无 CPU Provider 或 Session 加载失败时固定拒绝，消息不含路径
   与底层异常；
3. PyInstaller spec 未收集 `onnxruntime`、未从摘要锁定缓存装入模型和许可证，或冻结包内
   缺少任一文件时，专项打包契约必须失败；
4. 合法 factory 只以 CPU Provider 创建一次 Session；16 kHz 定长 chunk 才可推理，非法
   类型、长度或非有限样本均在调用 Session 前固定拒绝。
