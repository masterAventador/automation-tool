## 范围

本任务在 Local Executor 建立三级漏斗：先消费 LE-07 已测得的有效声音事实，再用随包
Silero VAD 区分人声与环境音，只对判为人声的素材抽取音轨并调用百炼 ASR。最终产出

素材的成片编排，也不引入本地 Whisper。

## T1 开工前【先定】

1. 第一级只消费 LE-07 `MaterialFacts.has_audio`，不从 `audio_codec`、响度、文件扩展名或
   是否存在音轨重新推断。`has_audio=False` 即使同时带有 `audio_codec`，也必须在加载
   VAD、抽音轨或调用 ASR 之前结束。
2. Executor 不依赖 Control Plane 领域对象。T1 定义供应商无关的
   `MaterialSpeechAnalysis`，字段形状与既有 Material 三个语音字段一致；无有效声音的唯一
   结果是 `has_speech=False`、空区间、无转写。
3. 二、三级先收敛在惰性的 `AudibleSpeechAnalyzerFactory` 与
   `AudibleSpeechAnalyzer` 协议后。只有 `has_audio=True` 才创建一次下级分析器并把同一份
   路径无关 `MaterialFacts` 交给它；T2/T3 再把真实 VAD、音轨抽取和 ASR 装进该实现，
   不为 T1 建测试专用生产分支。
4. T1 不接收源路径，也不发现模型、FFmpeg、环境变量或 PATH。这样无声音素材从类型上就
   无法触碰磁盘、VAD 模型和网络，路径窗口与随包装配留给真正拥有这些资源的后续层。
5. 输入不是精确 `MaterialFacts`、分析器不满足协议，或下级返回形状不合法时统一
   fail closed 为固定、路径无关的 `MaterialSpeechRejected`；不把下级异常、素材元数据或
   私有路径带进消息。

## T3 开工前【先定】

1. **本地抽取只有一条生产路径。** `has_audio=True` 后创建的具体分析器捕获
   `PackagedMediaTools`、注册表交付的 `source + approved stat`、VAD factory 和供应商
   无关 ASR Adapter；`AudibleSpeechAnalyzer.analyze()` 仍只接收路径无关
   `MaterialFacts`。执行顺序固定为 `tools.revalidate()` →
   `require_source_unchanged()` → 有界 FFmpeg → 再次
   `require_source_unchanged()`，任一步失败都转换为固定
   `MaterialSpeechRejected`，不携带路径或底层异常。
2. **FFmpeg 只落单声道 16 kHz little-endian signed 16-bit raw PCM。** argv 固定
   `-map 0:a:0 -vn -sn -dn -ac 1 -ar 16000 -c:a pcm_s16le -f s16le`，stdout、stderr 和
   stdin 全部接到 `DEVNULL`。输出只写分析器自有的 `0700` 临时目录内固定普通文件，
   子进程运行时持续量大小；超过
   `min(460_800_000, duration_ms * 32 + 1_024)` bytes 或超时即 kill + reap。超时按
   `min(900, 30 + ceil(duration_seconds / 8))` 秒计算；业务结果或拒绝先确定，临时目录
   清理只做 best effort，清理失败不得改写结果。该形状在本模块重新实现，绝不 import
   LE-08 私有 helper。
3. **VAD 聚合数值一次锁死。** 以 Silero 唯一支持的 512 samples / 32 ms 顺序读取 PCM，
