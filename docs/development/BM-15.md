实现和真实验收继续暴露并按 RED→GREEN 修复：

- `parallax-unzoom` 宿主类名写成不存在的 `parallax-pu-card`，真实计算样式探针失败；
- shimmer/vignette 等片段虽有可见样式但没有随时间变化，真实 Worker 静帧门禁失败；
- Windows Worker 测试以 `chrome.exe --version` 读版本；Chrome for Testing 会打开
  窗口而不退出，实测导致验收挂起；
- Windows 专用 worktree 首次创建暴露只读 `.git` 指针、`.cmd` 入口和缺少 Unix `cp`
  三个跨平台缺口，均由同一脚本测试先失败再修复。
- 最终 Review 逐项走正式工作区又发现 28 个新开放视觉零件会被演示占位资源或无需替换
  的字体权重挡住、16 个完整 component 被统一截成 3 秒、多镜头资源白名单会错误合并整棵
  工作区，以及带空格的 Windows `.cmd` 路径仍会被 `cmd /s` 拆开；均先补复现再修复。
- 全量装配随后又发现 5 个 21～24 秒转场超过单次 600 帧上限；现在保留完整源时间窗并
  压采样为 20 秒 / 600 帧，不截掉后半段，也不再让合法目录选择失败。
- 后续 Review 发现新开放转场仍可能捕获上游 `SCENE A/B` 演示画面，另外 shimmer、
  parallax 和 grid 片段只是共用通用位移；现在 27 个转场先绑定当前镜头真实文案再捕获，
  并隐藏演示说明，三类片段也分别使用自身效果时间轴。
- 再一轮 Review 发现空 `body/items` 会让 parallax 聚焦卡为空，以及合法边界文案会被
  固定大字号裁切；先增加 4 个失败用例，再补非空回退和按契约长度确定的字号/换行。
  真实内置 Chromium 计算得到 60 字标题为 46px、长标题卡为 106px，边界均落在
  1920×1080 画布内。
- 最终 Review 又发现同一零件被多个镜头选中时会复用并覆盖同一份工作副本、片段宿主
  会先转义 ASCII 再测量而误缩到 16px，以及 WebGL 转场直接从 DOM 节点抓文字时不会
  采用 CSS 自动换行。现在工作副本按 beat ID 隔离，字体按原始文案测量后再转义，长
  转场文案预先拆成最多 3 个真实子节点；真实内置 Chromium 已确认 60/120 字边界均
  完整进入 WebGL 画布。
- 收口 Review 继续发现模型看不到 `visual_only` 的文案语义，可能在需要屏显文案的镜头
  选中保留上游示例文字的完整 component；目录现在逐项向模型声明 `text_slots` 或
  `visual_only`，并明确后者不会写入当前分镜文案、只可在确实需要保留原画面时选择。
- 同轮 Review 发现无 `items` 时 detail 与 body 相等，原按字符串值猜字号会把说明区提升为
  110px 标题；转场绑定现按 scene A、scene B、detail 的角色显式传字号，不再从相等文本
  反推角色。
- Windows 删除 Chromium `debug.log` 的 Worker 路径方案即使复验两次 identity，仍有复验
  后到删除前的路径替换窗口。清理现移入 Rust 原生层：打开非 reparse 文件句柄、核对该
  句柄最终路径，再用 `SetFileInformationByHandle` 删除同一对象；junction 替换只能拒绝，
  不能把操作改指树外文件。
- 最后一轮 Review 发现上述清理只发生在 Worker 已返回事件的成功等待路径；Chromium
  超时或崩溃会在清理前返回，残留文件又会被下次发行目录校验当成额外文件。现在渲染等待
  失败会立即移除并停止该 Worker，统一停止路径在进程树退出后再次执行同一原生句柄清理。
- 最终收口 Review 发现三个 fragment host 没有全部保留 `headline/body/items`，且公开的
  `stop`/`stop_all` 会吞掉 Windows 诊断文件清理失败。三个宿主现在都显示所有非空分镜
  文案；停止接口在全部进程树完成回收后传播清理失败，`stop_all` 仍会先排空所有 Worker，
  不会因首个失败留下其余进程。

## 失败矩阵

- App/Tauri/Rust/Executor：非数组、超过 24 镜头、全 `null` 的非空覆盖、未知 ID、
  镜头数不一致均封闭拒绝；不会静默交回模型或截断。
- 所有权：用户指定的槽位替换模型结果，`null` 槽位保留模型选择；未指定任何镜头时
  提交空数组，不伪造用户接管。
- 视觉零件：没有文字槽位时不写 copy；未知 component 片段没有受审宿主则拒绝，
  不用空白页面或通用猜测宿主降级。
- 动效真实性：宿主缺 GSAP、探针失败、时间轴未注册或连续帧不变化均由真实 Worker
  拒绝；唯一静态 overlay 只有作为独立 film shot 时才注入受控时间轴。
- 正式包：PyInstaller 缺少 lazy entry 会在包级协议门禁失败；资源目录缺项、摘要错、
  Chromium major 漂移仍由既有生产启动门禁拒绝；冻结 Executor 只额外携带 25 个组件
  源文档（无 demo 页）读取捕获元数据，包内 `--author-motion` 已复验。
- 制作方式：固定模板预览与提交明确不消费一句话零件覆盖，不能把目录选择冒充为手工
  模板效果。
- 平台工具：Windows 成片检查显式使用已安装包内的 `ffprobe.exe`/`ffmpeg.exe`，不得
  从开发机 PATH 或 macOS 调试配置误取工具；内置 Chromium 退出后不得留下
  `debug.log`；诊断清理由 Rust 对已打开且最终路径匹配的原生文件句柄完成，遇到
  junction/reparse 或路径替换必须宁可残留并拒绝，不得跟随删除树外文件。
