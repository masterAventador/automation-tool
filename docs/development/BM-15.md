实现后的权威链路：

1. `VideoStudio` 在至少一个镜头有用户指定时提交有序
   `catalogPartOverrides: ["data-chart", null, null]`；完全未指定时提交空数组，不误把
   三个 `null` 当作用户接管。
2. TypeScript 目录从 `motion-part-slots.v1.json` 读取 37 项真实镜头集合：134 项继续
   浏览，自动推荐与手工指定只从 37 项产生；网关用同一集合拒绝全空、超长、未知和
   尚不可装配 ID。
3. Rust `MotionVideoBriefRequest` 把覆盖设为必需字段，按同一最大镜头数与 37 项冻结
   槽位契约再次校验，再原样写入冻结 Executor 请求。
4. Executor entry 保持兼容直接调用者，但对 App 提供的值执行封闭校验并交给 Agent。
5. Agent 提示模型必须输出与覆盖槽位完全相同的镜头数；模型答复解析后，用户拥有的
   槽位被权威覆盖，`null` 槽位保留模型决定，再写入 workspace storyboard。
6. 既有真实装配链从该 storyboard 解析逐镜头零件，生成真实 segment；RenderJob
   保存声明/实测镜头表，最终 MP4 由真实分段拼接和旁白混音产生。

## 失败矩阵

- App 请求：非数组、超过 24 个槽位、非空但全为 `null`、未知或 97 项当前不可装配 ID
  均在 invoke 前返回 `protocol_mismatch`，不启动模型或 RenderJob。
- Rust 请求：字段缺失因 `deny_unknown_fields`/必需字段反序列化失败；未知 ID、全空
  非空数组和超长数组构造失败，不进入 Executor。
- Executor 请求：非封闭 shape、非法槽位或不可选 ID 写
  `catalog_part_overrides_shape_invalid`，不会静默退回模型自动选择。
- 模型镜头数：用户提交三个槽位而模型不返回恰好三个 beats 时，
  `agent_catalog_part_overrides_do_not_match_storyboard_beats`，不猜测、不截断、不补位。
- 所有权：明确指定的槽位替换为唯一一个用户 ID；`null` 槽位保留模型原选择。
- 制作方式边界：固定模板预览和本机模板提交都明示不消费一句话覆盖，避免把目录选择
  冒充成固定模板效果。
- 真实零件边界：只允许锁定目录中可填充、可装配、可 seek 的零件；非法 part 不会进入
  `film_assembly.py`。

### T36 真实模型与真实成片

`scripts/run_t36_acceptance.py` 从真实 App 设置页输入真实视频创作模型凭据，再执行：
