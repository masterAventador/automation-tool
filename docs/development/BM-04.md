## 交付范围

- Node Worker（`workers/motion_composition/worker.mjs`）在 BM-03 渲染通道之上新增
  HMAC 认证命令 `worker.render.sandbox`：命令证明绑定到 `jobId` 与 sandbox 规格的
  **规范化 JSON**（递归键排序、紧凑分隔符），任何字段被篡改都使证明失配而被静默忽略。
- sandbox 规格严格校验：`workspace` 必须绝对路径；`entryHtml` 与 `allowedAssets`
  必须是无 `..`、无前导 `/`、无 `\`、无空段、无 NUL 的工作区相对路径；`allowedAssets`
  上限 128 项；`frameCount` 1–600；`maxDurationSeconds`/`maxCpuSeconds` 1–300；
  `maxMemoryMegabytes` 128–8192；`maxOutputBytes` 1–2147483647；键集合必须精确。
- 工作区边界在启动浏览器**之前**解析：`workspace` 必须是非符号链接真实目录；`entryHtml`
  和每个声明资产必须是常规、非符号链接文件，且 `realpath` 落在工作区内（越界/穿越/
  reparse 一律拒绝）；`frames` 输出目录必须尚不存在。
- 渲染沙箱在 BM-03 的 RenderJob 私有临时目录 + detached 进程组内以真实内置 Chromium
  无头启动，通过 CDP `--remote-debugging-pipe` 施加边界：
  - **默认断网**：`Network.emulateNetworkConditions offline` + `Fetch.enable` 全量拦截，
    只放行 `file://` 的入口文档与声明资产，其余远程/`file://` 越界请求一律
    `Fetch.failRequest`（记为 `blockedRequests`/`blockedNavigations`）；
  - **子帧不逃逸**：`Target.setAutoAttach{waitForDebuggerOnStart}` 递归拦截 iframe/子目标，
    子会话在解除暂停前已装好 Fetch/offline，堵住 OOPIF 网络逃逸洞；
  - **默认失联代理**：`--proxy-server=127.0.0.1:9 --proxy-bypass-list=<-loopback>` 把一切
    http/https/ws（含推测性 preconnect）导向失效本地代理，真实主机连 SYN 都收不到，
    本地 `file://` 不走代理仍可加载；
  - **导航/下载/弹窗/弹框拦截**：非入口顶层/子帧 Document 请求被拒（`blockedNavigations`）；
    `Browser.setDownloadBehavior deny` + `downloadWillBegin` 记 `blockedDownloads`；
    `--block-new-web-contents` + `Page.windowOpen` 记 `blockedPopups`；
    `Page.javascriptDialogOpening` 一律 dismiss 记 `blockedDialogs`；
  - **资源上限**：墙钟 `maxDurationSeconds`、按 `ps` 采样进程组 CPU 秒与 RSS 超
  `maxCpuSeconds`/`maxMemoryMegabytes` 立即终止整树（`render_timeout`/
  `render_resource_exceeded`）；POSIX 读取 `/bin/ps` 进程组，Windows 以固定绝对
  PowerShell 查询 `Win32_Process` 的 CPU/工作集并按父 PID 闭包累计；逐帧
  `Page.captureScreenshot` 累计字节超 `maxOutputBytes` 即 `render_output_exceeded`。
- 成功发 `worker.render.sandboxed`（携 `chromiumMajor`、`framesCaptured`、`outputBytes`
  与五类 blocked 计数，全部纳入事件 HMAC 证明）；失败只回固定 reasonCode，不泄漏路径。
- Rust 侧（`frontend/src-tauri/src/local_video_orchestrator.rs`）新增
  `VideoWorkerRenderSandboxRequest`（同构校验）、`VideoWorkerRenderSandboxSummary`、
  `LocalVideoOrchestrator::render_sandbox`（规范化 JSON 绑定命令证明、发命令、校验
  sandboxed/failed 事件 HMAC 与期望 major、`RenderRejected` 映射），token 新增
  `sandbox_command_proof`。
- 新增 `scripts/test_motion_video_render_sandbox.py`（Worker 层沙箱失败矩阵门禁）与

## 失败矩阵

- sandbox 规格非法（缺键/多键/类型错/`workspace` 相对/`entryHtml` 绝对或含 `..`、`\`、空、
  越界资产、资产超 128、各数值越界）：`render_sandbox_invalid`，浏览器从不启动，工作区无
  `frames`，错误不含路径正文。
- 工作区违规（缺失/符号链接工作区、缺失/符号链接入口、缺失/逃逸资产、`frames` 预存在）：
  `render_workspace_invalid`，浏览器从不启动。
- `renderBrowser: null` + 诱饵发现类环境变量：`render_browser_unavailable`，诱饵从未被调用。
- 声明 major 与实际不符：`chromium_major_mismatch`；POSIX 可在 `--version` 阶段提前
  拒绝，Windows 以无头 CDP `Browser.getVersion` 返回的实际产品版本拒绝。
- 伪造命令证明 / 篡改 sandbox 后复用旧证明 / 未绑定 sandbox 的证明：一律被 `timingSafeEqual`
  拒绝、静默忽略、不触碰浏览器、不产生事件。
- 墙钟超时（挂起浏览器）：`render_timeout`，终止整个 detached 自有树；Windows 实测
  原生 PE 父子 PID 均被清理。
- CPU 超限 / 内存超限：`render_resource_exceeded`；POSIX 按 `ps` 采样进程组，
  Windows 按 CIM 进程树累计 CPU 秒和工作集，并走同一整树强杀入口。
- 输出字节超 `maxOutputBytes`：`render_output_exceeded`。
- CDP 管道垃圾数据/超长/子会话建立失败/运行中 major 漂移：`render_protocol_invalid` /
  `chromium_major_mismatch`。
- 真实恶意 HTML：远程 script/img/fetch/WebSocket/iframe 与顶层跳转全被拦，`window.open`
  被拒，程序化下载被拒，`alert` 被 dismiss，工作区外 `file://` 机密不可读，诱饵端口 0 命中。
- Rust 侧：sandboxed 事件 major 与期望不符、计数越界、事件证明伪造、reasonCode 非法字符、
  未配置 renderBrowser（不发 IPC，Worker 保持健康）均 fail closed。
- 每条失败与成功路径都在 `finally` 删除 RenderJob 临时目录；失败路径额外删除已建 `frames`。

## 真实边界

- macOS arm64 与 Windows x86_64 均已用真实 Chrome for Testing 149.0.7827.55 完成
  恶意 HTML 沙箱纵向验收；Windows 另以真实 NTFS junction、原生 PE 父子树和
  Win32 CIM 资源计数闭合平台边界。macOS x86_64 发行暂存仍属于 EB-03 自身的原生目标
  验收，不改变本任务已验证的双平台沙箱契约。
- 资源采样间隔 300ms，超限判定在下一次采样生效，因此实际用量可能短暂高于阈值一个
  采样周期，属预期近似。POSIX 使用 `/bin/ps` 的 `pgid=,rss=,time=`；Windows 使用
  `Win32_Process` 的 100ns CPU 计数和 `WorkingSetSize`，固定系统命令不接收页面或任务输入。
- 逐帧渲染当前用 `Page.captureScreenshot` 作为帧产出与输出配额度量；BM-16 接入上游逐帧引擎时，
  本任务确立的工作区 containment、默认失联代理、子帧递归拦截、导航/下载/弹窗/弹框拦截与
  CPU/内存/时长/输出上限是其必须复用的沙箱边界，逐帧引擎不得绕过。
- macOS 验收链路使用开发机 Node wrapper；Windows 使用由 BM-02 唯一 builder 当场生成
  的官方 Node 22.23.1 x64 候选。BM-16 冻结生产包时仍需把上游逐帧引擎一并复验。

## 清理

- 每个 RenderJob 临时目录（`automation-tool-renderjob-<jobId>-*`）在 `finally` 删除；成功路径
  保留工作区内 `frames/` 供上层消费，失败路径删除已建 `frames/`。测试与验收结束断言系统临时
  目录无该前缀残留。
- 无头浏览器为 detached 自有进程树：POSIX 正常路径 `Browser.close` 退出，超时/资源
  超限 SIGKILL 进程组；Windows 正常路径在 `Browser.close` CDP 应答后用绝对
  `taskkill.exe /T /F` 回收仍持有管道的整树，超时/资源超限复用同一入口。验收按暂存
  绝对路径扫描进程并断言零残留。
- 暂存目录位于 `.local/embedded-browser-video-studio/ebvs-bm04-<pid>/`，验收结束整体删除；
  仓库不提交浏览器二进制；全部测试无头，不弹窗口。
