## 失败矩阵

| 场景 | 结果 |
| --- | --- |
| Executor Python 源码变化 | 摘要变化，自动选择新缓存 |
| spec/uv.lock/协议或只读资源变化 | 摘要变化 |
| 输入未变化 | 复用现有缓存 |
| 从主 checkout 运行 | `archive_path()` 解析主缓存 |
| 从 `wt/*` 运行 | 同一 resolver 兼容父级布局 |
| 请求强制重建 | 删除与 ensure 精确相同的摘要目录 |
| 只改未纳入摘要的输入 | 这是风险；测试必须随真实构建输入集合同步 |

## 真实边界

变异测试真实修改输入字节并观察缓存选择；T78 的视频驱动也使用了新键。但第二批没有逐一实跑
34 个所有调用方，所以不能写成“34 条验收全部证明已拿到新执行器”。这也是 T79 仍需聚合
执行器的原因之一。

## 清理

缓存重建只定向处理当前摘要目录；未清空共享 `.local`，未重新下载浏览器或 submodule。

## 文档与遗留

共享缓存键的输入集合是安全边界。新增影响 PyInstaller 输出的文件时，应先让摘要测试 RED，
再扩展单一输入清单。
