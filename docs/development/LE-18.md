## T1 RED 目标

1. 已登记映射可被幂等忘记；重启后仍不存在，其他素材映射不受影响。
2. 忘记映射只改私有注册表，绝不删除、改名或读取用户原文件。
3. 原子写失败时磁盘文档与当前进程内存都保留旧映射，不能出现“本进程忘了、重启又回来”。
4. 非规范 UUID 与运行中被放宽/替换的 state 目录继续 fail closed，错误和 traceback 不含路径。

## T1 GREEN、代码审查与功能验收

首次 RED 共 11 个断言，其中 9 个精确失败于 `MaterialPathRegistry` 没有 `forget`；既有
register/resolve 目录重校验两项保持绿色。GREEN 新增幂等 `forget`：先重校验私有 state 目录和
UUID，只在映射存在时复制条目并通过既有原子 `_write` 发布合法空/非空文档，持久化成功后才替换
内存条目。实现不 resolve、不 stat、不 open、不 unlink 用户源文件，因此源文件已消失时仍可清理
映射，也不会把路径挂到异常链。

逐文件 Review 复核了注册、删除、原子 writer、目录运行中替换和字节上限的共同边界，未发现未
关闭 finding。专项功能验收 `13 passed`；完整 `test_material_probe.py` 为 `419 passed`；两个改动
文件 Ruff format/E/F/I 与严格 mypy 全绿，路线图计数和 `git diff --check` 通过。T1 正式完成。

## T2 RED 目标

1. 按 Installation 隔离列出素材，游标必须规范、封闭且不携带路径；每页顺序稳定且不重不漏。
2. 未被时间线引用的素材可删除，越权和不存在统一为 404；既有任一不可变时间线修订引用时固定

3. 时间线保存与引用投影同事务；缺素材或素材属于另一 Installation 时整条保存回滚，不能留下
   timeline identity、revision 或半张引用表。
4. 迁移必须回填既有 JSONB 时间线引用，OpenAPI、生成 TypeScript 与 Rust 封闭操作清单同步。

## T2 GREEN、代码审查与功能验收

RED 首轮精确出现三类缺口：契约测试因 `MaterialInUse` 不存在而收集失败，真实仓储分页调用报
`list_page` 不存在，引用表写入报 relation 不存在；OpenAPI 快照随后按预期检测到新路由漂移。
GREEN 新增按 Material UUID 降序的 Installation 级不透明游标分页、`GET
/api/v1/editing-materials/library` 与 `DELETE /api/v1/editing-materials/{material_id}`。删除不存在或
越权素材为 404，被引用为固定 409，成功为无响应体 204，所有响应继续 `no-store`。

迁移 `0040` 新建 `timeline_material_references`。它用 timeline revision、project owner、material
owner 三组复合外键把 JSONB 中的素材引用投影成数据库事实；material 外键为 `ON DELETE
RESTRICT`，timeline 外键为 `ON DELETE CASCADE`。时间线仓储在写 revision 的同一事务去重写入
引用；缺素材或跨 Installation 引用转成无私密细节的 `timeline_material_missing`，整个事务回滚。
迁移会从既有 tracks/clips JSONB 回填，发现无法满足同 Installation 素材约束时升级 fail closed。

逐文件 Review 找到并关闭四项 drift：新增错误未进入动态错误闭集、OpenAPI 新操作未进入 Rust
操作 allowlist、引用表缺少迁移与 SQLAlchemy schema 精确对账、契约内存仓储漏实现既有 speech
协议导致严格 mypy 不完整。最终无未关闭 finding。专项功能验收为 `177 passed`，覆盖错误闭集、
素材 REST、OpenAPI、真实 PostgreSQL 仓储/迁移/结构门禁、时间线引用原子性与真实 Uvicorn HTTP
纵向路径；另有 Rust allowlist `1 passed`、前端生成契约 `2 passed`、TypeScript typecheck、Cargo

## T3 RED 目标

1. Rust 只能通过已认证的本机 Worker stdin 发送 `materialId + sourcePath`；命令对象、拒绝、事件、
   stderr 与 `repr` 都不得回显绝对路径。导入成功事件只返回可登记到 Control Plane 的素材事实。
2. 生产执行必须逐次调用公开操作 `approve_source → probe_material → register →
   require_source_unchanged`，首个受守卫 stat 必须贯穿完整窗口，禁止调用方自己拼 `Path.stat()`。
3. `register` 后最终 unchanged 失败时必须立刻 `forget`；忘记失败不能伪装成已经补偿。Control Plane
   登记失败后的显式 `worker.material.forget` 必须幂等，供 T4 完成跨进程补偿。
4. 素材导入/忘记与既有渲染共用单操作状态机；伪造认证、额外字段、并行命令、非法 UUID/路径、
   非法事实和越界消息全部 fail closed。
5. 真实 PyInstaller 冻结 Worker 必须用真实 ffprobe/ffmpeg 导入一条素材、持久化映射并成功忘记，
   且输出中没有源路径；平台相关边界在 macOS 与 Windows 同 SHA 复验。

## T3 GREEN、代码审查与功能验收

RED 首轮补齐 `worker.material.import` / `worker.material.forget` 认证命令和
`imported` / `import_failed` / `forgotten` / `forget_failed` 认证事件，素材路径只存在于
`repr=False` 的 Worker 私有命令对象。生产流程严格复用
`approve_source → probe_material → register → require_source_unchanged`；最终闭窗失败会同步
`forget`，补偿失败则升级为注册表拒绝码。素材操作与渲染共用一个活动槽，非法事实、UUID、额外
字段、并发命令和伪造 HMAC 均 fail closed。新建的 state 目录在 POSIX 显式设为 `0700`，既有
不安全目录只拒绝、不修复。

逐文件 Review 共发现并关闭四项真实问题：冻结探针先导入上游 App 会掩盖本机编辑运行时的冷导入

复跑又修正了两处仅影响测试的常量缺失/假二进制标志夹具。最终 Review 无未关闭 finding。

专项功能验收：macOS 完整素材探测、素材进程与协议测试 `473 passed`，冻结 Worker 边界

## T4 RED 目标

1. Rust/Tauri 只能从原生文件选择器取得路径并直接交给已认证 Worker；WebView、Control Plane、
   DTO、日志、错误和事件不得出现绝对路径或文件名。
2. 导入成功后把 Worker 返回的路径外事实登记到 Control Plane；内容摘要重复要返回稳定去重结果，
   Control Plane 登记失败必须调用 Worker forget，且补偿失败不能伪装成无本机残留。
3. 素材状态只返回 `available`、`file_missing`、`file_unreadable`、`file_changed` 等封闭状态；删除要
   协调 Control Plane 受约束删除与本机幂等 forget，不得删除或改写用户源文件。
4. Tauri command、Rust client、Worker 子进程协议和失败映射全部受严格 allowlist/大小界限约束；
   未认证事件、未知字段/状态/错误码、Worker 退出与并发操作均 fail closed。
