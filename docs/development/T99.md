更值得记的是第二句：**这个缺陷被人发现过、写进注释、然后用正则绕开了。**
`e2e/workbench-home.spec.ts` 与 `Workbench.test.tsx` 里都留着
「header's accessible name is `<折叠状态> 诊断信息`」这行注释，紧跟着一句 `name: /诊断信息/`。
缺陷被记录下来当成了环境事实，而不是当成待修的 bug。

## 缺陷是什么

antd 自己给 `Collapse` 的箭头贴上英文状态词 —— `antd/es/collapse/Collapse.js:69-72`：

```js
React.createElement(RightOutlined, {
  rotate: panelProps.isActive ? 90 : undefined,
  "aria-label": panelProps.isActive ? 'expanded' : 'collapsed'
})
```

面板头是 `role="button"`，名字**由内容计算**，于是把箭头的 `aria-label` 一并吞进去。
Chromium 实际暴露的（`ariaSnapshot()`，不是读 JSX 推断）：

```text
- button "collapsed 诊断信息":
    - img "collapsed"
    - text: 诊断信息
```

```text
- button "collapsed MIT 许可证全文（英文原文）":
    - img "collapsed"
- button "collapsed Apache-2.0 许可证全文（英文原文）"
- button "collapsed GPL-3.0 许可证全文（英文原文）"
- button "collapsed SIL Open Font License 1.1 许可证全文（英文原文）"
```

中文标签里读出一个英文状态词，而且**重复**——同一个按钮上已经有 `aria-expanded`，
状态本来就该从那里读。

## 为什么一直没红

**Playwright 的 `getByRole(name: "…")` 默认是子串匹配。** 实测（在未修复的渲染上）：

```text
✓ playwright default string match is a SUBSTRING match
PROOF: non-exact matched the polluted name -> substring default confirmed
```

`getByRole("button", { name: "诊断信息" })` 对 `"collapsed 诊断信息"` 匹配到 1 个，照样绿。

**Testing Library 正好相反：字符串名是全量匹配。** 这解释了单测为什么当初被迫写成正则——
在未修复的渲染上，把它改回普通字符串会直接报出污染后的名字：

```text
TestingLibraryElementError: Unable to find an accessible element with the role "button" and name "诊断信息"
  Name "collapsed 诊断信息":
```

所以本任务所有断言要么 `exact: true`、要么直接比对 `ariaSnapshot()`。子串断言对这个缺陷
不可能变红，作为守卫一文不值。

## 排查覆盖范围

用 Playwright 的 `ariaSnapshot()` 打出 Chromium 实际暴露的无障碍树，**以它为准**，不读 JSX 判断。
覆盖 8 个主页面 + 法律声明页 + 展开态 + 有运行中任务的工作台 + 运行详情 + 视频剪辑页签 +
发布流程 + revoked/flaky/unavailable 三个启动门：共 20 份树。另外做了两个 DOM 级探针
（`cursor:pointer` 但不可聚焦；每个 `.ant-tabs-tab` 是否含可聚焦后代）和一次真实 Tab 键序遍历。

搜索模式：`Collapse` / `expandIcon` / `aria-label` / `onClick` / 所有 `name-from-content` 角色的
带引号名 / 无名交互节点 / 名字里的拉丁字母。

## 修法

`expandIcon` 是 antd 给的公开扩展点（CLAUDE.md §6：优先用公开扩展点）。传入**同一个**
`RightOutlined`、**同一个** `rotate`，只是把状态标签换成 `aria-hidden="true"`——
`aria-hidden` 会把整棵子树移出无障碍树，名字计算就看不见它了。`<svg>` 本来就已经是
`aria-hidden`，泄漏的只有外层那个 span。

没有把 antd 的 SVG path 抄进源码：CLAUDE.md §6 明令「禁止复制内部实现」。
为此把 `@ant-design/icons` 提为直接依赖——它本来就是 antd 自己的依赖，版本 `^6.3.2`
解析到**已安装的同一个实例**，lockfile 只增加 3 行，没有下载任何新包。

复用位置按 `docs/project-structure.md:149` 已经预留的 `frontend/src/components/`
（“真正跨 Feature 复用的 UI”）——两个调用方分属 `features/workbench/` 与 `features/legal/`。
`VideoStudio` 用的是自绘 CSS 箭头，不调用它，注释里写明了原因。

## 视觉零变化（实测，不是声称）

同一段代码，改前改后各测一次几何值：

| | antd 默认（改前） | 本次修法（改后） |
| --- | --- | --- |
| 折叠态 svg transform | `none` | `none` |


## 既有 e2e 的子串匹配：查了，只收紧了 2 处

`e2e/` 下带 name 的 `getByRole` 共 **121** 处，**0** 处用 `exact`（其中 23 处用正则）。
`src/` 单测里 **312** 处，其中 31 处用正则。

**没有一律加 `exact: true`。** 判据是「这个名字有没有被污染的风险」——即：名字是固定字面量
**且** 角色由内容计算名字 **且** 控件内含可贡献文本的子元素（图标/徽标/状态指示）。
只有 `Collapse` 头部是这个形状。

收紧的 2 处（都是原来为绕开本缺陷才写成正则的）：

- `e2e/workbench-home.spec.ts:79` → `{ name: "诊断信息", exact: true }`
- `src/features/workbench/Workbench.test.tsx:192` → `{ name: "诊断信息" }`（TL 全量匹配）

两处的过时注释同时改掉——它们原来把缺陷描述成既定事实。

**故意保持宽松的，及理由：**

| 位置 | 形式 | 为什么不动 |
| --- | --- | --- |
| `ui-harness.spec.ts` ×3 | `/登录\|注册/` + `toHaveCount(0)` | 断言**不存在**。更宽的匹配器覆盖更多候选，是**更强**的断言；改成 exact 反而削弱 |
| `/暂.*停/`、`/恢.*复/`、`/取\s?消/`、`/重\s?试/`、`/登\s*录/` | 正则 | antd 会在两个 CJK 字之间插空格，正则正是为吸收它而写；写死字符串对 antd 的排版规则很脆 |
| `/发布到抖音/` 等 ×12 | 正则 | `ariaSnapshot()` 实测名字就是 `button "发布到抖音"`，干净、无图标子节点可吞。无风险可守，改动只是churn |
| `video-studio-density.spec.ts:137` `/详细说明/` | 正则 | 已被 `card.getByRole` 限定作用域；该控件已修好，且由本次 exact 断言锁住。该文件属另一条线（屏效） |

比起把 121 处逐条改严，真正的守卫是那条**整页扫描**用例：它按 `ariaSnapshot()` 检查所有
`name-from-content` 角色的名字里有没有状态词，能覆盖到根本没人写断言的控件。

## 一并排查、实测发现**没有**问题的（否定结论）

- **键盘可达性**：`.ant-tabs-tab` 看着是 `div`，实测是标准 roving tabindex（激活项
  `tabindex=0`、其余 `-1`、方向键切换），键盘可达，**不是**缺陷。真实 Tab 键序遍历确认
  视频制作 / 视频剪辑 / 新建任务 / 设置与诊断 四页都能走完。
- **无名控件**：20 份树里 `button`/`link`/`menuitem`/`tab`/`combobox`/`textbox`/`spinbutton`/
  `switch` **没有一个**空名字。
- **表单标签**：全部有名，且都是中文（`textbox "* 搜索关键词"`、`combobox "文案模型服务模型"`、
  `switch "保存成功任务的脱敏诊断"` 等）。
- **密码框显隐按钮**：`button "显示"` 内含 `img "eye-invisible"`，但按钮有显式 `aria-label`，
  **覆盖**了内容计算，名字是干净的。这是本仓库把它做对了的例子。
- **CLAUDE.md §6 上游名进无障碍名**：**未被违反**。`e2e/upstream-name-leak.spec.ts`
  （本来就用 `ariaSnapshot()` 扫 8 个页面）在全量里通过；我自己的 20 份树里，法律声明页
  以外没有任何上游项目名。视频制作两种方式的可访问名实测就是
  `button "选择智能素材成片"` / `button "智能素材成片的详细说明"` /
  `button "选择品牌动效成片"` / `button "品牌动效成片的详细说明"`，符合规则。

## 已知遗留：antd 数字输入框的英文按钮名（不修，说明原因）

`InputNumber` 的加减按钮暴露为 `button "Increase Value"` / `button "Decrease Value"`——
中文产品里的英文控件名。出现在「新建任务」的三个数字字段旁。

**不修**：`aria-label` 硬编码在
`@rc-component/input-number/es/StepHandler.js:76`（`isUpAction ? 'Increase Value' : 'Decrease Value'`），
既没有 prop 也没有 locale 钩子。改它必须动第三方源码或 Monkey Patch，CLAUDE.md §6 明令禁止。
按 §6 的顺序，剩下的正规路子是提上游 Issue/PR。

影响有限但不是零：这两个 span 是 `role="button"` 且**无** `tabindex`，键盘不可达，
数字本身由已正确命名的 `spinbutton` 用方向键操作；受影响的是浏览模式下的读屏用户。

同类还有若干装饰性图标以独立节点暴露英文图标名（`img "info-circle"`、`img "close-circle"`、
`img "down"` 等）。它们**不污染任何控件的名字**，且要消掉必须给 antd 组件传自定义 `icon`/
`suffixIcon`，有改变视觉的风险——本任务明确不动视觉，故只记录不修。
