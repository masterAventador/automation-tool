## 问题

演示当天最核心的动作是「制作视频」。1280×800（`src-tauri/tauri.conf.json`
声明的生产窗口，客户双击图标后的实际尺寸）下打开「视频制作」，首屏没有任何
可按下的动作——只有页签。

「新建视频」页签上每张制作方式卡的结构是：卡头 → 一句话摘要 → **10 行说明表
（`<dl>`，实测 466px 高）** → 「选择」按钮。按钮排在说明表后面，于是被那 466px
整体顶到折叠线以下。

### 一处顺带查明的事：这个仓库的 Playwright 视窗不是它自称的 800

第一次跑 RED 时断言消息里打出的折叠线是 **720**，不是 800。
`playwright.config.ts` 的 `use.viewport` 确实写着 1280×800，但它唯一的 project
在上面又铺了一层 `devices["Desktop Chrome"]`，那个预设自带 1280×720 并覆盖掉前者。
于是 `e2e/` 下**每一份**用例实际都在比它注释里声称的窗口矮 80px 的视窗里跑
——包括 T88 那份 `screen-density.spec.ts`，它的文件头明确写着"1280x800，即生产
Tauri 窗口的默认尺寸"。

对已有用例而言这个方向是偏严的（折叠线更高），所以没有掩盖过缺陷。
**本次没有去改共享配置**：拉长视窗会同时放松其它每一份用例的折叠线判定，而此刻
有多条工作线同时在改这个 App。本用例改为在自己文件里 `test.use` 显式钉住
1280×800，并把原因写进文件头注释。**共享配置那处是否要统一修，留给你判断。**

## 没改什么，以及为什么

以下都是「视频制作」链路上看得见的屏效问题，属于版式或产品取舍，**按你的要求登记
在此由你判断，没有擅自改**：

1. **「新建视频」四个字一屏内出现两次**——页签标签 y=176、卡片头 y=239，中间只隔
   17px，卡片头这 56px 是纯重复（T88 第 3 条已记）。删掉能让整块再上移 56px，但那是
   删除用户看得见的元素，不在"客观屏效"范围内。本次的重排已经把动作送进首屏，不靠它。
2. **说明表没有折叠**——把 10 行 `<dl>` 收进折叠区能再省约 466px，让整页从 1240px
   降到一屏内。没做的原因是：折叠控件必须有一个展开标签，那是**新增用户可见文案**，
   而你明确要求不动文案措辞。若你认可新增一个展开标签，这条可以立刻补做。
3. **`.video-studio-panel { min-height: 330px }` + `.ant-empty { margin-block: 70px }`**
   （T88 第 11 条）——「成片」等空状态页签因此定高，1440×900 下 329px 的卡片里只有
   96px 内容。不确定这个定高是不是刻意的，未动。
4. **`playwright.config.ts` 的 720/800 冲突**——见上文，属于共享配置，未动。

另外，按边界要求**完全没有碰**：`scripts/`、任何 `.rs`、
`frontend/src/features/app-updates/`、`frontend/src/features/video-editing/`、
工作台首页与任务列表、`frontend/src/test-tauri-main.tsx`、
`docs/demo-sprint-roadmap.md`。`global.css` 只增了一条注释、改了一条声明，
没有触碰另一条工作线新加的 `.video-editing-*` 与 `.publish-workspace-content`。
