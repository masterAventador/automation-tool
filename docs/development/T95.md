## 问题

演示当天最核心的动作是「制作视频」。1280×800（`src-tauri/tauri.conf.json`
声明的生产窗口，客户双击图标后的实际尺寸）下打开「视频制作」，首屏没有任何
可按下的动作——只有页签。

「新建视频」页签上每张制作方式卡的结构是：卡头 → 一句话摘要 → **10 行说明表
（`<dl>`，实测 466px 高）** → 「选择」按钮。按钮排在说明表后面，于是被那 466px
整体顶到折叠线以下。

### 一处顺带查明的事：这个仓库的 Playwright 视窗不是它自称的 800

第一次跑 RED 时断言消息里打出的折叠线是 **720**，不是 800。
`playwright.config.ts` 的 `use.viewport` 确实写着 1280×800，但它唯一的 project
在上面又铺了一层 `devices["Desktop Chrome"]`，那个预设自带 1280×720 并覆盖掉前者。
于是 `e2e/` 下**每一份**用例实际都在比它注释里声称的窗口矮 80px 的视窗里跑
——包括 T88 那份 `screen-density.spec.ts`，它的文件头明确写着"1280x800，即生产
Tauri 窗口的默认尺寸"。

对已有用例而言这个方向是偏严的（折叠线更高），所以没有掩盖过缺陷。
**本次没有去改共享配置**：拉长视窗会同时放松其它每一份用例的折叠线判定，而此刻
有多条工作线同时在改这个 App。本用例改为在自己文件里 `test.use` 显式钉住
1280×800，并把原因写进文件头注释。**共享配置那处是否要统一修，留给你判断。**

## 没改什么，以及为什么

以下都是「视频制作」链路上看得见的屏效问题，属于版式或产品取舍，**按你的要求登记
在此由你判断，没有擅自改**：

1. **「新建视频」四个字一屏内出现两次**——页签标签 y=176、卡片头 y=239，中间只隔
   17px，卡片头这 56px 是纯重复（T88 第 3 条已记）。删掉能让整块再上移 56px，但那是
   删除用户看得见的元素，不在"客观屏效"范围内。本次的重排已经把动作送进首屏，不靠它。
2. **说明表没有折叠**——把 10 行 `<dl>` 收进折叠区能再省约 466px，让整页从 1240px
   降到一屏内。没做的原因是：折叠控件必须有一个展开标签，那是**新增用户可见文案**，

3. **`.video-studio-panel { min-height: 330px }` + `.ant-empty { margin-block: 70px }`**

   96px 内容。不确定这个定高是不是刻意的，未动。
4. **`playwright.config.ts` 的 720/800 冲突**——见上文，属于共享配置，未动。

## ③ `min-height: 330px` 的查证结果

**结论：不是防内容加载跳动的措施，是骨架期给六个占位卡统一高度的装饰。已删。**

依据（不是推断，是提交里能读到的事实）：

1. `git log -L '/^\.video-studio-panel {/,/^}/:frontend/src/styles/global.css'` 显示这行
   自诞生起从未被改过，**唯一一次出现是 `d331d90「feat: 建立视频制作页面骨架」**；
2. 同一个 hunk 里它与 `.video-studio-panel .ant-empty { margin-block: 70px }` 和
   `.video-studio-new-form { width: min(760px, 100%) }` 是**同一批一起加进来的**
   —— 后者后来已被别人改成 `width: 100%`，说明这批骨架期 CSS 本来就是随真实内容
   到位而需要逐条重估的；
3. **决定性的一条**：`git show d331d90 -- .../VideoStudio.tsx` 里那个版本的
   `VideoStudio()` **不接任何 props、没有 gateway、没有 `useEffect`、没有任何取数**，
   六个页签里**五个**渲染的是静态 `EmptyVideoPage`。
   **那一刻不存在任何"内容加载"，也就不可能存在"加载时布局跳动"需要防。**
   它防的是六张空占位卡塌成细条、看起来不像个面板；
4. VF-06 自述范围也印证："只完成信息架构、导航和诚实空状态"。

它今天也没有在起防跳动的作用：`refresh()` 每 2 秒轮询，任务到达时
`EmptyVideoPage` 会换成真实任务卡，而真实任务卡**远高于 330px**，
330 这个下限对那次切换毫无约束力——它只对"内容比 330 矮"的空状态生效，
也就是只负责把空状态撑大。

因此按「随手写的定高」处理：连同配套的 `margin-block: 70px` 一起删除，
改用 antd `Empty` 自己的默认间距（32px），**产品不再往组件默认值上叠加任何自定义间距**。
实测 210px = 96（Empty）+ 32×2（antd 默认外边距）+ 24×2（卡片内边距），
空掉 114px 全部来自组件默认与卡片内边距本身。

## ② 折叠：默认收起，理由

**选了默认收起。** 三条理由：

1. **不收起就达不到目标。** 说明表是 466×2 px，是整页 1240px 里唯一能让它降到
   736px 的那一块。默认展开＝页面维持 1240px，本轮等于没做；
2. **客户第一眼要的信息并没有被藏起来。** 每张卡的一句话摘要（「让旁白、字幕和
   素材画面配合起来…」／「用品牌配色、文字、图表和界面动画…」）**保持常驻可见**，
   它才是回答"这是什么"的那句话。折进去的十行是
   最适合／不适合／举个例子／外部服务／本机处理／预计耗时／设备占用／临时磁盘／
   网络消耗／数据与隐私——那是**已经在两者之间做选择时**才逐项对照的比较表，
   不是第一眼的定位信息；
3. 展开是一次点击或一次回车，控件就在按钮正下方，不需要翻找。

新增的用户可见文案**只有折叠控件那一个标签**，每张卡一个：
`智能素材成片的详细说明` / `品牌动效成片的详细说明`。**没有改动任何既有措辞。**

标签里带方法名不是啰嗦，是无障碍必需：页面上并排两个同类控件，
若都叫「详细说明」，读屏用户会听到两个一模一样的按钮而无法分辨各自属于哪张卡。
把方法名写进**可见标签**而不是用 `aria-label` 覆盖，可见文本与无障碍名称保持同一个字符串。

组件选用 antd `Collapse` 而不是原生 `<details>`：本产品已经用 `Collapse` 承载
同类"长参考文本折叠"（`ThirdPartySoftwareNotice` 的许可证全文），复用既有惯例，
不引入第二套折叠写法。

### 顺带查出并修掉的一个无障碍缺陷

写键盘用例时发现，**Playwright 的 `getByRole` 默认按子串匹配无障碍名称**，
所以第一版用例是绿的，而 `ariaSnapshot()` 显示 Chromium 实际暴露的名字是：

```
- button "collapsed 智能素材成片的详细说明":
  - img "collapsed"
  - text: 智能素材成片的详细说明
```

antd 默认展开图标是 `<span role="img" aria-label="collapsed">`，
名称按内容计算时把它一起吞了进去——读屏用户会听到一个**英文状态词
"collapsed"** 夹在中文标签里，而且状态本来就已经由 `aria-expanded` 表达，纯属冗余。

改法：用 `expandIcon` 传入自绘的纯 CSS 箭头并标 `aria-hidden="true"`
（`@ant-design/icons` 不是本项目依赖，antd v6 下无法直接复用其图标组件）。
修后 `ariaSnapshot()`：

```
- button "选择智能素材成片"
- button "智能素材成片的详细说明"
```

用例同时改为 `exact: true`，否则这类泄漏还会继续被子串匹配掩盖。

**同一缺陷在 `features/legal/ThirdPartySoftwareNotice.tsx` 上同样存在**，已实测确认：

```
- button "collapsed MIT 许可证全文（英文原文）"
- button "collapsed Apache-2.0 许可证全文（英文原文）"
```

那是**本轮之前就有的产品级缺陷，不是本次引入**，且该文件不在本轮文件面内，
**未改动，登记在此请你决定是否单开任务**（同样是 `expandIcon` 一行的改法）。

### 中途两处必须记下来的返工

**一、③ 的阈值从 100 调到了 120。** 这不是为了让用例变绿而放宽门槛，
而是原阈值定在了"产品什么都不加"也达不到的位置：删掉自定义间距后实测 114px，
其中 48px 是卡片自身内边距、64px 是 antd `Empty` 的默认外边距，
**产品叠加的部分已经是 0**。要压到 100 以下就必须反过来写一条自定义负间距去
对抗组件默认值——那正是当初 `margin-block: 70px` 造成这个问题的同一种做法。
阈值改为 120 并在用例注释里写清 96+32×2+24×2 的构成，既容得下组件默认值，
又能拒绝任何重新往上叠产品间距的改动。

**二、第一轮的两条顺序断言被本轮改动打破，做了等价重写。**
antd `Collapse` **不会挂载收起状态下的面板内容**（实测 `.video-method-details`
数量为 0），原断言 `card.querySelector('.video-method-details')` 因此取到 null。
改为：收起时比较按钮与**折叠控件**的位置，再展开一次比较按钮与**说明表**的位置。
两半都保留——前者是客户初见页面时的状态，后者防止说明表日后被搬到按钮上方。
这比原断言更严，不是放松。
