1. 用后端 `timeline.py`/项目/作业领域的当前闭集整体替换旧 zod 副本：五种轨道、无 `cut`
   转场、Material 身份、来源窗、gain、原声三态、每种轨道唯一和画面真实重叠。
2. Project 改为 output + captionStyle + createdAt；Job 改为 jobId、六状态、单个输出 Artifact
   与八个失败码；删除已淘汰的 source/input/output 数组、paused 与 outcome_uncertain。
3. 编辑草稿与 Workbench 构造代码使用同一新形状，不能靠 `as` 绕过，也不能放宽响应解析以
   接受旧字段。
4. 首次 RED 必须由真实后端合法快照被旧 schema 拒绝、旧快照被错误接受，以及 Workbench
   仍引用旧字段共同证明。

## T1 RED、GREEN、代码审查与功能验收

新契约测试先写后跑，10 条中 8 条按预期失败：真实 Project/Timeline/Job 快照被旧 schema
拒绝，旧三轨枚举仍含 `audio`，output/caption style 与原声三态 schema 不存在，来源窗、音量、
真实转场重叠和六状态作业均不能通过。DTO GREEN 后，`pnpm typecheck` 又精确列出 Workbench、
local draft 测试与旧字段的全部编译漂移，证明不是只让独立 schema 测试变绿。

实现把 Project 改成 output/captionStyle，Timeline 改为 Material 身份、来源窗、gain、原声三态、
五条唯一轨道与真实 visual overlap，Job 改为六状态、单个输出 Artifact 和八个失败码。工作台草稿
同步支持旁白/原声/音乐、音量与原声处理；硬切只由 transition 缺省表达，不再保留 `cut` 别名。

逐文件 Review 找到两项缺口并各补直接 RED：文本校验只拒绝 `Cc/Cf`，会放过 Unicode 私用区
`Co`；加载现有时间轴再保存会把服务端 `trackId/clipId` 改成位置编号。现改为拒绝全部 Unicode
Other 类（字幕仅显式允许换行和制表），并让表单持有稳定领域身份；新建对象使用带 `clip-`/
`track-` 前缀的 UUID 本地 ID。复审无未关闭 finding。

最终功能验收：视频剪辑相关 Vitest `48 passed, 1 expected fail`；expected fail 是 T3 明确保留的
“生产 videoEditingGateway 尚未由真实 Tauri gateway 装配”守卫，不是 T1 回归。全量
`pnpm typecheck`、七个改动文件 ESLint、路线图计数与 `git diff --check` 全绿。T1 正式完成。

## T2 RED、GREEN、代码审查与功能验收

首次 RED 的三个 Rust 测试分别编译失败于 editing target、强类型 parser 和 client 方法不存在；
Tauri command 随后由独立 Node 边界测试锁住六个固定名称、client 调用和两个正式 handler，普通
`desktop-e2e` handler 明确不得登记。实现只暴露网关所需的项目列表/创建、时间轴读取/保存、
作业列表/提交六个 client 方法；每次调用先用设备凭据换取 `app.control-plane` 短会话，路径只由
校验后的 UUID/游标构造。保存时间轴对齐真实 `201`，三个写操作的传输中断统一折叠为
`outcome_uncertain`，不会伪装成安全可重试。

严格响应层用 `deny_unknown_fields` 加领域不变式校验所有 Project/Timeline/Job 快照；nullable
字段必须真实出现，缺字段不能静默补 `null`。真实 loopback HTTP 测试逐请求核对设备会话交换、
Bearer、request ID 回显、分页 GET、时间轴 PUT、空对象作业 POST、`no-store` 和 200/201。

逐文件 Review 找到并关闭四项：Serde 的 nullable 字段默认接受缺失；提交作业复用了分页 target
并携带无意义的 limit；手写 Unicode 列表放过未分配码位；时间轴 GET 未核对响应 `projectId`
是否等于请求项目。每项均先补 RED，再改为 required-nullable 反序列化、专用 submit target、
Regex Unicode `Other` 类防线和跨项目响应拒绝；同时删除不属于六操作网关的两个多余 public
client 方法。复审与 `git diff --check` 无未关闭 finding。

最终功能验收：完整 `control_plane::tests` 为 `38 passed`（含 5 条 editing 专项及真实 socket）；
原生命令所有权测试 `2 passed`；生产默认、`control-plane-e2e`、普通 `desktop-e2e` 三种 Rust
feature 均编译通过；本次库严格 Clippy 与 `cargo fmt --check` 通过。T2 正式完成。

## T3 RED 目标

1. 新建 `TauriVideoEditingGateway`，只 invoke 六个固定 command；所有 native 返回值必须再次经
   T1 zod 闭集解析，不能把 `unknown` 直接断言成领域对象。
2. 项目/作业列表逐页读取，限制总页数与总条数，并拒绝重复 cursor，避免恶意或漂移服务端让
   App 无限循环；对每页根结构和 `nextCursor` 做严格解析。
3. native 固定 `code/retryable` 错误折叠为 `VideoEditingGatewayError`，未知对象、字符串和私密
   message 一律不反射；写入结果不确定必须保留非重试语义。
4. 生产 `main.tsx` 只装配真实 Tauri gateway；sessionStorage 草稿网关降为测试夹具。首次 RED
   由现有 production wiring expected-fail 变为普通失败，并由 command/分页/错误矩阵共同证明。

## T3 RED、GREEN、代码审查与功能验收

先把 `videoEditingGateway` 移入生产装配强制清单并删除 `it.fails`，守卫按预期失败于
`main.tsx` 仍绑定本地草稿；新网关测试则因 `TauriVideoEditingGateway` 文件不存在而加载失败。
GREEN 新建真实 Tauri 网关，只调用 T2 的六个固定 command；Project/Timeline/Job 以及分页根
全部用 T1 zod schema 二次闭集解析，UUID 和创建/保存输入在 invoke 前拒绝。

项目与作业均以 100 条逐页读取，最多 100 页/10000 条；重复 cursor、重复领域 ID、跨项目
Timeline/Job、超量页和 malformed page 全部固定失败，不能无限循环或把私密字段带入 UI。
native error 只经共享 `nativeCommandErrorFields` 读取固定 code/retryable；写入
`outcome_uncertain` 保留不可重试语义，其余已知服务错误折叠为
`editing_service_unavailable`，未知对象/额外字段/私密 message 不反射。

逐文件 Review 找到两组缺口并先补 RED：最初误把 `Set.add()` 当布尔值，导致重复 cursor/ID
防线永不触发；以及 create/save/submit 只校验响应形状，未把响应语义绑定到本次请求。现改为
显式 `has` 后 `add`，创建回包必须逐字段等于输入，保存回包的 duration/tracks 必须等于草稿，
提交回包必须是本项目的 `queued` 作业。项目和作业双分页、重复 cursor、非法输入前置拒绝、
已知/未知错误矩阵均有直接测试；复审无未关闭 finding。

最终功能验收：剪辑 DTO、本地测试夹具、新 Tauri gateway、工作台与生产装配五组 Vitest
`48 passed`；全量 `pnpm typecheck`、改动文件 ESLint、正式 `pnpm build`、
`git diff --check` 全绿。生产 bundle 现只装配 `new TauriVideoEditingGateway()`，本地草稿只剩
test harness/单元测试调用。T3 正式完成。
