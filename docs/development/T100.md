## 结论先写：这 7px 不是某个 margin 写大了

任务交下来时的判断是「调一处 margin 就能消掉」。**逐层量完，这个前提不成立。**
整页 687.1px 里没有任何一个值是被写大的——每一项要么是 antd 默认值，
要么是本项目其它页面同样在用的约定，其中两项还是前面的任务**特意定成这样并写下了理由**的。

真正多出来的不是间距，是**一行重复的字**：卡片头 `新建剪辑项目` 就写在页签
`剪辑项目` 的正下方。它占 56px，而这一页只差 7px。

`main` 实得 **680px**。而 `main` 实测 **687.1px**，**超出 7.1px**（滚动条由此出现）。

## 为什么每一个「看起来能压」的地方都不能动

- **`.ant-empty` 的 32/32（能省 48px）**：`global.css:192` 上方留着一段记录——
  视频制作曾经在这里写过 `margin-block: 70px` 配 `min-height: 330px`，
  后来被删掉，理由写的是「**Removed rather than re-tuned — antd's own `Empty`
  spacing is what the rest of this product uses**」。现在再给 video-editing 写一条
  局部的 Empty 间距，就是把刚删掉的东西原样加回来；
- **`.video-editing { margin-top: 20px }`（能省 20px）**：T88 加它是因为
  视频剪辑和作品发布是仅有的两个标题行下间距为 **0** 的页面，其余 6 个都是 20px。
  改小就是把刚对齐的又拆散；
- **文本域 `rows={3}`（能省 22px）**：视频制作的文本域也是 `rows={3}`。
  改成 2 只会让视频剪辑变成唯一的例外；
- **`size="middle"` 的 16px 间隔**：`.settings-stack`、`.task-create-stack`、
  `.video-studio-new-form` 等全部在用。

**所以「压一处间距」这条路是没有的**——任何一处压下去，都是拿"和隔壁页面不一致"换 7px。

工作台和设置与诊断是本来就该滚的长页面。真正贴着 680px 这条线的是视频制作（678，差 2px 没超）
和视频剪辑（687.1，超 7px）——**两页结构完全一样**（同样 margin-top 20、同样 Tabs、
同样 Card + Empty、同样 `size="middle"`、同样 `rows={3}`），只差 9px 的内容量。

## 那改了什么：删掉卡片头「新建剪辑项目」

改动一行 JSX：`<Card className="video-editing-panel" title="新建剪辑项目">` → `<Card className="video-editing-panel">`。

**这个值原本为什么是那样**：页面搭起来的时候按"卡片要有标题"的惯性给了一个标题，
当时没有人把整屏连起来看过。

**为什么它是该动的那个**：屏幕上从上往下连着四行——

```
剪辑项目            ← 页签（导航，必须留）
新建剪辑项目         ← 卡片头            ← 56px
输入项目标题和要剪辑的素材引用…   ← 说明（告诉你要做什么）
[创建剪辑项目]       ← 按钮（告诉你会发生什么）
```

四行里都有「剪辑项目」，加上下面的「还没有剪辑项目」「创建剪辑项目后…」，
一屏之内这四个字出现 **6 次**。四行里卡片头是唯一一个不提供新信息的：
页签说明这是哪一步，说明句说要做什么，按钮说会发生什么。

**这不是我发明的取舍——隔壁页面已经做过同一个决定并写下了理由。**
`VideoStudio.tsx:490` 附近留着：

> No card head. 它说「新建视频」，正上方的页签也说「新建视频」——两者相距 17px，
> 同样三个字写了两遍。这个头占掉了这一步仅有的一屏中的 **56px**，
> 而它告诉操作者的东西，页签、页面标题和侧栏入口已经说过三遍。

而且这条约定在仓库里是**有测试守着**的：`e2e/video-studio-density.spec.ts`
既有 `「新建视频」在页面上只出现一次`，也有 `「新建视频」页签一屏装得下 › 整页不需要滚动`。
视频剪辑这次补的正是同一对保障中缺的那一半。

**改完为什么仍然合理**：卡片本身没有被压——内边距、字号、间距、行高全部保持 antd 默认，
一个像素都没有挤。卡片现在的形状与视频制作的「新建视频」卡片完全一致：
无头，首行是解释它是干什么的次要文字。截图见下，两页并排看是同一个样式。

**顺带修了一行文档**：`docs/user-help.md:280` 原来把「新建剪辑项目」当成界面上的一个卡片名引用，
删掉头之后界面上不再有这个名字，所以改写成按实际界面描述（在「剪辑项目」页填…，再点「创建剪辑项目」）。
不改的话就是我自己制造了一处文档与界面不符。

## 四个尺寸的修前 / 修后实测

`.desktop-content` 的 `scrollHeight − clientHeight`，0 表示不出滚动条：

| 视窗 | 修前（空状态） | 修后（空状态） | 修后（已建一个项目） |
| --- | --- | --- | --- |
| **1280×800（生产默认）** | **溢出 7** | **0**（`main` 687.1 → 632，余量 48px） | **0** |
| 960×640（最小） | 溢出 167 | 溢出 39 | 溢出 127 |
| 1440×900 | 0 | 0 | 0 |
| 1920×1080 | 0 | 0 | 0 |

960×640 是用户能拖到的最小尺寸，本来就装不下整页——按任务约定这是正常的，
不是本次要消灭的目标；顺带从 167 降到 39。

余量 48px 是有意留的：修完只差 1px 的话，下一句文案就会把它重新顶破。

## 实际看了页面，不是只信测试

按要求截图人工核对了四张（1280×800，无头）：

1. **修前空状态**：卡片头「新建剪辑项目」是一条占满宽度、下面带分隔线的色带，
   正下方 67px 处就是页签「剪辑项目」；页面底部被截断，出现滚动条；
2. **修后空状态**：卡片直接以说明句起头，底部留白充足，无滚动条；
3. **修后已建项目**：无头的表单卡片 + 有头的「剪辑项目列表」卡片。
   两张卡片一个无头一个有头并不别扭——页面上唯一的卡片头正好落在真正需要命名的那个（列表）上；
4. **修后创建失败**：错误提示整条可见，被截掉的只有空状态卡片的下边缘（见上文失败矩阵那一条）。

另外单独截了**视频制作**的「新建视频」页做对照，确认修后的视频剪辑与它是同一个形状
（无头、首行次要说明文字）。看完即删，`test-results/` 已清空。

### ⚠️ 创建失败这一屏仍然会滚 8px，本次没有修

写这份矩阵时我一开始按 `632 + 40 = 672 < 680` 推算它"仍不溢出"，
**差点把一条没量过的算术当成实测结论写进来**。实际去量是 **8px**：
错误 `Alert` 是表单 `Space` 的最后一项，除自身 40px 外还带一个 16px 间隔，
合计 56px，比修完剩下的 48px 余量多 8px。

**没有顺手修它，理由和上面一致**：这一页已经没有任何"多写了的间距"可以再让 8px 出来。
唯一能凑出 8px 的做法是再造一个改动——比如错误出现时把空状态卡片藏掉——
那是为了消掉 8px 去发明一个没有独立理由的行为变化，正是本任务一开始就排除的做法。

实拍确认这一屏的影响是有限的：**错误提示本身完整可见，被截掉的只是空状态卡片的下边缘**，
用户不会漏看任何信息，代价只是出现滚动条。

**这条留作已知状态交给调用方判断**，没有在台账里冒充已修。

## 真实边界

- 全部证据来自 **UI Harness + Playwright 无头浏览器**，按项目规则只能证明 React 版式与交互，
  **不能**证明真实 Tauri App、WebView 与签名包中的表现；
- 尤其是**滚动条的视觉表现按平台不同**：macOS WebView 默认是覆盖式滚动条（滚动时才出现），
  Windows WebView2 是经典滚动条（常驻并占约 15px 宽度，还会压窄内容列）。
  本次只在 Chromium 无头下量了溢出量，**两个目标平台的正式包表现需要分别复核**；
- 因此本任务标 `🔍 待验收`，等签名包上的人工复核。
