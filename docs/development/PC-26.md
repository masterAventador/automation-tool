## 0. 为什么开这个任务

PC-07 的合成（`voiceover.synthesize_voiceover`）与测长（`measure_audio_seconds`）
已真实验收（2.080/7.120/4.320 秒），但从未被链路调用：`_segments_for` 里
`BeatPlan(voice_seconds=None)` 恒为 None，PC-08 的 `max(语音, 动效)` 语音臂
一次没被选中过，成片无声。

## 1. 设计（依路线图「P0-1d 三个时长来源」定案：语音主导、画面跟随）

1. **文本归属**：`script.beats[i]` 就是 `storyboard.beats[i]` 的旁白词，一一对应。
   一句话契约提示词加上这条对应关系；authoring 校验两者条数相等
   （新拒绝语 `script beats must match storyboard beats one to one`，进词表）。
2. **合成时机**：`author()` 里 storyboard 过验后、装配之前逐拍合成并测真秒数，
   喂进 `BeatPlan.voice_seconds`——`plan_film` 的 max 臂、film 级预算拒绝
   （`FilmOverBudget`，渲染前拒）全部现成，不用改。
3. **注入模式**（同 `slot_probe` 先例）：`MotionAuthoringAgent(narrator=...)`，
   `narrator(beat_id, text) -> (workspace 相对音频路径, 秒数)`；`None`=无声
   （旧调用方行为不变）。真 narrator 由 entry 构造：TTS 凭据与视频创作同
   apiKey，模型 id 从 `bailian-model-catalog.v1.json` 的 `voiceover` 用途读；
   音频经 `workspace.write_bytes` 落 `narration/<beat_id>.wav`。
4. **ffprobe 跨层传入**（同 `browserExecutable` 先例）：执行器包不带 ffprobe，
   测长需要 App 的 media-toolchain 路径 → authoring 请求加可选字段
   `ffprobeExecutable`（Rust `runtime.toolchain.ffprobe_path()` → entry 校验
   绝对路径 → 两个新 entry token 进 refusal 契约）。缺字段=不合成（老 App 行为）。
5. **TTS 失败不许静默降级成无声片**：闭合拒绝（新 token，归非拒绝类——
   服务故障不是用户句子的错；注意 `model_transport_failed` 类被测试钉死为
   单元素，入类时要同步改那条断言或另立类）。
6. **answer 形状**：段带 `narrationAudio`（workspace 相对路径）与
   `narrationSeconds`；App 拼完视频后把各段旁白按段起点 adelay 进音轨混音
   （ffmpeg amix；「旁白天然是 ffmpeg 的另一条输入轨」）。
7. **判据**（台账行原文）：MP4 每段语音在本段内说完、总长 = Σ max()、
   ffprobe 读出音轨（`codec_type=audio`）；PC-08 的 🔍 一并收口。

## 2. 分片与续点

- **片 1（agent 语音臂）✅ 2026-07-31 先红后绿**：narrator 注入（None=无声，
  旧行为逐字节不变——无声下零件拍 144 帧的断言先按 180 写错、被跑红纠正：
  零件拍镜头长 = max(动效, 语音)，声明时长只在模板拍兜底）；旁白在装配前
  逐拍合成（修复轮只许改文案、拍数与 id 字节不变，故只合成一次）；条数
  1:1 校验；TTS 失败闭合拒绝不许静默出无声片；无目录安装不花 TTS 保持无声
  （单次整片捕捉没有逐拍分段可供语音臂消费）。7 条新单测；语音臂首次被
  选中的证据：8s 旁白 × 4.8s 动效 → 240 帧。3 条新拒绝语进词表
  （134 fixedReasons；`voiceover synthesis failed` 归 `model_transport_failed`
  ——TTS 轮失败是到模型服务的传输失败，不是用户句子的错，被钉死的单元素
  类断言同步放宽）。GREEN：backend 3393 / agent 109 / Rust 30；
- **片 2（entry + 真 narrator）✅ 2026-07-31 先红后绿**：请求可选字段
  `ffprobeExecutable`（缺失=无声老行为；空/相对路径两个新 token 归
  `app_request_invalid`，136 fixedReasons）；`voiceover_config_from_catalog`
  从 `load_voiceover_config` 拆出（子进程没有 secret 文件，key 随请求到达，
  同一段目录解析两个入口）；真 narrator 闭包 = synthesize_voiceover →
  `narration/<beat_id>.wav` → measure_audio_seconds(App 传入的 ffprobe)；
  answer 段带 `narrationAudio`/`narrationSeconds`，**无声片形状逐字节不变**
  （正式 App 段解析 deny_unknown_fields，有专测钉住旧键集）。打包契约门禁
  当场抓到 `bailian-model-catalog.v1.json` 未进执行器 spec——「仓库全绿、
  客户包起不来」那类，补进 spec 后 3399 全绿；
- **片 3（Rust）✅ 2026-07-31 先红后绿**：请求带 `ffprobeExecutable`
  （`runtime.toolchain.ffprobe_path()`，六参编译红先行）；
  `RenderSegmentAnswer` 旁白成对可选（serde default，老答案不变）；
  `accepted_segments` 校验音频真在工作区、秒数装得进这一拍
  （≤ 帧数/fps + 半帧浮点余量——子进程按 max(语音,动效) 排的镜头，
  一条比自己镜头还长的旁白说明答案不是那个 plan 产的）；
  `narration_mix_arguments` 纯函数编排 ffmpeg 参数（每条旁白 adelay 到
  自己镜头的起点 = 前序帧数和/fps，amix normalize=0——各镜头互不重叠
  不需要 headroom，`-c:v copy` 画面流禁止重编码）；
  `mix_narration_into_film` 混完重探（帧数/画布/像素格式不变才换文件，
  失败绝不拿坏片换掉已验证的片）；渲染循环 join 之后调用，无声片直接返回
  ——旁白之前的管线逐字节不变。真 ffmpeg 冒烟：逐字同一条滤镜链出片
  h264 6.0s + aac 5.5s（第二条旁白正确落在 3.0-5.5s）。
  `inspect_film` 加音轨断言：有目录的片子没音轨=TTS/混音那半静默脱落，
  从此 T36 门禁直接抓。cargo 全量 0 失败（32 条 authoring 测试含新增 2 条）；
- **片 4（真实验收）**：真 TTS + 真渲染出有声片，ffprobe 音轨读数 +
  逐段说完判据；PC-08 补验收同轮收口。
