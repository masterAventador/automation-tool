## 开工前【先定】

LE-12 复用已经在生产组合根中持有的 `LocalVideoOrchestrator`，不另起第二套进程管理器。
既有实现已经提供 Worker 自选随机 loopback 端口、32 字节随机会话令牌、stdin bootstrap、
ready/health/command HMAC、有限次崩溃重启、取消、stop/stop_all 和进程树回收。本 LE 不把这些
能力重新实现一遍，而是在同一条认证协议上补本地剪辑作业的强类型命令、进度、终态、紧停、
持久作业账本和 App 重启恢复。

本地剪辑 Worker 固定为 Python，首个 bootstrap 必须由 Rust 把 LE-07 已完整校验的
ffmpeg/ffprobe 绝对路径一次性下发。路径只进认证 stdin，不进 argv、环境、WebView、状态、
日志或错误；Python 接收端直接构造 `PackagedMediaTools` 并立即重验，不做发现、不查 PATH、
不读环境变量。旧素材 Worker 和 Node 动效 Worker 的 bootstrap 形状保持不变。

## T1 RED 目标

1. Rust 新增只允许挂到 Python Worker、只能设置一次的媒体工具对；两个路径都必须是绝对、
   普通、可执行、非链接文件，且不得由同一路径冒充两个工具。
2. 工具路径只能出现在带 256-bit 会话令牌的 stdin bootstrap；状态与 `Debug` 不得泄露路径，
   旧 Worker 在没有该配置时不得多出键。
3. Python 新本地剪辑 bootstrap parser 只接受唯一版本、唯一 Worker 身份、禁用 Web UI、无浏览器/
   模型配置、精确根键和精确 `mediaTools` 子键；重复键、多行、超限、错误 UTF-8、错误类型、相对
   路径、链接根和不可执行工具全部 fail closed。
4. Python parser 返回已经构造并重验的 `PackagedMediaTools`、解析后的私有会话密钥与规范资产根；
   不读取 argv、PATH 或环境变量。
5. 首次 RED 必须分别失败于 Rust 配置类型/挂载方法和 Python 接收模块不存在。

## T1 RED、GREEN、代码审查与功能验收

Rust 两条测试先写后跑，首次精确编译失败于 `VideoWorkerMediaToolsConfiguration` 和
`with_media_tools` 不存在；Python 测试首次收集失败于
`automation_tool.executor.local_editing_worker` 不存在。两个 RED 都由目标能力尚未实现造成。

GREEN 后，Rust 的 `VideoWorkerMediaToolsConfiguration` 在构造时复用进程编排器的可执行文件
边界校验，并拒绝同一路径；`with_media_tools` 只接受 Python Worker 且单次赋值。序列化字段
使用 `skip_serializing_if`，因此旧 Python 素材 Worker 与 Node 动效 Worker 没有配置时仍收到
原来的精确键集。真实临时 Worker 从 stdin 记录 `mediaTools`，完成认证 ready、health、stop，
并证明 ffmpeg/ffprobe 两条路径精确往返、状态和配置 `Debug` 均不含私有路径。

Python 新 parser 把 bootstrap 限在 16 KiB 和恰好一行，拒绝重复 JSON 键并要求 64 位小写
十六进制令牌。资产根和两个二进制都重验为本机绝对非链接对象；媒体工具直接构造
`PackagedMediaTools`，没有发现/PATH/env 分支。异常统一为无路径的
`local editing worker bootstrap rejected`，对象 `repr` 同时隐藏路径和令牌。

提交前结构化 Review 检查了：旧 Worker 键集兼容、Python/Node 身份隔离、单次配置、路径和令牌
泄漏、重复键、链接祖先、工具替换时的二次校验、异常折叠及平台差异。Review 补了 Node Worker
拒绝媒体工具对，以及资产根控制字符/不存在/最终链接/链接祖先/解析 I/O 异常、非文本工具路径和
同一工具冒充两项的直接测试；复审无未关闭 finding。

macOS 专项结果：Python `26 passed`，目标模块 73 条语句、20 个分支全部 `100%`；Ruff 与严格
mypy 全绿；Rust Worker 编排 `20 passed, 3 ignored`，媒体工具链 `9 passed`。Windows 真机在
`F:\automation-tool` 同步实现检查点后，Python 同样 `26 passed`，媒体工具链 `6 passed`。
Windows 首跑还真实发现专属 Worker test 在 LE-10 增加 canvas/source window 后没有同步构造

真机复跑为 `1 passed, 3 ignored`。这项平台漂移修复检查点为 `e5bfa6ea`，没有把编译失败误报

## T2 RED 目标

1. 定义版本化、严格闭集的本地剪辑作业命令和 Worker 事件；作业身份用 UUID v4，命令/事件必须
   绑定 Worker kind、协议版本、作业 ID 和规范 payload 后再做 HMAC，不能只靠 bearer token。
2. 开始命令只携带 Executor 所需的本机计划/绑定身份，不把路径回送 WebView 或 Control Plane；
   进度必须单调、有界并区分阶段，终态只能出现一次。
3. 普通取消是作业级协作取消，紧停必须由 Rust 立即终止 Worker 进程树；二者发生竞争时终态确定，
   迟到进度或伪造 proof 不得复活作业。
4. `WORKSPACE_UNUSABLE` 必须作为固定、不可重试的作业失败分类完整往返，不得折叠成素材损坏或
   普通进程失败；错误正文和诊断不携带私有路径。
5. T2 只交付运行期协议与内存态控制；持久账本和 App 重启恢复归 T3/T4。首次 RED 必须证明当前
   编排器没有本地剪辑 start/progress/emergency-stop 入口。

## T2 RED、GREEN、代码审查与功能验收

Python 作业协议测试先写后跑，首次收集精确失败于 `LocalEditingStartCommand` 等类型不存在；
Rust 五条 Worker 生命周期测试首次编译精确失败于 `VideoWorkerLocalEditingJobRequest`、
`start_local_editing_job`、`try_local_editing_event`、协作取消、紧停和终态确认入口不存在。两个
RED 都由目标能力缺失造成。

GREEN 把 start 命令固定为 job/project/timeline 三个 UUID v4 和正 revision，不携带任何本机路径；
规范 `editing` JSON 与 command/kind/protocol/job 一起进入 HMAC。Worker 同时只拥有一个作业，
活动终态必须由调度器显式确认后才能让位给下一作业。进度事件用 preparing/rendering/publishing
闭集阶段和 0～1000 千分比，Rust 与 Python 双侧都要求首事件为 preparing/0、阶段和总进度只前进
不后退。成功必须发生在 publishing/1000 并带规范 Artifact UUID v4；失败、取消和成功都只能
形成一次终态。

普通取消只写认证命令、不抢读 stdout，最终继续由轮询读到的认证终态决定，所以“取消已发出但
成片先完成”合法收敛为 succeeded；重复取消拒绝。紧停不等待 Worker ACK，直接从唯一编排器移除
Python Worker 并终止完整进程树。旧同步 `cancel` 在有本地剪辑作业时拒绝，避免它偷走进度事件。
`workspace_unusable` 保持独立、不可混淆的 Worker 失败码；`worker_lost` 不允许由仍活着的 Worker
自报，只能由 T3/T4 的 App 调度器根据真实进程丢失事实生成。

跨语言 GREEN 首轮真实暴露 wire 漂移：Python 发 `progressPermille`，Rust 自动 camelCase 把
`progress_per_mille` 推导成了 `progressPerMille`，三条 fake-Worker 纵向测试全部得到
`AuthenticationRejected`。修复不是放宽 parser，而是给字段加精确 wire 名；复验后 Rust 生成的
start proof 能被 Python fake 独立重算接受，Python fake 生成的 progress/failed/succeeded/cancelled
proof 也由 Rust 独立重算接受。

逐文件结构化 Review 又关闭四项 finding：补齐取消与成功竞态、伪造事件和单作业所有权用例；
移除 Worker 自报 `worker_lost`；终态事件改为先完成有界编码再释放 Python 活动作业，避免编码失败
丢失状态；Python semver parser 从只收三段数字改为与 Rust launcher 一致接受合法 prerelease/build，
同时继续拒绝前导零数字标识。Clippy 新报的九参数 helper 也重构成明确认证 envelope；余下 warning
均为本任务前已有的 `lib.rs`/旧测试问题，T2 没有新增 warning。最终复审无未关闭 finding。

macOS 最终专项：Python bootstrap + 作业协议 `55 passed`，目标模块 234 条语句、64 个分支全部
`100%`，Ruff 与严格 mypy 全绿；Rust Worker 编排 `25 passed, 3 ignored`，媒体工具链 `9 passed`。
Windows 真机同步 `adaf4d7e` 后，Python 同组也是 `55 passed`；Windows Worker 目标
`1 passed, 3 ignored`，媒体工具链 `6 passed`，证明新增 Rust API 在原生 Windows 目标编译通过且
既有进程树/工具链门禁未退化。T2 没有改数据库、HTTP 或真实 FFmpeg 执行面，因此按约定不重复跑
完整 `backend/tests/integration`；专项覆盖已经跨越 Python codec、Rust 进程边界和两种桌面目标。

T2 实现检查点为 `adaf4d7e`，已推送。T2 正式完成。

## T3 RED 目标

1. 在 App 私有状态目录建立唯一版本化本地剪辑作业账本，原子保存 job/project/timeline/revision、
   当前状态、单调进度、取消门闩、Worker restart generation 和最后确认终态；不得存令牌、用户文本、
   私有来源路径或未脱敏诊断。
2. 账本写入必须使用受限目录、受限文件权限、同目录临时文件 + 原子替换；链接/reparse、错误权限、
   超限、重复键、未知版本、截断和身份漂移全部 fail closed，错误不回显状态目录。
3. 调度状态严格对齐 `EditingJob`：queued→running，cancel race 进入 cancelling 后只由 succeeded/
   failed/cancelled 收口；从未派发的 cancelling 由调度器直接确认 cancelled。`workspace_unusable` 映射
   到明确资源/工作区失败，不得映成素材损坏；App 观察到 Worker 丢失才生成 worker_lost。
4. 每个认证进度/终态必须先以 CAS 写入本地账本，再向上层暴露；重复同值幂等，revision/进度倒退、
   终态改写或别的 job 冒领均拒绝。
5. T3 交付持久账本与单进程调度状态，不在本项自动重启作业；崩溃和 App 重开恢复归 T4。首次 RED
   必须失败于当前没有任何持久本地剪辑 job ledger/checkpoint。

## T3 RED、GREEN、代码审查与功能验收

Rust 账本测试先写后跑，首次编译精确失败于 `local_editing_job_ledger` 模块不存在。GREEN 后，
`LocalEditingJobScheduler` 作为生产组合根持有的 App 调度状态，把 job/project/timeline 身份、时间轴
revision、`queued/running/cancelling/succeeded/failed/cancelled` 状态、阶段与千分比进度、Worker
generation、本地 revision、失败码和成片 Artifact ID 保存到既有 `VideoJobWorkspaceStore` 的
`local-editing-job.v1` 检查点。检查点不含令牌、用户文本、来源路径或诊断；快照 `Debug` 和全部错误
正文固定脱敏。

调度器派发前先持久化 running，认证 Worker 事件先经过状态机和 revision 校验并原子写盘，随后才
返回上层。纵向 fake Worker 的 preparing/rendering/publishing/succeeded 四个事件每次返回后，都由
一个全新调度器从磁盘重开并逐字段相等；重复同值不加 revision，进度倒退、终态复活、身份漂移和
无效成功事实全部拒绝。取消门闩允许完成赢得竞争；从未派发的 queued 取消由 App 直接确认 cancelled。
`workspace_unusable` 映射为领域的 `resource_exhausted`，不冒充素材损坏；`worker_lost` 只允许从已派发
的 running/cancelling 生成。

账本复用工作区层已经审过的 0700 目录、同目录 0600 临时文件、fsync 和原子替换，并补强读取侧：
检查点打开后再次核对文件身份与 0600 权限。链接/reparse、超限、截断、未知版本、未知/缺失/重复键、
非法枚举、revision/身份漂移全部 fail closed。结构化 Review 真实找到并以 RED 关闭三类缺口：缺失
Option 键原先会被 serde 当成 null；0640 检查点原先仍可读；未派发 job 原先可误判 worker_lost，且
job/project 身份碰撞被错报为存储故障。Review 还把“终态已落盘但 Worker 内存确认恰逢并发退出”定为
以磁盘终态为准，不能把已确认结果重新隐藏。复审无未关闭 finding。

macOS 最终专项：Worker 编排 `26 passed, 3 ignored`，账本 `8 passed`，跨平台账本门禁 `1 passed`，

## T4 RED 目标

1. 为持久账本增加启动期 reconciliation：枚举受控工作区，但只接受精确 T3 checkpoint；终态只重开
   展示，queued 保持可派发，running 才允许恢复，损坏或冒领记录不得启动 Worker。
2. Worker 崩溃后只在有限 generation 预算内从同一份 path-free 身份重新派发；每次恢复意图必须先
   原子增加账本 generation/revision，再发 Worker 命令。预算耗尽、替换 Worker 启动失败或身份不符
   均固定收敛为 `failed/worker_lost`，不得无限重启或复活终态。
3. App 退出留下的 running 在下次启动时按同一有限预算从头重跑；遗留 cancelling 不重放取消中的
   不确定作业，而按 LE-04 既定责任收敛为 `failed/worker_lost`。重复 reconciliation 必须幂等。
4. 恢复过程中允许取消抢先：尚未重新派发则 App 直接 cancelled，已经重新派发则保持 cancelling，
   最终仍只接受认证的 succeeded/failed/cancelled；旧 Worker 的迟到事件不得跨 generation 入账。
5. 首次 RED 必须证明当前调度器没有启动期枚举/reconcile API，也不能把已持久 running 安全绑定到
   新 Worker generation。T4 不新增 WebView 路径、令牌或任意本机路径出口。
