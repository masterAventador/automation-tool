LE-12 复用已经在生产组合根中持有的 `LocalVideoOrchestrator`，不另起第二套进程管理器。
既有实现已经提供 Worker 自选随机 loopback 端口、32 字节随机会话令牌、stdin bootstrap、
ready/health/command HMAC、有限次崩溃重启、取消、stop/stop_all 和进程树回收。本 LE 不把这些
能力重新实现一遍，而是在同一条认证协议上补本地剪辑作业的强类型命令、进度、终态、紧停、
持久作业账本和 App 重启恢复。

本地剪辑 Worker 固定为 Python，首个 bootstrap 必须由 Rust 把 LE-07 已完整校验的
ffmpeg/ffprobe 绝对路径一次性下发。路径只进认证 stdin，不进 argv、环境、WebView、状态、
日志或错误；Python 接收端直接构造 `PackagedMediaTools` 并立即重验，不做发现、不查 PATH、
不读环境变量。旧素材 Worker 和 Node 动效 Worker 的 bootstrap 形状保持不变。

## T1 RED 目标

1. Rust 新增只允许挂到 Python Worker、只能设置一次的媒体工具对；两个路径都必须是绝对、
   普通、可执行、非链接文件，且不得由同一路径冒充两个工具。
2. 工具路径只能出现在带 256-bit 会话令牌的 stdin bootstrap；状态与 `Debug` 不得泄露路径，
   旧 Worker 在没有该配置时不得多出键。
3. Python 新本地剪辑 bootstrap parser 只接受唯一版本、唯一 Worker 身份、禁用 Web UI、无浏览器/
   模型配置、精确根键和精确 `mediaTools` 子键；重复键、多行、超限、错误 UTF-8、错误类型、相对
   路径、链接根和不可执行工具全部 fail closed。
4. Python parser 返回已经构造并重验的 `PackagedMediaTools`、解析后的私有会话密钥与规范资产根；
   不读取 argv、PATH 或环境变量。
5. 首次 RED 必须分别失败于 Rust 配置类型/挂载方法和 Python 接收模块不存在。

## T1 RED、GREEN、代码审查与功能验收

Rust 两条测试先写后跑，首次精确编译失败于 `VideoWorkerMediaToolsConfiguration` 和
`with_media_tools` 不存在；Python 测试首次收集失败于
`automation_tool.executor.local_editing_worker` 不存在。两个 RED 都由目标能力尚未实现造成。

GREEN 后，Rust 的 `VideoWorkerMediaToolsConfiguration` 在构造时复用进程编排器的可执行文件
边界校验，并拒绝同一路径；`with_media_tools` 只接受 Python Worker 且单次赋值。序列化字段
使用 `skip_serializing_if`，因此旧 Python 素材 Worker 与 Node 动效 Worker 没有配置时仍收到
原来的精确键集。真实临时 Worker 从 stdin 记录 `mediaTools`，完成认证 ready、health、stop，
并证明 ffmpeg/ffprobe 两条路径精确往返、状态和配置 `Debug` 均不含私有路径。

Python 新 parser 把 bootstrap 限在 16 KiB 和恰好一行，拒绝重复 JSON 键并要求 64 位小写
十六进制令牌。资产根和两个二进制都重验为本机绝对非链接对象；媒体工具直接构造
`PackagedMediaTools`，没有发现/PATH/env 分支。异常统一为无路径的
`local editing worker bootstrap rejected`，对象 `repr` 同时隐藏路径和令牌。

提交前结构化 Review 检查了：旧 Worker 键集兼容、Python/Node 身份隔离、单次配置、路径和令牌
泄漏、重复键、链接祖先、工具替换时的二次校验、异常折叠及平台差异。Review 补了 Node Worker
拒绝媒体工具对，以及资产根控制字符/不存在/最终链接/链接祖先/解析 I/O 异常、非文本工具路径和
同一工具冒充两项的直接测试；复审无未关闭 finding。

macOS 专项结果：Python `26 passed`，目标模块 73 条语句、20 个分支全部 `100%`；Ruff 与严格
mypy 全绿；Rust Worker 编排 `20 passed, 3 ignored`，媒体工具链 `9 passed`。Windows 真机在

## T2 RED 目标

1. 定义版本化、严格闭集的本地剪辑作业命令和 Worker 事件；作业身份用 UUID v4，命令/事件必须
   绑定 Worker kind、协议版本、作业 ID 和规范 payload 后再做 HMAC，不能只靠 bearer token。
2. 开始命令只携带 Executor 所需的本机计划/绑定身份，不把路径回送 WebView 或 Control Plane；
   进度必须单调、有界并区分阶段，终态只能出现一次。
3. 普通取消是作业级协作取消，紧停必须由 Rust 立即终止 Worker 进程树；二者发生竞争时终态确定，
   迟到进度或伪造 proof 不得复活作业。
4. `WORKSPACE_UNUSABLE` 必须作为固定、不可重试的作业失败分类完整往返，不得折叠成素材损坏或
   普通进程失败；错误正文和诊断不携带私有路径。
5. T2 只交付运行期协议与内存态控制；持久账本和 App 重启恢复归 T3/T4。首次 RED 必须证明当前
   编排器没有本地剪辑 start/progress/emergency-stop 入口。
