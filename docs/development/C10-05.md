# C10-05 Secret 管理

- 状态：✅ 已完成
- 日期：2026-07-23
- 范围：把数据库 URL、账号密码 Pepper、Session 指纹 key、账号运维 capability digest 与动作授权私钥从固定只读运行时文件交付给生产容器，并冻结生成、最小权限、轮换、重启和泄漏扫描边界；不创建云 Secret Store、不写入真实 Secret
- 前置依赖：C10-02 生产容器、C10-03 PostgreSQL 身份和 U9-03 账号 Session 已完成
- RED：先新增机器可读 Secret inventory、文件装载安全契约和真实容器验收，要求生产入口拒绝 Secret 环境变量/argv、只接受固定 `/run/secrets` 普通文件、限制大小和权限、拒绝 symlink/换行/不安全 mode、进程环境/镜像/日志不含 Secret，并证明轮换只在受控重启后生效；当前统一装载边界、inventory 和 C10-05 验收不存在，测试应准确失败
- GREEN：新增 `deploy/secrets/inventory.v1.json` 作为唯一 inventory，生产镜像固定 `files` 模式；数据库 URL、密码 Pepper、账号指纹 key、运维 capability digest 和动作授权私钥只从 `/run/secrets` 下五个固定文件名读取，Secret path 不是配置输入
- 文件边界：`O_NOFOLLOW + fstat` 只接受 runtime UID 自有 `0400` 或 root/runtime-group `0440` 普通文件；拒绝 symlink、其他 owner、任意写/执行/other-read、超过 8192 bytes、空值、非 UTF-8、首尾空白、换行和 NUL；file 模式发现任一同名 Secret 环境变量立即 fail closed
- 体系澄清：账号 access/refresh Session 与设备 credential 都是 CSPRNG opaque secret，服务端只保存 digest，因此不新增 Session 签名 Secret 或设备 credential 签发私钥；设备 Ed25519 私钥仍只在 App，服务端持有设备公钥；持久服务端签名私钥是既有动作授权 key
- 真实验收：PostgreSQL 使用 `POSTGRES_PASSWORD_FILE`，Control Plane/Alembic 使用只读 named-volume Secret，所有 Secret 值只经容器 stdin 初始化；验证镜像、argv、container config、`/proc/1/environ` 和日志零 Secret，unsafe mode 与 Secret env 被拒绝，无宿主端口；在线替换 DB Secret 不影响旧进程，受控重启读取坏值并 fail closed，恢复正确值后重启健康
- 回归：C10-02 镜像、C10-03 迁移/备份恢复、C10-04 TLS 链均已切换文件 Secret 并重新通过；Node 契约 183/183；后端 2373 passed、5 skipped，`16022/16022` 语句与 `3696/3696` 分支 100%；Ruff、格式和 Mypy 全绿
- 清理与边界：所有容器、网络、Secret volume 和镜像按任务唯一名称清除且零残留；没有创建云 Secret Store、写入真实 Secret、修改云 IAM 或执行部署，C10-08 获得用户明确授权后才产生云端事实
