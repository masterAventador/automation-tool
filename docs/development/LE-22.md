# LE-22 macOS 正式包纵向验收

状态：待真实包验收

用户可操作：是

## 边界与拆分

本任务只验证 macOS 正式包内已经交付的本地视频剪辑能力，不增加业务功能。验收必须从
新装 App 的正常页面导入一条真实人声视频，经一句话智能剪辑生成草稿和成片，再从正式
PostgreSQL、Timeline、Job、Artifact 与 ffprobe 结果交叉核对。有人声段必须形成同源
`ambient` 原声轨与转写字幕，且不得生成 `narration` TTS 轨。

1. T1：正式包用户旅程、受控人声素材和机器可读证据契约；
2. T2：复用生产 release assembly 构建并安装隔离 macOS 包，逐项核对随包运行时；
3. T3：真实模型纵向执行、Code Review、专项/必要全量门禁与路线图收口。

## 当前约束

真实旅程会把受控人声素材、抽帧和固定提示词发送给外部模型；当前尚无该外发授权。
完整包还依赖 LE-20 被审批器拒绝过的 PyInstaller 候选构建。实现与纯本地门禁可以继续，
但在两项条件满足前不得把 Harness、debug App 或分层测试冒充正式包验收。

## T1 正式包旅程与证据契约

状态：已完成

### TDD 与实现

RED 先固定两层缺口：Python 专项因 `le22_package_evidence` 不存在而收集失败；前端结构验收
因 `smart-edit-package.spec.ts` 不存在而直接失败。Green 后，正式页面旅程从启动环境检查、
真实设置页保存模型配置、正式导入按钮导入一条人声视频、创建项目和“生成草稿”开始，
等待素材理解、第 1 版 Timeline、人声转写回写，再从时间轴确认只有原声轨、没有旁白轨，
最后从“提交与任务”页面提交并等待成片入库。旅程不走一键直出片、测试 Harness 网关或
浏览器存储替身。

纯 Python 证据边界严格核对唯一视频素材的真实人声区间与转写、`visual/ambient/caption`
三轨逐字段对齐、同一个 Material ID、无 `narration`、成功 Job 与 Artifact 身份；ffprobe
必须得到 H.264 `720×1280@20`、AAC、帧数、与 Timeline 相差不超过 100 ms 的真实时长
及非空产物字节。runner 后续还必须把源人声窗口和成片都解为 8 kHz 单声道 PCM，以 20 ms
RMS 包络在 ±200 ms 内求最佳相关性；这能在图结构之外继续拒绝“实际混入 TTS”的成片。

### Code Review 与功能验收

首轮 Review 发现畸形 ffprobe stream 元素会泄漏原生 `AttributeError`，新增精确 RED 后统一
为固定 `LE-22 ffprobe evidence is invalid`；复审覆盖 UUID、区间顺序、同源身份、轨道闭集、
字幕等于转写、Artifact 时长与 PCM 边界，未发现剩余 actionable finding。

- 证据边界专项：`5 passed`；
- 正式包旅程结构验收：`1 passed`；
- 前端 TypeScript、改动面 ESLint、Python Ruff/格式与 `git diff --check` 全绿。

本单没有构建包、调用模型或生成成片，因此只标 T1 完成；T2/T3 与顶格 LE-22 继续实现中。

## T2 生产装配与隔离安装编排

状态：实现完成，待实包执行

### TDD 与实现

RED 先要求仓库提供 macOS 包 runner、独立 Tauri/WebDriver 配置和固定 `pnpm` 入口；首轮
因 runner 不存在而失败。Green 后，runner 复用生产 release assembly 装入已签名 Local
Executor、锁定 Chromium、三项视频运行时和 134 项动效目录，先核对组装后的 App，再制成
DMG、校验镜像、挂载并复制到全新隔离目录，最后重新核对从 DMG 取回的资源与代码签名。
它只通过允许的隐藏窗口和 WebDriver 挂载驱动自动化，产品仍沿正式资源解析、Rust 网络桥、
Control Plane、PostgreSQL 和本地 Worker 路径运行。

真实旅程使用随包 FFmpeg 把锁定人声样本制成一条受控视频，从正式页面完成配置、导入、
草稿和出片；随后从 PostgreSQL 收集 Material、Timeline、Job、Artifact 身份，以随包
ffprobe 和 PCM 包络核验 H.264/AAC、尺寸、帧数、时长与原声同源性。证据只保存成片、
ffprobe 和不含私有路径/密钥的机器可读摘要，源文件摘要必须保持不变。

### Code Review 与分层功能验收

首轮 Review 找到四项会削弱正式包证据的问题，并各自先加入失败断言：macOS 架构判断与
生产打包器可能漂移、DMG 回拷后的 App 没有再次核对内置浏览器、Control Plane 在隔离
PostgreSQL 退出后才停止、清理只覆盖视频 Worker 而未覆盖 App 与 Local Executor。
最小修复统一复用 `require_macos_target`，在组装前后各跑一次浏览器门禁，把控制面停机放进
数据库上下文内部，并按本次基线回收三个正式包进程；复审未发现剩余 actionable finding。

- 正式包编排结构验收：`1 passed`；
- 证据边界专项：`5 passed, 4 subtests passed`；
- runner 可由 Ruff 完整解析，前端 TypeScript、改动面 ESLint、Python Ruff/格式与
  `git diff --check` 全绿。

本阶段没有执行构建命令：它会进入当前未获准的 PyInstaller 候选构建，并在纵向旅程中把
受控人声、抽帧和固定提示词发送给外部模型。因此 debug 自动化壳、结构测试和分层证据均
不冒充正式包验收；T2/T3 及顶格 LE-22 保持待真实包验收。
