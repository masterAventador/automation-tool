# LE-22 macOS 正式包纵向验收

状态：已完成

用户可操作：是

## 边界与拆分

本任务只验证 macOS 正式包内已经交付的本地视频剪辑能力，不增加业务功能。验收必须从
新装 App 的正常页面导入一条真实人声视频，经一句话智能剪辑生成草稿和成片，再从正式
PostgreSQL、Timeline、Job、Artifact 与 ffprobe 结果交叉核对。有人声段必须形成同源
`ambient` 原声轨与转写字幕，且不得生成 `narration` TTS 轨。

1. T1：正式包用户旅程、受控人声素材和机器可读证据契约；
2. T2：复用生产 release assembly 构建并安装隔离 macOS 包，逐项核对随包运行时；
3. T3：真实模型纵向执行、Code Review、专项/必要全量门禁与路线图收口。

## 当前约束

受控人声素材、抽帧和固定提示词的外发已经获得授权，真实旅程已使用项目现有百炼密钥
完成。正式 App、DMG、隔离安装和模型纵向链路均有本机证据；没有进行 Apple notarization，
而 notarization 不属于本任务的功能验收条件。

## T1 正式包旅程与证据契约

状态：已完成

### TDD 与实现

RED 先固定两层缺口：Python 专项因 `le22_package_evidence` 不存在而收集失败；前端结构验收
因 `smart-edit-package.spec.ts` 不存在而直接失败。Green 后，正式页面旅程从启动环境检查、
真实设置页保存模型配置、正式导入按钮导入一条人声视频、创建项目和“生成草稿”开始，
等待素材理解、第 1 版 Timeline、人声转写回写，再从时间轴确认只有原声轨、没有旁白轨，
最后从“提交与任务”页面提交并等待成片入库。旅程不走一键直出片、测试 Harness 网关或
浏览器存储替身。

纯 Python 证据边界严格核对唯一视频素材的真实人声区间与转写、`visual/ambient/caption`
三轨逐字段对齐、同一个 Material ID、无 `narration`、成功 Job 与 Artifact 身份；ffprobe
必须得到 H.264 `720×1280@20`、AAC、帧数、与 Timeline 相差不超过 100 ms 的真实时长
及非空产物字节。runner 后续还必须把源人声窗口和成片都解为 8 kHz 单声道 PCM，以 20 ms
RMS 包络在 ±200 ms 内求最佳相关性；这能在图结构之外继续拒绝“实际混入 TTS”的成片。

### Code Review 与功能验收

字幕等于转写、Artifact 时长与 PCM 边界，未发现剩余 actionable finding。

- 正式包旅程结构验收：`1 passed`；

本单没有构建包、调用模型或生成成片，因此只标 T1 完成；T2/T3 与顶格 LE-22 继续实现中。

正式包真实旅程先后暴露并闭环了四类会直接阻断用户路径的问题：证据 SQL 使用不存在的
