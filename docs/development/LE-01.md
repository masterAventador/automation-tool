## 失败矩阵

- **迁移链断裂**：`0032`（`aliyun_editing_intents`）在链中间，`0033`
  （`bilibili_publish_reconciliations`）的 `down_revision` 直接指向它；若直接删除
  迁移文件会断链，已迁移到该版本的真实库也找不到升级路径、残留表不会被清理。
  应对：新增 `0035` drop 迁移（`down_revision` 指向链尾 `0034`），`downgrade`
  显式 `raise` 而不是重建供应商表；真实 PostgreSQL 集成测试
  `test_cloud_editing_tables_dropped.py` 断言 `upgrade head` 后三张表确实消失。
- **父包级联失败**：`domain/__init__.py` 曾重新导出 24 个云剪辑符号，删除子模块
  不同步清理会让整个 `domain` 包 import 失败，级联影响约 158 个导入方；Task 2 已
  清理并新增 `test_parent_packages_still_import` 区分「子模块没了」与
  「父包坏了」两种 `ModuleNotFoundError`。
- **前端类型检查失败**：`App.tsx` 中同一凭据入口的 import/prop 若不同步清理，
  `pnpm typecheck` 会因引用已删除模块报错；Task 4 已同步清理，本次 Step 11 的
  `pnpm --dir frontend typecheck` 实测 exit 0 确认无遗漏。
- **台账计数漂移**：`check_local_editing_roadmap_counts.py` 与
  `check_embedded_browser_video_roadmap.py` 各自守护两个台账文件的数字自洽；新
  守卫的三个 TDD 用例覆盖「总数被改错」与「小节标题计数与表格行数不符」两类漂移，
  且都用真实 CLI 子进程调用（非直接函数调用）验证。
- **xfail 误判**：若 Task 6 忘记去掉 `test_aliyun_editing_contract_file_is_gone`
  上的 `xfail` 装饰器，契约删除这一事实会被 `xfail` 静默吞掉而不会体现为「新增一
  个通过的强断言」；`strict=True` 把这种情况变成硬失败，本次已实测触发并处理。
