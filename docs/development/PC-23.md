## 目标

把 D6-10 从“App sidecar 与 runner 内第二个 Executor 争抢同一条命令”的失真编排，
改成一条真实、单执行器的桌面路径：

1. App 自己启动并管理正式签名 Executor 包；
2. 第一条发现命令保持活跃；
3. 第二条竞争任务在真实 App UI 显示 Installation busy；
4. UI 观察成立后释放第一条发现；
5. 同一个 Executor 完成候选收敛，App 正常退出并回收 sidecar。

仓储并发、Rust 423 映射和组件文案三层既有覆盖不改；本任务补的是第四层真实
App 用户路径。

## RED

改造前运行：

```bash
uv run --project backend --locked python scripts/run_d6_10_acceptance.py
```

稳定失败。数据库事实为：

```text
platform health=missing
attempts=[failed, failed]
commands=[task.discover acknowledged, task.discover acknowledged]
```

WebdriverIO 报：

```text
Competing Task did not show Installation busy
```

原因不是 UI 等待太短。启动门禁预装的普通生产 Executor 被 App sidecar 拉起后，
先于 runner 内的手写 Executor 消费命令；它的本地 ledger 没有抖音健康会话，
于是第一条发现立即 `login_required`/`failed`，竞争点击发生时已经不存在活跃
attempt。第二条也被同一 sidecar 接收并失败。

## 实现

### 验收专用签名包，不给生产代码加测试开关

新增：

- `backend/tests/fixtures/d6_10_executor.py`
- `backend/tests/fixtures/automation-tool-executor-d610.spec`

fixture 只替换 `ProductionDouyinDiscoveryOperation`，其余启动、bootstrap、签名包校验、
WebSocket、命令确认、事件与 App sidecar 生命周期全部沿用生产实现。spec 进入既有
PyInstaller 安全软链契约门禁。

生产包与生产源码没有 D6-10 分支；受控入口只被测试 fixture spec 打包。

### busy UI 是发现操作的释放闸门

受控发现收到第一条真实 `task.discover` 后记录
`discovery_waiting_for_busy_ui` 并等待 App data 内的信号文件。WebdriverIO 只有在
正文真实出现“当前设备已有任务正在运行”后才通过 Tauri command 写入该文件。

同一个 Executor 消费信号后依次记录：

```text
discovery_waiting_for_busy_ui
busy_ui_observed
discovery_completed
```

然后返回两个确定性候选。驱动要求事件逐项、逐序、仅出现一次，并要求信号已被
Executor 消费。因此“先完成、后伪造 busy 佐证”不能通过。

### App 拥有完整生命周期

`run_d6_10_acceptance.py` 不再交换第二张 Executor Session，也不再在线程里启动
`LocalExecutorProcess`。它先构建并签名测试包，装进真实 debug resource 布局，再由
App 启动 sidecar。

spec 最后调用既有 `exit_app_for_acceptance`，先执行
`shutdown_for_app_exit()`，再退出 App。runner 随后要求签名 Executor 进程在 30 秒内
自行消失；finally 中的精确终止只用于失败恢复，不计作 GREEN。

App 输出继续写私有临时文件，任何失败打印最后 60 行；成功或失败后临时文件自动删除，
不在 Application Support 留诊断残渣。

## GREEN

快速门禁：

```text
ruff: All checks passed
PyInstaller bundle contract: 7 passed
```

真实桌面全链路：

```text
[D6-10] Building the controlled real signed PyInstaller Executor
[D6-10] Starting isolated PostgreSQL
[D6-10] Applying the production Alembic migration chain
[D6-10] Starting the real Uvicorn boundary in the background
[D6-10] Running the real Tauri App with visible=false
[D6-10] Hidden-App busy-to-convergence acceptance passed
```

验收同时核对：

- 第一任务 `awaiting_confirmation`、revision 3、attempt `succeeded`；
- 竞争任务仍为 `draft` 且没有 attempt；
- Installation 下恰好一个 execution attempt；
- 恰好一条 `task.discover`，且 `acknowledged/task.accept`；
- 事件严格为 `task.discovery_started`、`task.awaiting_confirmation`；
- 两个目标逐字段匹配且 UI 不泄漏内部 `platform_target_id`；
- 恰好一张 `executor.connect` Session；
- App 正常退出后受控签名 Executor 无残留。
