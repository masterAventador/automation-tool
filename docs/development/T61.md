## 结论

原启动流程遇到删除中断或硬断电留下的坏 artifact 会永久 abort。修复后，初始化只删除损坏
artifact；只有安全清理本身失败才阻断启动。运行期 `list_artifacts()` 仍保持严格校验，避免
把坏产物当成有效视频返回。

## RED

启动恢复测试在实现前实际得到：

`restarted store: VideoWorkspaceError { code: StorageUnavailable }`

即同一私有工作区无法重新打开，准确暴露“一个坏视频让整个 App 永久起不来”的问题。

## GREEN

- `startup_discards_corrupt_artifacts_while_runtime_listing_stays_strict`
  使用真实临时文件系统制造损坏 artifact；
- 重启 Store 后坏产物被清理，其他产物仍可使用；
- 运行期清单在篡改发生后仍 fail closed；
- 外部软链目标不被跟随或删除；
- 第二批最终 Rust 门禁记录为 420 项通过、12 项忽略。

## 失败矩阵

| 场景 | 结果 |
| --- | --- |
| 删除 artifact 中途被杀，只剩部分文件 | 下次初始化定向清理该 artifact |
| payload 大小/摘要与 manifest 不符 | 下次初始化清理该 artifact |
| 正常 artifact | 保留 |
| 运行期发生篡改 | `list_artifacts()` 继续严格失败 |
| artifact 路径被替换为软链 | 拒绝跟随，外部目标不受触碰 |
| 清理动作本身权限拒绝或 I/O 失败 | 启动仍响亮失败，避免假装恢复 |

## 真实边界

Rust 集成测试使用真实目录、文件、权限和软链，不是内存 Fake；但它直接构造
`VideoJobWorkspaceStore`，没有从正式安装 App 启动入口制造损坏并观察页面。因此“文件系统
恢复策略”已验证，“正式包用户重启体验”仍待验收。

测试临时目录由夹具删除；软链外部 sentinel 断言保持不变。没有触碰用户实际视频目录。
