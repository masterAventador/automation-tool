## 正常用户路径验收

`scripts/run_vf_05_acceptance.py` 使用独立 App identifier 和随机 WebDriver loopback 端口，以
生产 `main.tsx` 构建真实 Tauri 程序；测试 bootstrap 只注入 WebDriver 插件，不替换 App、
StartupCheck、网关或页面。环境就绪时走左侧“设置与诊断”；环境被启动门禁拦住时走正式
启动页“本地修复工具”，不是测试专用页面或业务入口。用户可见流程完成：

1. 从生产 App 的“设置与诊断”或正式启动修复入口打开模型设置；
2. 在“文案模型服务”输入测试密钥并点击“保存配置”；
3. 页面显示“已配置”，密钥输入框立即清空，正文和可访问性文本均没有密钥；
4. 刷新 App 后重新从同一入口进入，仍显示“已配置”且不回显密钥；
5. 点击“测试连接”，真实百炼生产端点拒绝无效密钥，页面只显示固定中文认证错误；
6. 用户点击“视频创作复用文案服务密钥”，第二种用途变为“已配置”；
7. 退出后检查两个 Rust 私有秘密文件的字段、模型、用途及权限，再删除隔离数据。

这条验收没有使用 React Mock、直接调用内部方法或用单元测试替代 App 操作。没有可用百炼
密钥时不伪造“连接成功”或额度；成功响应和额度解析由真实 loopback HTTP 协议测试覆盖，
以后在 IM-04/BU-06 消费模型时再用用户提供的有效密钥补真实成功调用。

## 失败矩阵

- 非 `sk-` 密钥、过长密钥、用途不允许的模型、未知字段和损坏存储全部 fail closed。
- 视频创作不能选择无图像输入能力的 DeepSeek/GLM；文案用途仍可独立选择三种锁定模型。
- 生产构建只接受固定 HTTPS 地址、拒绝重定向；响应超过 64 KiB、无 choices/usage 或额度越界
  均拒绝。
- HTTP 401/403、402、429、400/404、5xx、超时和传输失败映射到固定错误码，不读取或反射
  服务端正文。
- Tauri/TypeScript 协议拒绝额外字段、密钥字段、错误模型、错误用途和越界额度；未知原生异常
  统一变成 `operation_unavailable`。
- 密钥类型、配置请求和持久化对象在 Rust drop 时主动清零；Debug、Display、公开快照和连接结果
  均无密钥。

## 真实边界

- 用户输入在提交前必然短暂存在于密码输入控件；保存后 React 状态立即清空，此后只读取配置
  状态。秘密持久化、读取和网络 Authorization 均在 Rust 内完成。
- 当前项目公共 `AppDataSecretStore` 的保护边界是 App 私有目录、原子写入、Unix `0700/0600`
  权限、symlink/reparse 拒绝和长度上限，不声称已接操作系统钥匙串加密。
- 本次没有用户提供的有效百炼密钥，因此没有声称真实“连接成功”或真实剩余额度。真实 401、
  App 脱敏失败态和本地协议成功/额度解析均已分别验证，缺少密钥不阻塞下一任务。
