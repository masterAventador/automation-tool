## 0. 为什么开这个任务

PC-03 做完替换实现后要接线，接线前先核了一遍「零件在用户那个包里到底在不在」。**不在。**

三条互相独立的证据：

```
1. 签名公证过的 .app 内零件 HTML 计数 = 0
   Contents/Resources/ 只有五个目录：
     embedded-browser 336 / local-executor 293 / material-video-worker 2107 /
     media-toolchain 8 / motion-video-worker 4
2. grep -rn "motion-catalog-release|releaseRoot" --include=*.py --include=*.rs
     只有 scripts/ 命中；backend/src 与 frontend/src-tauri 一个读取点都没有
3. Rust 侧唯一的运行时播种 seed_authoring_runtime 只放 gsap.min.js 一个文件
```

发布树 46 MB / 338 文件至今**只是开发机 `.local/` 下的构建产物**。

这不是新功能，是规则「单一构建路径」点名的既有缺口：

> **每一项运行时依赖都必须有生产装配路径**，并有门禁在产出可分发产物之前拒绝缺失的包。

自检那三问，第二问就答不上来：「这个功能依赖的每一样东西，在用户那个包里真的存在吗？我打开包看过吗？」——打开看过了，没有。

## 1. 单一事实源已经在，加一行就够

`contracts/quality/release-package-resources.v1.json` 的 `$comment` 自己写着：

> Single source: `scripts/release_assembly.py` derives VIDEO_RUNTIME_RESOURCES from the
> video entries, `frontend/scripts/audit-production-package.mjs` derives its
> required-resource assertion from all of them, and
> `scripts/check_release_package_wiring.py` derives the release wiring gate from the same
> file. **Adding a resource here is what makes every one** …

所以不新建第二份清单，往这份里加第六项。

**`category` 不能用 `video`。** 那三项的含义是「由 `prepare_video_runtime.py` 构建、缓存在
`~/Library/Caches/automation-tool-build`」，而零件树由 `build_motion_catalog_release.py`
产出、落在 `.local/motion-catalog-release/`，构建与缓存都是另一条。混进 `video` 会让
`VIDEO_RUNTIME_RESOURCES` 把它当成视频运行时去缓存目录里找，找不到。新开 `catalog` 一档。

## 2. RED

声明资源之后，派生门禁立刻点名缺谁负责装：

```
$ backend/.venv/bin/python scripts/check_release_package_wiring.py
release package wiring rejected: the macOS assembler does not install what the
bundler leaves out: missing ['motion-catalog'], unexpected []
rc=1
```

`frontend/scripts/audit-production-package.mjs` 同时变红。

**这条 RED 的形状值得记**：不是「我写了个测试断言零件在包里」，而是**在单一事实源里声明
一项资源，三个消费方自己发现没人负责它**。清单与实现之间的一致性由派生保证，不靠谁记得。

## 3. 一处产品取舍：装 134 个还是只装能用的

倾向**整棵树 134 个都装**，理由两条：

1. 发布树的聚合摘要锁在 `motion-catalog-release.v1.json` 里，是**整棵树一个数**。
   只装子集就得再锁一份子集摘要，等于第二份事实源；
2. PC-12 要给第二批 40 个混合型开槽，那时又得把它们装回去。

代价是 46 MB（dmg 现在 495 MB，约 +9%）。若日后确需瘦身，正确做法是让
`build_motion_catalog_release.py` 按 `motion-part-usability.v1.json` 的分批产出更小的发布树
并重算那一个聚合摘要，而不是在装配这一层挑文件。
