- 新增轮询对账模块 `backend/src/automation_tool/control_plane/domain/aliyun_ims_editing_reconciliation.py`：
  - **官方查询请求** `AliyunGetMediaProducingRequest`/`build_get_media_producing_request`：按官方
    `GetMediaProducingJob`（ice 2020-11-09，JobId 参数）组装确定性查询；封闭状态词汇
    `AliyunMediaProducingStatus`（Init/Queuing/Processing/Success/Failed），未记载 token 只承载
    不解释（`known_status()` 返回 None）。
  - **对账器** `AliyunImsEditingReconciler`：消费查询传输 Port 的状态报告，只经
    `EditingJobStateMachine` 合法转换推进（VE-05 的 `record_running`/`record_succeeded`/
    `record_failed` + 本任务新增 `record_outcome_uncertain`）：
    - `poll_once`：单次查询即幂等应用；本地终态短路（不再调网络），乱序/重复/迟到报告不回退
      任何状态（Init 不回退 RUNNING、重复 Success 只登记一次输出）；
    - `reconcile_until_terminal`：有界轮询预算 `AliyunEditingReconciliationPolicy`
      （max_polls/瞬时失败上限/间隔）；预算耗尽（超时定性）与连续查询失败一律收敛为
      `outcome_uncertain`，绝不臆造成功或失败；
    - **未知状态**（如未记载 token、网关 404 JobNotFound）→ `outcome_uncertain`；从 QUEUED
      收敛时先走 `cancelling`（协作式放弃）再落 `outcome_uncertain`，保持状态机合法路径；
    - `apply_vendor_status` 同时接受轮询词汇 `Failed` 与回调词汇 `Fail`（两份官方文档拼写不同，
      见来源清单）。
  - **取消** `request_cancel`：官方 RAM Action 全量清单中不存在任何取消/终止
    MediaProducingJob 的 Action，因此取消是纯本地协作式标注（`cancelling`），不调用云端；
    对账继续运行，仍可能收敛到真实 `succeeded`/`failed`（测试覆盖）；本 Adapter 的
    `cancelled` 终态不可达，如实写入模块文档。
  - **崩溃恢复** `recover`：扫描持久意图分桶——DISPATCHED 非终态 → 恢复轮询；PREPARED →

  - **成片登记 Port** `AliyunEditingOutputRegistrar`：确认成功时登记输出 Artifact；VE-07 用真实

## 失败矩阵

- 乱序/重复：终态后到达的任何报告（轮询或回调）返回已结清快照、不回退、不重复登记输出；
  Init 迟到不把 RUNNING 拉回 QUEUED；Success 重复只登记一次；Success 后伪造 Fail 事件被忽略。
- 超时定性：max_polls 耗尽仍非终态 → `outcome_uncertain`；连续查询失败（响应丢失/限流/网关
  404）达上限 → `outcome_uncertain`；均为状态机合法路径（QUEUED 先 `cancelling` 再落地）。
- 未知结果：未记载状态 token（含回调 payload 中的未知 Status）→ `outcome_uncertain`，不猜测；
  报告 JobId 与意图不符 → `provider_error` 且状态不动。
- 取消竞争：cancel 后云端仍完成 → 收敛 `succeeded`（真实终态优先）；cancel 后失败 →
  `failed`；cancel 后预算耗尽 → `outcome_uncertain`；终态后 cancel 保持原结果；未知任务
  cancel → `not_found`。
- 崩溃恢复：重启后（新引擎/新对账器实例）从 PostgreSQL 恢复全部意图并分桶；PREPARED 不被
  对账器重放；UNCERTAIN 永不自动重投（poll_once 直接返回，不调网络）。
- 回调伪造：签名篡改、错误密钥、过期/未来时间戳、非数字时间戳、空密钥集一律拒绝；事件
  类型白名单外、缺 JobId、非 JSON、超大文档一律拒绝，错误消息固定。
- 持久层：PREPARED 带 JobId、UNCERTAIN 带非 uncertain 状态、DISPATCHED 无 JobId、SUCCEEDED
  无输出、FAILED 无失败码、未知状态 token 等坏行被数据库 CHECK 约束拒绝；同一 vendor JobId
  归属第二个剪辑任务被唯一索引拒绝；数据库故障映射为封闭 `dependency_unavailable`，不泄露
  驱动/凭据细节。
