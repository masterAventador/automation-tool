- 正式签名与安装：runner 不构建或重签包，只接受绝对且无 symlink/reparse 祖先的 `.exe`。installer、installed main executable 与 `uninstall.exe` 都必须由 `Get-AuthenticodeSignature` 返回 `Valid`，在线 `X509Chain.Build` 成功，包含 Code Signing EKU `1.3.6.1.5.5.7.3.3`、时间戳证书和同一 thumbprint；当前 P9-04 `NotSigned` 普通候选必然被拒绝。安装前要求 `%LOCALAPPDATA%/PRODUCT_NAME`、`%APPDATA%/identifier` 与 HKCU/HKLM 同产品记录全部不存在；安装后只允许唯一 HKCU DisplayName/DisplayVersion/InstallLocation/UninstallString 且根固定 LocalAppData，HKLM 任一命中拒绝
- 正式包与无 Python：安装根必须只有一个非卸载主 `.exe`，并再次经 P9-05 Windows 完整包 auditor。App/installer/uninstaller 运行环境只保留 Windows 用户与系统目录，`PATH` 固定 System32/System32-Wbem，Python/虚拟环境/仓库 `AUTOMATION_TOOL_*` 不进入子进程。扫码浏览器打开时，runner 先从安装根 `embedded-browser/distribution-manifest.v1.json` 锁定 `windows-x86_64` 的唯一 `chrome.exe`，再要求 CIM 后代树只有一个 `automation-tool-executor.exe`、所有 Chromium 进程都来自该绝对包内路径、`--user-data-dir` 精确落在 App 私有 `embedded-browser-profiles/douyin/<UUIDv4>` 且零 Python；任何系统 Chrome/Edge 或第二浏览器都拒绝。Executor 还必须由 `IsProcessInJob` 证明处于 Job Object
- DPI 与强停恢复：Win32 probe 从真实可见主窗口调用 `GetProcessDpiAwareness/GetDpiForWindow/GetWindowRect`，要求 per-monitor awareness、实际 DPI `120..480`（至少 125%）且换算逻辑尺寸不小于生产最小 `960x640`。第一次启动完成扫码/预览/browse/结构化结果后正常退出；第二次启动确认 Session/任务恢复并重新打开内置 Chromium，runner 只对 App 主 PID 调用 `Stop-Process -Force`，明确禁止 `taskkill /T`。此前记录的 Executor/包内 Chromium 必须因 App Job handle 关闭全部退出，第三次启动再确认诊断、任务快照和零副作用重放
- 卸载与证据：第三次正常退出后运行已验签的 `uninstall.exe /S`，要求安装根、HKCU/HKLM 产品记录全部消失，但 production AppData 必须保留；这防止普通卸载静默删除平台登录态和用户本地证据。runner 检查 AppData owner 为当前 SID 且没有 Everyone/Authenticated Users/Builtin Users allow，再把本轮从空状态创建的数据移到 Windows 回收站。成功 JSON 只含 OS/架构、installer SHA-256、公开 signer thumbprint、版本、DPI、浏览器、零 Python、Job/安装/卸载结论和 checkpoint 布尔值；`SetAccessRuleProtection(true,false)` 后只授予当前 SID，不保存 PID、命令行、路径、账号、Cookie、页面或任务 ID
- 失败清理：runner 以本轮前置空状态声明唯一 ownership；正常、失败或中断先停止精确 App/已记录后代及安装/AppData 路径归属进程，再优先从唯一 HKCU record、否则从固定根寻找正式 uninstaller，不自行删注册表或程序目录。只有安装根和双 hive 记录均消失后才移动本轮 AppData；PID 清理还复核 executable path/command identity，避免 PID 复用时误杀其他进程
- 自动化 GREEN：初版 P9-07 聚焦 4/4；Frontend 全部 158 项 Node 契约、33 个 Vitest 文件/241 项测试、ESLint、严格 TypeScript、OpenAPI、生产构建与边界扫描全绿。2026-07-25 新增 Windows 确定性单测 4/4，覆盖未签名候选安装前拒绝、`windows-x86_64` manifest/包内可执行文件解析、Unicode/空格 Profile、`embedded-browser-profiles/douyin/<UUIDv4>` 和系统 Edge/错误可执行文件拒绝；P9-07 Node 契约 4/4、前端契约 212/212、Ruff、严格 Mypy、Python 编译和专项 Roadmap 门禁重新通过。没有把这些确定性测试冒充正式包和真实账号验收
