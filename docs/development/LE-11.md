## 开工前【先定】

「原声处理方式」采用 `TimelineClip` 上的强类型字段，不增加第六种轨道，也不收窄设计的
三态承诺。该字段只允许在 `AMBIENT` 原声 clip 上出现，三态为：

1. `AUTO_DUCK`：先应用 clip 的 `gain_db` 基准，再以旁白作为 sidechain 压低；默认值；
2. `FIXED_VOLUME`：只应用 `gain_db`，不经过 sidechain，也不作为 sidechain 源；
3. `MUTED`：保留 Timeline 中的用户选择和基准音量，但渲染时不排入任何混音分支。

`NARRATION` 只作为 sidechain 源并进入最终混音；`MUSIC` 继续经过旁白闪避；无有效音频的
视觉素材不生成 `AMBIENT` clip。把 mode 放在 clip 而不是轨道上，才能在同一原声轨逐片段
切换，且静音不需要删除 clip、丢掉用户设置。

首期所有音频先统一为 48kHz、stereo、`fltp`。每段严格按 Timeline 的 source window 取片、
按 start 延迟、按 duration 裁切，轨道补静音并裁到画面目标时长；最终成片恰好一个 H.264
视频流和一个 AAC 音频流，音轨时长与 LE-10 帧栅格成片时长一致到容器毫秒精度。

## T1 RED 目标

1. 新增闭集 `OriginalAudioMode`，只含 `auto_duck/fixed_volume/muted`；原始字符串不得冒充。
2. 每个 `AMBIENT` clip 必须显式带 mode；其他四种轨道必须为 `None`。`gain_db` 继续表示
   三态共同的基准值，`muted` 不删除 clip。
3. Timeline API 用 `originalAudioMode` 严格收发，PostgreSQL JSON 文档用
   `original_audio_mode` 往返；未知/错误类型 fail closed。
4. 本地 Timeline 生成器只给 `has_audio=true` 的原声生成 `AMBIENT + AUTO_DUCK`；无有效
   音频仍不生成原声轨，不把静音和“素材没有声音”混成一个事实。
5. 同步 OpenAPI/前端生成契约，领域、API、仓储与生成契约均有漂移守卫。

首次聚焦运行必须失败于 `OriginalAudioMode` 尚不存在；确认 RED 后才改生产模型。
