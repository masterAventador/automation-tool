## 1. 一个会让所有槽都错位的坑：锚必须取自发布树

每个零件在这个项目里**有两份**：

```
vendor/hyperframes/…/spotify-card.html            上游原样，只读 submodule
   ↓ BM-12 离线化：删掉指向 Google 的 <link>，依赖改本地路径
   ↓ BM-13 overlay：品牌词替换
.local/motion-catalog-release/1.0.0/items/…        发布树，这份才进安装包
   ↓ 出片时复制进 RenderJob 工作区
工作区副本                                          替换发生在这里
```

替换发生在最下面那份，所以锚必须取自它。实测 `spotify-card`，**两个锚同时对不上**：

```
submodule   idx=24 'HyperFrames'   idx=26 'HeyGen'       idx=36 'Spotify'
发布树       idx=22 '动效画布'      idx=24 '人物创作平台'   idx=34 '音频平台'
```

文字不同是因为 overlay 换掉了品牌词；序号从 24 移到 22 是因为离线化删掉了前面的
Google Fonts `<link>`。**从 submodule 建表的话，70 个被 overlay 碰过的零件全部锚错——
而且不是报错，是把文案写进错误的节点，下游没有任何门禁看得见。**

代价：这道门禁需要发布树存在（`.local` 下的构建产物）。与
`check_motion_catalog_release.py` 同一类，那道门禁没有构建产物时同样直接红。
发布树是确定的——它的聚合摘要锁在 `motion-catalog-release.v1.json` 里。

## 2. 筛选：第一遍不算筛选

36 个零件 419 个可见节点。第一遍我只按名字排除了 5 个整屏界面仿制件，剩下 116 个全收——
**那不是 curated，正是我自己在 PC-02 里警告过的毛病。** 把 116 条逐条读完，找出四类不能替换的：

| 类 | 例 | 为什么 |
| --- | --- | --- |
| **许可署名** | `© OpenStreetMap contributors © CARTO`（2 个零件） | 让模型改掉它就是违反地图数据许可 |
| **自我宣传的演示页** | `vfx-magnetic`「Pixels bend toward your cursor」「No html2canvas」、`vfx-liquid-glass`「Ship videos 10x faster」 | 讲的是这个技术本身，和可用性分级已经排除的 30 个转场演示页同一类，第一遍漏判 |
| **界面家具** | `liquid-glass-context-menu` 的 Share / New Tab / ⌘T；`Follow`↔`Following`、`Subscribe`↔`Subscribed` | 后两者是按钮的两个状态，动效正是从前者变后者，替换会弄坏这一镜要展示的东西 |
| **槽还表达不了的结构** | `news-ticker` 把一句标题按强调切成三个节点（27/28/29），又把四条跑马灯文案各镜像一份（40..44 与 50..54） | 需要槽位分组，而分组还没设计。本轮整件排除 |

排除项**按零件名和按原文逐条写明理由**，不用节点数阈值——阈值是判断的代用品，不是判断。

## 9. 一个合成 HTML 看不见、真零件上必炸的差异

门禁冻结 `original` 时存的是 `node.text.strip()`，而**48 个槽里有 3 个**在源文档里带前后空白。
第一版实现用逐字相等做锚比较，合成 HTML 全绿，真零件上这 3 个会报「锚不符」而拒绝出片。

定案：**锚比较用解码后 `strip()`（与冻结时同一形态），替换区间在源码上算前后空白。**
两侧不能用同一个量——`&nbsp;` 解码成 1 个字符却占 6 个源码字符，
拿解码长度算偏移会让它后面所有替换整体错位。

替换按槽位序号**从右往左**施加，这样先前算出的区间不需要因为已施加的编辑而调整。

## 10. 为什么发射器必须搬进 Executor 包

`automation-tool-executor.spec` 的 `pathex` 只有 `backend/src`，包内容由
`executor/__main__.py` 的 import 图决定（规则 §9.2），**`scripts/` 一个字节都不进产物**。
`part_font_css` 原本住在 `scripts/motion_part_typography.py`，
渲染期 import 它会得到「仓库检出里全绿、用户装的包里没有」——即 T32 那个形状。

所以按本文件第 6 节对枚举器立过的同一条规矩办：
**发射器（`part_font_css` + 两个 unicode-range + `ResolvedFace` + `cjk_codepoints`）
搬进 `part_typography.py`，扫描/契约/策略留在 `scripts/`，由脚本反向 import。**
`motion_cjk_font_probe.py` 的 `_CJK_RANGES` 与 `_CJK_UNICODE_RANGE` 一并改为转引——
它自己的 docstring 早就写着「两份手抄会漂移，而漂移只表现为字符静默掉回系统字体」。

## 11.1 渲染期字体解析链也一并搬进包内

只有发射器进包是不够的：还得有东西决定**发射哪些规则**。这条决策读的是零件文档自己
（它就在手边，正要被复制进工作区），把它写下的每个 `(family, weight)` 拿去对 PC-13 冻结的
策略与离线包实际带的字重。扫描器留在 `scripts/` 会得到「打包的渲染器能发射规则、
却算不出该发射什么」。

搬进 `part_typography.py` 的：`requested_faces`（扫描器）、`FamilyPolicy`、`family_policies`、
`packaged_weights`、`resolve_faces`、`face_artifact`，以及新的渲染期入口 `document_font_css`。
`scripts/` 只留开发机才做的事：读 submodule、读契约、读锁文件。

**解析不出来必须失败关闭**（新增 `FontRequestUnmet`）。理由是 PC-13 测出来的那条：
缺一个 face 是静默的，页面照渲，字掉进宿主机器有什么用什么。
`check_motion_part_typography.py` 已经证明 134 个零件没有未满足的请求，
所以渲染期真碰到一个，只能说明这份安装不是门禁检查过的那份。

命名上有个坑：`scripts` 侧的函数原名就叫 `part_typography`，与新模块同名。
模块改为 `as _rules` 别名导入，函数名保持不变，既有调用方和门禁一个字都不用改。

## 12. 第二轮的失败矩阵

| 情形 | 期望 | 实测 |
| --- | --- | --- |
| 槽的原文与文档不符 | 拒绝，不写任何东西 | 红 |
| 槽的序号超出文档节点数 | 拒绝 | 红 |
| 槽所在元素变了（`parentTag` 漂移） | 拒绝 | 红 |
| 文案指向没有声明槽的节点 | 拒绝 | 红 |
| 文案含 `<script>` 等 ASCII 字面量 | 转义后落地，不新增元素 | 绿（`<script>` 计数不变） |
| 没给文案的槽 | 保留原文 | 绿 |
| 带缩进的文本节点 | 只换文案，缩进保留 | 绿 |
| 文档没有 `</head>` | 拒绝，不静默跳过字体 | 红 |
| 零件请求的字重离线包没有（如 900） | 拒绝，不静默少发一条规则 | 红 |
| 零件请求的家族没人定过策略 | 拒绝 | 红 |
| 策略为 `host` 的家族（彩色 emoji） | 不发规则，也不算失败 | 绿 |
| 被替代的家族（`SF Pro`→`Inter`） | 用替代字体的文件，但按零件写的名字声明 | 绿 |
| 字体栈写成实体（`&quot;Inter&quot;`） | 扫描器先 unescape，认得出来 | 绿 |
