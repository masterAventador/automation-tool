## 0. 规则（产品负责人 2026-07-27 的纠正）

不是「总时长 = 各零件时长之和」——那等于让动效决定镜头长度。动效是**点缀**：让内容
出现时不生硬，播完停在末帧等着即可。它不该决定这一镜停多久，但**没播完就切走看着很难受**。

```
镜头时长 = max(这段话说完要多久, 动效播完要多久)
总时长   = Σ 各镜头时长
```

内容主导、动效兜底。语音 8 秒配 5.5 秒动效 → 8 秒（动效停在末帧）；语音 3 秒配 5.5 秒
动效 → 5.5 秒（等动效播完）。

## 1. 两个可选，理由不同

`motion_seconds` 可空：**25 个组件不声明时长**——上游给 block 画布与时间轴，给 component
两者都没有（PC-01 查证）。`voice_seconds` 可空：一镜可以没有旁白，收尾 logo 就不说话。
两者都空则拒绝——没有任何东西决定这一镜多长。

## 2. 帧数向上取整

4.81 秒的镜头需要 145 帧，144 帧会把话切掉。**每镜少至多一帧语音，在整片上累积起来是
听得出来的**，不是看得出来的。

## 3. 预算在渲染前判，并且点名

超预算的渲染会被 stall guard 杀掉，等待的人看到的是一个不带理由的失败。而判断所需的
两个数——零件声明的时长、合成出来的旁白实测秒数——**在浏览器启动之前就都有了**。
所以拒绝落在这里，并说清是哪一镜、多少帧：

```
shot 'transitions-dissolve' runs 24s, which is 720 frames —
one render may capture 600
```

**路线 A 解掉的是「片子」的上限，不是「一次渲染」的上限**：一段就是一次渲染，仍受
`SANDBOX_FRAMES_MAXIMUM` 约束。目录里已有 5 个零件单个就超（全是 deferred 转场），
而一段长旁白可以把任何一镜推过去。

## 5. 失败矩阵

| --- | --- | --- |
| 一镜既无旁白也无动效 | 拒绝 | 红 |
| 一镜超单次渲染帧上限 | 拒绝并点名镜头与帧数 | 红 |
| 一部片子一镜都没有 | 拒绝 | 红 |
