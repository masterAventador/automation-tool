## 一、点不动的真实原因

**不是 CSP。** 派单时怀疑 `tauri.conf.json` 的 `connect-src` 把 Streamlit 的 websocket 掐了。两条独立证据否定这个假设：

- **源码层**：Tauri 2.11.5 只在 `tauri://` 自定义协议返回资源时附加 CSP 头（`src/protocol/tauri.rs:182`，值由 `src/manager/mod.rs:435` 仅对 `.html` 资源计算）。本窗口是 `WebviewUrl::External(http://127.0.0.1:<port>/studio-<cap>/)`，响应由 Streamlit 自己的服务器产生，不经过该处理器。`src/webview/mod.rs:444` 的文档也明说这条链路「**not** executed when using external URLs」。
- **运行层**：真实复现里 `cspViolations: []`，websocket 事件只有 `OPEN ws://127.0.0.1:39781/studio-.../\_stcore/stream`，无 error、无 close。连接是通的。

**真实原因：上游引导（driver.js）把整页 `pointer-events` 关掉了，而产品把它唯一的出口藏了起来。**

链路逐段核实：

1. `vendor/moneyprinterturbo/webui/Main.py:17` 引入 `streamlit_tour`，`:1209 render_onboarding_tour()` 在每个会话首帧 `tour.start()`；
2. `streamlit_tour/__init__.py` 用的是 `streamlit.components.v2`——**不是 iframe 组件**，脚本直接跑在主文档里；
3. 其打包产物 `frontend/build/index-*.js` 中 `document.body.classList.add("driver-active")`，随附样式：
   `.driver-active .driver-overlay,.driver-active *{pointer-events:none}`
   `.driver-active .driver-active-element,...,.driver-popover,.driver-popover *{pointer-events:auto}`
   即**引导运行期间整页不可点，只放行高亮元素和气泡**；
4. `material_video_studio_init.js` 把 `.driver-popover`、`.driver-overlay` 设为 `display:none`——用户于是**没有任何办法点「完成」结束引导**，`driver-active` 永不摘除；
5. 该组件的「只弹一次」由 localStorage 判断，而 WebUI 每次启动绑定新的随机端口 → 新 origin → localStorage 每次都是空的，**所以每次打开都必然复现，不是偶发**。

旧脚本第 77 行 `.driver-active-element { pointer-events: auto !important; }` 说明此前已有人撞上过这个封锁，但只放行了那一个高亮元素。

## 二、难看的真实原因

内嵌 WebUI 在**启动那一刻**按 `prefers-color-scheme` 选定配色并固定下来。用户的 Mac 是深色 → Streamlit 渲染深色主题；产品样式又把 `body/.stApp` 刷成浅色，于是白页 + 深色控件 + 近白标签压在白底上。

实测（同一个 WebUI，只改 `colorScheme`）：

| | 深色（用户所见） | 浅色 |
| --- | --- | --- |
| `.stApp` 底色 | `rgb(14, 17, 23)` | `rgb(255, 255, 255)` |
| 输入框文字 | `rgb(250, 250, 250)` | `rgb(49, 51, 63)` |
| 字段标签 | `rgb(250, 250, 250)` | `rgb(49, 51, 63)` |

旧脚本里的 `:root { color-scheme: light }` 对此无效：`color-scheme` 只影响 UA 默认控件外观，**不改变 `prefers-color-scheme` 媒体查询的结果**，而 Streamlit 读的是后者。

### 走的哪条路

**在窗口一侧定下外观，而不是用 CSS 追控件颜色。** `material_video_studio.rs` 的 `WindowBuilder` 加 `.theme(Some(tauri::Theme::Light))`，WebView 内 `prefers-color-scheme` 恒为浅色，Streamlit 自己就渲染出一套自洽的浅色控件；产品样式只需在这个浅色底上铺产品配色。

**没有走的路，以及为什么：**

- **Streamlit 启动参数 / `[theme]` 配置**（`workers/material_montage/webui_runtime.py:372` 的 `sys.argv`）——这本是最正统的位置，但**改了不会进包**：`scripts/video_runtime_cache.py` 的缓存键 `contract_fingerprint()` 只哈希 `material-video-worker-package.v1.json` 与 `asset-rights-policy.v1.json` 两个契约，**不包含 `workers/material_montage/*.py`**。改 Worker 源码不会让缓存失效，发布会照旧复用旧二进制（见第五节实测）。
- **改 Streamlit 的 CSS 变量**——实测 `--st-primary-color` 等变量确实声明在页面上（`.st-emotion-cache-1r9ezoi`），但**全站没有任何规则 `var()` 引用它们**（`usageCount: 0`），控件颜色是编译期烧进 emotion 类的。覆盖变量不起作用。
- **改 vendor**——只读 Submodule，未触碰。

点不动的修复是**两层**，不是一层：

1. **不让引导启动**——启动脚本在页面任何脚本之前写入 `localStorage["stTour-mpt-onboarding-v1"]="1"`，命中组件自带的 `oneTimeTour` 短路（打包产物中 `v && De(d) ? (t("skipped", !0), …)`），driver.js 根本不运行；
2. **即便封锁还是发生了也点得动**——样式表里 `body.driver-active *` 恢复 `pointer-events: auto !important`。driver.js 那条规则**没有 `!important`**，所以产品规则无论注入早晚都压得住。这一层是为了让「上游改了 storage key」这类静默变更不会再把窗口变成死的。

配色取值与 `frontend/src/styles/global.css` 一致（页面 `#f3f6fb`、正文 `#182230`、描边 `#e2e8f2`、主色 `#1677ff`），不另立一套。

### 哪些部分单元测试证不了，怎么标注的

- **jsdom 不解析 `var()`**（实测：`var() -> "rgba(0, 0, 0, 0)"`，同一张表里字面量 `-> "rgb(255, 255, 255)"`）。所以颜色断言改为经 CSSOM 读取「规则确实存在且设置了该属性」+「它引用的 token 确实有值」，再由测试自己做一次替换。这证明的是**产品样式声明了什么**，不是**级联之后长什么样**；后者由第五节的真实浏览器核对。

## 六、失败矩阵

| 情形 | 行为 |
| --- | --- |
| localStorage 被禁用/写入抛错 | `suppressOnboardingTour()` 吞掉异常；引导会启动，但样式兜底与 `removeTour()` 摘除类名仍保证可点 |
| 上游改掉 storage key，引导照常启动 | 同上，样式兜底不依赖 key |
| 上游改掉 `driver-active` 类名 | 两层都失效；这是本次未覆盖的残余风险，见第八节 |
| driver.js 在产品脚本之后注入自己的样式 | 上游规则无 `!important`，产品规则带 `!important`，与注入顺序无关 |
| 引导反复重新加类名 | `MutationObserver` → `reconcile()` → `removeTour()` 再次摘除；期间样式兜底保证不会出现不可点的窗口 |
| 页面结构不再被识别 | 原有 `failClosed` 行为不变；兜底规则用 `:not(.automation-tool-studio-failed *)` 排除，不会让被封停的页面重新可点 |
| 系统处于深色 | 窗口强制浅色，Streamlit 渲染浅色主题 |
| 系统处于浅色 | 同上，行为一致（外观不再随系统变化） |

## 八、残余风险与未做的事

1. **上游若改掉 `driver-active` 类名或封锁方式**，两层防护都会失效。没有把它变成会红的门禁——那需要一个常驻的真实 WebUI 用例，成本与本任务不相称。已在契约 `suppressUpstreamOnboardingTourReason` 里写清机制，便于升级 Submodule 时复查。
2. **滑块填充条**是内联 `linear-gradient`，色标位置随取值变化，无法在不丢失读数的情况下改色，改用 `hue-rotate` 旋转色相。这是近似手段，不是精确取色。
3. **Streamlit 自身的主题参数没有采用**，理由见第二节（改 Worker 源码不会进包）。缓存键的缺陷本身不在本任务范围，另见第九节。

## 九、连带发现（不属本任务，已上报）

`scripts/video_runtime_cache.py` 的 `contract_fingerprint()` 只哈希契约 JSON，**不包含 `workers/material_montage/*.py`**，因此改 Worker 源码不会让构建缓存失效，发布会静默复用旧二进制。

实测证据——同一段 T32（去掉背景音乐控件）代码，两个产物行为不同：

| | 已安装正式包的 Worker（用户实际运行的那个） | 当前构建缓存的 Worker |
| --- | --- | --- |
| 私有样式表是否载入 | `stylesheetLoaded: false` | `stylesheetLoaded: true` |
| `bgm_volume_select` | `display: block`（可见） | `display: none` |
| `bgm_type_select` 提示 | `::after` 为 `none`（无提示） | 「当前版本不提供背景音乐素材…」 |
| 页面是否还有「背景音乐」 | `true` | `false` |

即 **T32 的实现是对的，只是没进用户手上那个包**。它与本任务的点不动是两个独立问题——`driverActive: true` 在两个产物上都成立。
