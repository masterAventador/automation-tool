## 0. 实验先行：拼接会怎么坏

三个真零件各自渲成片段（都经产品的工作区写入器、渲染沙箱、包内 Chromium 与包内 ffmpeg）：

```
seg-lt     lt-bold-block      1920x1080  30fps  144 帧  4.8s
seg-logo   logo-outro         1920x1080  30fps  180 帧  6.0s
seg-ig     instagram-follow   1080x1920  30fps  135 帧  4.5s   ← 竖屏
```

**同尺寸拼接没问题**，`-c copy` 直接成立：

```
324 帧 = 144 + 180        10.800000 秒 = 4.8 + 6.0
```

## 1. 混尺寸拼接是一次静默成功——这是本轮最重要的发现

把 1920x1080 与 1080x1920 两段用 concat demuxer + `-c copy` 拼起来：

```
ffmpeg 退出码       0
nb_read_frames      279       = 144 + 135，完全正确
format duration     9.300000  = 4.8 + 4.5，完全正确
stream width/height 1920x1080
```

**每一个便宜的指标都说成功。** 文件是坏的：后半段是竖屏内容装在声明为横屏的容器里，
抽帧出来一看就露馅，而退出码、帧数、时长三样都对得上。

所以本模块**在拼之前就拒绝**，调用方**在拼之后再量产物**。退出码和帧数都不作为
拼接成功的证据。

## 2. 正确做法（已实测）

把不在画布上的段等比缩放后补边：

```
scale=1920:1080:force_original_aspect_ratio=decrease,
pad=1920:1080:(ow-iw)/2:(oh-ih)/2:color=black,
setsar=1
```

`setsar=1` 不是整洁而是必需——不加它，补边后的流仍带着源的采样宽高比，播放器会把
结果再拉伸回去。

归一化后三段拼接：

```
459 帧 = 144 + 135 + 180      15.300000 秒 = 4.8 + 4.5 + 6.0
```

抽帧核对：竖屏内容居中、两侧黑边、比例未被拉伸。

**不拉伸而是补边**，因为零件是按它自己声明的舞台排版的，拉伸是一次没人要求的设计改动。

| 情形 | 期望 | 实测 |

| 段尺寸与画布不符 | 拼之前拒绝并点名 | 红 |

## 5. 执行层（真工具链实跑）

`probe_segment` / `normalise_segment` / `join_segments` 用包内 ffmpeg 与 ffprobe
跑完整条链，三段真片段：

```
段0 seg-lt    1920x1080 已在画布上，流拷贝
段1 seg-ig    1080x1920 → 1920x1080 已归一化
段2 seg-logo  1920x1080 已在画布上，流拷贝

预期总帧 459   成片实测 459 帧 1920x1080 30fps yuv420p
未归一化混入被拒: segment 1 is 1080x1920 …, not the film's 1920x1080 …
```

**只对需要的那一段重编码**，其余流拷贝——同舞台零件组成的片子不会为了拼接被整体重编。

`probe_segment` 用 `-count_frames` 而不是容器的帧数字段：容器是声称，解码流是事实，
而 PC-06 存在的全部理由就是两者会不出声地不一致。

`concat_listing` 对路径里的单引号做 `'\''` 转义。`-safe 0` 允许列表携带绝对路径，
这意味着路径是 demuxer 解析的数据，一个单引号就能提前结束条目。

## 6. 还差什么

**产品入口尚未调用**：本轮由驱动脚本发起，用的是产品自己的模块与包内工具链，但不是
从正式 App 的用户入口进去的，按「生产同路径验收」只算分层证据。

**混排本机模板段**：路线图要求「本机 4 layout 模板段与零件段可混排」。模板段输出
1280x720（640x360 @2），按本模块判定需要归一化——机制上与竖屏段是同一条路径，
但尚未用真模板段实跑。

## 7. 顺带发现（属于 PC-14/PC-17）

竖屏段那次渲染里，`自动化运营工具` 七个字塞进 `instagram-follow` 的昵称槽，被逐字换行
成一列。那个槽是为短昵称设计的。这是溢出的实例，说明 PC-17 的像素预算不是可选项，
也说明 PC-14 的溢出实测必须在真渲染里量而不是读样式表推断。
