## 一、查证结果（先查证，再动手）

### 1. 随包示范里的 CDN 引用：**还在**

`vendor/hyperframes` 是只读、带摘要校验的 Submodule（`CLAUDE.md` 第 6 节禁止修改），其中被
`contracts/video/motion-authoring-workflow.v1.json` 钉住、逐字送进模型提示词的两个文件之一：

```
$ grep -n -E "https?://|script src|gsap|cdn" \
    vendor/hyperframes/skills/hyperframes-core/references/minimal-composition.md
12:    <script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/gsap.min.js"></script>
53:      const tl = gsap.timeline({ paused: true });
```

这个文件的角色是 “smallest renderable seekable composition skeleton” —— 模型拿到的**唯一完整可抄的骨架示范**，第 12 行就是 CDN 标签。

> 契约 JSON 里的那些 `cdn.jsdelivr.net` 命中（`offline-motion-dependencies.v1.json`、
> `motion-catalog-rights.v1.json`）是 `downloadUrl` / `licenseUrl` 出处元数据，不是运行期引用，与本缺陷无关。

### 2. 渲染前的拦截：**有，而且正是它把缺陷推向更隐蔽的形态**

`agent.py` 的 `lint_composition` 拦远程引用拦得很严（scheme 子串 + 逐引用判定 + 按 entry 目录解析），其
docstring 甚至写着上一次同类事故。所以模型抄了 CDN 会被 `remote_reference` 打回。

**但修复提示词写的是「移除全部远程引用」**，最省事的照办方式就是——把 `<script src>` 删掉，保留
`gsap.timeline(...)` 调用。于是：

| 门禁 | 结果 |
|---|---|
| `remote_reference` | 通过（没有远程引用了） |
| `undeclared_asset` | 通过（不引用任何资源） |
| `missing_timeline`（`window.__timelines` 文本） | 通过（文本还在） |
| `timeline_not_paused`（`paused: true` 文本） | 通过（文本还在） |
| clip 区间 / 可见性 / 画布 | 全部通过 |

全部是**静态文本检查**，没有任何一道检查「被调用的动画运行时是否真的加载得到」。
渲染时 `gsap` 未定义 → 初始化脚本抛异常 → `window.__timelines` 从未赋值。

### 3. 渲染后的拦截：**一道都没有，而且 Worker 主动跳过了唯一会露馅的一步**

`workers/motion_composition/worker.mjs`：

```js
// 探针：没有可 seek 的时间轴时，seekableDuration 取 0
const seekableDuration = (... && timelineMetadata.timelineCount > 0) ? timelineMetadata.duration : 0;
...
for (let index = 1; index <= spec.frameCount; index += 1) {
  if (seekableDuration > 0) {        // ← 时间轴不存在时，整段 seek 被跳过
    ...
  }
  const shot = await pipe.send("Page.captureScreenshot", ...);   // 照样截图
}
```

`seekableDuration === 0` 时，**逐帧 seek 被整段跳过，但截图照跑**，于是把同一张首屏截了
`frameCount` 次，最后 `finish({ status: "complete" })`。这就是「静默成功」：链路全绿，成片是废的。

## 四、出口侧判据，以及为什么不会误杀合理的静止画面

**判据：一次渲染里「每一帧都与首帧字节相同」，且帧数 ≥ 2，才判 `render_static_frames`。**

四条判断依据（同样写进了 `worker.mjs` 的注释）：

1. **只要动就会变字节。** 位移一个像素、一次淡入、一档颜色变化都会产生不同的 PNG，真实动画不可能触发。
   误杀面精确等于「整段时长内一个像素都没变过」——那是缺陷，不是交付物：这个 Worker 的职责就是把可
   seek 的时间轴变成影片。
2. **比对全部帧，而不是首/中/末三帧采样。** 采样会犯反方向的错：一个正好走完整数个循环的脉冲动画，
   首、中、末三帧可能完全相同，而它全程都在动。要求**所有**帧相同，等于任何位置的任何运动都能放行。
3. **在这里字节相等是可信信号，不是采样运气。** 该渲染是构造性确定的：等字体就绪、冻结 CSS 动画并按
   seek 时刻驱动、warm-up 一直跑到画面不再变化。所以字节相同就意味着渲染状态相同。
4. **唯一残余风险是运动全部落在两次截图之间。** 授权侧按 `duration * 30` 请求帧数，相邻截图相隔
   33ms，肉眼可见的运动放不进这个间隙；真要用几帧覆盖长时长，那本来就粗到无法判断运动。

关于「纯文字卡片模板」这个合理静止场景：`check_composition` 已经强制多 clip 合成必须在时间轴上用
`autoAlpha` 控制出场/退场，所以多 clip 合成必然逐帧变化；剩下的单 clip 合成若整段一个像素不变，它与
缺陷产物在任何观测手段下都不可区分，且不构成「动效成片」这个产品承诺。

## 五、入口侧改动

`check_composition` 新增 `_runtime_findings`：**只拒绝那个精确的不可运行形态**——调用了 `gsap.`、
没有任何 `<script src=>`、也没有内联定义同名绑定。加载了本地运行时的、或自己内联了运行时的合成都不受影响
（两个对照测试各覆盖一种）。

`vendor/hyperframes` 不能改（只读 + 摘要校验），因此按 `CLAUDE.md` 第 6 节「外围适配」在提示词里点名
覆盖那个示范：明确说参考资料里的 CDN 写法是错的、不要照抄、渲染环境完全离线、照抄的后果是每帧都一样。
修复提示词也补上了 `missing_animation_runtime` 的具体改法，避免把静默失败换成无法收敛的硬失败。

## 六、失败矩阵

| 场景 | 行为 |
|---|---|
| 动画运行时加载不到（本缺陷） | 入口 `missing_animation_runtime` 拒绝；漏网则出口 `render_static_frames` 拒绝 |
| 合成完全不动 | 出口 `render_static_frames`（不依赖猜到病因，任何「没动」都被抓住） |
| 单帧渲染（frameCount = 1） | 不判定——一帧不构成证据 |
| 渲染中途取消 | 先命中既有 `cancelled`，不进入静止判定 |
| 判为静止后的资源清理 | 走既有 `succeeded = false` 路径，frames 目录照常删除 |
| 会动的合成 | 放行（真实 Chromium 对照测试常驻回归集） |
