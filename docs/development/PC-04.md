## 0. 一句话结论

一句话出片的提示词里，134 个裸 ID 换成 **76 个可用零件的真目录**（ID | 中文分类 | 时长 | 说明），
并把「零件时长会吃掉片子预算」这条后果说出来。真模型两轮实测：编造 0、合法率 100%、
时长判据从未过变为通过。

## 1. 改了什么

**之前**（`agent.py`）：

```python
f"只能使用以下 {len(LOCKED_CATALOG_PART_IDS)} 个 ID：\n"
f"{sorted(LOCKED_CATALOG_PART_IDS)}\n"
```

134 个标识符，没有标题、分类、时长、说明。模型只能靠 ID 猜。

**之后**：每行 `ID | 中文分类 | 时长秒 | 英文标题: 英文说明`，例如

```
lt-bold-block | 人名与身份条 | 4.8 | Lower Third — Bold Block: High-energy podcast
lower third: solid dark block wipes in, uppercase name slams up, accent tag pops
caption-blend-difference | 文字效果 | — | Blend Difference: Auto-inverting text using
mix-blend-mode: difference …
```

时长写「—」的是没有自己时间轴的局部效果，提示词里明确说了它不占镜头长度。
说明保留上游英文——那是它对自己零件的原话，本地翻译会变成一份下次 submodule 升级后
无人察觉的过期副本。分类用产品其他地方已经在展示的那份中文。

提示词从约 2.5 KB 变成 15.8 KB。**这是输入 token，不是输出**：T92 测出来的成本在模型打字，
不在读题。

## 2. 可选集合为什么是 76 而不是 36

PC-02 把 134 个分成 `first 36 / second 40 / deferred 58`。**闭集校验用的线是 `deferred`，
不是 `first`**：

- `deferred` 是**零件自身的属性**——30 个转场是演示页（渲染出来是 SCENE A / SCENE B 加一句
  `use glitch shader transition`），28 个把文案连同每词时间戳放在 JS 里（换文案 = 重排动画）。
  这两类给模型看就是浪费一次选择；
- `first` / `second` 的分界是**排期**——`second` 到 PC-12 就能用。把排期决定烧进校验边界，
  等于将来会拒绝一个自身没有任何变化的零件。

`entry.py` 的固定拒绝消息随之从 `catalog_parts must be locked catalog ids` 改为
`... must be selectable catalog ids`，wire token 同步换掉。

## 5. 真实模型验收（这是本任务的判据）

模型 `qwen3.7-max-2026-06-08`，经正式的 `call_video_creation_model` 走百炼网关。

**第一轮**，简报「给我们的智能客服产品做一条介绍片，突出 7×24 小时和响应快」，12 秒：

```
耗时 35.4s｜应答 2,289 B
beat-1  0~3s   智能客服   → shimmer-sweep, vignette
beat-2  3~6s   7×24h     → liquid-glass-widgets, grain-overlay
beat-3  6~9s   毫秒级响应 → flowchart, motion-blur
beat-4  9~12s  立即体验   → logo-outro, shimmer-sweep

选中 8 个｜编造 0
带自身时长的 3 个合计 26s｜简报 12s        ← 时长判据未过
```

合法率满分，但**把一个 12 秒的 flowchart 放进 3 秒的镜头**。原因是提示词告诉了它每个零件多长，
却没说这件事的后果——它老老实实按「每段 2~3 秒铺满 12 秒」排了。这是提示词的缺口，不是模型的。

补上这句之后：

> 选零件时必须同时看时长：带时长的零件放进哪一段，那一段就不能短于它——动效没播完就切走很难受。
> 因此这条片子总共只有 N 秒，所有带时长的零件加起来也不能超过它。片子短就挑短零件，或者这一段
> 干脆不用带时长的零件、只用「—」的局部效果。

**第二轮**，同一简报：

```
耗时 33.2s｜应答 2,521 B
5 段，选中 4 个零件，全部是「—」的局部效果
带时长的 0 个合计 0s / 预算 12s          ← 通过
```

**第三轮**，换一条 20 秒简报「做一条主播介绍片：先出主播姓名和头衔，再讲三个亮点，最后品牌收尾」，
用来分辨「正确地保守」还是「被说过头了」：

```
耗时 54.3s
beat-1  0~4s    林锐        → lt-bold-block(4.8s), shimmer-sweep(—)
beat-2  4~12s   三大硬核实力 → grain-overlay(—)
beat-3  12~16s  500万+      → motion-blur(—)
beat-4  16~20s  关注林锐     → vignette(—), caption-blend-difference(—)

零件 6｜编造 0｜带时长 1 个合计 4.8s / 预算 20s   ← 通过
```

**给「主播姓名和头衔」那一段选了下三分之一，语义完全正确。** 所以 12 秒那轮全用叠加效果是
恰当的保守——12 秒确实塞不下什么，不是过度矫正。

## 6. 一个已知偏差，以及为什么不用校验去拒绝

第三轮里 `beat-1` 排了 4 秒，而 `lt-bold-block` 是 4.8 秒——**违反了刚写进提示词的那条下限**。
两轮里出现一次。

**不加硬校验**。理由是无修复轮的情况下，按实测频率这会拒掉相当一部分请求，而用户的那句话
本来没问题。正确的处置是本机重算：P0-1d 定的 `镜头时长 = max(语音说完, 动效播完)` 本来就
意味着**模型给的 `start_seconds` / `duration_seconds` 在 PC-08 之后不再是权威**，本机会按
语音与动效两个下限把它撑开。提示词里这条的作用是降低偏差幅度，不是当判据。

这条记进 PC-08 的输入，不留成悬空约束。

## 7. 顺手补上的一道门禁（比 PC-04 本身更重要）

**PyInstaller 规格里的 contracts 是手抄清单。** 我这次新读了一份契约
（`motion-part-usability.v1.json`），如果忘了往规格里加，**开发机全绿、用户装完一句话出片
直接起不来**——因为测试跑在仓库检出里，那份文件本来就在。这正是这个项目栽过的坑。

所以先写门禁让它红，证明缺陷真的存在：

```
$ backend/.venv/bin/python -m pytest .../test_pyinstaller_bundle_contract.py -q
AssertionError: the authoring agent reads ['motion-part-usability.v1.json'] but
automation-tool-executor.spec does not package them; the built Executor would fail
to start the one-sentence path while every repository test still passes
1 failed, 6 passed
```

再补规格 → 绿。门禁是**派生式**的：扫 `motion_authoring` 包所有 `.py` 里的
`xxx.v1.json` 字面量，与规格里的资源清单按文件名比对；另一条同样派生地检查锁定 workflow
契约 pin 的每个文件都在规格里。**下一次新增契约读取无需任何人记得加测试。**
