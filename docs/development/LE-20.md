# LE-20 中文字体扩充与装配

状态：待双平台实包验收

用户可操作：是

## 边界与拆分

LE-09 交付的是字幕字体注册表、cmap fallback 和 fail-closed 机制；本任务负责先量化真实生产字体的缺口，再决定扩充，并把最终注册表中的每个字体装入真实 Worker 包、增加出厂门禁和用户选择入口。

本任务按以下可独立审查、可独立验收的单元推进：

1. T1：字体覆盖审计与引入决策；
2. T2：补充字体的版本/SHA/许可证/SBOM 锁定；
3. T3：生产包装配路径与出厂门禁；
4. T4：用户可选字体；
5. T5：macOS/Windows 实包、体积与 LE 级全量验收。

## T1 字体覆盖审计与引入决策

状态：已完成

### 口径

- Unicode 范围固定为 Unicode 17.0 第 18 章列出的基本区、扩展 A、扩展 B～J；扩展 I 按码位顺序位于 F 与 G 之间。
- 分母使用每个固定区块的全部码位槽，而不是宿主 Python 的 `unicodedata`，因此升级 Python 不会悄悄改变结果。
- 输入只接受 `KEY=PATH`，报告只输出计数与 `U+XXXX`，不回显字体路径或字幕原文。
- 基线是 rights register 已锁定 SHA-256 的 `NotoSansCJKsc-Regular.ttf`，不是系统字体，也不是与生产不一致的测试字体。

固定契约：`contracts/quality/caption-font-coverage.v1.json`。

## T3 生产包装配路径与出厂门禁

### TDD 与实现

RED 有两层：

1. rights 已新增 P1/P2 后，既有 `test_the_registry_matches_the_cleared_faces_in_the_rights_register` 失败，明确指出运行时注册表缺 `PlangothicP1-Regular.ttf` 与 `PlangothicP2-Regular.ttf`；

- PyInstaller spec 先用 rights 驱动的缓存把 Noto/遍黑提供给上游 WebUI，再遍历 `REGISTERED_CAPTION_FONTS`，对每个 key 调用运行时自己的 `resolve_font_file()` 与 `packaged_relative_path()`，装入 `_internal/fonts/<bundle>/...`；没有在 spec 重写文件名或目录布局。
- Noto 与遍黑的两份许可证从已验缓存复制；Big Shoulders 的字体继续使用仓库内锁定 WOFF2，其上游 OFL 文本按既有 SHA `338f9c…08771` 加入仓库并从 rights 的 `licensePath` 复制。
- 既有上游字体门禁改为验证全部四面获取字体和两份许可证的真实字节；新增运行时门禁逐个验证 5 面字体的精确路径、非符号链接、SHA/长度、Unicode cmap、fontTools 解析、Pillow 加载、name ID 0 attribution，以及 3 份许可证的 SHA/长度/OFL marker。
