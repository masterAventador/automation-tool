# LE-20 中文字体扩充与装配

状态：进行中

## 边界与拆分

LE-09 交付的是字幕字体注册表、cmap fallback 和 fail-closed 机制；本任务负责先量化真实生产字体的缺口，再决定扩充，并把最终注册表中的每个字体装入真实 Worker 包、增加出厂门禁和用户选择入口。

本任务按以下可独立审查、可独立验收的单元推进：

1. T1：字体覆盖审计与引入决策；
2. T2：补充字体的版本/SHA/许可证/SBOM 锁定；
3. T3：生产包装配路径与出厂门禁；
4. T4：用户可选字体；
5. T5：macOS/Windows 实包、体积与 LE 级全量验收。

## T1 字体覆盖审计与引入决策

状态：已完成

### 口径

- Unicode 范围固定为 Unicode 17.0 第 18 章列出的基本区、扩展 A、扩展 B～J；扩展 I 按码位顺序位于 F 与 G 之间。
- 分母使用每个固定区块的全部码位槽，而不是宿主 Python 的 `unicodedata`，因此升级 Python 不会悄悄改变结果。
- 输入只接受 `KEY=PATH`，报告只输出计数与 `U+XXXX`，不回显字体路径或字幕原文。
- 基线是 rights register 已锁定 SHA-256 的 `NotoSansCJKsc-Regular.ttf`，不是系统字体，也不是与生产不一致的测试字体。

固定契约：`contracts/quality/caption-font-coverage.v1.json`。

### TDD 与实现

RED 先固定六项行为：两面资产的版本化地址/SHA/长度、两份上游许可证、拒绝浮动或旁路下载地址、按字体家族生成独立 SBOM 组件、字体与许可证缓存名不得碰撞，以及覆盖契约必须绑定同一组候选字节。首次运行在生产没有 `candidate.assets`、没有多许可证 API、且缓存碰撞会走到下载校验时按预期失败。

Green 后：

- rights register 新增遍黑体 P1/P2 两项完整分发记录；
- 下载仅允许 Noto Sans2.004、遍黑体 V2.9.5795 Release 与该标签许可证三个固定前缀，最终仍逐文件校验 SHA-256 与长度；
- 字体二进制的 name ID 0 必须与登记 attribution 完全一致；
- 缓存现在携带 4 个字体文件和 2 个各自上游的 OFL 文本，任意同名会在联网前 fail closed；
- `subtitle-fonts` 与 `plangothic-fonts` 两个 UI/SBOM 组件全部从 rights register 派生，不能把不同版权人合并成一条声明；
- App 继续展示标准 OFL-1.1 全文，同时每个组件分别指向其在正式包内随字体分发的上游许可证文件。
