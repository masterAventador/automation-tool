# LE-20 中文字体扩充与装配

状态：进行中

## 边界与拆分

LE-09 交付的是字幕字体注册表、cmap fallback 和 fail-closed 机制；本任务负责先量化真实生产字体的缺口，再决定扩充，并把最终注册表中的每个字体装入真实 Worker 包、增加出厂门禁和用户选择入口。

本任务按以下可独立审查、可独立验收的单元推进：

1. T1：字体覆盖审计与引入决策；
2. T2：补充字体的版本/SHA/许可证/SBOM 锁定；
3. T3：生产包装配路径与出厂门禁；
4. T4：用户可选字体；
5. T5：macOS/Windows 实包、体积与 LE 级全量验收。

## T1 字体覆盖审计与引入决策

状态：已完成

### 口径

- Unicode 范围固定为 Unicode 17.0 第 18 章列出的基本区、扩展 A、扩展 B～J；扩展 I 按码位顺序位于 F 与 G 之间。
- 分母使用每个固定区块的全部码位槽，而不是宿主 Python 的 `unicodedata`，因此升级 Python 不会悄悄改变结果。
- 输入只接受 `KEY=PATH`，报告只输出计数与 `U+XXXX`，不回显字体路径或字幕原文。
- 基线是 rights register 已锁定 SHA-256 的 `NotoSansCJKsc-Regular.ttf`，不是系统字体，也不是与生产不一致的测试字体。

固定契约：`contracts/quality/caption-font-coverage.v1.json`。

### 决策

必须引入补充字体。候选锁定为遍黑体 V2.9.5795 的 P1/P2 两个独立 TTF：官方项目声明覆盖扩展 B～J，字体文件使用 OFL-1.1，并明确允许随软件嵌入、再分发。T2 仍会以实际下载字节的 SHA、长度、字体内 copyright name record 和真实 cmap 复核该声明，不能只信 README。
