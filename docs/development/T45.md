## 结论

Playwright 属于本机 Local Executor，不应进入独立部署的 Control Plane 镜像。原提交把它移入
默认启用的 `executor` 依赖组，让本地开发和执行器仍可直接使用；Dockerfile 构建 Control
Plane 时显式 `--no-group executor`，并同步锁文件和跨语言门禁。

## RED

原任务记录了两条实际断言失败：

- Python 依赖契约：`KeyError: 'executor'`；
- Node 镜像契约：Dockerfile 缺少 `--no-group executor`。

这是在实现前暴露依赖分组和镜像边界缺失的 RED。锁文件更新随后单独提交，便于审查。

## GREEN

- `backend/pyproject.toml` 和 `backend/uv.lock` 形成锁定的 executor 依赖组；
- `backend/Dockerfile` 明确排除该组；
- 离线 uv dry-run 记录确认 Control Plane 环境会移除 Playwright；
- `test_pyinstaller_bundle_contract.py` 守住执行器仍包含浏览器依赖；
- `control-plane-container-boundary.test.mjs`、`browser-packaging-boundary.test.mjs`、
  `deploy/cloud/test_cloud_deployment.py` 和 Chromium 兼容门禁同步通过。

## 失败矩阵

| 场景 | 结果 |
| --- | --- |
| Control Plane 默认安装 executor 组 | Docker/Node 边界测试拒绝 |
| Executor 漏装 Playwright | PyInstaller 包契约拒绝 |
| pyproject 与 uv.lock 漂移 | 锁定安装失败 |
| 容器构建命令以后被改回全组安装 | Dockerfile 文本与部署契约拒绝 |
| 浏览器版本与内置 Chromium 不相容 | 兼容性门禁拒绝 |

## 真实边界

本任务有真实解析和离线依赖解算证据，但没有在原提交内保存一次实际 Docker image 的逐层
`pip/uv` 内容清单。因此可以确认声明、锁和装配命令已收口，不能把它扩张为“某个已部署镜像
已现场核对完全不含 Playwright”。云端部署也不属于本任务授权。
