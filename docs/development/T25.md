## 结论

T25 与 T57b 不完全重叠。T57b 收口的是前端桌面 E2E 入口所有权；保留下来的视频线 Python 驱动仍通过 `wdio.video-studio.conf.ts` 启动真实 Tauri App。

逐项核对后，原问题只剩一个独立前置：

- signed Executor、隔离 PostgreSQL、Control Plane 和编译期启动配置由 `video_studio_startup_harness()` 在每次运行中自产；
- BM-08 与 IM-05 所需的视频 Worker / media toolchain 由各自驱动调用 `prepare_video_runtime.py` 自产；
- embedded-browser 的共享 harness 只会从平台缓存中校验并复制，缓存 manifest 缺失时直接拒绝；它不会在该次驱动中自产，生产命令是 `python3 scripts/desktop_e2e_prerequisites.py`。

因此本任务只向既有 `scripts/gate_prerequisites.py` 注册 `video-e2e-embedded-browser`，没有重复声明已经由驱动自产的资源，也没有改变 registry 结构。

## 失败矩阵

| 情形 | 结果 |
| --- | --- |
| cache manifest 缺失 | `require()` 响亮失败并打印同一声明生成的可执行生产命令 |
| 声明路径与 harness 平台路径漂移 | 单元测试直接比较真实 `embedded_browser_cache()` 结果并失败 |
| producer 指向不存在脚本 | 既有 `ProducersAreReachable` 失败 |
| producer 退出 0 却没有产出 manifest | 既有 `ensure()` 产物后检失败 |
| 已有 cache | `--list` 报 `ok`，不重复构建或下载 |
| 不支持桌面发行物的平台只查看 registry | 使用明确的 `unsupported-<platform>` 缺失路径，不让整份 registry 在 import 阶段崩溃 |
| 误把 Executor / PostgreSQL / Control Plane / 视频 runtime 重复登记 | 本任务通过调用链审计排除；它们继续由各自真实驱动自产 |

## 真实边界与遗留

- 本任务改变的是门禁元数据与可执行补救提示，不是用户产品行为；不启动 App 或 WebDriverIO。
- `scripts/desktop_e2e_prerequisites.py` 只从本机已经下载的锁定 Chromium archive 构建平台 cache；archive 本身缺失时仍会固定失败，不会暗中联网下载。
- T57b 之后仍保留的视频 Python 驱动是否继续有唯一执行者，由 T57b 的独立证据负责；T25 只保证它们缺 shared browser cache 时不再靠口头说明猜补救命令。
