## 交付范围

- “视频制作 → 智能素材成片 → 打开完整制作界面”成为唯一正式入口；React 只接收
  `opened + modelId`，不接收端口、能力路径、密钥或原始 localhost URL。
- Rust 创建任务私有工作区，启动冻结 Python Worker；Worker 在随机 loopback 端口和 32 字节熵的
  能力路径下启动真实 Streamlit WebUI，ready 事件用现有会话令牌签名。
- Tauri 在创建受保护 WebView 前再次请求真实 HTML 入口，404、静态资源缺失或伪造 ready 都会
  fail closed；只允许同端口同能力路径顶层导航，拒绝新窗口和下载。
- 上游 `app`、WebUI、Streamlit 静态资源及插件仍从锁定候选打包；运行时配置、资源副本、任务、上传
  和输出全部落在 RenderJob 私有工作区，不以硬链接把可写任务目录连回 submodule 或冻结包。
- App 关闭制作窗口、退出或启动失败时停止 Worker 及 WebUI 子进程并删除临时工作区。

2026-07-24 的 Windows 原生验收继续得到三项有效 RED：

1. Python `subprocess` 直接执行裸 `pnpm`，无法解析本机的 `pnpm.cmd`，报 `WinError 2`；
2. Rust 隔离 Worker 清空环境后只保留 `SystemRoot/WINDIR`，Streamlit 在 Windows 调用
   `Path.home()` 时无法确定 home；
3. Rust canonicalize 传入 `\\?\C:\...` 扩展路径，上游配置用 `/config.toml` 拼接后触发
   `Errno 22`。

修复后 pnpm 按平台解析；Worker 的 home/AppData/temp 全部指向任务私有 `work` 根而不是宿主
用户目录；已 canonicalize 的 Windows 本地/UNC 扩展路径只在进入上游兼容层前转换成等价普通
路径，containment 校验仍使用规范路径。

## 失败矩阵

- `enableWebUi` 缺失、类型错误、ready 字段组合不完整、端口/路径或签名不匹配：拒绝启动。
- 能力路径不是 `studio-` 加 43 个 URL-safe 字符、HTML 返回非 200/非 HTML/非 Streamlit：不建窗口。
- React/native 返回包含 URL、端口、能力路径、密钥或额外字段：前端协议拒绝。
- 模型未配置、秘密存储损坏、Worker/静态资源缺失、启动超时：只显示固定中文错误。
- WebView 跳出精确 loopback origin/能力路径、打开新窗口或下载：拒绝。
- 配置、任务或 storage 写入 submodule/冻结包，任务私有根出现 symlink/reparse：验收失败。
- 窗口关闭、App 退出、Worker 异常或 WebView 创建失败：停止完整进程树并清理当前任务工作区。
- Windows pnpm 入口未解析到 `.cmd`、Worker 继承宿主用户 home/cache/temp，或上游收到
  `\\?\` 扩展路径：回归契约拒绝。
