## 结论

Time Machine 或迁移助理可能把 App 私有视频目录权限恢复得过宽。原逻辑只检查并拒绝，导致
启动失败；修复后 Unix 使用不跟随软链的打开方式，复核 dev/inode 后执行 `fchmod 0700`，
并清掉 setgid/sticky 等多余位。只有修复本身失败才拒绝启动。

## RED

迁移权限测试在实现前实际失败：

`restarted store: VideoWorkspaceError { code: PathRejected }`

说明目录仅因权限漂移就无法重新打开，没有自愈。

## GREEN

- `startup_repairs_migrated_private_directory_permissions` 在真实临时目录上修改 mode 后重启；
- 普通过宽、setgid、sticky 权限均恢复为 0700；
- 修复前后复核目录身份，拒绝软链/替换竞争；
- 第二批最终 Rust 门禁记录为 420 项通过、12 项忽略。

## 失败矩阵

| 场景 | 结果 |
| --- | --- |
| 目录 mode 过宽 | 安全打开后修为 0700 |
| setgid/sticky 位残留 | 一并清除 |
| 目录在检查与修复间被替换 | dev/inode 复核失败，拒绝 |
| 路径是软链 | `O_NOFOLLOW`/既有路径门禁拒绝 |
| chmod 权限拒绝 | 响亮失败，不声称已修 |
| Windows ACL 漂移 | 本 Unix 实现不覆盖，不能由 macOS 测试代替 |

## 真实边界

macOS/Unix 权限操作使用真实文件系统调用，不是 Mock。没有在正式安装 App、Time Machine
恢复样本或 Windows ACL 上完成用户路径验收，因此这些边界保持明确。

## 清理

临时目录由测试夹具回收；不修改用户 AppData，不触碰其他 worktree。
